# payouts Specification

## Purpose

Выплаты инструктора (СБП, мок в MVP): заявка на вывод (банк, телефон) →
подтверждение оператором → выплата. Заявка не замораживает баланс —
списание происходит при подтверждении с гардом достаточности. Реальный
провайдер подключается на место мока без изменения контрактов.

## Requirements

### Requirement: Заявка вывода средств по СБП (мок)

Инструктор MUST уметь подать заявку вывода (мок СБП): сумма ≤ доступного
баланса; банк (Сбер/другие банки РФ) и телефон СБП обязательны. Заявки —
в ОТДЕЛЬНОЙ таблице payouts. Активная заявка — не более одной на
инструктора (гвард + частичный UNIQUE). Заявка баланс не меняет; списание
— при подтверждении оператором. Банк/телефон видны только владельцу и
оператору, в логи не попадают.

Источник: решение Заказчика 2026-11-14; FR-111; NFR-35/36.

#### Scenario: Заявка вывода создается

- **GIVEN** инструктор с балансом, большим нуля
- **WHEN** он подает заявку (сумма ≤ баланс, банк, телефон)
- **THEN** запись payouts со статусом «заявка» создана; баланс не изменился; заявка видна инструктору в списке своих выплат

#### Scenario: Сумма больше баланса отклоняется

- **GIVEN** баланс инструктора меньше запрошенной суммы
- **WHEN** заявка подается
- **THEN** сервер отклоняет запрос (ошибка валидации), записи нет

#### Scenario: Вторая активная заявка отклоняется

- **GIVEN** у инструктора есть неподтвержденная заявка вывода
- **WHEN** он подает еще одну заявку (в том числе параллельными запросами)
- **THEN** повторная подача отклоняется (конфликт); в БД — не более одной активной заявки инструктора (частичный UNIQUE)

#### Scenario: Мок без внешних интеграций

- **GIVEN** исходники контура выплат
- **WHEN** выполняется grep-гард QA-контура
- **THEN** внешних сетевых вызовов нет (httpx/requests/urlopen отсутствуют); канал sbp захардкожен как мок

### Requirement: Подтверждение выплаты оператором

Оператор MUST уметь подтвердить активную заявку («выплачено»): создается
журнальная транзакция payout, баланс инструктора уменьшается, статус —
«выплачено» с временем. Подтверждение идемпотентно (ровно одна
payout-транзакция на заявку). При недостатке баланса на момент
подтверждения действие отклоняется с объяснением, заявка остается
активной, списания нет.

Источник: решение Заказчика 2026-11-14; FR-112; NFR-34/35.

#### Scenario: Подтверждение списывает баланс один раз

- **GIVEN** активная заявка вывода с суммой ≤ текущего баланса
- **WHEN** оператор подтверждает выплату (в том числе повторным нажатием/параллельным запросом)
- **THEN** создана ровно одна транзакция payout, баланс уменьшился на сумму, статус «выплачено», время зафиксировано

#### Scenario: Недостача к моменту подтверждения

- **GIVEN** активная заявка, суммарные списания уменьшили баланс ниже суммы заявки
- **WHEN** оператор подтверждает выплату
- **THEN** подтверждение отклонено с объяснением (деньги не списаны, транзакции нет), заявка осталась активной

#### Scenario: Подтвердить чужую/уже выплаченную нельзя

- **GIVEN** заявка другого инструктора или уже в статусе «выплачено»
- **WHEN** оператор повторно пытается подтвердить
- **THEN** действие отклонено (конфликт), дубль-транзакции нет
