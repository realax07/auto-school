# Frontend Specification

## Purpose

Каркас фронтенда Vue 3 + Vite: постраничная миграция (multi-entry MPA), vendor-сплит с бюджетами NFR-26, сохранение e2e (NFR-27); пилот — «Ожидание модерации».

## Requirements

### Requirement: Каркас сборки Vue 3 + Vite — multi-entry, страница = отдельная точка входа

Мигрированные страницы MUST собираться каркасом Vue 3 + Vite, где каждая
страница — самостоятельная точка входа и собственный чанк (multi-entry
MPA); монолитный SPA с клиентским роутером ЗАПРЕЩЕН (директива Заказчика
ОВ-3). Мигрированная страница MUST отдаваться по своему существующему
маршруту сервиса; немигрированные страницы MUST продолжать отдаваться
как прежде. Стек и каркас MUST быть зафиксированы ADR-008.

Источник: requirements-sprint9.md FR-84, FR-86; ОВ-3, ОВ-4.

#### Scenario: Пилотная страница обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** гость открывает /instructors/pending
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /instructors/pending не изменился

#### Scenario: Немигрированные страницы живут как есть

- **GIVEN** мигрирована только пилотная страница
- **WHEN** открыт любой из остальных существующих маршрутов страниц
- **THEN** страница отдается как прежде (legacy-HTML из frontend/), без сборки и правок

#### Scenario: Клиентский роутер не вводится

- **GIVEN** открыта мигрированная страница
- **WHEN** пользователь переходит по ссылкам на другие страницы сервиса
- **THEN** переход выполняется обычной навигацией (загрузка целевой страницы по ее маршруту), монолитного SPA-роутинга нет

### Requirement: Vendor-сплит библиотек и бюджеты чанков (NFR-26)

Сборка MUST выносить библиотеки (runtime Vue и сторонние пакеты) в
отдельные vendor-чанки; вендорный код MUST отсутствовать в чанках страниц
(ОВ-3). Каждый vendor-чанк MUST быть ≤ 150 КБ в gzip; суммарный JS первого
захода КАЖДОЙ мигрированной страницы (чанк страницы + загружаемые ею
чанки) — ≤ 200 КБ
в gzip. Страница MUST загружать только свои чанки и требуемые vendor-чанки.
Бюджеты MUST проверяться на артефактах сборки.

Источник: requirements-sprint9.md FR-84, NFR-26; ОВ-3.

#### Scenario: Артефакты сборки содержат раздельные чанки

- **GIVEN** сборка выполнена
- **WHEN** просмотрены артефакты dist
- **THEN** есть отдельные vendor-чанки (runtime Vue) и чанки мигрированных страниц; вендорный код отсутствует внутри чанка страницы; каждый vendor-чанк ≤ 150 КБ gzip

#### Scenario: Бюджет JS первого захода мигрированной страницы

- **GIVEN** сборка выполнена
- **WHEN** просчитан суммарный gzip-размер JavaScript первого захода мигрированной страницы (чанк страницы + все загружаемые им чанки)
- **THEN** сумма ≤ 200 КБ gzip; фактические размеры чанков зафиксированы на приемке

#### Scenario: Страница загружает только свои чанки

- **GIVEN** открыта пилотная страница
- **WHEN** просмотрены сетевые запросы страницы
- **THEN** загружаются только ее чанк и требуемые vendor/общие чанки; код немигрированных страниц не загружается

### Requirement: Постраничная миграция — страница заменяет HTML-монолит целиком

Миграция MUST выполняться постранично: мигрированная страница заменяет
HTML-монолит целиком — маршрут начинает отдавать вход нового каркаса,
исходный HTML-файл монолита удаляется. МИГРАЦИЯ ЗАВЕРШЕНА (Спринт 15):
легаси-монолитов в frontend/ не осталось, каталог js/ удален целиком.
Правила vendor-сплита и план MUST быть зафиксированы в ADR (ADR-008);
параллельное существование двух версий одной страницы не допускается.

Источник: FR-84, FR-86; ОВ-3, ОВ-4; решение 2026-11-12 (финал).

#### Scenario: Мигрированная страница не оставляет legacy-версии

- **GIVEN** страница мигрирована
- **WHEN** проверены исходники сервиса
- **THEN** frontend/<page>.html удален, маршрут отдает вход каркаса; после Спринта 15 легаси-HTML-монолитов и каталога js/ в frontend/ НЕТ (финал миграции — 14 входов каркаса)

#### Scenario: ADR фиксирует план и правила миграции

- **GIVEN** ADR-008 открыт
- **WHEN** проверено его содержание
- **THEN** в нем зафиксированы стек, план страниц на Спринты 9–15, правила vendor-сплита и критерий приема (зеленый полный e2e)

### Requirement: Сохранение Playwright e2e без правок сценариев (NFR-27)

Существующие e2e-сценарии (tests/test_ui_playwright.py — 49 сценариев)
MUST остаться без правок и оставаться зелеными на мигрированных
страницах; шаг миграции принимается только при зеленом прогоне всего
набора в том же контуре. Маршруты страниц и публичные API-контракты
MUST не меняться ломающим образом. Прогон e2e MUST выполняться против
собранных артефактов каркаса (сборка dist — обязательный шаг перед
прогоном).

Источник: requirements-sprint9.md FR-85, NFR-27.

#### Scenario: Полный набор e2e зеленый после миграции пилота

- **GIVEN** пилотная страница мигрирована на Vue
- **WHEN** выполняется полный прогон набора e2e без правок сценариев
- **THEN** все 49 сценариев зеленые; файлы сценариев не изменены

#### Scenario: Сценарий «анкета → экран ожидания» проходит на Vue-странице

- **GIVEN** сценарий e2e «анкета инструктора → /instructors/pending» (TC-UI-004) без правок
- **WHEN** анкета отправлена на мигрированном контуре
- **THEN** редирект на /instructors/pending и заголовок экрана ожидания (h1 «Заявка на рассмотрении») совпадают с ожиданиями существующего сценария

#### Scenario: Маршруты и API не ломаются

- **GIVEN** шаг миграции выполнен
- **WHEN** проверены маршруты страниц и публичные API
- **THEN** существующие маршруты отвечают как прежде; /api/* не изменены; новая статика каркаса — добавление, а не изменение контрактов

### Requirement: Пилотная страница «Ожидание модерации» на Vue (FR-86, ОВ-4)

Страница /instructors/pending MUST быть переведена на Vue 3 + Vite и
реализовать на новом стеке функциональность блока 2 ТЗ (опрос статуса
заявки, переходы waiting→approved / waiting→rejected, остановка опроса
при уходе) по контракту change add-application-status-polling
(зависимый пакет). Визуальный результат MUST быть эквивалентен текущему
экрану (без редизайна).

Источник: FR-80…83, FR-86, NFR-28; ОВ-4; зависимость —
add-application-status-polling (задача 9.2).

#### Scenario: Страница обслуживается новым каркасом

- **GIVEN** пилотная страница открыта
- **WHEN** просмотрены обслуживаемые ресурсы
- **THEN** страница собрана каркасом Vue 3 + Vite (чанк страницы + vendor-чанки Vue), а не legacy-HTML-монолитом

#### Scenario: Функциональность блока 2 выполняется на Vue-версии

- **GIVEN** заявка в статусе waiting и экран ожидания открыт с сохраненным идентификатором заявки
- **WHEN** статус меняется админом на approved или rejected
- **THEN** на Vue-версии страницы выполняются переходы блока 2: approved — бесшовный переход в кабинет инструктора, rejected — показ статуса «заявка отклонена» с причиной отказа; опрос останавливается при уходе со страницы; интервал опроса — в границах блока 2 (10–15 с)

#### Scenario: Статический режим без идентификатора сохраняется

- **GIVEN** экран /instructors/pending открыт без сохраненного идентификатора заявки (прямая ссылка)
- **WHEN** просмотрены сетевые запросы страницы
- **THEN** страница показывает статический текст без запросов статуса и без ошибок

#### Scenario: Визуальная эквивалентность текущему экрану

- **GIVEN** сравнение мигрированной страницы с текущим экраном ожидания
- **WHEN** выполнено сопоставление содержимого
- **THEN** визуальная эквивалентность без редизайна: шапка, карточка статуса с заголовком «Заявка на рассмотрении», шаги 01/02/03, кнопки действий, футер

### Requirement: Статусный экран отказа заявки на Vue (/instructors/rejected)

Страница /instructors/rejected MUST обслуживаться каркасом Vue 3 + Vite —
точкой входа из dist; legacy html и js страницы MUST быть удалены (замена
монолита целиком). Причина отказа MUST приходить из ответа логина
(route/reason → sessionStorage «instructor_rejected_reason», контракт
логина не меняется); пустое/нет — экран без персональной причины;
статусные запросы при загрузке не выполняются; вид — без редизайна.

Источник: FR-13, FR-17, FR-84…86; NFR-27; ADR-008.

#### Scenario: Экран обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** гость открывает /instructors/rejected
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /instructors/rejected не изменился

#### Scenario: Причина отказа — из ответа логина, контракт не меняется

- **GIVEN** вход выполнен с email заявки в статусе deny с комментарием C (логин отвечает route=rejected и reason=C, модалка входа пишет sessionStorage «instructor_rejected_reason»)
- **WHEN** открыт экран /instructors/rejected
- **THEN** причина C видна на экране (элемент #reason-text) без входа и перелогина; сценарий TC-S9UI-003 проходит без правок; механика записи причины (login route/reason) не изменена

#### Scenario: Без причины — блок скрыт, запросов нет

- **GIVEN** экран /instructors/rejected открыт по прямой ссылке (ключа нет или пуст)
- **WHEN** просмотрены содержимое страницы и сетевые запросы
- **THEN** блок причины скрыт (персональная причина не раскрывается); статусные запросы при загрузке отсутствуют (0 обращений к API)

#### Scenario: Визуальная эквивалентность текущему экрану

- **GIVEN** сравнение Vue-версии с текущим экраном отказа
- **WHEN** выполнено сопоставление содержимого
- **THEN** эквивалентность без редизайна: шапка (бренд, «← Вернуться на лендинг»), карточка (kicker «Заявка инструктора», h1 «Заявка отклонена», пояснение), блок «Причина отказа», кнопки «На главную» / «О лендинге для инструкторов», футер

### Requirement: Форма отзыва на Vue (/review)

Страница /review MUST обслуживаться каркасом Vue 3 + Vite — точкой входа
из dist; legacy review-form.html и js/review-form.js MUST быть удалены
(замена монолита целиком). Wiring MUST воспроизводиться 1:1: query
?instructor=; без идентификатора — редирект на /my-requests (301 →
/cabinet#/my-requests); состояния «форма»/«уже оставлен» — данными
сервера; тосты и ошибки — как в legacy. Контракт POST отзыва MUST
не изменяться.

Источник: FR-5, FR-34, FR-35; FR-84…86; NFR-2/5/27; TC-UI-017/018.

#### Scenario: Страница обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** ученик открывает /review?instructor=<id>
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /review и query-параметр не изменились

#### Scenario: Контекст инструктора и переход из «Моих заявок»

- **GIVEN** ученик с принятой заявкой в «Моих заявках» кабинета
- **WHEN** он переходит на форму отзыва и открыт /review?instructor=<id>
- **THEN** карточка инструктора заполнена из GET /api/student/instructors/{id} (ФИО #i-name, стаж/авто, агрегат рейтинга); сценарий TC-UI-018 проходит без правок

#### Scenario: Отправка отзыва и повтор 409

- **GIVEN** ученик с сессией на /review?instructor=<id> (TC-UI-017 без правок)
- **WHEN** выбрана оценка и введен текст, отзыв отправлен; затем повторная попытка после reload
- **THEN** первый сабмит (200) — состояние «Отправлен» (#view-done, #done-title «Отзыв отправлен», #view-form скрыта) и тост; повторный сабмит (409) — состояние «уже оставлен» (#done-title «Отзыв уже отправлен»); прямой повторный POST — 409 (NFR-2/NFR-5, контракт прежний)

#### Scenario: Без ?instructor= — редирект в кабинет

- **GIVEN** открыт /review без query-параметра instructor
- **WHEN** выполнен переход
- **THEN** страница перенаправляет на /my-requests, который отдает 301 → /cabinet#/my-requests (раздел «Мои заявки» внутри кабинета, BUG-047); редирект-контракт не изменен

#### Scenario: Ошибки формы — тосты как в legacy

- **GIVEN** ученик на форме отзыва
- **WHEN** сервер отвечает 401, 403 или прочей ошибкой (инструктор не найден — 404 контекста)
- **THEN** реакции 1:1 как в legacy: 401 — редирект на вход; 403 — бизнес-ошибка тостом (без редиректа, NFR-2); прочие — тост ошибки сервера либо «Не удалось отправить отзыв»; длительность и тексты тостов сохранены

### Requirement: Лендинг ученика на Vue (/)

Страница / MUST обслуживаться каркасом Vue 3 + Vite (вход из dist);
legacy index.html и js/landing.js MUST быть удалены (монолит целиком).
Модалки входа/регистрации MUST быть вынесены в shared-компоненты
каркаса (разметка 1:1). Контракт входа (route/reason → sessionStorage
«instructor_rejected_reason» до редиректа) и регистрации (согласие
FR-78) MUST не изменяться; вид — без редизайна.

Источник: FR-1/2/13/17/78; FR-84…86; NFR-26/27; ADR-008.

#### Scenario: Лендинг обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** гость открывает /
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут / не изменился; legacy index.html и js/landing.js отсутствуют в исходниках

#### Scenario: Вход — route/reason контракт не меняется, включая rejected

- **GIVEN** вход из модалки m-login на Vue-лендинге с email заявки в статусе deny с комментарием C (логин отвечает route=rejected и reason=C)
- **WHEN** ответ получен
- **THEN** Vue-wiring модалки пишет sessionStorage «instructor_rejected_reason»=C ДО редиректа на /instructors/rejected (сценарий TC-S9UI-003 проходит без правок); approved → /instructor/dashboard, waiting → /instructors/pending, ученик → /cabinet; ошибка — текст сервера в #login-error

#### Scenario: Регистрация — согласие обязательно (FR-78)

- **GIVEN** модалка m-register на Vue-лендинге (TC-UI-002/043 без правок)
- **WHEN** чекбокс согласия снят / установлен
- **THEN** #reg-submit недоступен до установки и выполняет POST /api/register с consent после нее (200 → сессия и /cabinet; 422 — текст сервера в #reg-error); ссылка на /policy видна в блоке согласия

#### Scenario: Семантика модалок и заглушки сохранены

- **GIVEN** гость на Vue-лендинге
- **WHEN** открыты/закрыты модалки и нажаты элементы-заглушки
- **THEN** крестик #login-close, «Отмена» и Esc закрывают, клик по фону НЕ закрывает #m-login (BUG-055/056, TC-UI-053 без правок); чат-бар «Гига ГАИшник», .quick и #to-teachers ведут себя как в legacy (визуальные заглушки); TC-UI-001 проходит без правок

#### Scenario: Визуальная эквивалентность текущему лендингу

- **GIVEN** сравнение Vue-версии с текущим лендингом
- **WHEN** выполнено сопоставление содержимого
- **THEN** эквивалентность без редизайна: шапка с брендом, hero «Права — без лишнего пути.», шаги 01–04, чат-бар «Гига ГАИшник», плитки сервисов и футер — тексты дословно

### Requirement: Анкета инструктора на Vue (/instructors/apply)

Страница /instructors/apply MUST обслуживаться каркасом Vue 3 + Vite
(вход из dist); legacy instructor-apply.html и js/apply.js MUST быть
удалены (монолит целиком). Wiring MUST быть 1:1: multipart POST
/api/instructors/apply (поля + license_photo), согласие обязательно
(FR-77: кнопка блокирована до чекбокса; 422 позиция 1a), файловые
ошибки у поля ВУ, 200 → токены опроса и редирект
/instructors/pending; вид — без редизайна.

Источник: FR-10…12, FR-77; FR-84…86; NFR-26/27; ADR-008.

#### Scenario: Анкета обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** пользователь открывает /instructors/apply
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /instructors/apply не изменился

#### Scenario: Валидная анкета — экран ожидания, контракт не меняется

- **GIVEN** заполненная анкета с фото ВУ и установленным согласием (TC-UI-004 без правок)
- **WHEN** отправлена multipart-форма
- **THEN** POST /api/instructors/apply содержит те же поля и license_photo; 200 → application_poll_token/application_exchange_token в localStorage ДО редиректа на /instructors/pending (h1 «Заявка на рассмотрении»); механика опроса (С9) не изменена

#### Scenario: Согласие обязательно — 422 позиция 1a (FR-77)

- **GIVEN** анкета заполнена, чекбокс согласия не установлен
- **WHEN** пользователь пытается отправить форму / отправляет POST напрямую
- **THEN** кнопка сабмита недоступна на клиенте; прямой POST без согласия отвечает 422 {ok:false, error:"Согласие: поле обязательно"} — контракт сервера не изменен, заявка не создана

#### Scenario: Ошибки файла ВУ — видимое сообщение у поля загрузки

- **GIVEN** выбран файл ВУ больше 5 МБ / не-JPEG-PNG, либо сервер отвечает 413/415
- **WHEN** валидация выполнена / форма отправлена
