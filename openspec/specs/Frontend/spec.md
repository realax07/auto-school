# Frontend Specification

## Purpose

Каркас фронтенда Vue 3 + Vite: постраничная миграция (multi-entry MPA), vendor-сплит с бюджетами NFR-26, сохранение e2e (NFR-27); пилот — «Ожидание модерации».

## Requirements

### Requirement: Каркас сборки Vue 3 + Vite — multi-entry, страница = отдельная точка входа

Мигрированные страницы MUST собираться каркасом Vue 3 + Vite, где каждая
страница — самостоятельная точка входа и собственный чанк (multi-entry
MPA); монолитный SPA с клиентским роутером ЗАПРЕЩЕН (директива Заказчика
ОВ-3). Мигрированная страница MUST отдаваться по своему существующему
маршруту сервиса; немигрированные страницы MUST продолжать отдаваться
как прежде. Стек и каркас MUST быть зафиксированы ADR-008.

Источник: requirements-sprint9.md FR-84, FR-86; ОВ-3, ОВ-4.

#### Scenario: Пилотная страница обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** гость открывает /instructors/pending
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /instructors/pending не изменился

#### Scenario: Немигрированные страницы живут как есть

- **GIVEN** мигрирована только пилотная страница
- **WHEN** открыт любой из остальных существующих маршрутов страниц
- **THEN** страница отдается как прежде (legacy-HTML из frontend/), без сборки и правок

#### Scenario: Клиентский роутер не вводится

- **GIVEN** открыта мигрированная страница
- **WHEN** пользователь переходит по ссылкам на другие страницы сервиса
- **THEN** переход выполняется обычной навигацией (загрузка целевой страницы по ее маршруту), монолитного SPA-роутинга нет

### Requirement: Vendor-сплит библиотек и бюджеты чанков (NFR-26)

Сборка MUST выносить библиотеки (runtime Vue и сторонние пакеты) в
отдельные vendor-чанки; вендорный код MUST отсутствовать в чанках страниц
(ОВ-3). Каждый vendor-чанк MUST быть ≤ 150 КБ в gzip; суммарный JS первого
захода пилотной страницы (чанк страницы + загружаемые ею чанки) — ≤ 200 КБ
в gzip. Страница MUST загружать только свои чанки и требуемые vendor-чанки.
Бюджеты MUST проверяться на артефактах сборки.

Источник: requirements-sprint9.md FR-84, NFR-26; ОВ-3.

#### Scenario: Артефакты сборки содержат раздельные чанки

- **GIVEN** сборка выполнена
- **WHEN** просмотрены артефакты dist
- **THEN** есть отдельные vendor-чанки (runtime Vue) и чанк пилотной страницы; вендорный код отсутствует внутри чанка страницы; каждый vendor-чанк ≤ 150 КБ gzip

#### Scenario: Бюджет JS первого захода пилотной страницы

- **GIVEN** сборка выполнена
- **WHEN** просчитан суммарный gzip-размер JavaScript первого захода пилотной страницы (чанк страницы + все загружаемые им чанки)
- **THEN** сумма ≤ 200 КБ gzip; фактические размеры чанков зафиксированы на приемке

#### Scenario: Страница загружает только свои чанки

- **GIVEN** открыта пилотная страница
- **WHEN** просмотрены сетевые запросы страницы
- **THEN** загружаются только ее чанк и требуемые vendor/общие чанки; код немигрированных страниц не загружается

### Requirement: Постраничная миграция — страница заменяет HTML-монолит целиком

Миграция MUST выполняться постранично: мигрированная страница заменяет
HTML-монолит целиком — маршрут начинает отдавать вход нового каркаса,
исходный HTML-файл монолита удаляется; немигрированные страницы остаются
как есть. План очередности страниц на Спринты 9–11 и правила vendor-сплита
MUST быть зафиксированы в ADR (ADR-008); параллельное существование двух
версий одной страницы не допускается.

Источник: requirements-sprint9.md FR-84, FR-86; ОВ-3, ОВ-4; директива
«без большого переписывания».

#### Scenario: Мигрированная страница не оставляет legacy-версии

- **GIVEN** пилотная страница мигрирована
- **WHEN** проверены исходники сервиса
- **THEN** frontend/instructor-pending.html удален, маршрут /instructors/pending отдает вход каркаса; остальные 12 HTML-монолитов присутствуют без изменений

#### Scenario: ADR фиксирует план и правила миграции

- **GIVEN** ADR-008 открыт
- **WHEN** проверено его содержание
- **THEN** в нем зафиксированы стек, план страниц на Спринты 9–11, правила vendor-сплита и критерий приема (зеленый полный e2e)

### Requirement: Сохранение Playwright e2e без правок сценариев (NFR-27)

Существующие e2e-сценарии (tests/test_ui_playwright.py — 49 сценариев)
MUST остаться без правок и оставаться зелеными на мигрированных
страницах; шаг миграции принимается только при зеленом прогоне всего
набора в том же контуре. Маршруты страниц и публичные API-контракты
MUST не меняться ломающим образом. Прогон e2e MUST выполняться против
собранных артефактов каркаса (сборка dist — обязательный шаг перед
прогоном).

Источник: requirements-sprint9.md FR-85, NFR-27.

#### Scenario: Полный набор e2e зеленый после миграции пилота

- **GIVEN** пилотная страница мигрирована на Vue
- **WHEN** выполняется полный прогон набора e2e без правок сценариев
- **THEN** все 49 сценариев зеленые; файлы сценариев не изменены

#### Scenario: Сценарий «анкета → экран ожидания» проходит на Vue-странице

- **GIVEN** сценарий e2e «анкета инструктора → /instructors/pending» (TC-UI-004) без правок
- **WHEN** анкета отправлена на мигрированном контуре
- **THEN** редирект на /instructors/pending и заголовок экрана ожидания (h1 «Заявка на рассмотрении») совпадают с ожиданиями существующего сценария

#### Scenario: Маршруты и API не ломаются

- **GIVEN** шаг миграции выполнен
- **WHEN** проверены маршруты страниц и публичные API
- **THEN** существующие маршруты отвечают как прежде; /api/* не изменены; новая статика каркаса — добавление, а не изменение контрактов

### Requirement: Пилотная страница «Ожидание модерации» на Vue (FR-86, ОВ-4)

Страница /instructors/pending MUST быть переведена на Vue 3 + Vite и
реализовать на новом стеке функциональность блока 2 ТЗ (опрос статуса
заявки, переходы waiting→approved / waiting→rejected, остановка опроса
при уходе) по контракту change add-application-status-polling
(зависимый пакет). Визуальный результат MUST быть эквивалентен текущему
экрану (без редизайна).

Источник: FR-80…83, FR-86, NFR-28; ОВ-4; зависимость —
add-application-status-polling (задача 9.2).

#### Scenario: Страница обслуживается новым каркасом

- **GIVEN** пилотная страница открыта
- **WHEN** просмотрены обслуживаемые ресурсы
- **THEN** страница собрана каркасом Vue 3 + Vite (чанк страницы + vendor-чанки Vue), а не legacy-HTML-монолитом

#### Scenario: Функциональность блока 2 выполняется на Vue-версии

- **GIVEN** заявка в статусе waiting и экран ожидания открыт с сохраненным идентификатором заявки
- **WHEN** статус меняется админом на approved или rejected
- **THEN** на Vue-версии страницы выполняются переходы блока 2: approved — бесшовный переход в кабинет инструктора, rejected — показ статуса «заявка отклонена» с причиной отказа; опрос останавливается при уходе со страницы; интервал опроса — в границах блока 2 (10–15 с)

#### Scenario: Статический режим без идентификатора сохраняется

- **GIVEN** экран /instructors/pending открыт без сохраненного идентификатора заявки (прямая ссылка)
- **WHEN** просмотрены сетевые запросы страницы
- **THEN** страница показывает статический текст без запросов статуса и без ошибок

#### Scenario: Визуальная эквивалентность текущему экрану

- **GIVEN** сравнение мигрированной страницы с текущим экраном ожидания
- **WHEN** выполнено сопоставление содержимого
- **THEN** визуальная эквивалентность без редизайна: шапка, карточка статуса с заголовком «Заявка на рассмотрении», шаги 01/02/03, кнопки действий, футер
