# student-instructor-choice Specification

## Purpose

Выбор инструктора учеником: каталог (только validated авто), заявка в пару, статусы заявки.

## Requirements

### Requirement: Каталог одобренных инструкторов для ученика

В кабинете ученика MUST появиться раздел «Выбор инструктора»: карточки
одобренных инструкторов (ФИО, стаж, автомобили, рейтинг, часы работы).
Инструкторы с заявками waiting/deny не участвуют. Автомобили в карточках
и фильтрах каталога — только validated. Доступ — только по валидной
сессии ученика; гость и иные роли каталог не получают (FR-31, ОВ-2).

#### Scenario: Ученик видит карточки одобренных инструкторов

- **GIVEN** существуют одобренные инструкторы с заполненным профилем; ученик с валидной сессией
- **WHEN** ученик открывает раздел «Выбор инструктора»
- **THEN** отображаются карточки одобренных инструкторов с ФИО, стажем, автомобилями, рейтингом и часами работы

#### Scenario: В каталоге участвуют только проверенные автомобили

- **GIVEN** у одобренного инструктора есть автомобили в статусах draft, validating и validated
- **WHEN** новый ученик (без пары) открывает карточку инструктора в каталоге
- **THEN** в карточке показан только validated-автомобиль; draft и validating не отображаются

#### Scenario: Авто-фильтры каталога учитывают только validated

- **GIVEN** в каталоге есть инструкторы, у которых проверен только автомобиль с определенным типом КПП, а авто того же типа в draft/validating
- **WHEN** ученик применяет авто-фильтр по этому типу КПП
- **THEN** фильтр находит инструктора по validated-автомобилям; draft/validating-автомобили в фильтрации не участвуют

#### Scenario: Инструктор без validated-авто остается в каталоге

- **GIVEN** одобренный инструктор, у которого все автомобили в draft/validating (или авто нет)
- **WHEN** ученик открывает каталог
- **THEN** карточка инструктора присутствует с корректным пустым блоком автомобилей (инструктор не исчезает из каталога из-за статуса авто)

#### Scenario: Инструкторы в статусах waiting/deny не попадают в каталог

- **GIVEN** существуют заявки инструкторов в статусах waiting и deny (одобренных нет)
- **WHEN** ученик открывает раздел «Выбор инструктора»
- **THEN** такие инструкторы в списке не участвуют (список пуст — корректное пустое состояние)

#### Scenario: Каталог недоступен без сессии ученика

- **GIVEN** гость без сессии, либо пользователь с ролью 'instructor'
- **WHEN** запрашивается каталог инструкторов
- **THEN** доступ запрещен (401 для гостя, 403 для иной роли), каталог не возвращается

### Requirement: Фильтры каталога

Список инструкторов MUST поддерживать фильтры: машина (наличие/тип авто
по КПП), рейтинг, стаж, свободное время (пересечение с availability).
Применение фильтра оставляет только подходящие карточки; пустой результат
показывает корректное пустое состояние, а не ошибку (трассировка: FR-32).

Источник: requirements-instructor-student-loop.md FR-32.

#### Scenario: Фильтр по типу КПП

- **GIVEN** есть инструкторы с автомобилями на механике и на автомате
- **WHEN** ученик применяет фильтр «механика»
- **THEN** остаются только карточки инструкторов, имеющих автомобиль с механической КПП

#### Scenario: Фильтр по рейтингу

- **GIVEN** есть инструкторы с разными средними рейтингами по отзывам
- **WHEN** ученик применяет фильтр «рейтинг не ниже 4»
- **THEN** остаются только карточки со средней оценкой ≥ 4

#### Scenario: Фильтр по стажу

- **GIVEN** есть инструкторы с разным стажем
- **WHEN** ученик применяет фильтр «стаж от 5 лет»
- **THEN** остаются только карточки инструкторов со стажем ≥ 5 лет

#### Scenario: Фильтр по свободному времени

- **GIVEN** есть инструкторы с разными графиками availability
- **WHEN** ученик применяет фильтр «свободно Пн 10:00–12:00»
- **THEN** остаются только карточки инструкторов, чьи рабочие интервалы понедельника пересекаются с 10:00–12:00

#### Scenario: Пустой результат фильтра — пустое состояние

- **GIVEN** ни один инструктор не подходит под комбинацию фильтров
- **WHEN** ученик применяет фильтры
- **THEN** отображается корректное пустое состояние («ничего не найдено»), а не ошибка

### Requirement: Независимость каталога от картографических сервисов

Карточка инструктора и фильтры MUST работать без картографических
сервисов и гео-данных (точка расширения FR-33): отсутствие гео-привязки
не влияет на работоспособность каталога и не считается ошибкой
(трассировка: FR-33).

Источник: requirements-instructor-student-loop.md FR-33 (вне скоупа, точка расширения).

#### Scenario: Каталог работает без гео-данных

- **GIVEN** картографические сервисы недоступны и гео-данные отсутствуют
- **WHEN** ученик открывает каталог и применяет фильтры
- **THEN** каталог полностью работоспособен: карточки, фильтры и пустые состояния работают как описано выше, без ошибок
