# booking Specification

## Purpose

Бронирование занятий: ученик бронирует слоты графика принятого инструктора; решения по броням — немедленно на слотах календаря; статусы new/confirmed/rejected; отмена (BUG-049).

## Requirements

### Requirement: Расписание инструктора доступно только принятым ученикам

Ученик MUST видеть слоты (рабочие интервалы графика) инструктора
ТОЛЬКО после создания пары (принятая заявка). До принятия заявки (нет
заявки, «новая», «отказана») расписание инструктора недоступно — и в
интерфейсе, и при прямом вызове API. Проверка доступа выполняется на
сервере при каждом запросе; UI-скрытие проверкой не считается
(трассировка: FR-46, NFR-7).

Источник: requirements-booking-docs.md FR-46, NFR-7.

#### Scenario: Не принятому ученику расписание недоступно при прямом вызове API

- **GIVEN** у ученика нет заявки инструктору, или заявка «новая», или «отказана»
- **WHEN** он (в том числе прямым запросом к API) пытается открыть слоты инструктора
- **THEN** доступ запрещен, расписание не возвращается

#### Scenario: Принятый ученик видит актуальный график

- **GIVEN** заявка ученика принята (пара создана), у инструктора заполнен график
- **WHEN** ученик открывает раздел расписания
- **THEN** он видит актуальные интервалы графика инструктора

#### Scenario: Гость и иная роль не получают расписание

- **GIVEN** гость без сессии или пользователь с ролью «инструктор»
- **WHEN** запрашиваются слоты через ученический эндпоинт расписания
- **THEN** доступ запрещен (401 для гостя, 403 для иной роли), расписание не возвращается

### Requirement: Запрос брони на слот

Ученик пары MUST уметь выбрать слот графика инструктора (интервал
целиком, ОВ-3) и отправить запрос брони («новая»). Бронь
MUST быть только на будущих экземплярах — начало строго позже текущего
момента МСК, иначе отклонение сервером (FR-96/NFR-31); бронь MUST
фиксироваться на дате экземпляра (разовый — его дата; повторяющийся —
дата недели брони; поле даты аддитивно, без даты — ближайший будущий
экземпляр). Повторный запрос на занятый слот не создается; после
отклонения — допустим (ОВ-3…ОВ-5).

#### Scenario: Запрос создается со статусом «новая» и виден инструктору

- **GIVEN** пара создана и у инструктора есть свободный будущий слот
- **WHEN** ученик выбирает слот и отправляет запрос брони
- **THEN** запрос создан со статусом «новая» и появляется у инструктора в запросах брони

#### Scenario: Занятый слот не бронируется повторно

- **GIVEN** у слота есть активный запрос или подтвержденная бронь одного ученика пары
- **WHEN** другой ученик той же пары пытается забронировать этот слот
- **THEN** действие отклонено, дублирующий запрос не создан

#### Scenario: Слот бронируется целиком

- **GIVEN** у инструктора есть интервал графика 10:00–14:00
- **WHEN** ученик бронирует этот слот
- **THEN** занятием считается весь интервал 10:00–14:00 (нарезка на подынтервалы не выполняется)

#### Scenario: Повторный запрос после отклонения допустим

- **GIVEN** запрос брони ученика на слот отклонен инструктором (с комментарием)
- **WHEN** ученик снова отправляет запрос на этот же слот
- **THEN** новый запрос создается (повторная подача не ограничена)

#### Scenario: Бронь фиксируется на конкретной дате экземпляра

- **GIVEN** повторяющийся слот «Чт 16:00–18:00», ученик бронирует экземпляр на 12 ноября
- **WHEN** запрос брони отправлен с этой датой
- **THEN** бронь создана именно на 12 ноября 16:00–18:00 (дата экземпляра зафиксирована в записи брони); запрос с датой, не попадающей на день недели серии (или не равной дате разового слота), отклоняется сервером

#### Scenario: Запрос брони на прошедший или начавшийся слот отклоняется сервером

- **GIVEN** слот сегодня 10:00–12:00 при текущем времени 14:30 (или дата слота прошла)
- **WHEN** запрос брони на этот слот отправлен, в том числе прямым вызовом API в обход UI
- **THEN** сервер отклоняет запрос ({ok:false}), записи нет; в UI слот отображается без кнопки брони

#### Scenario: Запрос в старом формате (без даты) продолжает приниматься

- **GIVEN** клиент отправляет POST {availability_id} без поля даты на будущий слот
- **WHEN** сервер обрабатывает запрос
- **THEN** запрос принимается без ошибки: бронь создается на ближайшую будущую дату экземпляра серии (прежнее поведение), остальные проверки прежние

### Requirement: Решение инструктора по запросу брони

Инструктор MUST уметь подтвердить или отклонить запрос брони, адресованный
ему. Подтверждение выполняется без комментария и переводит бронь в статус
«подтверждена». Отклонение — с обязательным комментарием (причиной): без
комментария действие недоступно. Статусы брони: новая → подтверждена /
отклонена; комментарий отклонения виден ученику (трассировка: FR-48, ОВ-2).

Источник: requirements-booking-docs.md FR-48; ОВ-2.

#### Scenario: Подтверждение без комментария

- **GIVEN** у инструктора есть входящий запрос брони в статусе «новая»
- **WHEN** инструктор подтверждает бронь
- **THEN** бронь становится «подтверждена» без какого-либо комментария

#### Scenario: Отклонение без комментария заблокировано

- **GIVEN** у инструктора есть входящий запрос брони в статусе «новая»
- **WHEN** инструктор нажимает «Отклонить» с пустым комментарием
- **THEN** действие заблокировано (ошибка валидации), статус брони остается «новая»

#### Scenario: Отклонение с комментарием видно ученику

- **GIVEN** у инструктора есть входящий запрос брони в статусе «новая»
- **WHEN** инструктор вводит комментарий и отклоняет бронь
- **THEN** статус брони — «отклонена», и ученик видит статус и текст комментария

#### Scenario: Чужую бронь решить нельзя

- **GIVEN** запрос брони адресован инструктору А
- **WHEN** инструктор Б (со своей сессией) пытается подтвердить или отклонить этот запрос
- **THEN** действие отклонено, статус брони не меняется

### Requirement: Подтвержденная бронь в календарях обоих

Подтвержденный слот MUST отображаться в календаре ученика (дата,
время, инструктор, автомобиль с фото) и в календаре инструктора (ФИО
ученика, автомобиль пары с фото). Фото выдается с учетом статусной
видимости (validating/validated — да; draft — плейсхолдер; удален —
пустое состояние «—», MIN-3). Виджет «Занятия на сегодня» MUST показывать
реальные подтвержденные брони на текущую дату сервера; при отсутствии —
«Сегодня занятий нет».

#### Scenario: Календарь ученика показывает занятие

- **GIVEN** бронь ученика подтверждена
- **WHEN** ученик открывает свой календарь
- **THEN** слот показан как занятие с датой, временем, инструктором и автомобилем

#### Scenario: Календарь ученика показывает фото прикрепленного авто

- **GIVEN** бронь подтверждена; автомобиль пары в статусе validated (или validating) с загруженным фото
- **WHEN** ученик открывает бронь в своем календаре
- **THEN** рядом с автомобилем отображается его фото, полученное по URL авторизованного эндпоинта выдачи

#### Scenario: Draft-автомобиль в брони — без фото

- **GIVEN** бронь подтверждена; автомобиль пары переведен в статус draft
- **WHEN** ученик открывает бронь в своем календаре
- **THEN** бронь отображается (дата, время, инструктор), на месте авто — плейсхолдер без фото; изображение draft-авто не выдается

#### Scenario: Автомобиль пары удален — пустое состояние без ошибки

- **GIVEN** подтвержденная бронь; автомобиль пары удален (car_id пуст)
- **WHEN** ученик или инструктор открывает календарь
- **THEN** на месте автомобиля — корректное пустое состояние «—», бронь видна, ошибки нет

#### Scenario: Календарь инструктора показывает ученика и автомобиль

- **GIVEN** бронь подтверждена, за парой закреплен автомобиль
- **WHEN** инструктор открывает свой календарь
- **THEN** слот показан с учеником (ФИО) и автомобилем пары с фото

#### Scenario: Перекрепление авто меняет авто в отображении брони

- **GIVEN** подтвержденная бронь с отображаемым автомобилем пары
- **WHEN** инструктор перекрепляет ученика на другой свой автомобиль
- **THEN** в отображении подтвержденной брони показаны новый автомобиль пары и его фото

#### Scenario: Виджет «Занятия на сегодня» показывает реальные брони

- **GIVEN** существуют подтвержденные брони инструктора на текущую дату (локальная дата сервера — правило lesson_date)
- **WHEN** инструктор открывает главную кабинета
- **THEN** виджет «Занятия на сегодня» показывает эти брони (ученик, время)

#### Scenario: Нет броней на сегодня — прежнее пустое состояние

- **GIVEN** подтвержденных броней инструктора на текущую дату нет
- **WHEN** инструктор открывает главную кабинета
- **THEN** виджет показывает «Сегодня занятий нет» (пустое состояние, не ошибка и не фиктивные данные)

### Requirement: Занятый слот недоступен другим ученикам

Занятый слот (активный запрос или подтвержденная бронь) MUST быть
недоступен другим ученикам: не отображается как доступный и не
бронируется повторно; другому ученику пары виден как «занято» без
раскрытия, кем. Занятость — на уровне ЭКЗЕМПЛЯРА, КРОСС-СТРОЧНО
(строки графика, покрывающие дату+время): проверка ВНУТРИ транзакции
создания брони (BEGIN IMMEDIATE, single-writer), внутри строки —
частичный UNIQUE-индекс (availability_id, lesson_date).

#### Scenario: Занятый слот не отображается как доступный

- **GIVEN** экземпляр слота подтвержден ученику А
- **WHEN** ученик Б (другая пара с тем же инструктором) обновляет расписание этой недели
- **THEN** экземпляр недоступен для выбора

#### Scenario: Занятость видна без раскрытия, кем занято

- **GIVEN** экземпляр занят запросом/бронью ученика А
- **WHEN** другой ученик пары смотрит расписание
- **THEN** экземпляр помечен «занято», данные занявшего (кем именно) не раскрываются

#### Scenario: Другие даты повторяющейся серии остаются доступными

- **GIVEN** повторяющийся слот «Чт 16:00–18:00», экземпляр 12 ноября занят бронью ученика А
- **WHEN** ученик Б смотрит будущие недели
- **THEN** экземпляры серии на другие даты (например, 19 ноября) доступны для бронирования; занят только экземпляр 12 ноября

#### Scenario: Параллельные запросы на один слот — максимум одна бронь

- **GIVEN** два запроса брони на один экземпляр слота (дата+время) обрабатываются одновременно
- **WHEN** оба запроса обработаны хранилищем
- **THEN** подтверждена/активна максимум одна бронь, вторая получает явный отказ конфликта («Слот уже занят»), а не молчаливую порчу

#### Scenario: Бронь через вторую строку того же экземпляра отклоняется (MAJ-1)

- **GIVEN** разовый слот «12 ноября 16:00–18:00» совпал по дате+времени с экземпляром повторяющегося слота «Чт 16:00–18:00» (обе строки графика существуют), бронь ученика А создана через разовый слот
- **WHEN** ученик Б отправляет запрос брони на тот же экземпляр (12 ноября 16:00–18:00) через повторяющийся слот — вторую строку того же экземпляра
- **THEN** сервер отклоняет запрос (409 «Слот уже занят»), записи нет: на одном экземпляре максимум одна активная бронь независимо от строки графика

### Requirement: Замена графика при активных бронях отклоняется

Инструктор MUST НЕ иметь возможности сохранить график (полная замена),
удаляющий слот с бронью в статусе «новая» или «подтверждена»: сохранение
отклоняется с явным перечнем затронутых слотов, график остается прежним.
Решение по брони остается за инструктором; слоты с бронями только в
статусе «отклонена» замене не мешают (трассировка: NFR-8, MAJ-1 арх-ревью).

Источник: arch-review.md MAJ-1; requirements-booking-docs.md NFR-8.

#### Scenario: Сохранение графика без слота с активной бронью отклоняется

- **GIVEN** у слота (например, Пн 10:00–14:00) есть бронь в статусе «новая» или «подтверждена»
- **WHEN** инструктор сохраняет график, не содержащий этот слот
- **THEN** сохранение отклоняется с перечнем затронутых слотов, прежний график остается без изменений, брони не меняются

#### Scenario: После решения броней график сохраняется

- **GIVEN** сохранение графика было отклонено из-за активной брони слота
- **WHEN** инструктор подтвердил или отклонил (с комментарием) эту бронь и повторяет сохранение того же графика
- **THEN** график сохраняется (замена выполняется)

#### Scenario: Слоты с только отклоненными бронями замене не мешают

- **GIVEN** у удаляемого слота есть только бронь(и) в статусе «отклонена»
- **WHEN** инструктор сохраняет график без этого слота
- **THEN** график сохраняется без отказа

### Requirement: Календарь ученика: недели, реальные даты и разворот повторений

Календарь ученика MUST иметь ту же навигацию недель и реальный
календарь, что инструктор: «←»/«→» без перезагрузки, подпись диапазона,
реальные даты с верными днями недели, «сегодня» (МСК); при открытии —
неделя текущей даты. Повторяющиеся слоты MUST разворачиваться в
экземпляры дат недель; разовые — на своих датах; свои брони/запросы —
ровно на своих слотах. Прошедшие недели — только просмотр (история
броней) (FR-94, FR-95).

Источник: requirements-sprint10.md FR-94, FR-95.

#### Scenario: При открытии показана неделя с текущей датой и реальные даты колонок

- **GIVEN** ученик открыл раздел «Мои брони»
- **THEN** показана неделя с текущей датой, колонки — реальные даты с корректными днями недели

#### Scenario: Навигация неделями без перезагрузки страницы

- **GIVEN** открыт календарь ученика
- **WHEN** клик «→» или «←»
- **THEN** следующая/предыдущая неделя с корректными датами отображается без перезагрузки страницы; подпись диапазона согласована с колонками

#### Scenario: Граница месяца в подписи и колонках

- **GIVEN** отображаемая неделя пересекает границу месяца
- **THEN** подпись диапазона отражает обе части, колонки содержат реальные даты обеих частей с корректными днями недели

#### Scenario: «Сегодня» на реальной дате

- **GIVEN** открыт календарь ученика на текущей неделе
- **THEN** «сегодня» отмечена на колонке реальной сегодняшней даты (МСК)

#### Scenario: Повторяющийся слот развернут в экземпляры каждой отображаемой недели

- **GIVEN** инструктор имеет повторяющийся слот «Чт 16:00–18:00»
- **WHEN** ученик листает будущие недели
- **THEN** в каждой из них слот виден в колонке четверга 16:00–18:00 как конкретная дата этой недели

#### Scenario: Разовый слот виден только на своей дате

- **GIVEN** разовый слот инструктора на 12 ноября
- **WHEN** ученик листает недели
- **THEN** слот виден только в неделе с 12 ноября и только на этой дате

#### Scenario: Свои брони и запросы показаны ровно на своих слотах

- **GIVEN** броня ученика подтверждена на конкретную дату
- **WHEN** ученик открывает неделю этой даты
- **THEN** броня показана ровно на этом слоте (дата+время), на соседних слотах ее нет

#### Scenario: Прошедшая неделя — только просмотр

- **GIVEN** ученик открыл прошедшую неделю
- **THEN** видны только статусы своих броней/запросов (история с итоговыми статусами), слоты прошлых недель без действий (бронирование недоступно)
