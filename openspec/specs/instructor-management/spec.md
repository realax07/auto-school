## Requirements

### Requirement: Цена часа занятия задается инструктором

Инструктор MUST уметь выставить и изменить цену часа занятия в кабинете:
целые неотрицательные рубли. Цена не задана — занятия бесплатны
(бронирование без холда). Изменение цены не меняет суммы существующих
броней и холдов (снапшоты). Носитель — таблица instructors (user_id =
users.id; создается миграцией и при одобрении заявки).

Источник: решение Заказчика 2026-11-14; FR-100; NFR-33.

#### Scenario: Инструктор выставляет цену часа

- **GIVEN** одобренный инструктор без цены (или с ценой)
- **WHEN** он задает цену часа (целые рубли ≥ 0) в кабинете
- **THEN** цена сохранена; последующие брони тарифицируются по ней

#### Scenario: Изменение цены не трогает существующие холды

- **GIVEN** существует бронь со снапшотом цены и холдом
- **WHEN** инструктор меняет цену часа
- **THEN** снапшот и сумма холда существующей брони не изменились; изменение действует только на новые брони

#### Scenario: Некорректная цена отклоняется

- **GIVEN** инструктор ввел отрицательную или нецелую цену
- **WHEN** сохранение выполняется
- **THEN** сервер отклоняет (ошибка валидации), прежнее значение сохранено

### Requirement: Комиссия инструктора по умолчанию 10, границы 0–100

Каждому инструктору MUST назначаться комиссия платформы — целые проценты
0–100, по умолчанию 10; меняет её оператор админки, инструктор — нет.
Релиз MUST вычислять net по текущему значению: instructor_net =
floor(gross × (100 − комиссия) / 100), fee = gross − net; комиссия 0
дает fee = 0.

Источник: решение Заказчика 2026-11-14 («в админке ставится каждому
инструктору»); FR-106/109; NFR-33.

#### Scenario: Новому инструктору назначена комиссия по умолчанию

- **GIVEN** заявка инструктора одобрена оператором
- **WHEN** создается учетная запись инструктора
- **THEN** строка instructors создана с commission_percent = 10

#### Scenario: Релиз с комиссией 0 и 10 — целочисленный floor

- **GIVEN** проведенное занятие с холдом gross копеек; комиссия инструктора 0 (затем 10, затем 100)
- **WHEN** выполняется релиз холда
- **THEN** при 0: fee=0, net=gross; при 10: net = floor(gross×90/100), fee = gross − net; при 100: net=0, fee=gross; во всех случаях ровно одна транзакция release с gross/fee/net, суммы — целые копейки

### Requirement: Статистика заработка инструктора

Кабинет инструктора MUST содержать раздел «Доходы» (внутри страницы
кабинета): заработано за текущий месяц — итог (net, после комиссии) и
разбивка по ученикам; всего за месяц. Данные — агрегаты журнала release
(без отдельных таблиц-счетчиков); раздел виден только владельцу.

Источник: решение Заказчика 2026-11-14 («У него есть статистика сколько он
заработал на учениках за месяц и всего за месяц»); FR-110; NFR-33/34.

#### Scenario: Статистика месяца сходится с журналом

- **GIVEN** у инструктора есть release-транзакции текущего месяца по нескольким ученикам
- **WHEN** он открывает «Доходы»
- **THEN** итог за месяц и суммы по ученикам равны SUM net по журналу за месяц (разбивка по ученикам корректна)

#### Scenario: Месяц без заработка — нули без ошибки

- **GIVEN** релизов в текущем месяце нет
- **WHEN** инструктор открывает «Доходы»
- **THEN** показаны нули (итог месяца 0, разбивка пуста) — корректное пустое состояние

#### Scenario: Чужая статистика недоступна

- **GIVEN** два инструктора с сессиями
- **WHEN** один запрашивает экономику/статистику другого (прямым вызовом API)
- **THEN** доступ запрещен; чужие данные не возвращаются

### Requirement: Инструктор отмечает занятие проведенным

Инструктор MUST уметь отметить подтвержденную бронь проведенной, когда
экземпляр начался (начало ≤ NOW МСК): статус «проведена» с временем
отметки; холд остается замороженным до авто-релиза или решения по спору.
Будущие и не подтвержденные брони отмечать нельзя; отметка — только по
своим броням.

Источник: решение Заказчика 2026-11-14; FR-105.

#### Scenario: Начавшееся занятие отмечается проведенным

- **GIVEN** подтвержденная бронь, время начала экземпляра наступило
- **WHEN** инструктор отмечает занятие проведенным
- **THEN** статус брони — «проведена», время отметки зафиксировано; холд заморожен до авто-релиза/спора

#### Scenario: Будущее занятие отметить нельзя

- **GIVEN** подтвержденная бронь на будущее время
- **WHEN** инструктор пытается отметить ее проведенной
- **THEN** сервер отклоняет (ошибка валидации), статус не изменился
