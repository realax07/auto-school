## 6. Домен student-requests

- [ ] 6.1 [P] backend/student_requests.py — таблица student_requests
      (миграция в db.py; статусы new/accepted/denied, deny_comment,
      car_id, индексы); POST /api/student/requests (цель — одобренный
      инструктор → иначе 404; активная заявка этому инструктору → 409
      без записи); GET /api/student/requests (свои: статус, дата,
      deny_comment); GET /api/instructor/requests (только свои входящие);
      POST /api/instructor/requests/{id}/accept (заявка своя и 'new' →
      иначе 404/409; car_id — свое авто → иначе 422; 0 авто → 409;
      эффект: accepted + закрытие остальных АКТИВНЫХ заявок ученика —
      'new' И 'accepted' → denied с системным комментарием, текст
      одинаков для обоих исходов — ОВ-1, MAJ-1); POST
      /api/instructor/requests/{id}/deny (comment обязателен → 422 без);
      PATCH /api/instructor/students/{id}/car (перекрепление авто, ОВ-3 —
      MAJ-2: ученик с принятой заявкой этому инструктору → иначе 404;
      car_id — свое авто → иначе 422; эффект: car_id принятой заявки
      обновлен).
      Готовность: тесты — все сценарии specs/student-requests/spec.md:
      дубликат 409; параллельные заявки; повторная после отказа; чужие
      заявки не видны/не решаются; отказ без комментария заблокирован;
      принятие создает связь и закрывает остальные; 0 авто блокирует;
      MAJ-1: ученик принят у Б (accepted) + новая заявка А → accept А
      разрывает связь с Б (denied + системный комментарий), ученик
      числится принятым только у А; MAJ-2: перекрепление на свое авто
      обновляет car_id, чужое авто → 422, чужой ученик → 404.
      FR: FR-36, FR-37, FR-38, FR-39, FR-28 (перекрепление — ОВ-3).
      NFR: NFR-3, NFR-5. Зависит от: — (инструкторская роль users
      с Спринта 2).
