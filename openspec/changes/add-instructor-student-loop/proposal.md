# Change: add-instructor-student-loop

## Why (Зачем)

Спринт 3, Партия A: контур «инструктор ↔ ученик». После Спринта 2 цикл
разорван: одобренный инструктор не имеет профиля (автомобили, часы работы),
ученик не может найти инструктора, подать заявку и оставить отзыв; анкета
инструктора не сохраняла файл ВУ (зафиксированное ограничение Спринта 2,
requirements-instructor-flow.md). Этот объем замыкает цикл: профиль
инструктора (авто + часы работы) → выбор учеником (карточки с фильтрами) →
заявка → решение инструктора (принять с привязкой к авто / отказать
с обязательным комментарием) → привязка ученика → отзыв. Дополнительно —
реальная загрузка файлов ВУ с выдачей изображения в admin-API за
админ-токеном и виджеты главной кабинета инструктора.

Источник требований: `docs/ba/requirements-instructor-student-loop.md`
(УТВЕРЖДЕН, FR-23…FR-41, NFR-1…NFR-6, все Must; ОВ-1…ОВ-6 закрыты
Заказчиком 2026-10-15 — «Дефолты принимаю»).

## What Changes (Что меняет)

Новые возможности (все — ADDED; домены Спринтов 0–2 поведением не меняются,
кроме дополнения анкеты инструктора загрузкой файла — см. допущения):

- Домен `instructor-documents`:
  - анкета инструктора (POST /api/instructors/apply) принимает и сохраняет
    файл изображения ВУ (multipart; проверка типа JPEG/PNG и размера ≤5 МБ);
  - admin-API: детальная карточка заявки + выдача изображения ВУ только
    при валидном X-Admin-Token (механика Спринта 0);
  - карточка инструктора в админке открывается кликом по строке таблицы
    и показывает данные заявки с изображением ВУ.
- Домен `instructor-cars`:
  - раздел «Мои автомобили» кабинета инструктора: добавление, редактирование,
    удаление автомобиля (марка/модель, год, госномер, тип КПП) + фото
    (доступно только владельцу); связь автомобиль → инструктор —
    один-ко-многим (таблица instructor_cars).
- Домен `instructor-availability`:
  - раздел «Календарь»: выбор рабочих интервалов на сетке недели/дня,
    сохранение (таблица availability) и восстановление при следующем входе.
- Домен `student-instructor-choice`:
  - раздел «Выбор инструктора» кабинета ученика: карточки одобренных
    инструкторов (ФИО, стаж, автомобили, рейтинг, часы работы) с фильтрами
    (машина/тип КПП, рейтинг, стаж, свободное время — пересечение
    с availability); карта — вне скоупа, точка расширения зафиксирована.
- Домен `reviews`:
  - отзыв (оценка 1–5 + текст) — только пользователю с принятой заявкой
    к этому инструктору (серверная проверка); уникальная пара
    ученик↔инструктор (таблица reviews); агрегат рейтинга на карточке
    (средняя + количество; «нет отзывов» при пустом наборе).
- Домен `student-requests`:
  - подача заявки учеником из карточки инструктора; раздел «Мои заявки»
    ученика (статусы, включая комментарий отказа);
  - раздел «Запросы учеников» кабинета инструктора: принять (с выбором
    своего автомобиля; при 0 автомобилей недоступно; закрывает остальные
    активные заявки ученика) / отказать (комментарий обязателен);
  - виджеты главной кабинета инструктора: «Привязанные ученики» (реальные
    принятые ученики) и «Занятия на сегодня» (честная заглушка — «Сегодня
    занятий нет»).

## Impact (Последствия)

- Код: новые модули `backend/instructor_cars.py`,
  `backend/instructor_availability.py`, `backend/student_marketplace.py`,
  `backend/reviews.py`, `backend/student_requests.py`; правки
  `backend/instructors.py` (прием файла ВУ в multipart), `backend/instructor_admin.py`
  (карточка + изображение ВУ); правки `backend/db.py` (4 новые таблицы +
  колонка `license_photo_path` в instructor_applications; миграции
  idempotent — механика миграции users.role Спринта 2); правки `backend/app.py`
  (include роутеров, маршруты статики). Фронт: разделы существующих
  `frontend/instructor-dashboard.html` и `frontend/cabinet.html`, карточка
  в `frontend/admin-dashboard.html`; тесты в `tests/`.
- Хранилище файлов: `data/uploads/` (license/, cars/) — вне `frontend/`,
  статикой не раздается; выдача только через авторизованные эндпоинты
  (NFR-1). Каталог в .gitignore рядом с data/app.db.
- Master-spec: домены `instructor-documents`, `instructor-cars`,
  `instructor-availability`, `student-instructor-choice`, `reviews`,
  `student-requests` создаются этой дельтой; существующие домены
  не модифицируются (сценарий «анкета без файла» не меняется — файл
  опционален до фиксации обязательности макетом, задача 3.3).
- API-контракты, модель данных и правило префиксов API (закрытие MIN-3
  arch-review add-instructor-cabinet) фиксируются в `sdd.md` (раздел
  «Спринт 3, Партия A», §27+) и design.md настоящего пакета; sdd.md
  дополняется задачей приемки.

## Out of scope / допущения

- **Карта / гео-привязка** (FR-33) — вне скоупа; зафиксирована точка
  расширения: карточка и фильтры работают без картографических сервисов.
- **Реальное расписание занятий** (слоты, бронирование, отмена, оплата) —
  вне скоупа; виджет «Занятия на сегодня» — заглушка с пустым состоянием.
- Перенос/копирование часов работы, отпуска — вне скоупа.
- Чат ученик↔инструктор, уведомления (email/push) — вне контура.
- Модерация/удаление отзывов админом — нет в этом объеме (ОВ-6).
- Допущение (механика ОВ-1 «принятие закрывает остальные активные заявки»):
  закрытые заявки переводятся в статус «отказана» с системным комментарием
  «Заявка закрыта: ученик принят другим инструктором» — NFR-5 фиксирует
  три статуса, четвертый не вводится; видимость ученику сохраняется
  (комментарий виден в «Мои заявки»). Техрешение в границах спеки,
  зафиксировано design.md; не отменяет решение Заказчика по ОВ-1.
- Допущение (обязательность файла ВУ в анкете): правила обязательности
  полей — по утвержденному макету (задача 3.3); прием, проверка и
  сохранение файла — в этом объеме. До фиксации макетом файл
  обрабатывается при наличии.
- Допущение (публичность фото автомобиля): по NFR-1 фото автомобиля —
  только владельцу; на публичной карточке инструктора публикуются
  характеристики автомобиля (марка/модель, год, КПП) без фото и без
  госномера.
- Допущение (срок действия графика availability): график — недельный,
  без дат (перенос на конкретные даты — вне скоупа, «долгосрочное
  планирование»).
