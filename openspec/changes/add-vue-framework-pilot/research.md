# Research: add-vue-framework-pilot

Альтернативы ключевых техрешений ДО design (E12). Ограничение ТЗ:
директива Заказчика ОВ-3/ОВ-4 (2026-11-02) — Vue 3 + Vite, модульная
структура, вынос библиотек в chunks, постраничная миграция без
монолитного SPA, e2e сохраняются; NFR-26 — бюджеты 150/200 КБ gzip на
артефактах сборки.

## 1. Стек: Vue 3 / React / Svelte

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Vue 3 + Vite** | Прямое решение Заказчика (ОВ-3); runtime ~20 КБ gzip (composition API) — вписывается в бюджет NFR-26 с запасом; SFC-компоненты продолжают модульную модель Спринта 6 (страница = модуль); Vite нативно поддерживает multi-entry MPA без слоя конфигурации | Одна экосистема вместо «без фреймворка» | **ВЫБРАНО** (решение Заказчика) |
| React | Самая широкая экосистема | Не решение Заказчика (ТЗ: «не рассматриваются»); runtime тяжелее; JSX дальше от текущей HTML-модульности | Отклонено (запрещено ТЗ) |
| Svelte | Минимальный runtime | Не решение Заказчика; компиляторная модель — новый класс рисков сборки; экосистема меньше | Отклонено (запрещено ТЗ) |

Технические соображения приведены для полноты — выбор зафиксирован
решением Заказчика, альтернативы по стеку из процедуры исключены.

## 2. Форма приложения: multi-entry MPA / SPA-монолит / один entry + динамические импорты

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Multi-entry MPA: страница = отдельный HTML-вход Vite** | Точное соответствие ОВ-3 («постранично, не монолитный SPA»); страница грузит только свои чанки (NFR-26); миграция изолирована — остальные 12 страниц не затронуты; e2e-маршруты не меняются | Чанки общих частей дублируются между страницами (решается shared-чанком) | **ВЫБРАНО** |
| SPA-монолит (vue-router, один вход) | Классический DX | ПРЯМО ЗАПРЕЩЕН ОВ-3; вся навигация и все страницы в одном бандле — бюджеты NFR-26 не выполнить; риск для 49 e2e | Отклонено (запрещено ТЗ) |
| Один entry + динамические импорты страниц (MSPA-lite) | Один html-вход, страницы — lazy-чанки | Замаскированный SPA: единый runtime-вход и роутер-обвязка против буквы ОВ-3; «страница = точка входа» не выполняется | Отклонено |

## 3. Сборщик: Vite / webpack

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Vite** | Прямое решение Заказчика; multi-entry и manualChunks из коробки; dev-сервер мгновенного старта для постраничной миграции | Нулевой опыт в репо (сборки не было вообще) | **ВЫБРАНО** (решение Заказчика) |
| webpack (с Vue CLI) | Зрелость | Решение Заказчика — Vite; больше конфигурации ради того же multi-entry + сплита | Отклонено |

## 4. Каталог каркаса: frontend/vue/ / верхнеуровневый app/

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **frontend/vue/** | Весь фронт — в frontend/ (существующее зонирование); единый Docker-контекст и .dockerignore уже обслуживают фронт; dist рядом с входами | Вложенный workspace внутри frontend/ | **ВЫБРАНО** |
| Верхнеуровневый app/ (отдельное приложение) | «Чистый» отдельный пакет | Коллизия имени с backend/app.py; расширение Docker-контекста; фронт размазан по двум корням репо — против сложившейся структуры | Отклонено |

## 5. Доставка dist в контур: node builder-этап / коммит dist / том с хоста / npm на runtime

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Node builder-этап в Dockerfile (pinned node), COPY --from в runtime** | Наследует multi-stage ADR-006 («окружение — артефакт репозитория», урок INC-001); dist воспроизводим из исходников; node_modules и dev-зависимости в прод-образ не попадают | Удорожание сборки образа (npm ci); второй pinned базовый образ | **ВЫБРАНО** |
| Коммит dist в git | Простейшая доставка | Артефакт сборки в VCS — расхождение исходники/дистрибутив, шум diff, против практики INC-001 | Отклонено |
| Сборка на хосте + монтирование dist | Образ не пересобирается | Ломает инвариант «образ самодостаточен» (ADR-006); bare-metal/ compose расходятся | Отклонено |
| npm ci + build на runtime-этапе | Один образ-этап | Node и dev-зависимости в прод-образе — против NFR-11/чистоты ADR-006 | Отклонено |

## 6. Отдача мигрированных страниц: тем же FastAPI / nginx static

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **FastAPI: маршрут → Vue-вход из dist + статика /vue/assets (паттерн /js/)** | Наследует ADR-001 (статика тем же сервисом) и FR-57 (bare-metal/compose — один код); маршруты страниц не меняются (NFR-27) | app.py остается точкой статики (известный компромисс, revisit — Релиз 1) | **ВЫБРАНО** |
| nginx отдает dist напрямую (том/копия в образ nginx) | Разгрузка app | Новый контур доставки в nginx (образ nginx pinned и не содержит сборки), bare-metal требует второй конфиг — FR-57 страдает; revisit Релиза 1 (паттерны 1/2) | Отклонено |

## 7. Контур e2e: против собранного dist / против legacy-страницы

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Полный прогон против собранного dist (npm ci → npm run build → playwright)** | NFR-27 в букве: те же 49 сценариев, тот же контур (uvicorn backend.app:app), мигрированная страница реально под нагрузкой e2e | Новый обязательный шаг сборки перед прогоном | **ВЫБРАНО** |
| Мигрированный маршрут временно отдает legacy-файл для e2e | Ноль новых шагов | Пилот «мигрирован», но e2e гоняет старую страницу — приемка фиктивна; нарушение FR-86/GIVEN «страница обслуживается новым каркасом» | Отклонено |

## 8. Состояние страницы: локальное состояние / pinia / vue-router

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Локальное состояние SFC + нативные ссылки** | Странице ожидания достаточно; ноль лишних vendor-чанков — бюджеты NFR-26 с запасом | При миграции кабинетов (Спринты 10–11) вопрос состояния вернется | **ВЫБРАНО** (по потребности страницы; revisit — план ADR-008) |
| pinia | Общее состояние на будущее | Лишний vendor-чанк и код в пилоте; потребности нет | Отклонено в объеме |
| vue-router | SPA-навигация | Прямо против ОВ-3 (страница = точка входа, навигация — обычные ссылки) | Отклонено (запрещено ТЗ) |
