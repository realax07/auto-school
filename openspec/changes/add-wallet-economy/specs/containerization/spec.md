## ADDED Requirements

### Requirement: Compose-стек app + nginx

Репозиторий MUST содержать docker-compose-стек из ДВУХ сервисов: app
(образ из Dockerfile) и nginx (reverse proxy: статика и /api/* на app,
TLS из монтируемых файлов вне образов). Данные БД и загрузок — на
именованных томах (db, uploads), переживают пересоздание контейнеров.
Сервисов minio и тома minio-data в стеке быть не должно.

Источник: решение Заказчика 2026-11-14 («Закрой minio»); BACKLOG п.4
(PR#134); FR-52, NFR-15.

#### Scenario: Данные переживают пересоздание контейнеров

- **GIVEN** поднятый стек, в котором создан пользователь и загружен файл
- **WHEN** выполняется `docker compose down` и затем `docker compose up`
- **THEN** записи БД и загруженные файлы доступны без восстановительных действий (named volumes db и uploads)

#### Scenario: В стеке ровно два сервиса и нет MinIO

- **GIVEN** docker-compose.yml репозитория
- **WHEN** перечислены сервисы и volumes
- **THEN** services = {app, nginx} (ровно); сервиса minio и volume minio-data нет; `docker compose config` валиден

### Requirement: Секреты вне образа и публикация только портов nginx

Секреты (админ-креды, TLS-ключи) MUST попадать в контейнеры только через
окружение (env_file) и монтируемые файлы. Наружу публикуются только
порты nginx (80/443); порт app (8390) не публикуется и доступен только
внутри сети стека (nginx ↔ app).

Источник: requirements-containerization.md NFR-14/16; решение Заказчика
2026-11-14 («Закрой minio»).

#### Scenario: Секреты не зашиты в образ

- **GIVEN** образ приложения собран
- **WHEN** образ и контекст сборки инспектируются
- **THEN** ни один секрет (админ-креды, TLS-ключи) не присутствует в слоях образа и в контексте сборки — секреты приходят только через env_file и монтирования

#### Scenario: Наружу публикуются только порты nginx

- **GIVEN** стек поднят
- **WHEN** просматриваются публикуемые порты хоста
- **THEN** слушаются только порты nginx (80/443); порт app не публикуется и доступен только внутри сети стека

#### Scenario: CI собирает compose без MinIO-переменных

- **GIVEN** job сборки образа в CI
- **WHEN** выполняются compose-команды
- **THEN** шаг создания dummy .env с MinIO-переменными отсутствует (интерполяции ${MINIO_*:?} в compose больше нет); compose-команды выполняются без ручных переменных

## MODIFIED Requirements

### Requirement: Образ приложения

Репозиторий MUST содержать Dockerfile, собирающий образ приложения на
базе официального python-slim: зависимости — в виртуальном окружении
(.venv), устанавливаемом на multi-stage builder-этапе и переносимом в
финальный образ; приложение в контейнере запускается от непривилегированного
пользователя; версии базового образа и зависимостей зафиксированы
(трассировка: FR-51, NFR-11, NFR-12). Pin образов compose-стека
распространяется на nginx (tag+digest); MinIO-пин утрачивает силу вместе
с удалением сервиса.

Источник: requirements-containerization.md FR-51, NFR-11, NFR-12; решение
Заказчика 2026-11-14 («Закрой minio»).

#### Scenario: Сборка образа на чистой машине

- **GIVEN** чистая машина с установленным Docker и копия репозитория
- **WHEN** выполняется сборка образа из репозитория
- **THEN** сборка проходит без ручных шагов, запуск образа поднимает uvicorn, а процесс в контейнере работает не от root

#### Scenario: Builder-артефакты не попадают в финальный образ

- **GIVEN** образ собран через multi-stage (builder-этап с pip-кэшами и venv)
- **WHEN** финальный образ инспектируется
- **THEN** в нем нет артефактов builder-этапа (кэши pip, компиляторы), а виртуальное окружение с зависимостями присутствует

#### Scenario: Версии зафиксированы

- **GIVEN** Dockerfile и requirements.txt изменены вне задачи
- **WHEN** выполняется повторная сборка без изменения зафиксированных входов
- **THEN** базовый образ, версии зависимостей и образ nginx (tag+digest) берутся из зафиксированных значений, а не из плавающих тегов
