# Delta: instructor-dashboard

## ADDED Requirements

### Requirement: Доступ к кабинету инструктора

Страница /instructor/dashboard MUST быть доступна только пользователю с
валидной сессией (X-Session-Token), чья учетная запись имеет роль
'instructor'. Проверка роли MUST выполняться на бэкенде при запросе данных
кабинета: без действующей сессии или при иной роли доступ запрещается.
Страница не показывается: пользователь возвращается на главную (к модалке
входа) (трассировка: FR-18).

Источник: requirements-instructor-cabinet.md FR-18.

#### Scenario: Одобренный инструктор с сессией видит кабинет

- **GIVEN** одобренный инструктор (role='instructor') выполнил вход, валидная сессия выдана
- **WHEN** он открывает /instructor/dashboard
- **THEN** кабинет отображается по макету (демо-данные), данные учетной записи подставлены

#### Scenario: Обращение к данным кабинета без сессии отклоняется

- **GIVEN** пользователь не выполнял вход (токена нет)
- **WHEN** страница /instructor/dashboard запрашивает данные кабинета
- **THEN** бэкенд отвечает 401, страница не показывается — пользователь возвращается на главную (к модалке входа)

#### Scenario: Сессия истекла — редирект на вход

- **GIVEN** сессия инструктора истекла (TTL 12 ч) или аннулирована выходом
- **WHEN** он открывает /instructor/dashboard
- **THEN** бэкенд отвечает 401, пользователь возвращается на главную (к модалке входа)

#### Scenario: Сессия ученика не дает доступ к кабинету инструктора

- **GIVEN** пользователь с ролью 'student' с валидной сессией
- **WHEN** он открывает /instructor/dashboard
- **THEN** доступ запрещен: страница кабинета инструктора не показывается, пользователь возвращается на главную (к модалке входа)

#### Scenario: Открытие страницы напрямую без сессии

- **GIVEN** пользователь не выполнял успешный вход
- **WHEN** он открывает /instructor/dashboard напрямую
- **THEN** страница не открывается — пользователь возвращается на главную (к модалке входа)

### Requirement: Соответствие утвержденному макету кабинета

Кабинет инструктора MUST соответствовать макету design/mocks/
dashboard-instructor.html дословно: тексты, структура, стили ключевых блоков
(полный состав блоков зафиксирован сценариями ниже). Все данные — демо
(макет «Все данные вымышлены») (трассировка: FR-19).

Источник: requirements-instructor-cabinet.md FR-19; ограничения ТЗ (демо-данные).

#### Scenario: Структура кабинета соответствует макету

- **GIVEN** инструктор открыл /instructor/dashboard
- **WHEN** страница отображается
- **THEN** присутствуют все блоки макета: сайдбар с перечисленными разделами, 4 карточки статистики, расписание недели, список сегодняшних занятий, ближайшее занятие, автомобиль, последние операции, быстрые действия — с текстами и стилями ключевых блоков как в макете

#### Scenario: Данные кабинета — демо

- **GIVEN** инструктор открыл кабинет
- **WHEN** он просматривает содержимое блоков (статистика, расписание, занятия, операции)
- **THEN** отображаются демо-данные макета («Все данные вымышлены»), реальные данные БД (заявки, пользователи) не выводятся

### Requirement: ФИО инструктора из учетной записи

ФИО инструктора в шапке кабинета MUST подставляться из учетной записи
(фамилия, имя, отчество записи пользователя); инициалы в аватаре MUST
вычисляться из ФИО. Демо-ФИО макета не отображается (трассировка: FR-20).

Источник: requirements-instructor-cabinet.md FR-20.

#### Scenario: ФИО подставлено из учетной записи

- **GIVEN** одобренный инструктор с ФИО «Иванов Иван Иванович» вошел и открыл кабинет
- **WHEN** страница отображается
- **THEN** в шапке показано «Иванов Иван Иванович» вместо демо-«Михаил Самойлов»

#### Scenario: Инициалы аватара из ФИО

- **GIVEN** одобренный инструктор с ФИО «Иванов Иван Иванович» вошел и открыл кабинет
- **WHEN** страница отображается
- **THEN** в аватаре показаны инициалы из ФИО (например, «ИИ»), а не демо-«МС»

### Requirement: Разделы сайдбара — визуальное переключение на демо-данных

Переключение разделов сайдбара в этом объеме MUST быть визуальным: при выборе
раздела меняются заголовок и хлебная крошка страницы, содержимое остается
демо-данными; разделы помечены как демо-данные. Реальное содержимое разделов
(расписание, ученики, доходы, автомобиль, материалы, профиль) — вне объема
(трассировка: FR-21).

Источник: requirements-instructor-cabinet.md FR-21; ограничения ТЗ.

#### Scenario: Выбор раздела меняет заголовок, контент остается демо

- **GIVEN** инструктор открыл кабинет (активен раздел «Мой день»)
- **WHEN** он выбирает раздел «Расписание»
- **THEN** заголовок страницы и хлебная крошка меняются на «Расписание», содержимое остается демо-данными, раздел помечен как демо

#### Scenario: Все разделы сайдбара переключаются

- **GIVEN** инструктор открыл кабинет
- **WHEN** он последовательно выбирает каждый раздел сайдбара
- **THEN** для каждого раздела заголовок и крошка меняются на его название, содержимое остается демо-данными

### Requirement: Выход из кабинета

Кабинет MUST предоставлять выход (через «Профиль и документы» и прямым
элементом): выполнение выхода вызывает POST /api/auth/logout с текущим
токеном, после ответа очищает sessionStorage и выполняет редирект на главную.
После выхода сессия недействительна (трассировка: FR-22).

Источник: requirements-instructor-cabinet.md FR-22.

#### Scenario: Выход через профиль

- **GIVEN** инструктор с валидной сессией открыл кабинет
- **WHEN** он выполняет выход через «Профиль и документы»
- **THEN** вызван POST /api/auth/logout, sessionStorage очищен, выполнен редирект на главную

#### Scenario: Выход прямой кнопкой

- **GIVEN** инструктор с валидной сессией открыл кабинет
- **WHEN** он выполняет выход прямым элементом выхода
- **THEN** поведение идентично выходу через профиль: logout-вызов, очистка sessionStorage, редирект на главную

#### Scenario: После выхода повторный доступ к кабинету отклоняется

- **GIVEN** инструктор выполнил выход (токен аннулирован)
- **WHEN** он открывает /instructor/dashboard повторно без входа
- **THEN** страница не открывается — пользователь возвращается на главную (к модалке входа)

#### Scenario: Переход после входа ведет в кабинет

- **GIVEN** одобренный инструктор (role='instructor') выполняет вход через модалку входа с верными учетными данными
- **WHEN** вход успешен (ответ содержит route='cabinet')
- **THEN** он попадает на /instructor/dashboard
