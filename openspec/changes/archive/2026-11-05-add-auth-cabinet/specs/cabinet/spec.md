# Delta: cabinet

## ADDED Requirements

### Requirement: Доступ к кабинету по сессионному токену

Доступ к кабинету /cabinet MUST требовать действующий сессионный токен;
без него пользователь MUST возвращаться на страницу входа (трассировка:
FR-7).

Источник: requirements.md FR-7.

#### Scenario: Переход в кабинет после входа

- **GIVEN** ученик успешно вошел и получил действующий сессионный токен
- **WHEN** он открывает /cabinet с этим токеном
- **THEN** кабинет открывается

#### Scenario: Попадание в кабинет без токена

- **GIVEN** пользователь не выполнял вход (или его сессия истекла/аннулирована)
- **WHEN** он открывает /cabinet без действующего токена
- **THEN** система возвращает его на страницу входа, содержимое кабинета не показывается

### Requirement: Отображение ФИО ученика

Кабинет MUST отображать ФИО ученика из его учетной записи (трассировка:
FR-5).

Источник: requirements.md FR-5.

#### Scenario: ФИО в кабинете совпадает с учетной записью

- **GIVEN** ученик Иванов Иван Иванович зарегистрирован и вошел в систему
- **WHEN** он открывает кабинет
- **THEN** в кабинете отображаются его фамилия, имя и отчество из учетной записи (полное ФИО в шапке, имя в приветствии)

#### Scenario: ФИО берется из учетной записи, а не подставляется константой

- **GIVEN** зарегистрированы два ученика с разными ФИО, оба вошли в систему
- **WHEN** каждый открывает свой кабинет
- **THEN** в кабинете каждого отображается его собственное ФИО из учетной записи

### Requirement: Чат-бар и плитки-сервисы как визуал-заглушки

Кабинет MUST содержать чат-бар (Гига ГАИшник) и три плитки-сервиса
(Обучение ПДД, Онлайн экзамен, Найти водителя) как визуал-заглушки; клики
по ним MUST NOT выполнять сервисных действий (трассировка: FR-6).

Источник: requirements.md FR-6.

#### Scenario: Состав элементов кабинета

- **GIVEN** ученик открыл кабинет
- **WHEN** выполняется проверка состава элементов страницы
- **THEN** присутствуют чат-бар «Гига ГАИшник» и три плитки-сервиса: «Обучение ПДД», «Онлайн экзамен», «Найти водителя»

#### Scenario: Плитка не выполняет сервисного действия

- **GIVEN** ученик открыл кабинет
- **WHEN** он нажимает на любую из плиток-сервисов (или элементы чат-бара)
- **THEN** никакого сервисного действия не происходит (элемент — визуальная заглушка, реальные данные/сервисы не открываются)

### Requirement: Соответствие утвержденному мокапу кабинета

Тексты и стили кабинета MUST соответствовать утвержденному мокапу
design/mocks/cabinet-student.html дословно; допустимые отличия — только
wiring (связка с API) и подстановка ФИО вместо примера мокапа
(трассировка: FR-9).

Источник: requirements.md FR-9.

#### Scenario: Тексты кабинета совпадают с мокапом

- **GIVEN** ученик открыл кабинет
- **WHEN** выполняется текстовое сравнение страницы с утвержденным мокапом design/mocks/cabinet-student.html
- **THEN** заголовки, текстовки плиток, тексты чат-бара и подписи совпадают с мокапом дословно (кроме подстановки ФИО ученика вместо примера «Иван Иванов»/«Иван»)

#### Scenario: Оформление кабинета соответствует мокапу

- **GIVEN** ученик открыл кабинет
- **WHEN** выполняется визуальное сравнение страницы с утвержденным мокапом
- **THEN** структура, расположение блоков и стили соответствуют мокапу
