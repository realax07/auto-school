# Research: add-auth-cabinet

Ключевые техрешения наследуют утвержденный дизайн Спринта 0
(docs/superpowers/specs/2026-10-08-registration-admin-design.md): стек
FastAPI + SQLite, фронт — статика из design/mocks без сборки, пароли —
bcrypt. Ниже — альтернативы по новым решениям Спринта 1 (E12).

## 1. Авторизация: отдельный модуль или вплетение в register.py

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Отдельный модуль backend/auth.py** | Изоляция домена (ограничение ТЗ: «авторизация — отдельный сервис/модуль, не вплетена в register.py»), register.py не меняется,.auth-логика тестируется отдельно | Чуть больше файлов | **ВЫБРАНО** (ограничение ТЗ) |
| Эндпоинты внутри register.py | Меньше файлов | Нарушение ограничения ТЗ; слияние доменов регистрации и входа | Отклонено |

## 2. Механизм сессий

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **In-memory токен + TTL 12 ч (как у админа Спринта 0)** | Единый механизм с уже реализованным admin-токеном (переиспользование паттерна), ноль зависимостей, отзыв при рестарте | Теряется при рестарте; single-worker | **ВЫБРАНО** (консистентность со Спринтом 0) |
| JWT | Stateless, переживает рестарт | Новая зависимость, управление секретом/ротацией; отзыв (FR-8 — выход с аннулированием) требует доп. хранилища | Отложено |
| Сессионные cookie + серверное хранилище | Классика | CSRF-поверхность; расходится с механизмом Спринта 0 | Отклонено |

Ограничение (потеря сессий при рестарте) то же, что у админ-токена, и
задокументировано как приемлемое.

## 3. Где хранить учетные данные для входа

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Существующая таблица users (email + password_hash от регистрации)** | Данные уже там (FR-3: «в отдельной таблице users»); регистрация Спринта 0 не меняется; нет дублей данных | Роль хранится неявно (все записи users — ученики) | **ВЫБРАНО** (интерпретация FR-3, зафиксирована в proposal) |
| Отдельная таблица credentials с дублем email/хэша | Явное разделение доменов | Дублирование данных, синхронизация, изменение Спринта 0 | Отклонено |
| Колонка role в users | Готовность к водителям | Водители вне спринта — преждевременная колонка без потребителя | Отложено (спринт водителей) |

## 4. Передача токена фронтендом

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Заголовок, токен в sessionStorage (как админка Спринта 0)** | Единый паттерн с /api/admin/*; 401 → редирект на вход (FR-7) напрямую ложится на JS | sessionStorage чистится при закрытии вкладки (приемлемо: сессия требует повторного входа) | **ВЫБРАНО** (консистентность) |
| Cookie | Автоматическая отправка | CSRF-поверхность; второй механизм параллельно админскому | Отклонено |

## 5. Инкрементальные мелочи

Форма входа — утвержденная модалка «Вход» на лендинге
(design/mocks/landing-students.html, блок m-login); страница кабинета —
утвержденный мокап cabinet-student.html. Формат ответов API наследует
Спринт 0 ({ok, error} / 401 {ok:false}). Альтернативы не рассматривались —
инкремент тривиален.
