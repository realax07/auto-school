# Change: add-auth-cabinet

## Why (Зачем)

Спринт 1 площадки-автошколы: ученик, зарегистрировавшийся в Спринте 0, пока
не может войти в систему — учетные данные сохраняются, но не используются.
Нужны авторизация (отдельный сервис, решение Заказчика: «Авторизация отдельным
сервисом, есть два типа учеток, ученики, водители. Сейчас делаем учеников») и
личный кабинет ученика по утвержденному мокапу
`design/mocks/cabinet-student.html` (плитки-сервисы и чат — визуал-заглушки).

Источник требований: `requirements.md` (УТВЕРЖДЕН, Спринт 1: FR-1…FR-9,
NFR-1…NFR-3, все Must). Решение Заказчика на create_change:
`decisions/2026-10-09-create-change-auth-cabinet.md`.

## What Changes (Что меняет)

Новые возможности (все — ADDED; спеков по этим доменам в `openspec/specs/`
нет, регистрация Спринта 0 не меняется):

- Домен `auth`:
  - вход ученика по email и паролю с выдачей сессионного токена
    (POST /api/auth/login);
  - единое сообщение об отказе без раскрытия деталей (неверный email /
    неверный пароль / нет учетной записи — неотличимы для клиента);
  - проверка пароля против bcrypt-хэша учетной записи в таблице users
    (учетные данные — в таблице users, созданной регистрацией Спринта 0);
  - сессии в памяти процесса с TTL 12 ч (тот же механизм, что у админа
    Спринта 0);
  - выход: аннулирование сессионного токена (POST /api/auth/logout);
  - GET /api/auth/me — данные текущей учетной записи по токену.
- Домен `cabinet`:
  - страница личного кабинета /cabinet по утвержденному мокапу — тексты и
    стили дословно (кроме wiring и подстановки ФИО);
  - отображение ФИО ученика из учетной записи (шапка — полное ФИО,
    приветствие — имя);
  - чат-бар (Гига ГАИшник) и три плитки-сервиса (Обучение ПДД, Онлайн
    экзамен, Найти водителя) как визуал-заглушки: клики не выполняют
    сервисных действий;
  - доступ по действующему сессионному токену; без него — возврат на
    страницу входа.

## Impact (Последствия)

- Код: новый модуль `backend/auth.py` (авторизация — отдельный модуль,
  не вплетена в register.py — ограничение ТЗ); новая страница
  `frontend/cabinet.html` + wiring модалки входа на лендинге; тесты в
  `tests/`. Существующие `backend/register.py`, `backend/admin.py`, схема
  `users` — без изменений.
- Master-spec: домены `auth` и `cabinet` создаются этой дельтой
  (openspec/specs/ по ним пуст).
- API-контракты и сессионный механизм фиксируются в `sdd.md` (раздел
  Спринт 1); изменение контракта — отдельная дельта.

## Out of scope / допущения

- **Водители (вторая учетка) — вне спринта** (решение Заказчика: «Пока не
  трогай водил»). Таблица/модель хранит только учеников; расширение под
  водителей — будущий change.
- Реальные сервисы за плитками и работающий чат — вне спринта (визуал).
- Восстановление пароля, смена пароля, email-подтверждение, refresh-токены —
  вне спринта.
- Допущение (интерпретация FR-1): вход только по email; placeholder мокапа
  «email или телефон» сохраняется дословно, но телефон как логин не
  принимается (FR-1 говорит только про email; расхождение с текстом placeholder
  зафиксировано здесь, тексты модалки входа не меняются).
- Допущение (интерпретация FR-3): «отдельная таблица users» — учетные данные
  ученика хранятся в таблице users, уже созданной регистрацией Спринта 0
  (email + bcrypt-хэш там есть); отдельная таблица паролей не заводится.
