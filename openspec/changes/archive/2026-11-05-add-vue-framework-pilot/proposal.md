# Change: add-vue-framework-pilot

## Why (Зачем)

Спринт 9, задачи 9.3/9.4 PLAN.md (решение Заказчика 2026-11-02,
decisions/2026-11-02-s9-vue-framework-pilot-go.md). Фронт сегодня —
13 HTML-монолитов `frontend/*.html` (разметка, стили и контент вперемешку,
«дословность макета» FR-19), модульный JS Спринта 6 вынес только скрипты в
ES-модули `frontend/js/*`; сборки нет — нет ни чанков и бюджетов, ни
переиспользования компонентов, ни минификации. Дальнейшее наращивание
кабинетов на монолитах не масштабируется.

Директива Заказчика ОВ-3 (дословно: «давай, но не забывай про модульную
структуру, выносы библиотек и прочее»): миграция на Vue 3 + Vite —
ПОСТРАНИЧНО (не монолитный SPA), библиотеки — в отдельные chunks,
существующие Playwright e2e сохраняются и остаются зелеными. ОВ-4: пилотная
страница — «Ожидание модерации» (/instructors/pending), на ней же
реализуется блок 2 ТЗ (синергия задач 9.2 и 9.4). Цель старта — каркас и
пилот без большого переписывания: мигрированная страница заменяет HTML-
монолит целиком, немигрированные живут как есть.

Источник требований: `docs/ba/requirements-sprint9.md` (УТВЕРЖДЕН) —
блок 3 (FR-84…FR-86), NFR-26 (бюджеты чанков 150/200 КБ gzip),
NFR-27 (e2e-совместимость); решения ОВ-3, ОВ-4
(decisions/2026-11-02-sprint9-scope.md).

## What Changes (Что меняет)

- ADR-008 — новый файл `architecture/adr/008-vue3-vite-migration.md`
  (эталон формата — ADR-007): стек Vue 3 + Vite (обоснование против
  React/Svelte), каркас multi-entry (страница = отдельная точка входа, НЕ
  SPA-монолит), правила vendor-сплита и бюджеты NFR-26, постраничный план
  миграции на Спринты 9–11, доставка сборки в контур, критерий приема e2e.
- Каркас сборки `frontend/vue/` (решение по каталогу — design.md: весь
  фронт в frontend/, зонирование репозитория сохраняется): npm-workspace с
  Vite — multi-entry (по HTML-входу на мигрированную страницу),
  vendor-чанки отдельными файлами (runtime Vue и сторонние пакеты — свои
  чанки, в чанках страниц вендорного кода нет), общий код страниц —
  отдельный shared-чанк, `base: /vue/`, артефакты — `frontend/vue/dist`
  (в git не коммитятся).
- Доставка в контур: Dockerfile получает node builder-этап (pinned node
  образ, `npm ci` → `npm run build`), runtime-этап забирает dist через
  `COPY --from`; `docker-compose.yml` и nginx-контур — БЕЗ ИЗМЕНЕНИЙ
  (статика по-прежнему тем же сервисом — ADR-001; bare-metal FR-57
  работает). `.dockerignore` дополняется (frontend/vue/node_modules, dist).
- backend/app.py: маршрут `/instructors/pending` начинает отдавать Vue-вход
  из `frontend/vue/dist`; добавляется статика собранных ассетов по
  префиксу `/vue/` (паттерн существующей `/js/{filename}`). Остальные 12
  маршрутов страниц и все `/api/*` — без изменений.
- Пилотная страница «Ожидание модерации» на Vue 3: перенос
  instructor-pending.html с визуальной эквивалентностью (тексты и
  заголовки сохранены — h1 «Заявка на рассмотрении», по нему assertion
  существующего e2e TC-UI-004) + реализация блока 2 ТЗ (опрос статуса
  FR-80…83) на новом стеке по контракту change
  add-application-status-polling — ЗАВИСИМОСТЬ (параллельный пакет, задача
  9.2). Legacy-файл `frontend/instructor-pending.html` удаляется (замена
  монолита целиком); немигрированные страницы живут как есть.
- Проверка бюджетов NFR-26 на артефактах сборки (gzip-размеры чанков dist:
  каждый vendor-чанк ≤150 КБ gzip; JS первого захода пилота ≤200 КБ gzip) —
  приемочный шаг.

## Impact (Последствия)

- Код: новый `frontend/vue/` (package.json с pinned версиями,
  vite.config.mjs, src/pages/instructor-pending/, src/shared/);
  `backend/app.py` (маршрут пилота + статика `/vue/`); `Dockerfile`
  (node builder-этап); `.dockerignore`; `.gitignore` (frontend/vue/dist/,
  node_modules). nginx (`deploy/container/nginx.conf`,
  deploy/nginx-autoschool.conf) и `docker-compose.yml` — БЕЗ ИЗМЕНЕНИЙ.
- Удаление: `frontend/instructor-pending.html` (после миграции пилота;
  остальные 12 монолитов не трогаются).
- e2e: `tests/test_ui_playwright.py` — БЕЗ ПРАВОК (NFR-27); перед прогоном
  обязателен шаг сборки (npm ci → npm run build → playwright) — единый
  порядок для CI и локально.
- Master-spec: ADDED домен `Frontend` (каркас миграции: multi-entry,
  vendor-сплит и бюджеты, постраничность, сохранение e2e, пилот).
- Зависимость: change `add-application-status-polling` (задача 9.2,
  параллельный пакет) — контракт опроса статуса заявки (неперебираемый
  идентификатор, интервал 12 с, переходы waiting→approved/rejected,
  обмен идентификатора на сессию). Пилотная страница — потребитель
  контракта; чтобы не получить две конкурирующие реализации опроса на
  одной странице, после миграции пилот реализует блок 2 на Vue, а точку
  интеграции/очередность сводит приемка Спринта 9 (задача 9.5).

## Out of scope / допущения

- Миграция остальных 12 страниц (лендинги, анкета, кабинеты, админка) —
  Спринты 10–11 по плану ADR-008; в объеме только /instructors/pending.
- Монолитный SPA, клиентский роутер (vue-router), глобальное состояние
  (pinia) — НЕ вводятся (ОВ-3: страница = отдельная точка входа; странице
  ожидания достаточно локального состояния).
- React, Svelte и иные фреймворки — не рассматриваются (решение Заказчика —
  Vue 3 + Vite; ТЗ фиксирует запрет).
- Перенос отдачи статики на nginx / новый статик-контур — вне объема
  (статика тем же сервисом — ADR-001; revisit — Релиз 1, паттерн 1/2).
- Серверная сторона блока 2 (эндпоинт статуса, обмен на сессию,
  идентификатор заявки) — в пакете add-application-status-polling; пилот —
  только клиентская сторона на новом стеке.
- Редизайн пилотной страницы — вне объема: визуальная эквивалентность
  текущему экрану (FR-86).
- Подключение новых сторонних библиотек сверх Vue — не в объеме; правило
  бюджета для будущих зависимостей фиксирует ADR-008.
