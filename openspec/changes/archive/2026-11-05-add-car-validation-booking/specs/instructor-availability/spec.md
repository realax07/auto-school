# Delta: instructor-availability

## MODIFIED Requirements

### Requirement: Сохранение и восстановление графика

График часов работы MUST сохраняться (сущность availability) и MUST
восстанавливаться при следующем входе инструктора. Изменение графика
перезаписывает ранее сохраненный. Редактирование графика в календаре
инструктора выполняется через кнопки «Сохранить» и «Отменить» (FR-68):
изменения (добавление/удаление/правка слотов) применяются ТОЛЬКО по
«Сохранить» — один PUT /api/instructor/availability (существующий
контракт полной замены); «Отменить» возвращает календарь к последнему
сохраненному состоянию (перезагрузка данных с сервера) БЕЗ вызова PUT.
Кнопки «Сохранить/Отменить» относятся ТОЛЬКО к графику: решения по
броням на слотах (подтвердить/отклонить, FR-67) применяются немедленно
и в «Сохранить» не входят (ОВ-6). Полная замена согласована с booking
(MAJ-1 арх-ревью): интервалы с активными бронями («новая» или
«подтверждена») НЕ заменяются молча — PUT, удаляющий такой интервал,
MUST отклоняться с 409 и перечнем затронутых интервалов, прежний график
остается без изменений, брони не меняются (наследование требования
«Замена графика при активных бронях отклоняется» спеки booking);
интервалы с бронями только в статусе «отклонена» замене не мешают.

Источник: requirements-car-validation-booking.md FR-68; ОВ-6;
наследование MAJ-1 арх-ревью Спринта 5 (requirements-booking-docs.md).

#### Scenario: График восстанавливается после перезахода

- **GIVEN** график сохранен (например, Пн 10:00–14:00)
- **WHEN** инструктор выходит, входит заново и открывает календарь
- **THEN** отмечены те же интервалы, что были сохранены

#### Scenario: Изменение графика перезаписывает сохраненный

- **GIVEN** график Пн 10:00–14:00 сохранен
- **WHEN** инструктор снимает этот интервал, добавляет Ср 09:00–12:00 и сохраняет
- **THEN** при следующем входе отмечен только Ср 09:00–12:00

#### Scenario: «Сохранить» отправляет один PUT полной замены

- **GIVEN** инструктор изменил слоты календаря (добавил, удалил, поправил)
- **WHEN** он нажимает «Сохранить»
- **THEN** отправляется один PUT /api/instructor/availability с полным новым графиком; после ответа календарь отражает сохраненный график, и при перезаходе он восстанавливается

#### Scenario: «Отменить» возвращает сохраненный график без вызова PUT

- **GIVEN** инструктор изменил слоты календаря и еще не сохранял
- **WHEN** он нажимает «Отменить»
- **THEN** календарь перезагружает последний сохраненный график с сервера; PUT не вызывается, на сервере ничего не изменилось

#### Scenario: PUT с удалением интервала с активной бронью отклоняется (MAJ-1)

- **GIVEN** у интервала (например, Пн 10:00–14:00) есть бронь в статусе «новая» или «подтвержденная»
- **WHEN** инструктор нажимает «Сохранить», и новый график не содержит этот интервал
- **THEN** PUT отклоняется с 409 и перечнем затронутых интервалов; прежний график остается без изменений, брони не меняются, календарь показывает ошибку и сохраненное состояние

#### Scenario: Интервалы с только отклоненными бронями замене не мешают

- **GIVEN** у удаляемого интервала есть только бронь(и) в статусе «отклонена»
- **WHEN** инструктор сохраняет график без этого интервала
- **THEN** график сохраняется без отказа
