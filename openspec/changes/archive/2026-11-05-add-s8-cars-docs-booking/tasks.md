      (в) повторное воспроизведение. ФИКС: POST …/photo/sts — при
      ОТСУТСТВИИ действующего СТС → photo_sts + verified v1 (первичная
      дозагрузка); ПРИ ЗАМЕНЕ → pending-версия документа, photo_sts НЕ
      перезаписывается; статус авто НЕ меняется — validated остается
      validated (ОВ-6; правило MAJ-1 «validated → validating» остается
      ТОЛЬКО для 5 ракурсов — их ветки не трогать); замена не трогает
      ракурсы, has_sts и счетчики комплектности.
      Готовность: тесты — СТС загружается/заменяется на существующем
      авто; первичная дозагрузка: photo_sts заполнен, verified v1;
      замена у validated: статус авто остался validated, photo_sts не
      изменился, pending создана; повторная загрузка заменила
      ожидающую; PDF/6 МБ → 422, прежнее СТС не изменено; замена ракурса
      у validated → validating (регресс MAJ-1); корень симптома
      зафиксирован в отчете ДО фикса.
      FR: FR-69, ОВ-6, ОВ-7. NFR: NFR-9, NFR-7, NFR-10. Зависит от:
      1.1 (контракт таблицы).

## 4. Верификация документов админом (backend, ОВ-1/ОВ-4)

      /api/admin/documents?status=pending (default pending; версия,
      тип, uploaded_at; license — ФИО инструктора; car_sts — марка/
      модель/госномер + владелец; без токена → 401); GET
      /api/admin/documents/{version_id}/file (предпросмотр image/*,
      ОВ-4); POST …/verify (только pending → иначе 409; версия verified,
      предыдущая verified — архив, каноническая колонка
      license_photo_path/photo_sts переключается на файл версии — одна
      транзакция, decided_at); POST …/reject (body {reason} обязателен:
      нет/пусто → 422 — ОВ-1; версия rejected с reject_reason,
      предыдущая verified ОСТАЕТСЯ действующей, каноническая колонка не
      меняется). Согласованность с 2.1/3.1 — контракты design.md.
      Готовность: тесты — pending-список содержит ФИО/авто+госномер;
      предпросмотр возвращает изображение; verify: действующей стала
      новая версия (файл по doc_id-эндпоинту и photo_sts/license_photo_path
      обновлены), инструктор видит новую; reject: 422 без причины,
      rejected с причиной, действующая версия прежняя; не-pending →
      409; без токена → 401.
      FR: FR-70 (verify/reject), ОВ-1, ОВ-4. NFR: NFR-22, NFR-10.
      Зависит от: 1.1.
