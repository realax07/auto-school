# Delta: instructor-availability

## ADDED Requirements

### Requirement: Запросы и брони учеников на слотах календаря

Календарь MUST показывать запросы (new) и брони (confirmed) РОВНО на
выбранных учеником слотах (дата+время запроса = слоту availability),
без агрегированных списков и попаданий на соседние слоты.
«Сохранить/Отменить» графика — наследование FR-68 (409 MAJ-1 — без
правок бэкенда). Раздел «Бронирования» удаляется без остатков; старые
ссылки — редирект в календарь (BUG-047). Контракты booking/
availability не меняются (NFR-23).

Источник: requirements-sprint8.md FR-74, NFR-23; ОВ-6, MAJ-1.

#### Scenario: Запрос виден именно на выбранном слоте

- **GIVEN** ученик отправил запрос на слот 14:00–15:00 даты D (слот задан графиком инструктора)
- **WHEN** инструктор открывает календарь на дату D
- **THEN** запрос показан именно на слоте 14:00–15:00 (ячейка слота) с кнопками подтвердить/отклонить; на соседних слотах запроса нет; отдельного списка запросов «рядом с календарем» нет

#### Scenario: Решения по брони — немедленно, мимо кнопок графика

- **GIVEN** в календаре есть запрос ученика на слоте и несохраненные правки графика
- **WHEN** инструктор подтверждает (или отклоняет) запрос
- **THEN** решение применяется немедленно (POST confirm/reject), вызов PUT графика не требуется; кнопки «Сохранить/Отменить» относятся только к графику

#### Scenario: «Сохранить/Отменить» графика — наследование без изменений

- **GIVEN** инструктор изменил отметки слотов и нажал «Сохранить»
- **WHEN** отправляется изменение
- **THEN** отправляется ОДИН PUT полной замены; «Отменить» возвращает сохраненный график перезагрузкой GET без PUT; PUT, удаляющий интервал с активной бронью, получает 409 с перечнем затронутых — показывается с сохраненным графиком

#### Scenario: Раздел «Бронирования» удален без остатков

- **GIVEN** инструктор открыл кабинет
- **WHEN** отображена навигация
- **THEN** пункта меню «Бронирования» нет; секция раздела и его JS-контур отсутствуют; GIVEN старая ссылка #/bookings открыта THEN выполняется редирект в календарь

#### Scenario: API-контракты броней и графика не меняются

- **GIVEN** существующие брони и график инструктора
- **WHEN** раздел «Бронирования» удален и календарь переработан
- **THEN** контракты GET /api/instructor/bookings, POST confirm/reject/cancel, PUT/GET /api/instructor/availability не изменены (NFR-23); существующие брони и запросы доступны в календаре
