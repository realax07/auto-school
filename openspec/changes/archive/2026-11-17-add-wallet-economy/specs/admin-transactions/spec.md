# Delta: admin-transactions

## ADDED Requirements

### Requirement: Раздел «Транзакции» — весь журнал с фильтрами

Админка MUST содержать НОВЫЙ раздел «Транзакции» внутри страницы
админ-панели: весь журнал всех пользователей и всех типов (topup, hold,
release, refund, payout) — id, дата, тип, роль, пользователь, источник,
сумма; фильтры тип/роль/пользователь/период дат; свежие сверху; доступ
только по админ-токену; журнал только читается.

Источник: решение Заказчика 2026-11-14 («оператор видит транзакции все»);
FR-113; NFR-34/37.

#### Scenario: Оператор видит все транзакции без фильтров

- **GIVEN** в системе есть транзакции разных типов и пользователей
- **WHEN** оператор открывает раздел «Транзакции»
- **THEN** показан журнал всех типов и всех пользователей, свежие сверху

#### Scenario: Фильтры сужают журнал

- **GIVEN** журнал с транзакциями разных типов, ролей, пользователей и дат
- **WHEN** применены фильтры (тип; роль; пользователь; период дат)
- **THEN** показаны только подходящие записи; пустой результат — валидное состояние (не ошибка)

#### Scenario: Доступ только у оператора

- **GIVEN** ученик или инструктор с валидной сессией
- **WHEN** прямой вызов API журнала
- **THEN** доступ запрещен (роли админа нет); журнал не возвращается

### Requirement: Баланс компании в админке

Раздел «Транзакции» MUST показывать БАЛАНС КОМПАНИИ — накопленные комиссии
платформы, вычисленные как SUM fee по журналу release (без отдельной
таблицы). Инструкторы с комиссией 0 MUST учитываться фактом 0 (их релизы
вносят нулевой fee и не увеличивают баланс). Баланс компании виден только
оператору.

Источник: решение Заказчика 2026-11-14 (дословно: «балланс компании нужен
в админке»); FR-114; NFR-33/34.

#### Scenario: Баланс компании равен сумме комиссий релизов

- **GIVEN** в журнале есть release-транзакции с fee (в том числе с fee=0 при комиссии 0)
- **WHEN** оператор открывает раздел «Транзакции»
- **THEN** «Баланс компании» равен SUM fee по журналу; релизы с комиссией 0 не изменили баланс

### Requirement: Комиссии каждого инструктора за год

Раздел «Транзакции» MUST показывать таблицу «сумма комиссий каждого
инструктора за год»: инструктор × SUM fee его release-транзакций за
выбранный год; по умолчанию — текущий год; MUST быть селектор года.
Агрегаты вычисляются из журнала (без отдельной таблицы); инструктор без
релизов за год показывается с суммой 0.

Источник: решение Заказчика 2026-11-14 (дословно: «сумма комиссий каждого
инструктора за год»); FR-115; NFR-33/34.

#### Scenario: Таблица за текущий год по умолчанию

- **GIVEN** инструкторы с release-транзакциями текущего года (в том числе комиссия 0)
- **WHEN** оператор открывает таблицу комиссий
- **THEN** каждая строка — инструктор и сумма его fee за текущий год; инструкторы без релизов — с 0

#### Scenario: Селектор года переключает период

- **GIVEN** таблица комиссий открыта
- **WHEN** оператор выбирает другой год
- **THEN** суммы пересчитаны по release-транзакциям выбранного года (агрегат журнала)

### Requirement: Подтверждение выплат и решения по спорам в разделе

Раздел MUST содержать операционные блоки: очередь активных заявок выплат
с подтверждением оператора (диалог подтверждения; недостача — честное
сообщение, заявка остается) и открытые споры (бронь, ученик, инструктор,
комментарий) с решением — перевести инструктору или вернуть ученику —
с обязательным комментарием (без текста действие недоступно). Решение
закрывает спор и холд журнальной транзакцией.

Источник: решение Заказчика 2026-11-14; FR-108/112; NFR-35.

#### Scenario: Оператор подтверждает выплату из раздела

- **GIVEN** очередь выплат с активной заявкой
- **WHEN** оператор подтверждает выплату
- **THEN** заявка «выплачено», транзакция payout создана, баланс инструктора уменьшился (ровно один раз)

#### Scenario: Оператор решает спор

- **GIVEN** открытый спор по проведенному занятию с холдом
- **WHEN** оператор выбирает решение (перевести инструктору / вернуть ученику) и вводит комментарий
- **THEN** холд закрыт (release или refund — ровно одна транзакция), спор закрыт, повторного решения нет; без комментария действие недоступно

### Requirement: Комиссия инструктора редактируется оператором

В разделе «Транзакции» оператор MUST уметь задавать комиссию КАЖДОМУ
инструктору: целые проценты 0–100; по умолчанию — 10. Изменение комиссии
MUST применяться к последующим релизам (текущее значение на момент
релиза); существующие транзакции и холды не пересчитываются.

Источник: решение Заказчика 2026-11-14 (дословно: «Комиссия нужна, в
админке ставится каждому инструктору»); FR-109.

#### Scenario: Оператор задает комиссию инструктору

- **GIVEN** инструктор с комиссией по умолчанию 10
- **WHEN** оператор задает 25 (или 0) и сохраняет
- **THEN** комиссия сохранена и применена к следующему релизу; существующие журнальные записи не изменились

#### Scenario: Некорректная комиссия отклоняется

- **GIVEN** оператор ввел комиссию вне 0–100 или нецелую
- **WHEN** сохранение выполнено
- **THEN** сервер отклоняет (ошибка валидации), значение не изменилось
