# Change: add-calendar-weeks-availability

## Why (Зачем)

Спринт 10. Блокер UX календарей (решение Заказчика 2026-11-04, дословно —
decisions/2026-11-04-sprint10-calendar-go.md; requirements-sprint10.md
УТВЕРЖДЕН: FR-87…FR-97, NFR-29…NFR-32):

1. Неделя фиксированная: сетка инструктора строится только для текущей
   недели (js/dashboard-instructor.js считает понедельник текущей недели,
   навигации нет), ученик видит слоты тем же перечислением дней недели без
   дат (cabinet.html «График на неделю»). Прошлые недели недостижимы —
   история графика и броней в календарях не просматривается.
2. Тип ячейки один: график — множество интервалов «день недели + время»
   (PUT /api/instructor/availability, полная замена), что фактически означает
   повторяемость каждую неделю без явного типа и без дат. Выставить слот
   «только на конкретную дату» невозможно.
3. Нет привязки к реальному календарю: сетка не учитывает число дней
   месяцев, попадание дат в дни недели, границы месяцев/годов.
4. Нет границы «прошедшее/будущее»: правки и бронирование формально
   возможны на любую неделю; прошедшее ничем не защищено на сервере.

Решение Заказчика: навигация прошлые/будущие недели у ОБОИХ календарей;
для КАЖДОЙ ячейки инструктора — тип «разово» (конкретная дата + время)
или «повторяющееся» (еженедельное) через графическое мини-окно НАД ячейкой
поверх страницы (popover); правки только ≥ текущей даты/времени, прошедшее
— просмотр; календарь учитывает реальный календарь (число дней, попадание
в дни недели, год/месяц); ученику — та же навигация недель, бронирование
только будущих слотов.

Защита активных броней (MAJ-1 арх-ревью Спринта 5, 409 с перечнем)
сохраняется и переносится с уровня интервала на уровень ЭКЗЕМПЛЯРОВ слота
— конкретных дат и времени (FR-92). Существующий контракт availability
сохраняется/расширяется только обратно-совместимо (NFR-29); существующие
интервалы продолжают действовать как ПОВТОРЯЮЩИЕСЯ слоты без повторного
сохранения инструктором (FR-97, миграция — NFR-30).

## What Changes (Что меняет)

- Модель слотов (MODIFIED, FR-90, FR-97, NFR-30): каждая запись availability
  получает тип `recurring` (еженедельная серия: день недели + время) или
  `one_off` (конкретная дата + время). СУЩЕСТВУЮЩИЕ строки становятся
  recurring по умолчанию колонки — без перезаписи данных (решение СА:
  design.md «Модель данных», D1–D2); разворот серий в даты выполняется при
  выдаче/рендере, экземпляры не материализуются в строки. Прошедшие
  one_off-записи — история, неизменяемы.
- Контракт availability (MODIFIED, FR-92, NFR-29): расширение СУЩЕСТВУЮЩЕГО
  PUT /api/instructor/availability (новый эндпоинт НЕ вводится — решение СА,
  research.md): тело пополняется необязательными slot_type/date; запрос в
  старом формате продолжает приниматься и означает график из recurring
  слотов тела, при этом сохраненные разовые слоты остаются без
  изменений (MAJ-2 арх-ревью: design.md «Совместимость», research.md
  R7); GET дополняет интервалы типом и датой (аддитивно). MAJ-1 — на
  уровне экземпляров: 409 с перечнем (дата, время, статус брони); прежний
  график не меняется, брони не меняются. «Сохранить график» = один PUT
  полного нового графика, «Отменить» = перезагрузка GET (наследование
  FR-68).
- Запрет правки прошлого (ADDED, FR-93, NFR-31): правки (отметить, снять,
  сменить тип, убрать) — только для слотов с началом ≥ текущего момента
  (локальное время сервера, МСК); проверка на клиенте И на сервере: PUT,
  создающий/меняющий прошедший слот или убирающий прошедший one_off,
  отклоняется независимо от UI. Прошедшие недели целиком — просмотр.
- Попап-редактор (ADDED, FR-89): клик по ячейке открывает графическое
  мини-окно НАД ячейкой, поверх страницы, с выбором «Разово/Повторяющееся»
  (индивидуально для каждой ячейки) и действиями подтверждения; закрытие
  без подтверждения не меняет ячейку; окно не сдвигает и не переполняет
  сетку, у границ вьюпорта сдвигается внутрь. Клиентский UX-контракт —
  design.md (D10).
- Календарь инструктора (MODIFIED, FR-87, FR-88): секция #sec-calendar
  получает навигацию «←»/«→» с подписью диапазона недели (обе части при
  пересечении месяца/года), точку возврата «эта неделя»; сетка строится из
  реального календаря — 7 реальных дат с корректным днем недели на границах
  месяцев/годов и в високосных годах; «сегодня» — на реальной дате (МСК);
  переходы без перезагрузки страницы (NFR-32: неделя отрисовывается по
  загруженным данным, догрузка асинхронна).
- Календарь ученика (MODIFIED, FR-94…FR-96): «График на неделю» — та же
  навигация недель и реальный календарь; повторяющиеся слоты РАЗВОРАЧИВАЮТСЯ
  в экземпляры конкретных дат всех отображаемых недель (решение СА: выдача
  экземпляров недели сервером — design.md D7); бронирование только будущих
  слотов (начало строго больше текущего момента; серверная проверка —
  NFR-31), прошедшие недели — история своих броней без действий. Остальной
  контур брони — без изменений: слот целиком (availability_id), POST
  /api/student/bookings, «Слот уже занят», доступ по принятой паре, решения
  инструктора немедленно.
- Бронь на экземпляре (MODIFIED, FR-92, FR-95): lesson_date брони становится
  ТОЧНОЙ датой экземпляра; занятость «Слот уже занят» — на уровне экземпляра
  (дата+время): разные даты одной повторяющейся серии бронируются
  независимо (решение СА: design.md D4 — расширение частичного
  UNIQUE-индекса, контракт POST не меняется; легаси-вызов без даты —
  ближайшая дата серии как сейчас). Экземпляр может быть представлен
  двумя строками графика (разовый слот поверх совпадающего экземпляра
  серии — FR-90): правило «одна активная бронь на экземпляр» действует
  кросс-строчно — проверка в транзакции создания брони BEGIN IMMEDIATE
  по всем строкам графика инструктора (MAJ-1 арх-ревью Спринта 10);
  выдача ученику дедуплицирует совпавшие экземпляры (решение СА:
  design.md «GET slots?date=», research.md R6).

Модульность (директива Заказчика, наследуется): типы/миграция — внутри
домена availability (backend/instructor_availability.py + db.py);
бронирование/экземпляры — внутри домена booking (backend/booking.py);
фронт — правки существующих ES-модулей (js/dashboard-instructor.js,
js/cabinet.js), новых страниц НЕТ.

## Impact (Последствия)

- Код: РАСШИРЕНИЯ `backend/db.py` (миграция: колонки slot_type/slot_date +
  перестройка таблицы availability под новый UNIQUE + расширение частичного
  индекса брони на (availability_id, lesson_date) — idempotent, guard по
  наличию колонки), `backend/instructor_availability.py` (PUT/GET: типы и
  даты, серверный запрет прошлого, 409 на уровне экземпляров, дифф-запись
  с сохранением id строк и перепривязкой брони при покрытой замене
  носителя — MAJ-1 арх-ревью Спринта 10),
  `backend/booking.py` (POST bookings: необязательная date, проверка
  будущего, точная lesson_date, кросс-строчная проверка экземпляра в
  транзакции; GET slots с выдачей экземпляров недели ?date= с
  дедупликацией; helper MAJ-1 — экземпляры). Фронт:
  `frontend/instructor-dashboard.html` + `frontend/js/dashboard-instructor.js`
  (навигация недель, реальный календарь, попап-редактор, типы ячеек,
  клиентский запрет прошлого), `frontend/cabinet.html` +
  `frontend/js/cabinet.js` (навигация недель, реальный календарь, разворот
  серий, бронирование будущих). GET /api/student/bookings,
  /api/instructor/bookings, confirm/reject/cancel — БЕЗ ИЗМЕНЕНИЙ.
- Хранилище: та же таблица availability (перестройка существующей БД на
  volume — idempotent-миграция init_db через lifespan, наследование

  UNIQUE-индекса (данные совместимы: две активные брони одного availability_id
  сегодня невозможны). Потеря строк графика или броней при переходе не
  допускается (NFR-30, отказ приемки).
- Master-spec: MODIFIED — `instructor-availability` («Сохранение и
  восстановление графика» — типы, экземпляры, запрет прошлого, legacy-тело);
  ADDED — `instructor-availability` (5: типы слотов, навигация/реальный
  календарь инструктора, попап-редактор, запрет правки прошлого, миграция в
  recurring), `booking` (1: календарь ученика — недели/разворот/история);
  MODIFIED — `booking` («Запрос брони на слот» — будущие слоты и точная
  дата экземпляра; «Занятый слот недоступен другим ученикам» — занятость
  экземпляра, кросс-строчная гарантия «один экземпляр — одна активная

## Out of scope / допущения

- Исключение отдельного экземпляра повторяющейся серии в одной неделе
  («отменить слот только на конкретную дату» без правки серии) — точка
  расширения; правка серии применяется к текущим/будущим экземплярам.
- Копирование недели/шаблоны графика, ограничение горизонта бронирования,
  уведомления об изменениях графика — точки расширения/backlog.
- Навигация неделями ограничивается ±12 месяцев от текущей (дефолт
  открытого вопроса — защита от бесконечной прокрутки; решение ПМ может
  пересмотреть) — клиентское ограничение, не серверное.
- История состояний серий не хранится: прошлые недели серий отображаются по
  текущему состоянию серии; фактическая история броней/запросов — записи
  booking с lesson_date (сознательное ограничение, design.md D8).
- Перенос/отмена подтвержденных броней при правке графика — не
  автоматизируются (MAJ-1: 409); отмена/перенос занятия учеником,
  «повторения раз в N недель» — вне объема.
- Нарезка слотов (2-часовой шаг, слот целиком) — наследование, не
  ревизируется; контур модерации, каталог, пары, админ-разделы — без
  изменений.
- Миграция календарей на Vue 3 — вне Спринта 10 (по плану ADR Спринта 9).
