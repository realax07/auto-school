# Change: add-pdd-learning

## Why (Зачем)

Спринт 17 — «Обучающие разделы ПДД в кабинете ученика». Решение Заказчика
2026-11-15 («Так, давай поработаем над кабинетом ученика…») вводит четыре
обучающих раздела в сайдбар кабинета ученика: «Знаки» (8 групп, 321 знак),
«Правила» (26 глав), «Билеты» — интерактивный тренажёр (таймер, картинки
вопросов, проверка ответов) и «Штрафы» (таблица источника + поиск).
Подготовка выполнена в С16→С17-интервале и уже в main: контент-корпус
content/pdd/ (PR#137/138: 26 глав правил, 8 групп знаков, 80 билетов ×
20 вопросов, штрафы; 1613 изображений, ~48 МБ) и 4 СОГЛАСОВАННЫХ мокапа
(P#138: design/mocks/pdd-znaki-student.html, pdd-pravila-student.html —
двухколоночный по правке Заказчика, pdd-bilety-trenazher.html,
pdd-shtrafi-student.html; согласование — «отлично, погнали»). На момент
решения продукт НЕ менялся («Пока работаем только с текстом, на сайт ничего
не реализуем») — реализация разделов и есть Спринт 17.

Ключевое ограничение производительности: кабинет уже мигрирован на каркас
Vue (С15, multi-entry MPA) и живет под бюджетами NFR-26 (первый заход
страницы ≤ 200 КБ gzip). 48 МБ изображений и ~2 МБ текстов НЕ должны
попасть в первый заход кабинета — разделы контента обязаны быть отдельными
lazy-чанками, картинки — статикой вне vite-бандла.

## Сверка состава с фактом (решение сформулировано частично неточно)

- **«321 знак: номер+название+описание» — описания в корпусе ЕСТЬ**:
  znaki/*.md дают номер (`## N.N`) + название; тексты описаний и штрафов
  выгружены в content/pdd/znaki-details.json (индивидуальные страницы
  источника): 321 запись (ключ — slug источника; поля title/desc/fine/
  img/long). desc непуст у 319/321 — пусты ровно два знака, 5.33.1 и
  5.34.1 (допустимые пустоты источника, покрыты гейтом-допуском
  генератора); тексты штрафов (fine, свободный текст с отсылками к
  КоАП) — у 166/321. Решение: деталь знака в S17 = крупное изображение +
  номер + название + группа + блок описания (desc) + блок штрафа при
  наличии fine; тексты НЕ сочиняются — рендер строго по znaki-details.json
  (номер записи join-ится по title, группа — только из znaki/*.md,
  см. design «Решение 1»).
- **«63 сводных строки» штрафов — фактическая таблица 58 строк**:
  content/pdd/shtrafi/shtrafi-gibdd.md содержит 58 табличных строк
  («Пункт КоАП\tНарушение\tНаказание», tab-separated) + 5 строк блока
  «Популярные штрафы» = 63 строки со «Ст.»; согласованный мокап показывает
  63 `<tr>`. Примечание решения («Источник показывает 63 сводных строки»)
  относится к сайту-источнику. Раздел рендерит таблицу ПО КОРПУСУ (сейчас
  58 строк; расхождение 63↔58 не блокирует — состав раздела тот же);
  пополнение — только перегенерацией.
- **Оглавление правил в мокапе — 29 пунктов, факт корпуса — 26 глав**:
  toc мокапа иллюстративный (включает «Дорожную разметку», которой нет
  отдельной главой). Раздел строит оглавление из корпуса (26 файлов
  r1_…r26_, у каждого ровно один H1 — проверено).
- **Группы знаков: 8 групп, счётчики мокапа совпадают с корпусом**:
  47/13/38/24/63/37/22/77 = 321 ✓. Формат группы t8 («Таблички»)
  отличается: `## | 8.1.1` (pipe перед номером) — генератор обязан
  обрабатывать оба формата (S17-факт корпуса, файлы руками не правятся).
- **Картинки билетов: 1094 ссылки на изображение в 1600 вопросах, все
  существуют на диске (0 missing) — целостность ✓**; 1292 файла в
  images/bilety, 198 не упоминаются ни одним md (дубли загрузки с
  источника) — НЕ удаляются (корпус не трогаем), статикой отдаются «как
  есть». Все 321 знак имеют ровно один файл images/znaki/<номер>small.png
  (уникальные stem'ы, формат .png) — правило маппинга номер→файл.
- **README корпуса устарел** (content/pdd/README.md: «7 групп знаков,
  244», «Изображения вопросов НЕ выгружались») — факту S17-подготовки
  (PR#138: 8 групп, 321 знак, 1292 изображения вопросов) противоречит.
  Синхронизация README — задача 17.2 (документация корпуса, сами .md не
  правятся).
- **«таймер»** — без величины в решении; принят 20:00 на билет 20 вопросов
  (формат экзамена ГИБДД на источнике; постановка СА в спринт-задаче).
- **Плитка «Обучение ПДД» (СКОРО) на «Главной» НЕ переключается** на новый
  раздел: разметка плиток — вербатим-гард test_cabinet_page.py
  (дословный перенос мокапа кабинета); переходы к обучению — только через
  сайдбар (постановка: «разделы в сайдбаре»).

## What Changes (Что меняет)

- **Разделы сайдбара кабинета ученика (NEW learning)**: 4 кнопки в
  .snav после «Кошелек» — «Знаки», «Правила», «Билеты», «Штрафы» (итого
  9 пунктов); разметка синхронно в обоих носителях (frontend/vue/cabinet.html
  + src/pages/cabinet/App.vue — правило С15 «Разметку держать синхронной»);
  хеш-навигация по прецеденту #/my-requests: #/pdd-signs, #/pdd-rules,
  #/pdd-tickets, #/pdd-fines (reload сохраняет раздел, replaceState);
  секции — Vue-компоненты с динамическим импортом (lazy-чанки), монтируются
  при первом открытии раздела. Сайдбар при 9 пунктах получает прокрутку
  (одна добавленная CSS-строка в конце styles.css — вербатим-гард мокапа
  допускает ТОЛЬКО добавление правил в конец).
- **«Знаки» (NEW)**: чипы 8 групп с счётчиками → сетка карточек
  (изображение /pdd-assets/znaki/<номер>small.png + номер + название) →
  деталь знака (крупное изображение, номер, название, группа, блок
  описания из znaki-details.json; блок штрафа рендерится при наличии
  записи fine в znaki-details.json — 166/321 — и отсутствует при её
  отсутствии; условная семантика MUST, см. «Сверка» и design
  «Решение 4»).
- **«Правила» (NEW)**: двухколоночный макет согласованного мокапа —
  оглавление 26 глав слева, глава справа; переход по клику в toc.
- **«Билеты» — тренажёр (NEW)**: выбор категории (A/B/M | C/D) и билета
  (1–40); таймер 20:00 на билет (авто-финиш на 00:00); вопрос с картинкой
  если есть; клик по варианту → фиксация ответа, подсветка верного/
  неверного, показ пояснения; навигация 1–20 со статусами вопросов
  (отвечен верно/неверно/не отвечен); досрочная «Сдать»; экран результата
  со счётом. Состояние — клиентское (Vue ref), персистентность НЕ
  требуется (MVP, решение Заказчика). Данные — build-time JSON того же
  генератора (по билету — отдельный чанк).
- **«Штрафы» (NEW)**: таблица всех строк корпуса (статья/нарушение/
  наказание) + клиентский поиск (подстрока, без учёта регистра, по всем
  трём колонкам).
- **Доставка контента (NEW, инфраструктура)**: тексты — build-time
  генератор frontend/vue/scripts/generate-pdd-json.mjs (шаг `npm run
  build`: node generate-pdd-json.mjs && vite build) → frontend/vue/src/
  pages/cabinet/pdd-data/*.json (в git НЕ коммитятся) → lazy-чанки
  разделов; изображения НЕ в vite-бандле — статика: GET /pdd-assets/
  {group}/{file} из content/pdd/images (group ∈ znaki|bilety) в
  backend/app.py — прецедент /vue/assets (ADR-001: один сервис отдает
  API и статику; nginx отклонён там же); Dockerfile — COPY content/
  content/ (+~48 МБ к образу, допустимо).
- **Бюджеты (NFR-26-семейство)**: check:budgets дорабатывается —
  замыкание первого захода считается ТОЛЬКО по статическим импортам
  (`from"…"`; соответствует собственному тексту NFR-26 «static-import
  graph» — текущая регулярка ошибочно включает и динамические `import(…)`
  чанки), новые правила: каждый lazy-чанк ≤ 150 КБ gzip; ни один
  lazy-чанк не входит в статическое замыкание ни одной из 14 страниц
  (гард «кабинет не распухает»). PAGES = 14 без изменений (новых
  html-входов НЕТ — разделы живут внутри /cabinet).
- **НЕ входит**: «Вопросы по темам» (36 тем) — дословно «пока не надо»;
  персистентность прогресса тренажёра; сочинение контента и карты
  знак→статья КоАП сверх записей znaki-details.json (блок штрафа —
  только из записей fine корпуса); правки файлов корпуса (только
  перегенерация); новые API/таблицы БД (контент статикой, клиентское
  состояние).
