# Change: add-instructor-cabinet

## Why (Зачем)

Спринт 2, часть 2: личный кабинет инструктора. После Спринта 2.1 одобренный
инструктор после входа попадает только на заглушку «кабинет скоро»
(/instructor/cabinet-stub) — кабинет как визуал отсутствует. Макет кабинета
design/mocks/dashboard-instructor.html утвержден Заказчиком и сохранен именно
под этот объем (решение Спринта 2.1: «макет — следующий объем»).

Источник требований: `requirements-instructor-cabinet.md` (УТВЕРЖДЕН,
FR-18…FR-22, NFR-2/3, все Must). Решение: `decisions/2026-10-13-instructor-cabinet.md`.

## What Changes (Что меняет)

Новая возможность (ADDED; существующие домены registration/auth/cabinet/admin/
instructor-application/admin-moderation/instructor-auth поведением не
меняются):

- Домен `instructor-dashboard`:
  - страница /instructor/dashboard — кабинет инструктора по макету дословно
    (тексты, структура, стили ключевых блоков; все данные — демо, макет
    «Все данные вымышлены»);
  - доступ — только инструктору с валидной сессией (X-Session-Token,
    role='instructor'); роль проверяется на бэке (require_session + role);
    иначе — редирект на главную (к модалке входа);
  - ФИО в шапке и инициалы аватара — из учетной записи инструктора
    (учетные данные users; GET /api/auth/me уже отдает ФИО — состав данных
    переиспользуется, выдача кабинету идет через защищенный эндпоинт
    кабинета с серверной проверкой роли, см. design.md);
  - переключение разделов сайдбара — визуальное (заголовок/crumb меняются,
    контент остается демо); разделы помечены как демо-данные;
  - выход (через «Профиль и документы» / прямая кнопка) → POST
    /api/auth/logout → очистка sessionStorage → редирект на главную.
- Роутинг после входа (wiring фронта): route='cabinet' ответа
  /api/auth/login ведет на /instructor/dashboard (назначение маршрута
  меняется с /instructor/cabinet-stub на полноценный кабинет; контракт
  ответа login §15.5 — ключ route="cabinet" — не меняется).

## Impact (Последствия)

- Код: новый модуль `backend/instructor_dashboard.py` (GET /api/instructor/me —
  require_session + проверка role); новая страница
  `frontend/instructor-dashboard.html`; правка `app.py` (маршрут статики +
  роутер — единственная точка правки существующего бэка); wiring
  `frontend/index.html` (route cabinet → /instructor/dashboard); тесты в
  `tests/`.
- Master-spec: домен `instructor-dashboard` создается этой дельтой;
  существующие домены не модифицируются. Заглушка /instructor/cabinet-stub и
  ее спека (instructor-auth) остаются в силе как страница.
- API-контракты и статика фиксируются в `sdd.md` (раздел «Спринт 2, часть 2»,
  §20–25); модель данных — без изменений схемы (users §4/§16 достаточна).

## Out of scope / допущения

- **Реальное расписание, доходы/выплаты, ученики, автомобиль, материалы** —
  вне объема: все цифры и списки кабинета — демо-данные макета; реальная
  бизнес-логика — будущие объемы (backlog ТЗ). Разделы сайдбара «Мои
  ученики», «Доходы и выплаты», «Мой автомобиль», «Материалы и обучение»,
  «Профиль и документы» — разделы-заглушки с демо-контентом (FR-21).
- **Загрузка файлов** (документы профиля, материалы) — не реализуется.
- Допущение (FR-19 vs макет): HTML макета не содержит nav-кнопок сайдбара
  (стили .nav и механика navTo заданы), при этом FR-19 перечисляет разделы
  явно. Разделы сайдбара строятся по перечню FR-19 («Мой день, Расписание,
  Мои ученики, Доходы и выплаты, Мой автомобиль, Материалы и обучение,
  Профиль и документы») в стилистике макета; дословность текстов/структуры/
  стилей ключевых блоков из FR-19 не затрагивается. Зафиксировано в
  design.md.
- Допущение (демо-поля учетки): строка «Инструктор · Категория B» в шапке и
  все содержимое карточек — демо (в users нет категории ВУ/расписания/доходов;
  категория хранится только в заявке). Подставляются только ФИО и инициалы
  (FR-20).
- Допущение (роутинг): назначение route='cabinet' после входа меняется с
  заглушки на /instructor/dashboard — иначе кабинет недостижим из флоу входа
  и объем теряет смысл. Контракт login (§15.5) не меняется; дельта по домену
  instructor-auth не создается, сценарий перехода после входа покрыт в домене
  instructor-dashboard.
