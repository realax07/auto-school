# Change: add-personal-data-policy

## Why (Зачем)

Спринт 9, задача 9.1 (PLAN.md). Политика персональных данных — БЛОКЕР
запуска сервиса в эксплуатацию: сервис собирает ПД (ФИО, телефон, email,
адрес, реквизиты ВУ, фото ВУ/СТС, госномер, фото авто), но:

1. Страницы политики не существует; в анкете инструктора стоит заглушка
   «Перед запуском здесь должна быть ссылка на утверждённую политику и
   текст согласия» (frontend/instructor-apply.html, checkline).
2. Форма регистрации ученика (модалка «Регистрация» на лендинге) не
   имеет ни чекбокса согласия, ни ссылки на политику — согласие ученика
   не выражается вовсе.
3. Согласие инструктора (введено Спринтом 3, MIN-2) только проверяется
   на клиенте/сервере — НЕ фиксируется: ни даты согласия, ни версии
   политики в заявке нет; подтвердить, СОГЛАСИЕ НА КАКУЮ ВЕРСИЮ текста
   выразил заявитель, невозможно.

Решение Заказчика 2026-11-02 (ОВ-1, ОВ-2): стандартный шаблон 152-ФЗ,
текст политики — ОТДЕЛЬНЫЙ заменяемый артефакт (подмена без правки кода
и пересборки — NFR-25); обязательные чекбоксы согласия в ОБОИХ контурах
регистрации (инструктор + ученик) со ссылками на /policy; фиксация
согласия (дата + версия) в заявке/записи.

Источник требований: `docs/ba/requirements-sprint9.md` (УТВЕРЖДЕН;
ОВ-1…ОВ-4 — decisions/2026-11-02-sprint9-scope.md), решение на
create_change — decisions/2026-11-02-s9-personal-data-policy-go.md.
Объем настоящего пакета — ТОЛЬКО блок 1 (FR-76…FR-79, NFR-25): блоки
2 (polling статуса) и 3 (Vue 3 + Vite) — соседние пакеты Спринта 9.

## What Changes (Что меняет)

- Домен `PersonalData` (ADDED): публичная страница /policy (без входа)
  с текстом политики 152-ФЗ под данные сервиса и его версией; текст —
  из ОТДЕЛЬНОГО артефакта (файл с метаданными версии/даты), в исходниках
  страниц (HTML/JS) текста политики нет (NFR-25, ОВ-1).
- Артефакт политики (ADDED): файл в контуре деплоя с точкой монтирования
  (решение СА — design.md); подмена = замена файла (+ перезапуск
  контейнера), без правки кода и без пересборки бандлов, ≤ 15 минут без
  разработчика (NFR-25). Первая версия — 1.0 (дата релиза Спринта 9).
- Контур инструктора (MODIFIED, FR-77, FR-79): чекбокс согласия в анкете
  дополняется ссылкой на /policy (заглушка удаляется) и клиентской
  блокировкой кнопки сабмита до установки; серверная проверка согласия
  уже есть (MIN-2, Спринт 3) — добавляется ФИКСАЦИЯ: consent_at (UTC
  сервера) + consent_policy_version (из артефакта на момент сабмита) в
  заявке. Контракт /api/instructors/apply обратно-совместим (поле
  consent существовало; ответ {ok:true} без изменений).
- Контур ученика (MODIFIED, FR-78, FR-79): в модалку «Регистрация»
  добавляется обязательный чекбокс согласия со ссылкой на /policy,
  кнопка сабмита блокирована до установки; POST /api/register получает
  НОВОЕ обязательное поле consent (отсутствие/false → 422 {ok:false},
  пользователь не создается — прямое требование FR-78) и фиксирует
  consent_at + consent_policy_version в записи users. Ответ
  {ok:true, token} — без изменений.
- Модель данных (ADDED-колонки, NFR-27): consent_at и
  consent_policy_version в users и instructor_applications —
  idempotent-миграция (механика _COLUMN_MIGRATIONS db.py). Легаси-строки
  (созданные до введения политики) получают NULL — БЕЗ seed/backfill:
  повторное согласие у уже зарегистрированных — вне объема.
- Раздача (ADDED): GET /api/policy — публичный (без авторизации, механика
  /api/health): текст + метаданные артефакта; страница /policy —
  оболочка frontend/policy.html, текст получает из API при загрузке
  (рендер текстовыми узлами — XSS-гигиена).

Модульная архитектура (директива Заказчика, наследуется): домен ПД —
в ОТДЕЛЬНОМ модуле backend/policy.py (парсер артефакта + раздача);
register.py/instructors.py — точечные расширения (фиксация согласия);
новых страниц, кроме /policy, нет; фронт — правки существующих
ES-модулей frontend/js/*.

## Impact (Последствия)

- Код: НОВЫЙ backend/policy.py (чтение/парсинг артефакта, GET
  /api/policy, хелпер версии для фиксации), backend/app.py (страница
  /policy в _PAGE_ROUTES + роутер policy), backend/register.py (поле
  consent + фиксация), backend/instructors.py (фиксация согласия),
  backend/db.py (4 колонки, idempotent), frontend/policy.html (НОВАЯ
  страница-оболочка БЕЗ текста политики), frontend/index.html +
  frontend/js/landing.js (чекбокс/ссылка/consent в модалке регистрации),
  frontend/instructor-apply.html + frontend/js/apply.js (ссылка на
  /policy, клиентская блокировка кнопки).
- Хранилище: 4 NULL-able колонки (users, instructor_applications) —
  idempotent-миграция на существующем volume (init_db через lifespan —
  наследование add-containerization); данные НЕ мигрируют (легаси — NULL,
  сознательное решение).
- Артефакт: deploy/policy/policy.md — шаблон 152-ФЗ v1.0, версия/дата
  в шапке артефакта; deploy-контур: точка монтирования + POLICY_FILE
  (docker-compose, RUNBOOK — операция подмены).
- Master-spec: ADDED — PersonalData (5 требований: страница /policy,
  согласие инструктора, согласие ученика, фиксация согласия,
  заменяемость артефакта).
- API-контракты и модель данных — design.md настоящего пакета;
  sdd.md (раздел «Спринт 9») дополняется задачей приемки.
- Тесты: обязательность consent в /api/register — легитимные правки
  тестовой поддержки: conftest valid_body/register → consent:true,
  негативные кейсы 422, Playwright-сценарий модалки регистрации — клик
  чекбокса (DOM пополнился контролом). FR-85 (запрет правки e2e)
  относится к шагам МИГРАЦИИ блока 3 — на настоящий change не
  распространяется; проверки существующих сценариев не меняются.

## Out of scope / допущения

- Блоки 2 и 3 Спринта 9 (polling статуса заявки, ADR/каркас Vue 3 +
  Vite, пилотная страница) — соседние change-пакеты; настоящий пакет
  их не касается.
- Юридическая экспертиза и кастомизация текста — НЕ в объеме:
  стандартный шаблон 152-ФЗ (ОВ-1); замена текста на собственный —
  операция подмены артефакта силами владельца сервиса.
- Повторное согласие у УЖЕ зарегистрированных инструкторов/учеников при
  смене версии политики; консент-журнал аудита повторных согласий —
  точки расширения (фиксация только в момент регистрации, FR-79).
- Скачивание политики файлом (PDF), ссылка на /policy в футерах
  лендинга/кабинетов помимо двух обязательных мест согласия — точки
  расширения (MoSCoW: не Must).
- Ревизия состава собираемых данных анкет — не в объеме: политика
  описывает данные, собираемые СУЩЕСТВУЮЩИМИ формами.
- Хранение истории версий текста политики (несколько артефактов с
  выборкой по версии) — не в объеме: артефакт один, «актуальный».
