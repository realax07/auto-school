# Research: add-registration-admin

Ключевые техрешения зафиксированы утвержденным дизайном Заказчика
(docs/superpowers/specs/2026-10-08-registration-admin-design.md, чат-лог
2026-10-08). Ниже — рассмотренные альтернативы и обоснование выбора (E12).

## 1. Бэкенд-фреймворк

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **FastAPI** | Автогенерируемый OpenAPI (контракты по паттерну 7 map.md), валидация входа, быстрая разработка | — | **ВЫБРАНО** (утверждено Заказчиком; ограничение ТЗ) |
| Flask | Простой | Валидацию и OpenAPI нужно прикручивать вручную | Отклонено |
| Django + DRF | Готовая админка | Избыточен для одного API-сервиса спринта 0, тяжелее контур | Отклонено |
| aiohttp/Litestar | Производительность | Меньше готового, нет автогенерации контрактов «из коробки» | Отклонено |

Выбор продиктован ограничением ТЗ (стек: FastAPI + SQLite) и потребностью
фиксировать API-контракты (OpenAPI автогенерируется). NFR-1 (≤ 500 мс)
FastAPI на типичных данных выполняет с запасом.

## 2. База данных

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **SQLite (файл, WAL)** | Ноль инфраструктуры, файл data/app.db, параметризованные запросы, WAL покрывает конкурентность спринта 0 | Один писатель; не для горизонтального масштабирования | **ВЫБРАНО** (утверждено Заказчиком; ограничение ТЗ) |
| PostgreSQL | Конкурентность, типы | Требует сервер/контейнер — вне границ спринта 0 (без деплоя/контейнеров) | Отложено до Релиза 1 |
| JSON-файл вместо БД | Простейший | Нет атомарности/уникальности email, конфликт с паттерном 5 (БД — хранение данных) | Отклонено |

Паттерн 3 (map.md, «свои данные у сервиса») соблюдается: одна SQLite-БД
принадлежит этому сервису. SQL — только параметризованный (NFR-2).

## 3. Авторизация админа: токен

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **In-memory токен (secrets.token_urlsafe, TTL 12ч)** | Тривиальная реализация, мгновенный отзыв рестартом, без внешних зависимостей | Теряется при рестарте; single-worker | **ВЫБРАНО** (утверждено Заказчиком для спринта-0) |
| JWT (HS256) | Stateless, переживает рестарт | Нужна библиотека и управление секретом/ротацией; для одного админа избыточно | Отложено (следующие спринты) |
| Сессионные cookie | Классика для браузера | CSRF-поверхность; избыточно для API-дашборда с fetch + заголовком | Отклонено |

Ограничение in-memory токена (потеря при рестарте, single-worker)
задокументировано в дизайне как приемлемое для спринта 0. FR-8 выполняется:
токен выдается только после успешной сверки ADMIN_USER + bcrypt-хэша.

## 4. Хэширование паролей

**bcrypt напрямую (cost 12)** — утверждено дизайном; обертка passlib не
нужна (лишняя зависимость). Альтернативы argon2id/scrypt отклонены:
ограничением ТЗ задан bcrypt cost 12.

## 5. Инкрементальные мелочи

Статика без сборки (plain HTML/CSS/JS из design/mocks), чтение конфига из
.env — тривиальны, альтернативы не рассматривались (инкремент тривиален).
