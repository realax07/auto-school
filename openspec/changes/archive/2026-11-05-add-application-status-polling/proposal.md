# Change: add-application-status-polling

## Why (Зачем)

Заявитель-инструктор, отправивший анкету, попадает на статичный экран
«Ожидание модерации» (/instructors/pending): сегодня это «просто экран» —
статус проверяется ТОЛЬКО при логине (FR-13, Спринт 2; комментарий в
frontend/instructor-pending.html). Чтобы узнать решение, заявитель
вынужден перелогиниваться: боль пользователя и лишние проходы через
контур входа (анти-брутфорс) без причины.

Спринт 9 (решение Заказчика 2026-11-02 — состав «1 3 5 давай»;
create_change — decisions/2026-11-02-s9-application-status-polling-go.md,
PLAN.md 9.2): экран ожидания САМ опрашивает статус заявки без перелогина
(интервал 10–15 с), waiting → approved — автоматический бесшовный
переход в кабинет инструктора, waiting → rejected — показ причины
отказа без входа. Опрос останавливается при уходе со страницы.
Ограничения NFR-28: ≤5 запросов/мин, неперебираемый идентификатор,
404-неразличение, эндпоинт только чтение.

Источник требований: docs/ba/requirements-sprint9.md, блок 2
(FR-80…FR-83) + NFR-28 (УТВЕРЖДЕН Заказчиком 2026-11-02). Экран
ожидания одновременно — пилотная страница миграции на Vue 3 + Vite
(ОВ-4, FR-86): функциональность блока 2 реализуется НА новом стеке —
синергия задач 9.2 и 9.4 PLAN.md (зависимость от change
add-vue-framework-pilot).

## What Changes (Что меняет)

- Неперебираемый идентификатор заявки (FR-80): при успешной отправке
  анкеты POST /api/instructors/apply сервис выдает ДВА случайных токена
  (secrets.token_urlsafe(32) — тот же генератор, что у сессий Спринта 1):
  poll_token — многоразовый идентификатор опроса статуса, exchange_token —
  одноразовый токен обмена на сессию при approved (решение СА по
  открытому вопросу п.1 — design.md). Ответ apply расширяется полями
  обратно-совместимо (NFR-27); заявка хранит токены (idempotent-миграция
  двух колонок; backfill НЕ делается — исторические заявки работают как
  сегодня).
- Новый read-only эндпоинт статуса (FR-80, NFR-28): GET
  /api/instructors/application-status по заголовку X-Poll-Token —
  одиночный параметризованный SELECT, без записи и побочных эффектов;
  чужой/несуществующий токен → 404-неразличение; токен в заголовке, НЕ
  в URL (access-логи path+query токенов не содержат).
- Обмен идентификатора на сессию (FR-81): POST
  /api/instructors/application-exchange по одноразовому exchange_token —
  ТОЛЬКО при approved: сессия users (роль instructor) выдается
  существующей фабрикой сессий auth.py (единый in-memory реестр, TTL
  12 ч — НОВОЙ сессионной механики НЕТ); токен потребляется той же
  транзакцией; повторный/чужой токен → 404-неразличение; статус
  не-approved → 409. Контур модерации и login — БЕЗ ИЗМЕНЕНИЙ.
- Экран ожидания — polling (FR-80…FR-83): интервал 12 с (первый тик —
  сразу при открытии с идентификатором; бюджет ≤5 запросов/мин
  соблюдается); waiting → approved — обмен токена на сессию и переход
  на /instructor/dashboard (route 'cabinet' — та же механика, что после
  логина; sessionStorage 'session_token' — БЕЗ повторного ввода
  пароля); waiting → rejected — статус «заявка отклонена» и причина
  отказа без входа (переиспользуются существующий экран
  /instructors/rejected и механика sessionStorage логина — единый путь
  показа отказа, Спринт 2); ошибка обмена ПЕРЕХОДНАЯ (409/сеть) — экран
  остается в waiting, опрос продолжается; ПОСТОЯННЫЙ отказ обмена (404 —
  токен потреблен/чужой) — терминально: опрос остановлен, токены
  localStorage удалены, нейтральная подсказка входа; при УСПЕШНОМ
  обмене токены удаляются из localStorage ДО перехода в кабинет;
  остановка опроса при уходе (скрытие вкладки —
  visibilitychange, закрытие/переход — pagehide/beforeunload: таймеров,
  переживающих страницу, нет); сетевая ошибка — молча, интервал прежний
  (без учащения и всплывающих ошибок); экран без сохраненного
  идентификатора — прежний статичный режим без запросов (FR-80).
- Vue-пилот (FR-86, ОВ-4): страница /instructors/pending мигрирует на
  каркас Vue 3 + Vite change add-vue-framework-pilot — весь блок 2
  реализуется на новом стеке (чанк страницы + vendor-чанки, budgets
  NFR-26 — объем пилотного пакета). ЗАВИСИМОСТЬ: фронт-часть этого
  пакета стартует ПОСЛЕ каркасной задачи пакета
  add-vue-framework-pilot (PLAN.md: 9.3 → 9.4); бэкенд-часть независима.

## Impact (Последствия)

- Код: backend/db.py — РАСШИРЕНИЕ (колонки poll_token / exchange_token в
  instructor_applications + уникальные частичные индексы;
  idempotent-миграция механики db.py, init_db через lifespan —
  существующий volume); backend/instructors.py — РАСШИРЕНИЕ (генерация и
  выдача токенов в ответе apply); backend/application_status.py — НОВЫЙ
  домен (эндпоинт статуса + обмен; директива модульности: новые маршруты
  НЕ раздувают instructors.py/auth.py); backend/app.py — include
  роутера. Фронт: страница /instructors/pending — Vue-версия (каркас
  add-vue-framework-pilot) с polling-логикой блока 2;
  frontend/js/apply.js — сохранение poll_token/exchange_token в
  localStorage перед СУЩЕСТВУЮЩИМ редиректом на /instructors/pending.
  БЕЗ ИЗМЕНЕНИЙ: auth.py (login/logout/me, анти-брутфорс — только
  переиспользование фабрики сессий), instructor_admin.py (контур
  модерации), admin.py, существующие e2e-сценарии (NFR-27).
- Хранилище: ALTER TABLE instructor_applications ADD COLUMN poll_token /
  exchange_token (idempotent, на существующем volume). Backfill НЕ
  выполняется: исторические заявки без токенов — экран ожидания для них
  в прежнем статичном режиме (статус по логину, как сегодня); поведение
  для существующих пользователей не меняется.
- Master-spec: ADDED домен StudentFlow («Автоопределение статуса заявки
  на экране ожидания») — дельта specs/StudentFlow/spec.md настоящего
  пакета; сливается при архивации (сводит СА).
- API-контракты и модель данных — design.md настоящего пакета; sdd.md
  (раздел «Спринт 9»: контракты, механизм токенов, матрица трассировки)
  дополняется задачей приемки.

## Out of scope / допущения

- Уведомления о смене статуса (email/push) — backlog (пункт 4), не в
  Спринте 9 (requirements §Границы скоупа).
- Автовход вне цепочки «анкета → ожидание → кабинет» (например,
  автовход для учеников) — вне объема (requirements §Границы).
- Контур модерации (waiting/approved/deny, обязательный комментарий
  отказа) — БЕЗ ИЗМЕНЕНИЙ: блок 2 только читает статус и причину.
- Серверный rate-limiter НЕ вводится: NFR-28 — бюджет клиента
  (интервал 12 с → ≤5 запросов/мин), проверяется тестами и приемкой;
  эндпоинт дешевый (одиночный SELECT по индексу).
- Показ номера заявки на экране ожидания (открытый вопрос п.4
  requirements, решение за ПМ) — в объем НЕ включен.
- Опрос исторических заявок (без выданных токенов) — НЕ реализуется:
  их владельцы, как и сегодня, узнают статус логином; backfill токенов
  «в никуда» (выдать их заявителю некому) не делается.
- Каркас Vue 3 + Vite, ADR на стек, vendor-сплит, бюджеты чанков
  (NFR-26) — объем change add-vue-framework-pilot; этот пакет
  поставляет функциональность блока 2 НА каркасе и зависит от него,
  не дублируя ADR/бюджеты.

## Отслеживание

- FR-80 (идентификатор опроса при сабмите, интервал 12 с, статичный
  режим без идентификатора, актуальность ≤1 интервала) →
  specs/StudentFlow/spec.md (ADDED «Автоопределение статуса заявки на
  экране ожидания»; сценарии «Экран опрашивает статус по
  неперебираемому идентификатору», «Экран без сохраненного
  идентификатора — статичный режим без запросов»).
- FR-81 (бесшовный переход при approved; ошибка обмена) → сценарии
  «waiting → approved: бесшовный переход в кабинет без ввода пароля»,
  «Ошибка обмена оставляет экран в waiting», «Обмен вернул 404 (токен
  потреблен или чужой) — терминальное состояние с подсказкой входа».
- FR-82 (отказ с причиной; нейтральный текст без комментария) →
  сценарий «waiting → rejected: причина отказа без входа».
- FR-83 (остановка при уходе; сетевая ошибка без учащения) → сценарии
  «Опрос останавливается при уходе со страницы», «Сетевая ошибка не
  меняет график опроса».
- NFR-28 (неперебираемость, 404-неразличение, ≤5 запросов/мин, только
  чтение, латентность ≤15 с) → сценарии «Чужой или несуществующий
  идентификатор — 404-неразличение», «Один открытый экран — не более
  5 запросов статуса в минуту»; «только чтение» — в тексте требования
  и сценарии опроса.
- NFR-27 (без ломающих изменений: apply расширяется полями, контракты
  login/модерации/e2e не меняются) — сквозное: решения design.md,
  контроль — задачи tasks.md (сборка и приемка).
