# Delta: StudentFlow

## ADDED Requirements

### Requirement: Автоопределение статуса заявки на экране ожидания

Экран «Ожидание модерации» (/instructors/pending) MUST автоматически
опрашивать статус заявки без перелогина по неперебираемому
идентификатору из ответа apply (интервал 12 с, допустимо
10–15 с). Переходы: waiting → approved — бесшовно, в кабинет;
waiting → rejected — статус и причина отказа без входа. Опрос MUST
останавливаться при уходе; успешный обмен удаляет идентификаторы с
экрана; 404 обмена (токен потреблен/чужой) — терминально, с
нейтральной подсказкой входа. Нормы — по сценариям.

#### Scenario: Экран опрашивает статус по неперебираемому идентификатору

- **GIVEN** анкета отправлена успешно (apply 200 с poll_token/exchange_token), идентификатор сохранен на экране ожидания, заявка waiting
- **WHEN** экран ВИДИМ (вкладка активна) и проходит очередной интервал 12 с
- **THEN** экран показывает «на рассмотрении» и опрашивает статус по неперебираемому идентификатору (запрос только чтения, без записи и побочных эффектов); GIVEN статус сменен админом THEN при видимом экране изменение отражается не позднее одного интервала (≤15 с) без действий пользователя (скрытая вкладка — опрос остановлен FR-83; латентность отсчитывается с возврата видимости)

#### Scenario: Экран без сохраненного идентификатора — статичный режим без запросов

- **GIVEN** /instructors/pending открыт по прямой ссылке без сохраненного идентификатора (историческая заявка или чужое устройство)
- **WHEN** экран загружен
- **THEN** экран работает в прежнем статичном режиме: текст «на рассмотрении», запросов статуса нет, ошибок нет

#### Scenario: waiting → approved: бесшовный переход в кабинет без ввода пароля

- **GIVEN** заявка waiting, экран ожидания опрашивает статус по идентификатору, у заявителя одноразовый токен обмена
- **WHEN** админ одобряет заявку (approved) и проходит очередной интервал
- **THEN** экран обменивает одноразовый токен на существующую сессию users (роль instructor) и заявитель оказывается в кабинете инструктора (/instructor/dashboard) без повторного ввода пароля; идентификаторы удаляются с экрана ДО перехода — возврат на /instructors/pending после успеха: статичный режим без запросов (сценарий «Экран без сохраненного идентификатора — статичный режим без запросов»)

#### Scenario: Ошибка обмена оставляет экран в waiting

- **GIVEN** статус заявки approved, но обмен одноразового токена на сессию не удался по ПЕРЕХОДНОЙ причине: 409 (guard статуса — заявка уже/еще не approved, вырожденное «approved без users») или сетевая ошибка; токен при этом НЕ потреблен
- **WHEN** экран обрабатывает результат обмена
- **THEN** экран остается в «на рассмотрении» и опрос продолжается по графику (12 с); токен сохранен — повторный обмен возможен на следующем тике (ПОСТОЯННЫЙ отказ обмена — 404: потребленный/чужой токен — отдельный терминальный сценарий ниже)

#### Scenario: Обмен вернул 404 (токен потреблен или чужой) — терминальное состояние с подсказкой входа

- **GIVEN** статус заявки approved, но обмен завершился 404-неразличением: exchange_token уже потреблен (сессия выдана при более раннем обмене — например, бесшовный переход уже состоялся в этой или другой вкладке) ЛИБО токен чужой/несуществующий
- **WHEN** экран обрабатывает ответ обмена
- **THEN** повторный обмен невозможен по построению — экран в терминальном состоянии: опрос остановлен (таймер снят, запросов больше нет), application_poll_token и application_exchange_token удалены из localStorage, экран показывает нейтральную подсказку войти с email и паролем (без деталей о токене/заявке — 404-неразличение сохраняется); GIVEN пользователь возвращается на /instructors/pending THEN экран в статичном режиме без запросов (сценарий «Экран без сохраненного идентификатора — статичный режим без запросов»)

#### Scenario: waiting → rejected: причина отказа без входа

- **GIVEN** админ отклонил заявку с обязательным комментарием «нечитаемое фото ВУ»
- **WHEN** экран получает статус rejected на очередном тике
- **THEN** заявитель видит статус «заявка отклонена» и текст причины «нечитаемое фото ВУ» без входа и без перелогина; GIVEN комментарий отказа отсутствует (историческая заявка) THEN виден нейтральный текст отказа без причины; вход для просмотра не требуется

#### Scenario: Опрос останавливается при уходе со страницы

- **GIVEN** экран ожидания опрашивает статус (таймер 12 с активен)
- **WHEN** вкладка закрывается, пользователь уходит по любой ссылке ИЛИ вкладка скрывается (visibilitychange hidden)
- **THEN** новые запросы статуса не отправляются; таймеров, переживающих страницу, нет; при возврате видимости опрос возобновляется по обычному графику; GIVEN страница восстановлена из back/forward cache (back-навигация, pageshow persisted=true) THEN таймер перевооружается — опрос продолжается по обычному графику (без немедленного тика)

#### Scenario: Сетевая ошибка не меняет график опроса

- **GIVEN** экран ожидания опрашивает статус по графику 12 с
- **WHEN** очередной тик не удался по сети
- **THEN** пользователь ничего не видит (без всплывающих ошибок), экран остается в «на рассмотрении», следующий тик — через те же 12 с (без учащения)

#### Scenario: Чужой или несуществующий идентификатор — 404-неразличение

- **GIVEN** опрос статуса с несуществующим ИЛИ чужим идентификатором (подобранным/подделанным)
- **WHEN** обрабатывается ответ эндпоинта статуса
- **THEN** ответ — 404-неразличение: чужая и несуществующая заявка неотличимы, существование чужих заявок не раскрывается; сессия не выдается

#### Scenario: Один открытый экран — не более 5 запросов статуса в минуту

- **GIVEN** один открытый экран ожидания с сохраненным идентификатором, интервал опроса 12 с
- **WHEN** измеряется число запросов статуса за минуту непрерывной видимости
- **THEN** запросов не более 5; при сетевой ошибке интервал не уменьшается; после ухода со страницы запросы прекращены
