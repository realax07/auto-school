# Delta: booking

## ADDED Requirements

### Requirement: Расписание инструктора доступно только принятым ученикам

Ученик MUST видеть слоты (рабочие интервалы графика) инструктора
ТОЛЬКО после создания пары (принятая заявка). До принятия заявки (нет
заявки, «новая», «отказана») расписание инструктора недоступно — и в
интерфейсе, и при прямом вызове API. Проверка доступа выполняется на
сервере при каждом запросе; UI-скрытие проверкой не считается
(трассировка: FR-46, NFR-7).

Источник: requirements-booking-docs.md FR-46, NFR-7.

#### Scenario: Не принятому ученику расписание недоступно при прямом вызове API

- **GIVEN** у ученика нет заявки инструктору, или заявка «новая», или «отказана»
- **WHEN** он (в том числе прямым запросом к API) пытается открыть слоты инструктора
- **THEN** доступ запрещен, расписание не возвращается

#### Scenario: Принятый ученик видит актуальный график

- **GIVEN** заявка ученика принята (пара создана), у инструктора заполнен график
- **WHEN** ученик открывает раздел расписания
- **THEN** он видит актуальные интервалы графика инструктора

#### Scenario: Гость и иная роль не получают расписание

- **GIVEN** гость без сессии или пользователь с ролью «инструктор»
- **WHEN** запрашиваются слоты через ученический эндпоинт расписания
- **THEN** доступ запрещен (401 для гостя, 403 для иной роли), расписание не возвращается

### Requirement: Запрос брони на слот

Ученик пары MUST уметь выбрать слот из графика инструктора и отправить
запрос брони; слот — интервал графика целиком, без нарезки на
подынтервалы (ОВ-3). Запрос создается со статусом «новая» и виден
инструктору. Повторный запрос на занятый слот (активный запрос или
подтвержденная бронь) не создается. Повторный запрос после отклонения
допустим, без ограничений на количество (трассировка: FR-47, ОВ-3,
ОВ-4, ОВ-5).

Источник: requirements-booking-docs.md FR-47; ОВ-3, ОВ-4, ОВ-5.

#### Scenario: Запрос создается со статусом «новая» и виден инструктору

- **GIVEN** пара создана и у инструктора есть свободный слот
- **WHEN** ученик выбирает слот и отправляет запрос брони
- **THEN** запрос создан со статусом «новая» и появляется у инструктора в запросах брони

#### Scenario: Занятый слот не бронируется повторно

- **GIVEN** у слота есть активный запрос или подтвержденная бронь одного ученика пары
- **WHEN** другой ученик той же пары пытается забронировать этот слот
- **THEN** действие отклонено, дублирующий запрос не создан

#### Scenario: Слот бронируется целиком

- **GIVEN** у инструктора есть интервал графика 10:00–14:00
- **WHEN** ученик бронирует этот слот
- **THEN** занятием считается весь интервал 10:00–14:00 (нарезка на подынтервалы не выполняется)

#### Scenario: Повторный запрос после отклонения допустим

- **GIVEN** запрос брони ученика на слот отклонен инструктором (с комментарием)
- **WHEN** ученик снова отправляет запрос на этот же слот
- **THEN** новый запрос создается (повторная подача не ограничена)

### Requirement: Решение инструктора по запросу брони

Инструктор MUST уметь подтвердить или отклонить запрос брони, адресованный
ему. Подтверждение выполняется без комментария и переводит бронь в статус
«подтверждена». Отклонение — с обязательным комментарием (причиной): без
комментария действие недоступно. Статусы брони: новая → подтверждена /
отклонена; комментарий отклонения виден ученику (трассировка: FR-48, ОВ-2).

Источник: requirements-booking-docs.md FR-48; ОВ-2.

#### Scenario: Подтверждение без комментария

- **GIVEN** у инструктора есть входящий запрос брони в статусе «новая»
- **WHEN** инструктор подтверждает бронь
- **THEN** бронь становится «подтверждена» без какого-либо комментария

#### Scenario: Отклонение без комментария заблокировано

- **GIVEN** у инструктора есть входящий запрос брони в статусе «новая»
- **WHEN** инструктор нажимает «Отклонить» с пустым комментарием
- **THEN** действие заблокировано (ошибка валидации), статус брони остается «новая»

#### Scenario: Отклонение с комментарием видно ученику

- **GIVEN** у инструктора есть входящий запрос брони в статусе «новая»
- **WHEN** инструктор вводит комментарий и отклоняет бронь
- **THEN** статус брони — «отклонена», и ученик видит статус и текст комментария

#### Scenario: Чужую бронь решить нельзя

- **GIVEN** запрос брони адресован инструктору А
- **WHEN** инструктор Б (со своей сессией) пытается подтвердить или отклонить этот запрос
- **THEN** действие отклонено, статус брони не меняется

### Requirement: Подтвержденная бронь в календарях обоих

Подтвержденный слот MUST отображаться в календаре ученика (дата,
время, инструктор, автомобиль) и в календаре инструктора (ФИО ученика,
автомобиль пары; перекрепление авто меняет автомобиль и в отображении
брони — ОВ-6). Виджет «Занятия на сегодня» MUST показывать реальные
подтвержденные брони на текущую дату; при их отсутствии — пустое
состояние «Сегодня занятий нет» (трассировка: FR-49, ОВ-6).

Источник: requirements-booking-docs.md FR-49; ОВ-6.

#### Scenario: Календарь ученика показывает занятие

- **GIVEN** бронь ученика подтверждена
- **WHEN** ученик открывает свой календарь
- **THEN** слот показан как занятие с датой, временем, инструктором и автомобилем

#### Scenario: Календарь инструктора показывает ученика и автомобиль

- **GIVEN** бронь подтверждена, за парой закреплен автомобиль
- **WHEN** инструктор открывает свой календарь
- **THEN** слот показан с учеником (ФИО) и автомобилем, привязанным к паре

#### Scenario: Перекрепление авто меняет авто в отображении брони

- **GIVEN** подтвержденная бронь с отображаемым автомобилем пары
- **WHEN** инструктор перекрепляет ученика на другой свой автомобиль
- **THEN** в отображении подтвержденной брони показан новый автомобиль пары

#### Scenario: Виджет «Занятия на сегодня» показывает реальные брони

- **GIVEN** существуют подтвержденные брони инструктора на текущую дату
- **WHEN** инструктор открывает главную кабинета
- **THEN** виджет «Занятия на сегодня» показывает эти брони (ученик, время)

#### Scenario: Нет броней на сегодня — прежнее пустое состояние

- **GIVEN** подтвержденных броней инструктора на текущую дату нет
- **WHEN** инструктор открывает главную кабинета
- **THEN** виджет показывает «Сегодня занятий нет» (пустое состояние, не ошибка и не фиктивные данные)

### Requirement: Занятый слот недоступен другим ученикам

Занятый слот (активный запрос или подтвержденная бронь) MUST быть
недоступен другим ученикам: не отображается как доступный и не
бронируется повторно; другому ученику пары виден как «занято» без
раскрытия, кем. Гарантия — на уровне хранилища: на один слот максимум
одна активная/подтвержденная бронь; параллельные запросы не создают
двойного подтверждения (трассировка: FR-50, NFR-8).

Источник: requirements-booking-docs.md FR-50, NFR-8.

#### Scenario: Занятый слот не отображается как доступный

- **GIVEN** слот подтвержден ученику А
- **WHEN** ученик Б (другая пара с тем же инструктором) обновляет расписание
- **THEN** слот недоступен для выбора

#### Scenario: Занятость видна без раскрытия, кем занято

- **GIVEN** слот занят запросом/бронью ученика А
- **WHEN** другой ученик пары смотрит расписание
- **THEN** слот помечен «занято», данные занявшего (кем именно) не раскрываются

#### Scenario: Параллельные запросы на один слот — максимум одна бронь

- **GIVEN** два запроса брони на один слот обрабатываются одновременно
- **WHEN** оба запроса обработаны хранилищем
- **THEN** подтверждена/активна максимум одна бронь, вторая получает явный отказ конфликта (а не молчаливую порчу)

### Requirement: Замена графика при активных бронях отклоняется

Инструктор MUST НЕ иметь возможности сохранить график (полная замена),
удаляющий слот с бронью в статусе «новая» или «подтверждена»: сохранение
отклоняется с явным перечнем затронутых слотов, график остается прежним.
Решение по брони остается за инструктором; слоты с бронями только в
статусе «отклонена» замене не мешают (трассировка: NFR-8, MAJ-1 арх-ревью).

Источник: arch-review.md MAJ-1; requirements-booking-docs.md NFR-8.

#### Scenario: Сохранение графика без слота с активной бронью отклоняется

- **GIVEN** у слота (например, Пн 10:00–14:00) есть бронь в статусе «новая» или «подтверждена»
- **WHEN** инструктор сохраняет график, не содержащий этот слот
- **THEN** сохранение отклоняется с перечнем затронутых слотов, прежний график остается без изменений, брони не меняются

#### Scenario: После решения броней график сохраняется

- **GIVEN** сохранение графика было отклонено из-за активной брони слота
- **WHEN** инструктор подтвердил или отклонил (с комментарием) эту бронь и повторяет сохранение того же графика
- **THEN** график сохраняется (замена выполняется)

#### Scenario: Слоты с только отклоненными бронями замене не мешают

- **GIVEN** у удаляемого слота есть только бронь(и) в статусе «отклонена»
- **WHEN** инструктор сохраняет график без этого слота
- **THEN** график сохраняется без отказа
