## 1. Домен auth (backend/auth.py)

- [x] 1.1 [P] backend/auth.py — модуль авторизации (отдельный от register.py,
      ограничение ТЗ): POST /api/auth/login (SELECT по email через
      параметризованный запрос, bcrypt.checkpw против password_hash,
      единое сообщение об отказе для всех причин — неверный email / неверный
      пароль / нет записи; токен secrets.token_urlsafe(32), in-memory реестр
      {token: (expires, user_id)} TTL 12ч, где user_id — источник данных
      /me (как у admin-токена, но с привязкой к записи users)), зависимость
      require_session (заголовок X-Session-Token), POST /api/auth/logout
      (аннулирование токена), GET /api/auth/me ({id, surname, name,
      patronymic, email} по токену). Ответы: 200 {ok:true, ...};
      401 {ok:false, error:"<единое сообщение>"} на входе и 401 {ok:false}
      на защищенных; 422 {ok:false, error:"<поле-ру>: поле обязательно"}
      при пустых полях (хендлерная валидация, формат Спринта 0).
      Анти-брутфорс (решение Заказчика, вариант (б), MAJ-3; требования —
      design.md «Минимальная анти-брутфорс защита /api/auth/login», спека —
      Requirement «Ограничение попыток входа (анти-брутфорс)»): учет
      неудачных попыток входа подряд с одного IP, после превышения порога
      (3–10, точное значение фиксирует разработчик) — временная блокировка
      входа с IP с нарастающей длительностью (от ≥30 с до ≤15 мин), сброс
      счетчика при успешном входе; заблокированный запрос отвечает тем же
      401 с единым сообщением (не раскрывает блокировку). Учет — в памяти
      процесса (single-worker; рестарт сбрасывает — документированное
      ограничение design.md).
      Готовность: тесты — успешный вход (токен выдается), все три причины
      отказа дают 401 с идентичной строкой ошибки, logout аннулирует токен
      (после logout запрос с токеном → 401), /me возвращает данные записи,
      истекший/подделанный токен → 401; пароль не попадает в логи;
      превышение порога неудачных попыток с одного IP приводит к отказу
      входа с этого IP без проверки учетных данных (тот же 401/сообщение),
      после успешного входа счетчик сброшен.
      FR: FR-1, FR-2, FR-3, FR-8. NFR: NFR-2, NFR-3.
