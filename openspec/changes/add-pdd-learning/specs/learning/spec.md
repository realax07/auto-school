# Delta: learning

## ADDED Requirements

### Requirement: Разделы сайдбара кабинета ученика — «Знаки», «Правила», «Билеты», «Штрафы»

Кабинет ученика MUST получить 4 пункта сайдбара — «Знаки», «Правила»,
«Билеты», «Штрафы» — к порядку существующих. Разделы открываются ВНУТРИ
кабинета (standalone-страницы запрещены); активный пункт подсвечен;
раздел синхронизируется с хешем URL — перезагрузка сохраняет его, хеш
открывает напрямую. Сайдбар из 9 пунктов при нехватке высоты
прокручивается.

Источник: решение 2026-11-15; мокапы pdd-*.html; прецедент
#/my-requests; разметка синхронна в обоих носителях.

#### Scenario: Открытие раздела из сайдбара

- **GIVEN** ученик авторизован и находится в кабинете
- **WHEN** он нажимает пункт сайдбара «Знаки» (аналогично «Правила», «Билеты», «Штрафы»)
- **THEN** открывается содержимое раздела в контентной области кабинета, пункт сайдбара подсвечен, хеш меняется на #/pdd-signs, остальные разделы скрыты

#### Scenario: Хеш открывает раздел напрямую

- **GIVEN** ученик открыл /cabinet#/pdd-fines (или другой хеш раздела)
- **WHEN** страница загружается
- **THEN** раздел «Штрафы» открыт сразу, без клика по сайдбару; перезагрузка страницы сохраняет раздел

#### Scenario: Существующие разделы не сломаны

- **GIVEN** кабинет до и после спринта
- **WHEN** ученик переключается между «Главная», «Мои заявки», «Мои брони», «Кошелек» и новыми разделами
- **THEN** все разделы переключаются взаимоисключающе; хеши #/my-requests, #/my-bookings, #/wallet работают как прежде; плитки «Главной» и wiring авторизации не изменены

#### Scenario: Сайдбар из 9 пунктов прокручивается

- **GIVEN** окно браузера низкой высоты, в сайдбаре 9 пунктов
- **WHEN** список пунктов не помещается по высоте
- **THEN** сайдбар прокручивается по вертикали, ни один пункт не становится недоступным

### Requirement: Раздел «Знаки» — группы, сетка карточек, деталь знака

Раздел «Знаки» MUST показывать чипы 8 групп со счётчиками из корпуса
(321 знак), сетку карточек выбранной группы (изображение + номер +
название) и деталь знака (крупное изображение, номер, название, группа,
возврат). Изображения — статика /pdd-assets/znaki/. Фильтрация и
переходы — клиентские. Блок штрафа (MAY) — только при наличии карты
знак→статья КоАП в данных; в S17 её нет.

Источник: решение 2026-11-15; мокап pdd-znaki-student.html; корпус
content/pdd/znaki + images.

#### Scenario: Группы и счётчики соответствуют корпусу

- **GIVEN** раздел «Знаки» открыт
- **WHEN** рендерятся чипы групп
- **THEN** ровно 8 групп; счётчики 47/13/38/24/63/37/22/77; сумма 321

#### Scenario: Сетка карточек группы

- **GIVEN** выбрана группа «Предупреждающие»
- **WHEN** рендерится сетка
- **THEN** 47 карточек; каждая содержит изображение /pdd-assets/znaki/<номер>small.png, номер и название знака; знаки других групп не показаны

#### Scenario: Деталь знака

- **GIVEN** ученик кликнул карточку знака 1.1 в сетке
- **WHEN** открывается деталь
- **THEN** показано крупное изображение знака, номер «1.1», название «Железнодорожный переезд со шлагбаумом», группа; есть возврат к группе; блок штрафа отсутствует (карта соответствия в корпусе отсутствует)

#### Scenario: Знак группы «Таблички» (формат t8)

- **GIVEN** корпус содержит группу t8 «Таблички» в формате «## | 8.1.1»
- **WHEN** ученик открывает группу «Таблички» и карточку 8.1.1
- **THEN** знак распознан и показан как остальные (номер без pipe, название, изображение 8.1.1small.png)

### Requirement: Раздел «Правила» — оглавление и глава (двухколоночный макет)

Раздел «Правила» MUST показывать двухколоночный макет мокапа (правка
Заказчика): слева оглавление всех 26 глав (заголовки из корпуса), справа
— содержимое выбранной главы. Переход по клику — клиентский; активная
глава подсвечена. Содержимое — текст корпуса без правок (toc мокапа из
29 пунктов — иллюстрация; рендер по корпусу — 26).

Источник: решение 2026-11-15; мокап pdd-pravila-student.html; корпус
content/pdd/pravila.

#### Scenario: Оглавление из 26 глав

- **GIVEN** раздел «Правила» открыт
- **WHEN** рендерится оглавление
- **THEN** ровно 26 пунктов, первый — «Общие положения», порядок соответствует корпусу r1_…r26_

#### Scenario: Переход к главе

- **GIVEN** открыта глава 1 «Общие положения»
- **WHEN** ученик кликает пункт оглавления «Проезд перекрестков» (глава 13)
- **THEN** справа рендерится текст главы 13 из корпуса; активный пункт оглавления подсвечен; страница не перезагружалась

### Requirement: Раздел «Билеты» — интерактивный тренажёр с таймером

Раздел «Билеты» MUST быть тренажёром: выбор категории (A/B/M | C/D) и
билета 1–40; таймер 20:00 (00:00 — авто-финиш); вопрос — текст и
изображение, если есть; клик фиксирует ответ с подсветкой неверного/
верного и пояснением корпуса, повторный клик не меняет; навигация 1–20
со статусами; результат со счётом. Состояние — клиентское, без
персистентности. Изображения — /pdd-assets/bilety/, лениво.

Источник: решение 2026-11-15; мокап pdd-bilety-trenazher.html; корпус
content/pdd/bilety (80×20).

#### Scenario: Старт попытки по билету с картинками

- **GIVEN** ученик выбрал категорию A/B/M и билет 1
- **WHEN** попытка стартует
- **THEN** показан вопрос 1 билета из корпуса, таймер установлен на 20:00 и начинает обратный отсчёт; у вопросов с изображением в корпусе картинка загружается с /pdd-assets/bilety/

#### Scenario: Фиксация ответа и пояснение

- **GIVEN** открыт вопрос 2 билета с вариантами
- **WHEN** ученик кликает вариант
- **THEN** ответ зафиксирован однократно; неверный выбор подсвечен красным, верный — зелёным; раскрыто пояснение из корпуса; клики по другим вариантам этого вопроса больше не меняют ответ

#### Scenario: Навигация со статусами и досрочная сдача

- **GIVEN** в попытке отвечены вопросы 1 (верно) и 2 (неверно), текущий — 3
- **WHEN** ученик смотрит навигацию 1–20 и нажимает «Сдать»
- **THEN** точки 1/2 показывают статусы верно/неверно, 3–20 — не отвечен; результат показывает счёт 1 верный из 2 отвеченных и статусы всех 20 вопросов

#### Scenario: Авто-финиш по таймеру

- **GIVEN** идёт попытка, таймер истекает до 00:00
- **WHEN** таймер достигает 00:00
- **THEN** попытка завершается автоматически с тем же экраном результата (отвеченные засчитаны, неотвеченные — не отвечен)

#### Scenario: Состояние не переживает перезагрузку (MVP)

- **GIVEN** завершённая или идущая попытка
- **WHEN** ученик перезагружает страницу или уходит в другой раздел и возвращается
- **THEN** попытка начинается заново с выбора билета; никаких серверных записей прогресса не создается

### Requirement: Раздел «Штрафы» — таблица и поиск

Раздел «Штрафы» MUST показывать таблицу всех строк корпуса (статья /
нарушение / наказание; сейчас 58 сводных строк — расхождение с «63»
решения зафиксировано в proposal «Сверка») и поиск с клиентской
фильтрацией: подстрока без учёта регистра по всем трём колонкам; пустой
результат — с сообщением. Данные — build-time JSON того же генератора;
сервер не участвует.

Источник: решение 2026-11-15 («Еще раздел Штрафы есть, тоже надо»);
мокап pdd-shtrafi-student.html (63 иллюстративные строки).

#### Scenario: Таблица всех строк корпуса

- **GIVEN** раздел «Штрафы» открыт, поиск пуст
- **WHEN** рендерится таблица
- **THEN** показаны все строки корпуса (58 на момент спринта) с колонками «Пункт КоАП», «Нарушение», «Наказание»

#### Scenario: Поиск фильтрует клиентски

- **GIVEN** таблица открыта
- **WHEN** ученик вводит «скорост»
- **THEN** остаются только строки, содержащие подстроку в любой колонке (без учёта регистра); очистка поля возвращает все строки

#### Scenario: Пустой результат поиска

- **GIVEN** введена строка без совпадений
- **WHEN** фильтрация выполнена
- **THEN** таблица пуста и показано сообщение об отсутствии результатов

### Requirement: Доставка контента — build-time JSON и статика изображений

Тексты корпуса MUST попадать в продукт через build-time генератор
(generate-pdd-json.mjs в npm run build → pdd-data/*.json, в git не
коммитятся) — lazy-чанки разделов; content/pdd/** руками не правится —
только перегенерация. Изображения (~48 МБ) MUST идти статикой: GET
/pdd-assets/{group}/{file} (group ∈ znaki|bilety, иное — 404) по
паттерну /vue/assets, вне vite-бандла. Образ копирует content/.

Источник: решение 2026-11-15 («возьми с источника пока»); NFR-26;
design.md «Решение 1» (ADR-001).

#### Scenario: Сборка воспроизводит контент без ручных шагов

- **GIVEN** чистая выкачка репозитория (pdd-data/ отсутствует)
- **WHEN** выполняется npm ci && npm run build
- **THEN** генератор создает JSON из content/pdd/, vite собирает dist с lazy-чанками pdd-*; повторный прогон идемпотентен

#### Scenario: Изображения вне бандла

- **GIVEN** собранный dist и образ
- **WHEN** запрашиваются /pdd-assets/znaki/1.1small.png и /pdd-assets/bilety/6942508s.jpg
- **THEN** 200 с корректным content-type; файлы изображений отсутствуют в dist/assets (48 МБ не в бандле); /pdd-assets/other/x.png → 404; /pdd-assets/znaki/../secret → 404

#### Scenario: Раздел грузится лениво

- **GIVEN** ученик открыл /cabinet (раздел «Главная»)
- **WHEN** страница загрузилась и ученик не заходил в обучающие разделы
- **THEN** чанки pdd-* браузером не запрошены; при первом клике на «Знаки» загружается чанк секции и его JSON-чанк

### Requirement: Целостность контента проверяется на сборке

Генератор MUST валидировать корпус и проваливать сборку при нарушении:
20 вопросов × 80 билетов; один ✅ и 2–5 вариантов на вопрос; ссылки на
изображения вопросов существуют; 321 знак с images/znaki/<номер>small.png;
26 глав с единственным H1; строки штрафов с тремя полями. Правки корпуса
руками запрещены — только перегенерация с валидацией.

Источник: точность контента (решение 2026-11-15); инвентарь design.md.

#### Scenario: Сборка падает на недостающем изображении

- **GIVEN** в корпусе ссылка на изображение вопроса, отсутствующего в images/bilety/
- **WHEN** выполняется npm run build
- **THEN** генератор завершается ошибкой с указанием файла/вопроса; dist не собирается

#### Scenario: Позитивный прогон на текущем корпусе

- **GIVEN** корпус в main (80×20 вопросов, 1094 ссылки на изображения, 321 знак, 26 глав, 58 строк штрафов)
- **WHEN** выполняется генератор
- **THEN** все проверки проходят, JSON созданы без предупреждений о потерянных данных

### Requirement: Производительность кабинета — lazy-чанки и бюджеты (NFR-26)

Разделы MUST быть отдельными lazy-чанками: первый заход каждой из 14
страниц — в бюджете NFR-26 (≤ 200 КБ gzip) и без pdd-чанков; JSON —
отдельные lazy-чанки (билеты — по билету), каждый lazy-чанк ≤ 150 КБ
gzip. Носитель гейта — npm run check:budgets: замыкание первого захода —
по статическим импортам («static-import graph»); PAGES = 14.

Источник: NFR-26; постановка S17 («кабинет НЕ должен распухнуть»);
design.md «Бюджеты чанков».

#### Scenario: Первый заход кабинета не изменился

- **GIVEN** сборка с обучающими разделами
- **WHEN** выполняется npm run check:budgets
- **THEN** первый заход cabinet (page + static graph: shared + vendor) ≤ 200 КБ gzip; ни один pdd-чанк не входит в статическое замыкание ни одной из 14 страниц

#### Scenario: Каждый lazy-чанк в бюджете

- **GIVEN** dist с чанками pdd-znaki, pdd-pravila, pdd-shtrafi, pdd-bilety-index, pdd-bilety-<cat>-<nn>
- **WHEN** выполняется check:budgets (правило (г))
- **THEN** каждый lazy-чанк ≤ 150 КБ gzip; чанки билетов не объединены в один большой (файл билета грузится при выборе)

#### Scenario: Гард срабатывает при распухании

- **GIVEN** ленивый чанк превысил 150 КБ gzip или попал в статическое замыкание страницы
- **WHEN** выполняется check:budgets
- **THEN** проверка завершается ошибкой с указанием чанка и правила
