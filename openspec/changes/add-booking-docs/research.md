# Research: add-booking-docs

Ключевые техрешения объема и рассмотренные альтернативы (кратко; выбор —
в design.md).

1. Хранение 5 ракурсов + СТС: (а) 6 колонок в instructor_cars против
   (б) отдельной kind-таблицы «авто → фото». Выбрано (а): состав фото
   фиксирован и конечен, пофайловых метаданных не нужно, (б) добавляет
   JOIN и таблицу без выигрыша; миграция колонок idempotent проще.
   Файлы при этом — через существующий uploads.py с новыми kinds
   (car_photo, car_sts) — директива Заказчика, дублирования helper нет.
2. Гарантия «один слот = одна активная/подтвержденная бронь» (NFR-8):
   (а) только проверка SELECT перед INSERT — проигрывает гонкам;
   (б) обычный UNIQUE(availability_id) — блокирует повторный запрос после
   отклонения (ОВ-5); (в) частичный UNIQUE-индекс по availability_id WHERE
   status IN ('new','confirmed') + транзакция BEGIN IMMEDIATE. Выбрано (в):
   уникальность на уровне хранилища (буква NFR-8), отклоненные не мешают
   повторному запросу, проигравший в гонке получает 409, а не порчу.
3. Даты в календарях при недельном availability без дат: (а) вычислять
   дату при чтении — недетерминизм между чтениями и неоднозначность
   «today_lessons»; (б) материализовать lesson_date (ближайшая будущая
   дата weekday) в момент брони. Выбрано (б) — фиксируется допущением в
   proposal.md; повторение слота по неделям — точка расширения.
4. «Мои документы»: (а) расширять instructor_cars.py / instructors.py —
   раздувает существующие модули (против директивы модульности);
   (б) отдельный backend/instructor_documents.py. Выбрано (б) — новый
   маленький модуль над готовыми данными (license_photo_path,
   instructor_cars.photo_sts).
5. Виджет «Занятия на сегодня»: (а) собирать брони прямо во фронтенде из
   GET /api/instructor/bookings — логика на клиенте (против паттерна 5
   карты архитектуры); (б) расширить существующий GET
   /api/instructor/summary. Выбрано (б) — серверная агрегация, контракт
   виджета сохраняется (пусто → «Сегодня занятий нет»).
6. Комплектность фото: серверная блокировка сохранения авто с неполным
   комплектом против человеческой валидации в админке. Выбрана админка —
   прямое решение Заказчика по ОВ-1 («все обязательны. Валидирует человек
   в админке»); сервер хранит факт комплектности и флаг блокировки.
7. PUT availability (полная замена графика) при активных бронях
   (MAJ-1 арх-ревью): (а) запрет — PUT отклоняется 409 с перечнем
   затронутых слотов, пока у них есть брони 'new'/'confirmed'; (б)
   каскад — брони удаляемых слотов автоматически 'rejected' с системным
   комментарием. Выбрано (а), по рекомендации ревью: минимально-сюрпризно,
   решение по брони остается за инструктором с его комментарием (ОВ-2);
   каскад — молчаливое решение за инструктора, против духа NFR-8.
8. Правило даты для lesson_date и «today» виджета (MIN-1): (а) локальная
   дата сервера; (б) UTC. Выбрано (а), по рекомендации ревью: календари и
   виджет живут в показаниях серверных часов, единое правило исключает
   расхождение «ближайшая будущая дата» и «Занятия на сегодня» на границе
   недели.
