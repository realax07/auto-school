# Change: add-booking-docs

## Why (Зачем)

Спринт 5 — два контура одного объема. (1) Документы и фото автомобиля:
у сохраненных автомобилей не отображаются загруженные фото (баг 5.2 —
фото в БД есть, до клиента не доходит/не показывается); автомобиль не
имеет полного фотонабора (нужны 5 ракурсов + обязательное фото СТС при
создании); у инструктора нет единого места своих документов (ВУ + СТС).
(2) Реальное расписание: после Спринта 3 у инструктора есть график
(availability) и принятые ученики (student_requests.status='accepted'),
но бронировать занятия нечем — виджет «Занятия на сегодня» остается
честной заглушкой. Этот объем строит бронирование ПОВЕРХ готовых сущностей
Спринта 3, новые таблицы пар не заводятся.

Источник требований: `docs/ba/requirements-booking-docs.md`
(УТВЕРЖДЕН, FR-42…FR-50, NFR-7…NFR-10, все Must; ОВ-1…ОВ-6 закрыты
Заказчиком 2026-10-22 — «1 все обязательны. Валидирует человек в админке.
2. Да. 3. Целиком. 4. Без лимита. 5. Да. 6. Да»).

## What Changes (Что меняет)

- Домен `instructor-cars` (MODIFIED + ADDED):
  - фикс бага 5.2: фото загруженного и сохраненного автомобиля
    отображается владельцу и ученику пары после перезагрузки и повторного
    входа; без фото — плейсхолдер, не битая картинка (FR-42);
  - 5 фото ракурсов (спереди/сзади/слева/справа/салон — ВСЕ обязательны,
    ОВ-1), хранение и замена каждого ракурса независимо; фото ракурсов
    доступно владельцу и ученикам его пары (FR-43, NFR-7, NFR-9);
  - при СОЗДАНИИ автомобиля фото СТС обязательно — без него авто не
    создается; СТС хранится отдельно и ученикам не выдается (FR-44);
  - валидация комплектности — человеком в админке (ОВ-1): админ-эндпоинт
    комплектности + кнопка блокировки авто с неполным комплектом;
    заблокированное авто недоступно ученикам.
- Домен `instructor-documents` (ADDED): раздел «Мои документы» кабинета
  инструктора — единый список ВУ (из анкеты Спринта 3) и СТС по каждому
  авто с типом, привязкой, датой загрузки, просмотром и скачиванием;
  доступ — только самому инструктору (FR-45, NFR-7).
- Домен `booking` (НОВЫЙ, ADDED):
  - ученик видит слоты инструктора ТОЛЬКО при принятой паре — проверка
    на сервере, прямой API-вызов мимо UI закрыт (FR-46, NFR-7);
  - запрос брони на слот (слот = интервал графика целиком, ОВ-3); занятый
    слот не бронируется повторно; после отклонения запрос возможен снова
    (ОВ-5) (FR-47);
  - инструктор подтверждает (без комментария) / отклоняет (комментарий
    обязателен, ОВ-2) (FR-48);
  - подтвержденная бронь — в календарях обоих: ученик (дата, время,
    инструктор, авто), инструктор (ФИО ученика, авто пары — следует за
    перекреплением, ОВ-6); виджет «Занятия на сегодня» показывает реальные
    подтвержденные брони вместо заглушки (FR-49);
  - занятый слот недоступен другим («занято» без раскрытия, кем);
    единственность брони слота — на уровне хранилища (частичный UNIQUE +
    транзакция, отказ конфликта 409) (FR-50, NFR-8).

Модульная архитектура (директива Заказчика): бронирование — ОТДЕЛЬНЫЙ
модуль `backend/booking.py` (существующие модули не раздуваются);
файлы авто — через СУЩЕСТВУЮЩИЙ `backend/uploads.py` (расширение перечня
kinds: car_photo — ракурсы, car_sts — СТС).

## Impact (Последствия)

- Код: НОВЫЕ модули `backend/booking.py` (домен booking),
  `backend/instructor_documents.py` («Мои документы»); РАСШИРЕНИЯ
  `backend/instructor_cars.py` (ракурсы, СТС при создании, админ-комплектность/
  блокировка), `backend/uploads.py` (kinds car_photo/car_sts — механика без
  изменений), `backend/instructor_summary.py` (today_lessons из реальных
  броней), `backend/instructor_availability.py` (валидация PUT полной
  замены графика: при активных бронях 'new'/'confirmed' на удаляемых
  слотах — 409 с перечнем; MAJ-1 арх-ревью), `backend/db.py`
  (колонки фото instructor_cars + флаг блокировки +
  таблица booking; миграции idempotent — механика users.role), `backend/app.py`
  (include роутеров, маршруты статики новых страниц). Фронт: обновление
  раздела «Мои автомобили» `frontend/instructor-dashboard.html` и карточки
  `frontend/instructor-choice.html` (фото у пары), виджета «Занятия на
  сегодня»; НОВЫЕ страницы (дашборды не раздуваем): `frontend/documents.html`,
  `frontend/booking.html`, `frontend/instructor-bookings.html`,
  `frontend/admin-cars.html`. Тесты в `tests/`.
- Хранилище файлов: существующий `data/uploads/` (новые подкаталоги
  car_photo/, car_sts/) — вне `frontend/`, статикой не раздается, выдача
  только через авторизованные эндпоинты (NFR-7).
- Master-spec: домен `booking` создается этой дельтой; `instructor-cars`
  — MODIFIED (требование «Фото автомобиля доступно владельцу» — правило
  доступа и набор фото меняются) + ADDED (СТС, комплектность);
  `instructor-documents` — ADDED («Мои документы»). Остальные домены
  не меняются.
- API-контракты и модель данных — design.md настоящего пакета; sdd.md
  (раздел «Спринт 5») дополняется задачей приемки.

## Out of scope / допущения

- Оплата занятий — вне скоупа; модель брони оплату не предполагает.
- Перенос/отмена подтвержденного занятия — ТОЧКА РАСШИРЕНИЯ: статусы и
  календари проектируются под добавление новой операции без переделки
  требований; операций изменения брони в этом объеме нет.
- Карты/гео, файловое хранилище (volume/S3/бэкапы), досыл/замена ВУ через
  «Мои документы», уведомления (email/push), нарезка availability на
  подынтервалы, чат ученик↔инструктор — вне скоупа (границы ТЗ).
- Допущение (дата занятия): availability — недельный график без дат, а
  календари показывают конкретную дату; при создании брони дата занятия
  материализуется (ближайшая будущая дата соответствующего weekday слота).
  Повторение слота по неделям/перенос даты — вне объема (фиксируется
  design.md, наблюдаемое поведение — в сценариях календарей).
- Допущение (разблокировка авто): требования фиксируют кнопку БЛОКИРОВКИ
  авто без комплекта; снятие блокировки в объем не входит (точка
  расширения — фиксируется design.md).
- Диагностика бага 5.2: БА фиксирует наблюдаемое требование (FR-42),
  корень вскрывается задачей диагностики в tasks.md (гипотезы и план —
  design.md), способ починки спекой не предписан.
