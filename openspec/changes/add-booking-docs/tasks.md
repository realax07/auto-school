## 4. Бронирование слотов

- [ ] 4.1 [P] backend/booking.py (НОВЫЙ модуль) + backend/db.py —

      'rejected' не мешают (MAJ-1; helper в booking.py, вызов из
      instructor_availability.py — подключение на 5.1);
      GET /api/student/instructors/{id}/slots (СЕРВЕРНАЯ проверка пары →
      иначе 403 в т.ч. при прямом вызове; состояние слотов: свободен/
      занято без раскрытия кем/на рассмотрении — свой запрос);
      POST /api/student/bookings (пара → иначе 403; слот инструктора
      пары → иначе 404; транзакция BEGIN IMMEDIATE + частичный UNIQUE →
      409 без записи; lesson_date = ближайшая будущая дата weekday по
      ЛОКАЛЬНОЙ ДАТЕ СЕРВЕРА — MIN-1);
      GET /api/student/bookings (свои: статус, дата/время, инструктор,
      авто, reject_comment); GET /api/instructor/bookings (только свои);
      POST /api/instructor/bookings/{id}/confirm (своя и 'new' → иначе
      404/409; без комментария; атомарно); POST …/reject (comment
      непустой → иначе 422, действие заблокировано; слот освобождается).
      Готовность: тесты — все сценарии specs/booking/spec.md: слоты без
      пары недоступны прямым вызовом; запрос «новая» виден инструктору;
      занятый слот → 409 и «занято» без раскрытия кем; ГОНКИ: два
      параллельных POST на один слот — максимум одна бронь, вторая 409
      (тест на конкурентный вызов); confirm без комментария; reject без
      комментария заблокирован, с комментарием виден ученику; повторный
      запрос после отклонения создается; чужая бронь → 404; PUT графика
      без слота с активной бронью → 409 с перечнем, график прежний,
      после confirm/reject брони — сохранение проходит (MAJ-1);
      ГРАНИЦА ДАТЫ: lesson_date на границе недели (ближайшая будущая
      дата weekday) — по локальной дате сервера (MIN-1); авто пары
      удален (car_id NULL) → GET броней возвращает бронь с пустым авто,
      не ошибку (MIN-3).
      FR: FR-46, FR-47, FR-48, FR-50. NFR: NFR-7, NFR-8, NFR-10.
      Зависит от: —.
