# Delta: instructor-cars

## ADDED Requirements

### Requirement: Замена СТС не влияет на статус валидации автомобиля

Статус документа СТС и статус валидации авто MUST быть независимы:
замена СТС НЕ меняет статус авто (ОВ-6) — у validated валидация не
сбрасывается, повторная валидация — отдельный submit. Замена
действующего СТС создает pending-версию, photo_sts не меняется до
верификации; комплектность не меняется. Правило ракурсов — без
изменений (MAJ-1): замена любого из 5 ракурсов у validated →
validating.

Источник: requirements-sprint8.md FR-69, FR-70; ОВ-2, ОВ-6; MAJ-1.

#### Scenario: Замена СТС у validated-авто не сбрасывает валидацию

- **GIVEN** автомобиль в статусе validated с действующим СТС
- **WHEN** владелец загружает замену СТС (POST …/photo/sts)
- **THEN** создана ожидающая версия документа, photo_sts (действующий файл) не изменился, статус автомобиля остался validated; ответ содержит итоговый статус авто и статус документа

#### Scenario: Ракурсы сохраняют правило сброса (MAJ-1, наследование)

- **GIVEN** автомобиль в статусе validated
- **WHEN** владелец заменяет любой из 5 ракурсов
- **THEN** автомобиль возвращается в validating (регресс-контроль: правило Спринта 7 не изменено)

#### Scenario: Правило «пустой СТС» едино для seed и sts-ветки

- GIVEN документ без файла (None и '' — обе формы)
- WHEN seed-миграция и sts-ветка принимают решение о наличии СТС
- THEN результат одинаковый для обеих форм (одно правило, тест
  TC-S8BE-008)

- **GIVEN** симптом Заказчика «СТС-дозагрузка на созданном авто не работает в UI»
- **WHEN** выполняется диагностика цепочки по звеньям (эндпоинт → фактические вызовы UI модалки авто/«Моих документов» → воспроизведение)
- **THEN** корень симптома зафиксирован в отчете задачи ДО фикса; после фикса СТС загружается/заменяется на существующем автомобиле из модалки авто и «Моих документов»

#### Scenario: Замена СТС не трогает комплектность и ракурсы

### Requirement: Выдача фото автомобилей через photo-эндпоинты

Плитки «Мои автомобили» и карточка авто в «Моих бронях» ученика используют
те же photo-эндпоинты, что и модалка-галерея (баг 5.2; FR-68/FR-74-контур).

#### Scenario: Плитки «Мои автомобили» используют photo-эндпоинты (баг 5.2)

- WHEN инструктор открывает «Мои автомобили» с загруженными ракурсами и СТС
- THEN плитки ссылаются на параметризованный photo-эндпоинт; отдельного
  legacy-маршрута kind=car_sts нет

#### Scenario: Карточка авто инструктора видна ученику в «Моих бронях»

- WHEN ученик открывает «Мои брони» с подтвержденной бронью
- THEN рядом со слотами отображается карточка авто инструктора (фото из
  photo-эндпоинта); без фото — честное пустое состояние

- **GIVEN** автомобиль с полным комплектом (5 ракурсов + СТС) в статусе validating
- **WHEN** владелец загружает замену СТС
- **THEN** ракурсы, has_sts и счетчики комплектности не изменились, статус автомобиля не изменился
