# Design: add-mobile-adaptive

## Context

Кабинет ученика (С15-финал) и остальные страницы — Vue multi-entry MPA,
desktop-вёрстка устоялась (носители e2e 84 + носители чтения
test_cabinet_page/test_pdd_sections/test_sidebar_unified). Мокапы v3
design/mocks/mobile/*.html согласованы Заказчиком 2026-11-17 («Давай
реализуем»): фиксированный таб-бар снизу 54px с пятью разделами, шиты
bottom-sheet с grab-хендлом, одноколоночные карточки вместо таблиц.
Решение Заказчика: адаптация представления (≤760px), контракты /api/*,
sessionStorage-ключи, хеш-навигация и SPA-механика — без изменений.

## Цели и не-цели

Цели: таб-бар ≤760px (5 разделов, шиты «Обучение»/«Профиль»), сокрытие
desktop-сайдбара, одноколоночные карточки (кошелек/заявки/брони,
инструктор, админка), адаптив ПДД-разделов по мокапам pdd-*.html,
модалки bottom-sheet, носители + мобильный e2e (390×844).

Не-цели: отдельное мобильное приложение/второй фронт; правки контрактов
API; новый роутинг; tablet-брейкпоинты сверх ≤760px/>760px; правки
desktop-вёрстки >760px (носители защищают).

## Решение 1: Таб-бар — компонент MobileTabBar, двойная защита видимости

Канонический модуль src/components/MobileTabBar.vue (паттерн
StudentSidebar): 5 кнопок с SVG-иконками дословно из мокапа
mobile-home.html; шиты «Обучение» (4 раздела ПДД)/«Профиль» (ФИО
из /api/auth/me + «Выйти» — FR-5/FR-7/FR-8, wiring внутри компонента).
Показ только ≤760px — ДВЕ защиты: JS matchMedia('(max-width:760px)') в
компоненте + CSS `@media(min-width:761px){.mtabs{display:none!important}}`
(BUG-068: wiring `openTab` обязан быть в возвращаемых bindings setup —
носитель test_mtabs_setup_bindings_exposed + e2e TC-UI-077 кликами).
Страницы-носители ПОДКЛЮЧАЮТ компонент и не дублируют разметку
(cabinet/App.vue, instructor-choice/App.vue).

## Решение 2: Стекинг-слои mobile (z-архитектура)

Desktop-наследование опасно: `.frame` кабинета — стекинг-контекст
(position:relative; z-index:1). Слои ≤760px: контент 1 < таб-бар 60
(`.mtabs`) < модалки кабинета 70 (`.backdrop,.wal-backdrop`, media
≤760px поднимает + `.frame{z-index:auto}` снимает контекст — BUG-069)
< шиты таб-бара/деталь знака 80 (`.mtab-backdrop`, `.zn-overlay`).
Отвергнутая альтернатива: подъем `.frame` до 70 (весь контент начинал
перехватывать клики табов при скролле — рантайм-проверка 18.4).

## Решение 3: Grid-инвариант .app кабинета (BUG-070)

`.app{display:grid;grid-template-columns:236px minmax(0,1fr)}`: корневой
div MobileTabBar (рендерится всегда) — прямой grid-потомок; на desktop
пустой div занимал ячейку row1-col2, `.hero` уезжал в row2-col1 (236px)
— контент сжимался с С18.1. Фикс: класс `.mtab-root` + страховка
`@media(min-width:761px){.mtab-root{display:none!important}}`. Урок:
геометрия desktop (не только видимость) — в e2e desktop-инварианта
(TC-UI-079: сетка знаков >2 колонок на 1440×900).

## Решение 4: Носители и e2e

- Носитель test_mobile_tabbar.py (8): 5 табов/порядок, иконки дословно
  из мокапа, wiring bindings (BUG-068), matchMedia+CSS-страховка,
  шиты, подключение в кабинет/instructor-choice, отсутствие дублей
  разметки, высота 54px ≤ 64px спеки.
- Медиа-носители (18.4.1): test_cabinet_page/test_pdd_sections/
  test_sidebar_unified — desktop-фрагменты не тронуты (дифф = 0).
- e2e (18.4.2): TC-UI-077 вход (bottom-sheet входа)→кабинет→табы→модалки
  (клик «Отмена» — регресс BUG-069); TC-UI-078 тренажер 390×844 (сетка
  навигатора 10 колонок, exam-bar wrap, ответ→пояснение); TC-UI-079
  desktop-инвариант 1440×900 (таб-бар скрыт, сайдбар 9 пунктов, таблица
  штрафов thead, сетка знаков auto-fill).
- Бюджеты NFR-26: без изменений (MobileTabBar — в графах
  cabinet/instructor-choice, гейт check:budgets на приемке).

## Риски / сознательные ограничения

- Новые fixed-слои на ≤760px требуют сверки с z-архитектурой (60/70/80)
  — прецедент BUG-069.
- openTab-подобные пропуски bindings setup сборка не ловит (BUG-068) —
  контроль кликовыми e2e.
- Тост кабинета (z20) геометрически выше таб-бара (bottom:70px mobile),
  стекинг не поднимался — при переносе тоста сверить.
- Контент ≤760px не оптимизирован под <320px (min-width:320px body —
  наследие С0).
