## 1. Модель: миграция recurring/one_off + занятость экземпляра (backend)

- [ ] 1.1 [migration][code][tests] backend/db.py — idempotent-миграция
      (guard по отсутствию колонки slot_type; одна транзакция BEGIN
      IMMEDIATE): перестройка availability — колонки slot_type TEXT NOT
      NULL DEFAULT 'recurring' CHECK (recurring|one_off), slot_date TEXT
      NOT NULL DEFAULT '' (+CHECK: recurring ⇒ '', one_off ⇒ непустая),
      новый UNIQUE (instructor_id, weekday, start_time, end_time,
      slot_date); INSERT … SELECT id, instructor_id, weekday, start_time,
      end_time, created_at (id/created_at сохраняются — ссылки
      booking.availability_id валидны); существующие строки → recurring
      через DEFAULT без перезаписи (FR-97); пересоздание
      idx_availability_instructor. Замена частичного индекса
      uq_booking_active_slot → (availability_id, lesson_date) WHERE
      status IN ('new','confirmed') (занятость экземпляра — design D4).
      Готовность: тесты — предсозданная БД со старыми интервалами и
      бронями: после миграции каждая строка recurring ('' date), id и
      created_at сохранены, ни одна бронь не потеряла availability_id;
      повторный запуск — no-op (0 изменений); one_off на тот же
      день+время другой даты вставляется, recurring-дубликат —
      IntegrityError; две активные брони одной серии с разными датами
      возможны, одной даты — нет.
      FR: FR-97, FR-90. NFR: NFR-30, NFR-8. Зависит от: —.
      Кейсы: TC-S10BE-001.

## 2. Домен booking: экземпляры, будущие брони, недели ученика (backend)

- [ ] 2.1 [code][tests] backend/booking.py — (а) helper
      blocking_bookings → уровень ЭКЗЕМПЛЯРОВ (design «Контракт
      availability»): активная бронь ('new'/'confirmed') → экземпляр
      (weekday, start_time, end_time, date=lesson_date); конфликт, если
      новый график не покрывает (дата, время) — покрытие серией или
      one_off (правило совпадения design.md); экземпляры с началом <
      NOW (МСК) не конфликтуют; conflict_error_response — conflicts с
      полем date (null для легаси-экземпляров). (б) POST
      /api/student/bookings: опциональная date ('YYYY-MM-DD': recurring —
      weekday(date) = weekday слота, one_off — date = slot_date, иначе
      422; без date — materialize_lesson_date как прежде); lesson_date =
      точная дата экземпляра; проверка будущего: date+start_time строго
      больше NOW (МСК) → иначе 422 {ok:false} (NFR-31); гонка и доступ —
      без изменений (BEGIN IMMEDIATE, 409 «Слот уже занят» на экземпляре,
      403/404 наследуются). (в) GET
      /api/student/instructors/{id}/slots?date=YYYY-MM-DD — экземпляры
      недели (server приводит к понедельнику): week {monday, sunday} +
      instances [{availability_id, date, weekday, start_time, end_time,
      state}] с разворотом recurring в даты недели и one_off на
      slot_date; state free/busy/pending по (id, date); без параметра —
      легаси-ответ slots без изменений; доступ 403/404 — без изменений.
      Готовность: тесты — бронь с датой на конкретный экземпляр серии;
      другой экземпляр той же серии бронируется другим учеником; занятый
      экземпляр → 409, другая дата серии — свободна; начавшийся/прошедший
      → 422 (прямой вызов); date не на weekday серии → 422; легаси-POST
      без date — ближайшая дата; ?date= возвращает instances недели
      (recurring-даты, one_off на своей дате, states), без параметра —
      прежний ответ; 403 без пары, 404 чужой инструктор.
      FR: FR-92, FR-95, FR-96. NFR: NFR-31, NFR-8, NFR-7. Зависит от:
      1.1 (индекс экземпляров). Кейсы: TC-S10BE-004, TC-S10BE-006,
      TC-S10BE-007, TC-S10BE-008.

## 3. Домен availability: PUT/GET типы и даты + запрет прошлого (backend)

- [ ] 3.1 [code][tests] backend/instructor_availability.py — GET: +
      slot_type/date (date null для recurring; сортировка прежняя);
      PUT: полная замена графиком обоих типов (slot_type default
      'recurring'; one_off — date обязательна, weekday = дню недели даты,
      иначе 422; recurring с date → 422; дубликаты с учетом type/date
      схлопываются); ЗАПРЕТ ПРОШЛОГО (NFR-31, каждый PUT): 422 при
      payload, создающем/меняющем прошедший one_off (начало ≤ NOW МСК),
      и при убирании/изменении существующего прошедшего one_off
      (immutable-история — design D6); 409 MAJ-1 через helper 2.1 в той
      же транзакции BEGIN IMMEDIATE (сериализация с create_booking —
      наследование M-3); запись DELETE+INSERT с type/date; ответ 200 —
      формат GET. Легаси-тело (без slot_type/date) = график из recurring
      слотов — коды/формат прежние (NFR-29).
      Готовность: тесты — PUT со смешанным графиком (recurring + one_off
      на одну дату) сохраняется и восстанавливается GET-ом; one_off без
      date / с чужим weekday / recurring с date → 422; PUT, убирающий
      one_off с будущей активной бронью → 409 с датой в перечне; только
      rejected-брони → сохраняется; прошедшая one_off в БД убрана из
      payload → 422, прошла по времени в момент сохранения → 422;
      легаси-тело → 200 recurring-график (регресс тестов s3/s7 —
      без правок).
      FR: FR-90, FR-91, FR-92, FR-93, FR-97. NFR: NFR-29, NFR-31.
      Зависит от: 1.1, 2.1 (helper). Кейсы: TC-S10BE-002, TC-S10BE-003,
      TC-S10BE-004, TC-S10BE-005.
