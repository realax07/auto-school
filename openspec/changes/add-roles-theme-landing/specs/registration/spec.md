# Delta: registration

## MODIFIED Requirements

### Requirement: Сохранение регистрации ученика

Форма регистрации на лендинге MUST начинаться с явного выбора роли
(«Я ученик» / «Я инструктор», мокап auth-register-choice, решение
Заказчика 2026-11-19): выбор ученика открывает форму ученика
(ФИО, email, телефон, пароль, подтверждение, согласие), выбор
инструктора — существующую анкету инструктора с модерацией. Сервер
MUST подтверждать роль аккаунта при регистрации (role=student|instructor)
и сохранять запись с выбранной ролью. История сценариев ученической
формы сохраняется без ослаблений.

#### Scenario: Выбор роли перед формой

- **GIVEN** открыта модалка регистрации на лендинге
- **WHEN** пользователь видит экран выбора «Я ученик / Я инструктор» и выбирает роль
- **THEN** открывается форма выбранной роли: ученик — форма ученика, инструктор — анкета инструктора с модерацией

#### Scenario: Успешная регистрация ученика

- **GIVEN** открыта страница регистрации (модалка на лендинге)
- **WHEN** ученик заполняет все поля (фамилия, имя, отчество, email, телефон, пароль, подтверждение пароля) корректными значениями и отправляет форму
- **THEN** система сохраняет регистрацию с ролью student: в хранилище появляется запись с указанными фамилией, именем, отчеством, email, телефоном; пароль хранится только в виде необратимого хэша

#### Scenario: Пароль не хранится в открытом виде

- **GIVEN** выполнена успешная регистрация ученика с паролем P
- **WHEN** администратор просматривает сохраненные данные регистрации
- **THEN** значение пароля P недоступно ни в каком списке/выгрузке/хранилище в открытом виде (только хэш)
