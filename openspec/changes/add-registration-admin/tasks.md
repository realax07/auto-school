## 2. Домен registration

- [ ] 2.1 POST /api/register: модель запроса (7 полей, все со значениями по
      умолчанию `str = ""` — обязательность НЕ через Pydantic-required,
      а в хендлере: отсутствующий ключ JSON обрабатывается как пустое поле,
      чтобы вернуться контрактный 422, а не Pydantic `{detail:[...]}`),
      валидация в фиксированном порядке (обязательность всех полей → формат
      email → телефон ≥ 10 цифр → пароль ≥ 8 → совпадение подтверждения →
      уникальность email), bcrypt cost 12, параметризованный INSERT.
      Ответы: 200 {ok:true}; 422 {ok:false, error:"<поле>: <причина>"} —
      первая ошибка; повторный email — 422, не 500.
      Готовность: тесты — успешная регистрация (проверка записи в БД,
      password_hash ≠ открытый пароль), каждый негативный случай из FR-2
      (включая дубликат email), отсутствие записи при отклонении; тело без
      ключа `email` → 422 в контрактном формате {ok:false,
      error:"email: …"} (не Pydantic detail).
      FR: FR-1, FR-2, FR-3. NFR: NFR-1, NFR-2.

## 3. Домен admin

- [ ] 3.1 [P] POST /api/admin/login: сверка с config (ADMIN_USER +
      bcrypt.checkpw против ADMIN_PASSWORD_HASH), выдача
      secrets.token_urlsafe(32), реестр {token: expires} TTL 12ч,
      зависимость require_admin (заголовок X-Admin-Token).
      Ответы: 200 {ok:true, token}; 401 {ok:false}.
      Готовность: тесты — успешный вход, неверный пароль/логин → 401 без
      токена; админ-API без токена / с поддельным / с истекшим → 401.
      FR: FR-5, FR-8.
- [ ] 3.2 GET /api/admin/users: SELECT всех пользователей ORDER BY
      created_at DESC; fio = surname + name + patronymic через пробел.
      Ответ: 200 {count, users:[{id, fio, email, phone, created_at}]}.
      Готовность: тест — два пользователя, свежий первым, count совпадает,
      доступ только с валидным токеном. FR: FR-6, FR-8.
- [ ] 3.3 GET /api/admin/users/export.csv: CSV UTF-8 с BOM, разделитель «;»,
      колонки ФИО;Email;Телефон;Роль;Дата регистрации, роль «Ученик»,
      Content-Disposition attachment. CSV-санитизация (MAJ-2, решение ПМ
      2026-10-08): значение ячейки из пользовательских полей (ФИО, email,
      телефон), начинающееся с `=`, `+`, `-`, `@`, получает префикс `'`.
      Дата регистрации — пересчет UTC→локаль перед форматированием
      DD.MM.YYYY (created_at хранится в UTC через datetime('now')).
      Готовность: тест — тело начинается с BOM (\xef\xbb\xbf), заголовок из 5
      колонок с «;», строка на каждого пользователя, «Ученик» в строке;
      пользователь с email `=1+1@x` (или ФИО `=1+1`) попадает в CSV как
      `'=1+1…` (префикс `'`, формула не исполняется); дата регистрации в CSV
      соответствует локальному дню регистрации; без/с плохим токеном → 401
      и пустое тело. FR: FR-7, FR-8.
