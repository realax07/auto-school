# Change: add-registration-admin

## Why (Зачем)

Спринт 0 площадки-автошколы: нужен минимальный работающий контур
«регистрация ученика → БД → админка». Сейчас в проекте нет ни бэкенда, ни БД,
ни админ-контура — есть только утвержденные Заказчиком HTML-макеты
(design/mocks) и утвержденное ТЗ (requirements.md, статус УТВЕРЖДЕН).
Без этого контура заявки учеников негде хранить, а администратор школы не
может их просматривать и выгружать.

Источник требований: `requirements.md` (УТВЕРЖДЕН, FR-1…FR-9, NFR-1…NFR-3,
все Must). Утвержденный дизайн Заказчика:
`docs/superpowers/specs/2026-10-08-registration-admin-design.md`.

## What Changes (Что меняет)

Новые возможности (все — ADDED, brownfield-спеков по этим доменам нет):

- Домен `registration`:
  - сохранение регистрации ученика (7 полей формы, включая пароль + подтверждение — решение Заказчика от 2026-10-08);
  - валидация: обязательность полей, формат email, длина пароля ≥ 8, совпадение пароля и подтверждения, уникальность email;
  - хранение пароля только в виде bcrypt-хэша (cost 12);
  - редирект на страницу «Регистрация завершена» после успеха;
  - страницы лендинга/модалок соответствуют утвержденным макетам дословно.
- Домен `admin`:
  - вход администратора по логину/паролю из .env (ADMIN_USER + ADMIN_PASSWORD_HASH, bcrypt — решение Заказчика);
  - список зарегистрированных пользователей (свежие сверху);
  - выгрузка CSV (BOM, «;», колонки ФИО;Email;Телефон;Роль;Дата регистрации);
  - токен авторизации админ-API, выдаваемый только после успешного входа.

## Impact (Последствия)

- Код: новый `backend/` (FastAPI-сервис), новый `frontend/` (статика из макетов), `tests/`, `data/` (в .gitignore), `.env.example`. Спринт 0 — без кабинетов, инструкторов, nginx/контейнеров/деплоя (границы ТЗ).
- Master-spec: домены `registration` и `admin` создаются этой дельтой (openspec/specs/ пуст).
- API-контракты и модель данных фиксируются в `sdd.md`; изменение контракта — отдельная дельта (architectural map, паттерн 7).

## Out of scope / допущения

- Личные кабинеты, инструкторы, восстановление пароля, email/SMS-подтверждение, refresh-токены — следующие спринты (раздел «Не в этом спринте» дизайна).
- Nginx/TLS, контейнеры, оркестрация — Релиз 1 (architecture/map.md, открытые вопросы).
- FR-9 трактую как: HTML-страницы переносятся из design/mocks дословно; к переносу добавляется ТОЛЬКО wiring (fetch на /api/register, редирект, показ ошибки) и два новых поля Пароль/Подтверждение — прямо предписано утвержденным дизайном. Текстовки макетов не меняются.
