# Delta: Frontend

## ADDED Requirements

### Requirement: Статусный экран отказа заявки на Vue (/instructors/rejected)

Страница /instructors/rejected MUST обслуживаться каркасом Vue 3 + Vite —
точкой входа из dist; legacy html и js страницы MUST быть удалены (замена
монолита целиком). Причина отказа MUST приходить из ответа логина
(route/reason → sessionStorage «instructor_rejected_reason», контракт
логина не меняется); пустое/нет — экран без персональной причины;
статусные запросы при загрузке не выполняются; вид — без редизайна.

Источник: FR-13, FR-17, FR-84…86; NFR-27; ADR-008.

#### Scenario: Экран обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** гость открывает /instructors/rejected
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /instructors/rejected не изменился

#### Scenario: Причина отказа — из ответа логина, контракт не меняется

- **GIVEN** вход выполнен с email заявки в статусе deny с комментарием C (логин отвечает route=rejected и reason=C, модалка входа пишет sessionStorage «instructor_rejected_reason»)
- **WHEN** открыт экран /instructors/rejected
- **THEN** причина C видна на экране (элемент #reason-text) без входа и перелогина; сценарий TC-S9UI-003 проходит без правок; механика записи причины (login route/reason) не изменена

#### Scenario: Без причины — блок скрыт, запросов нет

- **GIVEN** экран /instructors/rejected открыт по прямой ссылке (ключа нет или пуст)
- **WHEN** просмотрены содержимое страницы и сетевые запросы
- **THEN** блок причины скрыт (персональная причина не раскрывается); статусные запросы при загрузке отсутствуют (0 обращений к API)

#### Scenario: Визуальная эквивалентность текущему экрану

- **GIVEN** сравнение Vue-версии с текущим экраном отказа
- **WHEN** выполнено сопоставление содержимого
- **THEN** эквивалентность без редизайна: шапка (бренд, «← Вернуться на лендинг»), карточка (kicker «Заявка инструктора», h1 «Заявка отклонена», пояснение), блок «Причина отказа», кнопки «На главную» / «О лендинге для инструкторов», футер

### Requirement: Форма отзыва на Vue (/review)

Страница /review MUST обслуживаться каркасом Vue 3 + Vite — точкой входа
из dist; legacy review-form.html и js/review-form.js MUST быть удалены
(замена монолита целиком). Wiring MUST воспроизводиться 1:1: query
?instructor=; без идентификатора — редирект на /my-requests (301 →
/cabinet#/my-requests); состояния «форма»/«уже оставлен» — данными
сервера; тосты и ошибки — как в legacy. Контракт POST отзыва MUST
не изменяться.

Источник: FR-5, FR-34, FR-35; FR-84…86; NFR-2/5/27; TC-UI-017/018.

#### Scenario: Страница обслуживается каркасом Vue

- **GIVEN** сборка каркаса выполнена (dist существует)
- **WHEN** ученик открывает /review?instructor=<id>
- **THEN** страница отдается входом каркаса Vue (html со ссылками на ассеты префикса /vue/), а не legacy-HTML-монолитом; маршрут /review и query-параметр не изменились

#### Scenario: Контекст инструктора и переход из «Моих заявок»

- **GIVEN** ученик с принятой заявкой в «Моих заявках» кабинета
- **WHEN** он переходит на форму отзыва и открыт /review?instructor=<id>
- **THEN** карточка инструктора заполнена из GET /api/student/instructors/{id} (ФИО #i-name, стаж/авто, агрегат рейтинга); сценарий TC-UI-018 проходит без правок

#### Scenario: Отправка отзыва и повтор 409

- **GIVEN** ученик с сессией на /review?instructor=<id> (TC-UI-017 без правок)
- **WHEN** выбрана оценка и введен текст, отзыв отправлен; затем повторная попытка после reload
- **THEN** первый сабмит (200) — состояние «Отправлен» (#view-done, #done-title «Отзыв отправлен», #view-form скрыта) и тост; повторный сабмит (409) — состояние «уже оставлен» (#done-title «Отзыв уже отправлен»); прямой повторный POST — 409 (NFR-2/NFR-5, контракт прежний)

#### Scenario: Без ?instructor= — редирект в кабинет

- **GIVEN** открыт /review без query-параметра instructor
- **WHEN** выполнен переход
- **THEN** страница перенаправляет на /my-requests, который отдает 301 → /cabinet#/my-requests (раздел «Мои заявки» внутри кабинета, BUG-047); редирект-контракт не изменен

#### Scenario: Ошибки формы — тосты как в legacy

- **GIVEN** ученик на форме отзыва
- **WHEN** сервер отвечает 401, 403 или прочей ошибкой (инструктор не найден — 404 контекста)
- **THEN** реакции 1:1 как в legacy: 401 — редирект на вход; 403 — бизнес-ошибка тостом (без редиректа, NFR-2); прочие — тост ошибки сервера либо «Не удалось отправить отзыв»; длительность и тексты тостов сохранены
