## Решения design.md — оценка на прочность

- POST /api/ai/chat + адаптер-провайдер в backend/ai: шов корректный,
  замена провайдера не требует правок фронтенда — поддерживаю. Риски
  временного провайдера (внешний CLI, latency, конкурентные сессии):
  latency/доступность закрыты таймаутом ≤30 с + человеческой ошибкой у поля;
  НЕ закрыты в design: (а) канал передачи сообщения — argv процесса виден
  в ps на хосте (MIN-2), (б) поведение при параллельных запросах — sync-хендлер
  FastAPI уходит в threadpool, несколько hermes-процессов одновременно
  возможны, осознанность допущения не зафиксирована (MIN-3). Оба —
  фиксируются текстом design, код не трогают.
- ai_messages + retention 14 дней: схема (id, user_id, role, text,
  created_at), изоляция по user_id токена, параметризованный SQL —
  соответствует паттернам карты; см. ответ ОВ-2.
- Замена #sec-home по макетам: состав удалений совпадает с фактом App.vue;
  навигация «Найти водителя»/«Мои заявки» остается через сайдбар/таб-бар —

Исправить: в tasks 19.4.2/design уточнить — дословная сверка макета покрывает

### MIN-2. Канал передачи сообщения провайдеру — argv (design.md Решение 1)

`hermes chat -q "<текст ученика>"` кладет пользовательский текст в argv
процесса — он виден в process-list хоста (ps) весь ход генерации; NFR
«секреты/служебные argv в логи не попадают» этот канал не покрывает
(системный промпт, судя по design, тоже идет аргументом).
Исправить (текстом design для 19.2.3): передачу текста через
`--query-file` (файл/stdin; проверено в `hermes chat --help`: «Safe for
arbitrary text») и бюджет через `--run-budget SECONDS` + собственный
таймаут ≤30 с.

### MIN-3. Конкурентные вызовы провайдера не зафиксированы (design.md Решение 1 / Риски)

FastAPI sync-хендлер исполняется в threadpool — при одновременных запросах
двух учеников возможны параллельные hermes-процессы (память/нагрузка хоста,
нестабильный latency на боевой сессии 19.4). Для v1 допустимо, но допущение
должно быть явным.
Исправить (текстом design): зафиксировать одно из — семафор/очередь на
вызовы провайдера внутри backend/ai, либо осознанное допущение «нагрузки
спринта малы, параллелизм не ограничиваем» с пометкой проверки/непроверки.
Заодно: убрать ставший мертвым wiring заглушек App.vue:1219 из объема 19.3.1
(упомянуть в задаче, чтобы verbatim-гарды нового файла не считали его живым).
