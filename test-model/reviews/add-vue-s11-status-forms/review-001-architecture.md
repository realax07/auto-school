## 1. Соответствие ADR-008 — без отступлений

- Multi-entry MPA: два новых входа (instructors-rejected.html,
  review-form.html) по одному на страницу; SPA/vue-router/pinia не
  вводятся (ОВ-3) — proposal/design/tasks формулировки едины.
- Vendor-сплит и бюджеты NFR-26: manualChunks в vite.config.mjs не
  меняется; check:budgets расширяется, а не ослабляется. Соответствует
  ADR-008 п.3.
- Замена монолита ЦЕЛИКОМ с удалением legacy (ADR-008 п.4): 4 файла
  удаляются, «параллельное существование двух версий» отклонено явно
  (design, «Сознательные ограничения»).
- Статика тем же сервисом (ADR-001): существующие `GET /vue/assets/*`
  (backend/app.py:149–163, карта суффиксов .js/.css) покрывают новые
  чанки без правок; шрифты/картинки страницам не нужны — сверено с
  legacy (системные шрифты, эмодзи-глифы).
- Контур доставки: Dockerfile (node builder-этап собирает dist из ВСЕХ
  входов vite.config одной командой), compose, nginx, CI — правок не
  требуется; claim пакета сверен с фактическим Dockerfile-паттерном
  пилота (dist забирается целиком COPY --from). Верно.

## 2. Точки входа, маршруты, механизм отдачи — корректно

- Имена входных файлов vs сегменты: `/instructors/rejected` →
  instructors-rejected.html — паттерн пилота 1:1
  (/instructors/pending → instructors-pending.html); `/review` →
  review-form.html — историческое имя артефакта сохранено
  сознательно (документировано). Несоответствия «сегмент = имя файла»
  механизму не важно: карта `_PAGE_ROUTES` отображает маршрут → файл,
  это ее контракт.
- Механизм `vue:<file>` в `_PAGE_ROUTES`: сверено с фактическим кодом
  (backend/app.py:39–67, 165–178). Все маршруты карты — точные строки,
  регистрируются циклом ПОСЛЕ выделенного пилотного хендлера
  (:137–142); `/instructors/pending` в карте отсутствует — двойной
  регистрации и теневых совпадений нет, generic-цикл пилотный хендлер
  не ломает. Цикл отдачи с префиксом `vue:` (читать из VUE_DIST_DIR,
  404 без dist, media_type text/html; charset=utf-8) — механическое
  расширение существующего `_page`-цикла, карта остается единственным
  декларативным реестром. Решение здоровое; выделенный пилотный
  хендлер не трогается (унификация — будущая консолидация, риск
  работающего маршрута не оправдан) — согласен.
- Переходное состояние 3.1→3.2 (маршрут без отдачи) существует только
  внутри одной сессии, гейт 5.1 — документировано, деление 3.1/3.2
  запрещено («НЕЛЬЗЯ делить»). ОК.
- test_auth_route::test_new_static_routes_served (:246–257) проверяет
  оба маршрута на 200 text/html — без правок; локально требует
  собранного dist (то же поведение, что у пилотного маршрута) —
  задокументировано в design («Локальный регресс»).

## 3. Контрактные риски — не найдены

- Причина отказа rejected: контракт логина route/reason не меняется;
  пишет ключ sessionStorage «instructor_rejected_reason» landing.js:70
  (не затрагивается) и пилотная pending-страница
  (App.vue:52 REJECTED_REASON_KEY) при polling-переходе — оба носителя
  вне диффа. Vue-экран читает ключ в onMounted, try/catch, ноль
  запросов (наследование behavior js/instructor-rejected.js — сверено:
  в legacy нет fetch). Причина при Vue-рендере НЕ теряется; прямой
  вход — нейтральный экран без персональной причины (не раскрывать
  чужую — сохранено). Якорь TC-S9UI-003 #reason-text — в списке
  дословных якорей.
- review-form: ?instructor= → числовой id; без id → location.href=
  '/my-requests' → 301 → /cabinet#/my-requests (BUG-047) — редирект
  `_PAGE_REDIRECTS` (backend/app.py:73–76) без изменений, e2e
  TC-UI-017 идет через этот же путь (page.wait_for_url
  **/cabinet#/my-requests) — совместимо. POST-контракт (backend/
  reviews.py): реакции 401→toLogin / 403→тост (NFR-2) / 409→done
  «уже оставлен»+кнопка активна / прочие→тост — воспроизведение 1:1
  сверено по строкам legacy js/review-form.js:83–96 (включая
  «состояние данными сервера», reload показывает форму — TC-UI-017).
- XSS: legacy-правило «пользовательские строки — только textContent»
  → интерполяция {{ }} + v-html ЗАПРЕЩЕН (наследование review-001
  add-s3-frontend-links, NIT-3). Корректный перенос.
- id-якоря e2e: список design (#reason-text; #uname/#avatar/#i-name/
  #i-ava/#i-sub/#i-rating/#stars-lab/#review-text/#counter/#send/
  #view-form/#view-done/#done-title/#toast/.star[data-v]) сверен с
  фактическими селекторами TC-S9UI-003/TC-UI-017/TC-UI-018 — полный,
  ничего не потеряно. Дополнительно проверен needle TC-S3BE-040
  («Оставить отзыв» в статической разметке входа) — в таблице
  потребителей design он учтен.
- MIN-2 (уточнение внесено в design): needle TC-S3BE-041
  `instructors/'+instructorId+'/reviews` проверяется дословно — это
  требует от Vue-кода СОХРАНИТЬ строковую конкатенацию URL как в
  legacy (не template literals). Из этого ранее не следовало явно;
  зафиксировано в design.md («Страница /review на Vue»).

## 5. Бюджеты NFR-26 — план реалистичен

- Текущий scripts/check-budgets.mjs: page-роль захардкожена
  ('instructors-pending'), замыкание первого захода строится от
  dist/instructors-pending.html. Расширение до карты трех page-чанков
  (chunkRole по набору имен; замыкание от каждого dist/<page>.html;
  first-load и «чужие page-чанки» по каждой странице) — небольшой
  механический рефакторинг без новых зависимостей; регулярка входа
  `/vue/assets/<name>.js` в html не зависит от порядка link/script
  (требует .js) — обобщается корректно.
- Запас: фактические замеры пилота (code-reviews/add-vue-framework-
  pilot/review-005-4.1.md) — vue-чанк 23.2 КБ gzip, полный первый
  заход 25.6 КБ gzip при бюджете 200 КБ. Review-страница = vue +
  shared (+utils в shared) + page-чанк — запас ~7x. «Замыкание без
  чужих page-чанков» выполняется конструктивно (manualChunks по
  входам). План 1.1/4.1 реалистичен; бюджет-контроль остается ручным
  приемочным шагом — наследование ограничения пилота, задокументировано.
