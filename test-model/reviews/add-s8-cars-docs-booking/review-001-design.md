# Design review: спринт 8 (change add-s8-cars-docs-booking) — сверка реализации с согласованными мокапами

Проверка документарная (тексты/структура/порядок мокап vs реализация, файл за файлом).
CSS длинными строками сверялся по смыслу правил (чтение с номерами строк), полные
диффы не требовались — правки CSS Спринта 8 (.ds-*, .subver, .warnbox, .doc-actions,
.cal-slot.booked/.reqslot, .stu-*, .dc-*) локализованы и совпадают с мокапными
прототипами. Git не затронут.

## Экран «Мои документы» (мокап my-documents-s8.html vs #sec-docs + dashboard-instructor.js)

Совпадает дословно:
- Заголовки секций и порядок: «Водительское удостоверение» (hint «личный документ ·
  из анкеты инструктора») → «СТС автомобилей» (hint «по одному на каждый автомобиль…»),
  счетчики-бейджи `.n` у обеих секций — как в мокапе.
- Карточка документа: миниатюра + «⤢ Смотреть», плашка «замена на проверке» (pendtag),
  имя («Водительское удостоверение», «СТС · <марка модель>»), блок «Ожидает проверки
  замены» с текстом «Пока администратор её не подтвердил, действует текущая версия —
  документ «не мигает».», блок «Причина отказа от администратора» с хвостом «действует
  предыдущая версия, можно загрузить заново» — дословно.
- Кнопки карточки: «Открыть» / «Заменить», у отсутствующего СТС — «Загрузить» без
  диалога (первая загрузка — как в мокапе, FR-71).
- Диалог замены #m-replace: «Заменить документ?», warnbox с жирным «Замена не
  вступает в силу сразу.», абзац «Если администратор отклонит замену, вы увидите
  причину отказа, а действующей останется текущая версия — документ не будет утерян.»
  — дословно; явная кнопка «Заменить» + «Отмена» (без клика по «Заменить» файл не
  отправляется — FR-71, TC-UI-033).
- Просмотр полного размера #m-view: клик по изображению, подпись эндпоинта
  GET /api/instructor/documents/{doc_id}/file — как в мокапе.
- Виджетов «привязанные ученики / запросы / занятия на сегодня» в разделе нет
  (FR-73, класс day-content; TC-UI-035). СТС — по одному на каждый авто, авто без
  СТС — карточка «нет СТС» (ОВ-2/FR-69).

Разрешенные дельты (wiring/ревью): строка версии «версия N · загружено <дата>»
(review-005, «версии/бейджи»); мета ВУ «ВУ № <номер>» из контракта API вместо
демо-«серия…»; бейдж состояния всегда «Действует» + субблоки pend/rej вместо
мокапных пилюль «На верификации»/«Замена отклонена» (соответствует FR-70 «документ
не мигает», review-005 approve); честные тосты после загрузки (ветвление
wasMissing — review-005 MINOR закрыт).

## Экран админ-«Документы» (мокап admin-documents.html vs #sec-documents + admin-dashboard.js)

Совпадает дословно:
- h1 «Документы»; подзаголовок раздела (дословно, кроме одной оговорки — см.
  замечание 4); вкладки «Ожидают ·N» / «История»; фильтры «Все типы/ВУ/СТС» и
  «Все решения/Подтверждённые/Отклонённые»; строка-счетчик «Ожидающих версий: N» /
  «Записей в истории: N».
- Строка ожидающей версии: тип-бейдж «ВУ»/«СТС», ВУ — ФИО инструктора, СТС —
  марка/модель · госномер + владелец (ОВ-4); бейдж «Ожидает верификации» + пометка
  «действует предыдущая версия»; кнопки «Предпросмотр» / «✓ Подтвердить» /
  «Отклонить…» — дословно.
- История: note «История решений. Подтверждение: новая версия verified, предыдущая
  — архив. Отклонение: версия rejected с причиной…» — дословно; бейджи
  «Подтверждено»/«Отклонено», «решение от <дата>», блок «Причина отказа: …».
- Предпросмотр #dc-view: изображение открывается (fetch→blob→objectURL с
  X-Admin-Token; naturalWidth>0 в TC-UI-036 — ОВ-4 «изображения открываются»).
- Отклонение #dc-deny: «Отклонить замену», label «Причина отказа — обязательна»,
  deny-note дословно, кнопка «Отклонить» ЗАБЛОКИРОВАНА без непустого текста
  (пробелы не разблокируют — TC-UI-036), «Отмена» (ОВ-1, правка по ревью —
  разрешенная дельта).
- Порядок сайдбара: Пользователи / Заявки инструкторов / Автомобили / Документы /
  Платежи / Настройки — как в мокапе.

Разрешенные дельты (wiring/ревью): «версия №N» вместо мокапного «doc_id N»
(review-007, версии/бейджи); foot предпросмотра «{version_id}» вместо «{doc_id}»
(реальный контракт 4.1).

## Экран «Мои ученики» (мокап my-students.html vs #sec-students + dashboard-instructor.js)

Совпадает дословно:
- Подразделы-вкладки «Ученики ·N» / «Запросы учеников ·N» внутри раздела; отдельного
  пункта сайдбара «Запросы учеников» нет (TC-UI-039; ОВ-5).
- Карточка ученика: блок «Следующее плановое занятие»; пустой вариант «нет —
  подтверждённых броней впереди не запланировано»; счетчики «плановых занятий
  дальше» / «проведено» — дословно (только confirmed, ОВ-5).
- Пустое состояние «Учеников пока нет»; честная ошибка при недоступности 9.1
  (#stu-error + тост, TC-UI-039b — разрешенная дельта «честные ошибки»).
- Принятие запроса с выбором авто, отказ — с обязательным комментарием (кнопка
  заблокирована до текста) — функционал контура Спринта 3 (FR-75: «без изменений»).

Дельты — см. замечания 5 и 6 (поля карточки и тексты подраздела запросов).

## Экран «Календарь» (мокап calendar-booking-s8.html vs #sec-calendar + dashboard-instructor.js)

Совпадает по смыслу и ключевым текстам:
- Запросы (new) и брони (confirmed) — РОВНО на выбранных слотах: точное совпадение
  weekday + час начала, соседние слоты чистые (TC-UI-038: data-k '2-14', 2-16
  не помечен) — FR-74.
- Метки на слотах: имя ученика; у запроса клик → модалка решения, у брони —
  «Подтверждённая бронь»; легенда содержит «Подтверждённая бронь» и «Новый запрос
  ученика»; индикатор «Есть несохранённые изменения» (dirty).
- Решение на слоте, немедленно, мимо «Сохранить»: «✓ Принять» одним кликом;
  отклонение — комментарий обязателен, кнопка заблокирована без текста (пробелы —
  блокировка, POST {comment}, слот освобождается — TC-UI-038); «Закрыть»
  (наследование FR-68/ОВ-6 Спринта 7).
- Раздел «Бронирования» удален без остатков: пункта меню нет, #sec-bookings в DOM
  нет (grep: 0), старая ссылка #/bookings — редирект в «Календарь» с очисткой хеша
  (механика BUG-047, TC-UI-038).

Дельты — см. замечание 7 (кнопки графика, легенда, мелкие метки).

## Замечания

1. minor — Вводные абзацы мокапов не перенесены: «Мои документы» («Водительское
   удостоверение и СТС каждого автомобиля — по одному на машину…»), «Мои ученики»
   («Привязанные ученики и ваши пары с ними…»), «Календарь» («Ваш график на
   неделю…»). Причина — секции встроены в дашборд (BUG-047-прецедент): заголовок
   раздела дает topbar #page-title. Рекомендация: перенести абзацы в начало секций
   либо зафиксировать у ПМ как адаптацию встраивания.
2. minor — «Мои документы»: бейдж состояния всегда «Действует» (даже при
   pending/rejected-версии) вместо мокапных пилюль «На верификации»/«Замена
   отклонена»; состояние выражается плашкой «замена на проверке» + субблоками.
   Соответствует FR-70/НАМЕРЕНИЕ («виден действующий старый документ с пометкой»)
   и review-005 (approve) — разрешенная дельта «версии/бейджи», зафиксировано здесь
   для истории.
3. minor — «Мои документы», точечные текстовые дельты в пользу требований: hint СТС
   дополнен «· замена — после проверки администратором»; viewer-foot «Чужой
   документ вернёт 404» → «Чужой или несуществующий документ вернёт 404»; средняя
   фраза warnbox переформулирована под дословную формулировку FR-71 («Замена
   вступит в силу только после проверки администратором: до подтверждения действует
   предыдущая версия — документ «не мигает»»). Тексты FR-первоисточника осознанно
   приоритетнее демо-формулировок мокапа.
4. minor — Админ-«Документы»: подзаголовок мокапа «До вашего решения действует…» в
   реализации сокращен до «До решения действует…» (потеряно «вашего»); строка-счетчик
   без хвоста мокапа «— подтверждение или отклонение только для ожидающих»; чип
   «Доступ: X-Admin-Token подтвержден» в раздел не перенесен (остался в шапке
   «Пользователи»); empty-текст мокапа (заголовок + строка) объединен в одну строку.
   Рекомендация: восстановить формулировки мокапа (копирайтинг, без кода).
5. minor (требуется решение ПМ/Заказчика) — Карточка «Мои ученики» беднее мокапа:
   нет «в паре с <дата>», авто пары (carline «🚗 <марка> · <госномер>») и бейджа
   статуса авто «Проверено»/«Не проверено». Эти поля отсутствуют в контракте
   GET /api/instructor/students (задача 9.1: full_name, next_lesson, planned_count,
   completed_count); review-015 утвердил карточку по этому контракту. Состав FR-75
   (следующее плановое + 2 счетчика) выполнен полностью. Решение: дополнить контракт
   9.1 (авто пары + статус) или утвердить упрощенную карточку.
6. minor — Подраздел «Запросы учеников»: тексты/структура мокапа my-students.html
   (слот-пилюля «◷ <дата · время>», «хочет заниматься у вас · слот в вашем
   графике», бейдж «Новый запрос», блок «Комментарий ученика», модалки «Принять в
   пару»/«Отклонить запрос») не перенесены — реализация сохраняет контур Спринта 3
   (фильтры Все/Новые/Принятые/Отказанные, инлайн-панели выбора авто/комментария,
   «Стаж вождения…», бейджи «Новая/Принята/Отказана»). Основание — FR-75
   («функционал принятия/отказа — без изменений, наследование Спринта 3») и
   review-010→015. Зафиксировать как осознанное наследование либо завести отдельную
   задачу на перенос текстов мокапа.
7. minor — Календарь: мокапные кнопки «Сохранить» + «Отменить» (disabled до правок)
   реализованы одной кнопкой «Сохранить график» + индикатор dirty; отмена = повторное
   открытие раздела (GET без PUT) — наследование FR-68 зафиксировано review-013
   (approve). Прочие мелочи: легенда «Рабочий интервал»/«Не работаю» (наследование
   Спринта 3) вместо мокапной «в графике — свободно (клик — правка графика)»; угол
   сетки «МСК» вместо «время»; на слоте брони слово «бронь» вместо имени авто из
   мокапа (авто показано в модалке решения: «авто: <марка модель>»); метка запроса
   «запрос» в нижнем регистре (в мокапе «Запрос» с uppercase-CSS); кнопки навигации
   недель «←»/«Неделя →» из мокапа отсутствуют (сетка — текущая неделя, наследование).
8. info — «Мои автомобили» (в рамках change): явная кнопка «Заменить СТС»/
   «Загрузить СТС» в модалке-галерее; галерейный путь замены СТС ведет через общий
   диалог FR-71 (review-003 MAJ-2, TC-UI-040); note «замена СТС статус авто не
   меняет» (ОВ-6); тексты FR-69/FR-71/ОВ-6 — разрешенные дельты (s8-мокапа авто в
   объеме сверки нет).
9. info — Сайдбар кабинета: «Бронирования» и отдельный «Запросы учеников»
   отсутствуют (FR-74/FR-75); «демо»-пункты («Расписание», «Мой автомобиль»,
   «Материалы и обучение», «Профиль и документы») — наследие Спринтов 3–7, не дельта
   Спринта 8, не оценивались.
10. info — e2e-покрытие: TC-UI-033 (статусы версий + замена ВУ через FR-71),
    TC-UI-034 (дозагрузка/замена СТС, честная 422), TC-UI-035 (FR-73, экраны без

    история), TC-UI-038 (снос «Бронирований», запрос на своем слоте), TC-UI-039/
    039b (карточки/счетчики/подраздел, честная ошибка), TC-UI-040 (галерейный

    совпадающие с мокапными. Прогон тестов — ось QA (прогон ПМ 358 passed, ссылки
