# BUG-069: таб-бар перекрывал низ bottom-sheet модалок кабинета — клики по
# кнопкам шита перехватывались (.mtab intercepts pointer events)

- **Обнаружено:** Спринт 18, волна 18.4 (2026-11-17, e2e TC-UI-077 на
  390×844, сразу после фикса BUG-068): модалка пополнения кошелька
  открывается, но клик по «Отмена» невозможен —
  «button .mtab on … subtree intercepts pointer events». Таб-бар
  (`.mtabs`, z-index 60, fixed bottom) лежит ПОВЕРХ бэкдропов модалок
  кабинета `.backdrop`/`.wal-backdrop` (z-index 30): у прижатых к низу
  bottom-sheet (18.2) таб-бар перекрывал grab-хендл и нижние кнопки
  («Пополнить»/«Отмена»).
- **Причина (уточнена рантайм-замером 18.4):** НЕ «низкий z-index
  бэкдропа», а СТЕКИНГ-КОНТЕКСТ. `.frame` кабинета — контекст
  (`position:relative; z-index:1`): бэкдроп с любым z-index (пробовали
  70 — в dist правило было, перехват сохранялся) рисуется на УРОВНЕ
  `.frame` (1) и в контексте `.app` проигрывает таб-бару (60) атомарно —
  `.mtabs` — прямой потомок `.app` вне `.frame`. zn-overlay (деталь
  знака) не задет — свой z-index 80.
- **Что сделано:** в media ≤760px styles.css кабинета снят контекст
  (`​.frame{z-index:auto}`; desktop не меняется — там z-index:1
  сохранен) и бэкдропы подняты в КОРНЕВОМ контексте над таб-баром:
  `​.backdrop,.wal-backdrop{z-index:70}` (> 60; язык мокапов: sheet
  поверх tabs). Вариант «поднять сам `.frame` до 70» отвергнут
  рантайм-проверкой: весь контент frame начинал перехватывать клики
  ТАБОВ при скролле. Регресс закреплен e2e TC-UI-077 (открыть модалку →
  клик «Отмена» проходит, модалка закрылась).
- **Статус:** FIXED (волна 18.4).
