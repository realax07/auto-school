# BUG-070: desktop-контент кабинета сжат до ширины сайдбара (236px) —
# корневой div MobileTabBar занимал grid-ячейку .app

- **Обнаружено:** Спринт 18, волна 18.4 (2026-11-17, e2e TC-UI-079
  `test_s18_desktop_tabbar_hidden_and_fines_table_intact`, 1440×900 —
  новый desktop-инвариант волны 18.4): `.zn-grid` на desktop выдавал
  ОДНУ колонку вместо auto-fill (~7): computed
  `grid-template-columns:190px`, ширина сетки 188px.
- **Причина (рантайм-замер DOM):** корневой `<div>` MobileTabBar.vue
  (без класса, рендерится ВСЕГДА — независимо от v-if таб-бара) Vue
  монтирует прямо потомком `.app` кабинета (grid
  `236px minmax(0,1fr)`): auto-placement отдавал ему ячейку row1-col2
  (1204px), `.hero` (весь контент) уезжал в row2-col1 (236px). Итог с
  С18.1: desktop-кабинет геометрически сжат до колонки сайдбара
  (таблицы/сетки 236px) — визуально не ловилось: прогон 18.1 «e2e 84
  green» не проверял геометрию контента. instructor-choice не задет
  (его `.app` без grid-колонок).
- **Что сделано:** корневому div присвоен класс `.mtab-root` +
  страховка в MobileTabBar.vue рядом с существующей:
  `@media(min-width:761px){.mtab-root{display:none!important}}` — div
  >760px ячейку не генерирует, `.hero` возвращается в row1-col2
  (1204px); ≤760px не задет (внутри div — fixed `.mtabs`, box div
  нулевой высоты). Регресс закреплен геометрией в e2e TC-UI-079
  (.zn-grid > 2 колонок на 1440×900). Сборка OK, бюджеты NFR-26 OK.
- **Статус:** FIXED (волна 18.4; найден носителем desktop-инварианта
  18.4.1 — «desktop-фрагменты не тронуты» отработал как задумано).
