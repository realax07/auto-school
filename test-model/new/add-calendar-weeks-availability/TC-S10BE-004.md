  - Scenario: Другие даты повторяющейся серии остаются доступными

## GIVEN / WHEN / THEN
- GIVEN свежая БД (init_db): строка recurring-серии «Чт 16:00–18:00» (id 1, инструктор 7) и активная бронь ученика 5 на 2026-11-12 (status 'new') — уровень хранилища, без API
- WHEN выполняются прямые INSERT в booking: активная (confirmed) бронь ученика 6 на ДРУГУЮ дату серии 2026-11-19; вторая активная бронь на ТУ ЖЕ дату 2026-11-12; бронь status='rejected' на дату 2026-11-12
- THEN бронь на другую дату серии вставляется (занят только экземпляр, не вся серия); вторая активная бронь на тот же экземпляр (availability_id, lesson_date) отклоняется IntegrityError — частичный UNIQUE uq_booking_active_slot (availability_id, lesson_date) WHERE status IN ('new','confirmed'); rejected-бронь вставляется — выпадает из частичного индекса (повторный запрос после отклонения допустим, ОВ-5)
