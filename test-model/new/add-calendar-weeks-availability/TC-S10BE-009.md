# TC-S10BE-009 — Занятый экземпляр: 409 чужому и себе, другая дата серии свободна, гонка — ровно один 200

- Автотест: `tests/test_s10_backend.py::test_s10_booking_instance_occupancy_and_race`
- Приоритет: Must (FR-95, NFR-8)
- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-calendar-weeks-availability (Спринт 10, backend)
- Трассировка:
  - Requirement: Занятый слот недоступен другим ученикам
  - Scenario: Другие даты повторяющейся серии остаются доступными
  - Scenario: Параллельные запросы на один слот — максимум одна бронь
  - Scenario: Занятый слот не бронируется повторно

## GIVEN / WHEN / THEN
- GIVEN фиктивный NOW; инструктор с recurring-серией «Чт 16:00–18:00»; два ученика разных принятых пар, id слота; d1 = четверг следующей недели, d2 = d1+7, d3 = d1+14; ученик 1 уже забронировал d1 (200)
- WHEN ученик 2 бронирует тот же занятый d1; ученик 1 повторно бронирует свой d1 («на рассмотрении»); ученик 2 бронирует d2 (другая дата серии); затем два ПАРАЛЛЕЛЬНЫХ POST на свободный d3 (threading.Barrier(2), потоки с токенами обоих учеников)
- THEN чужой POST на занятый экземпляр → 409; повторный POST на свой активный запрос → 409; в БД по слоту ровно 1 запись; другая дата серии → 200 (занят только экземпляр d1); гонка: статусы ровно [200, 409] — один запрос проходит, второй получает явный конфликт, активных броней на d3 в БД ровно 1 (BEGIN IMMEDIATE + частичный индекс)
