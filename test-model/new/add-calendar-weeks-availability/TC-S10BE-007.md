# TC-S10BE-007 — Легаси-POST без даты: ближайший будущий экземпляр; one_off → slot_date; невалидный date → 422

- Автотест: `tests/test_s10_backend.py::test_s10_booking_legacy_without_date`
- Приоритет: Must (NFR-29 — совместимость POST; MIN-1)
- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-calendar-weeks-availability (Спринт 10, backend)
- Трассировка:
  - Requirement: Запрос брони на слот
  - Scenario: Запрос в старом формате (без даты) продолжает приниматься

## GIVEN / WHEN / THEN
- GIVEN фиктивный NOW (сегодня 08:00 МСК); инструктор с recurring-серией «Чт 16:00–18:00», принятая пара, id слота; в БД прямым INSERT добавлен one_off «Чт 16:00–18:00» на ближайшую будущую дату weekday 3
- WHEN POST {availability_id} БЕЗ поля date (старый формат клиента) для серии; затем POST без date для one_off; затем POST с date = «12.11.2026» (не ISO) и date = «2026-02-30» (несуществующая)
- THEN легаси-бронь серии принимается (200) на ближайшую будущую дату экземпляра: lesson_date == materialize_lesson_date(3) — прежнее поведение; one_off без date → lesson_date = slot_date (200); не-ISO и несуществующая дата → 422

## Примечание
- Партия change add-calendar-weeks-availability (Спринт 10, волна D-1 backend); кейсы живут трассировкой TC-ID в docstring автотеста (rule 6).
- Полный прогон: 365 passed — факт ПМ; контрольный живой прогон сессии (2026-11-05): tests/test_s10_backend.py — 19 passed.
