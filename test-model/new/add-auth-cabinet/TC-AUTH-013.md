# TC-AUTH-013 — Блокировка действует на свой IP, чужой IP не затронут

- ID кейса: TC-AUTH-013
- ID чеклиста: CHK-17
- Источник: CHK-17 → Requirement «Ограничение попыток входа (анти-брутфорс)» (домен auth) → FR-2; Scenario «Блокировка после превышения порога попыток» (изоляция по IP, граница)
- Тип: граничный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_bruteforce_block_is_per_ip

## GIVEN / WHEN / THEN
- GIVEN вход с IP-A заблокирован по превышению порога неудачных попыток
- WHEN в течение блокировки IP-A с другого IP-B выполняются вход (успешный и отказной)
- THEN IP-B не затронут: успешный вход → 200 {"ok": true, "token": "..."}, отказной → обычный 401 с единым сообщением; учет попыток ведется по IP раздельно (request.client.host; D6: проверяемо только без обратного прокси)

## Предусловия
- Как в TC-AUTH-001; отдельные IP источника для нарушителя (10.0.0.2) и «другого» клиента (10.0.0.3); деплой без прокси (D6).

## Шаги
1. POST /api/register → 200.
2. С IP 10.0.0.2 выполнить _BF_MAX_FAILURES неудачных попыток (ghost@example.com) → каждая 401.
3. С IP 10.0.0.3 выполнить POST /api/auth/login с корректными кредами.
4. С IP 10.0.0.3 выполнить POST /api/auth/login с неверным паролем.
5. Контроль: с IP 10.0.0.2 попытка с корректными кредами → 401 (блокировка активна).

## Ожидаемый результат
3. 200 {"ok": true, "token": "..."} — другой IP работает штатно во время блокировки первого.
4. 401 {"ok": false, "error": "Неверный email или пароль"} — обычный отказ, не блокировочный (счетчик IP-B не затронут).
5. 401 — контроль изоляции (блокировка осталась на IP-A).

## Тестовые данные
IP нарушителя 10.0.0.2, IP другого клиента 10.0.0.3; креды базового пользователя TC-AUTH-001.
