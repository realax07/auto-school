# TC-CAB-003 — 401 на /me при открытом кабинете: редирект и очистка sessionStorage

- ID кейса: TC-CAB-003
- ID чеклиста: CHK-20
- Источник: CHK-20 → Requirement «Доступ к кабинету по сессионному токену» (домен cabinet) → FR-7; Scenario «Попадание в кабинет без токена» (ветка истекшего/аннулированного токена); контроль риска D4 (fail-open при сетевой ошибке — вне спеки, но 401-ветка обязана быть fail-closed)
- Тип: негативный
- Приоритет: Must
- Статус: manual/toBeAutomated (браузерный сценарий; косвенный автоконтроль wiring — tests/test_cabinet_page.py::test_cab_wiring_401_redirect_to_landing, test_cab_wiring_auth_me_with_session_token_header)

## GIVEN / WHEN / THEN
- GIVEN кабинет открыт (вход выполнен, токен в sessionStorage); затем токен стал невалидным: истек (TTL) или аннулирован logout'ом с другой вкладки/повторным logout
- WHEN страница кабинета выполняет GET /api/auth/me и получает 401 {"ok": false}
- THEN выполняется редирект на страницу входа (лендинг / с модалкой m-login) и очистка sessionStorage; контент кабинета с чужими/пустыми данными не остается открытым (fail-closed)

## Предусловия
- Браузер/Playwright; пользователь зарегистрирован и вошел (кабинет открыт).

## Шаги
1. Войти, открыть /cabinet (как TC-CAB-001).
2. Инвалидировать токен на сервере: вариант A — сдвинуть время сервера за TTL (тестовый механизм); вариант B — POST /api/auth/logout с этим токеном вне браузера (аннулирование).
3. В кабинете инициировать повторный запрос /me (перезагрузка /cabinet).
4. Зафиксировать: статус ответа /me (401), итоговый URL, состояние sessionStorage.

## Ожидаемый результат
3. GET /api/auth/me → 401 {"ok": false}.
4. Редирект на «/» (модалка m-login); sessionStorage.session_token удален (removeItem); приветствие/ФИО кабинета не отображаются — контент не остался открытым.

## Тестовые данные
Базовый пользователь TC-AUTH-001.
