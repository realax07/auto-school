# TC-AUTH-008 — Истекший токен отклоняется (TTL, сдвиг времени без sleep)

- ID кейса: TC-AUTH-008
- ID чеклиста: CHK-9
- Источник: CHK-9 → Requirement «Сессии с ограниченным сроком действия» (домен auth) → FR-1, FR-7; Scenario «Запрос с истекшим токеном»; дефект спеки D1 (TTL = 12 ч зафиксирован в design.md/sdd §9, в дельте не фиксирован — проверка параметрическая)
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_expired_token_401

## GIVEN / WHEN / THEN
- GIVEN ученик вошел и получил токен; срок действия токена (TTL = 12 ч, in-memory реестр) истек
- WHEN GET /api/auth/me с этим токеном после истечения TTL
- THEN 401 {"ok": false} — отклонен как неавторизованный; на фронте — редирект на страницу входа (по D3: лендинг / с модалкой m-login; браузерная часть — TC-AUTH-020/TC-AUTH-021)

## Предусловия
- Как в TC-AUTH-001.
- time.sleep запрещен (спека qa-pipeline): «сейчас» сдвигается вперед мимо expires прямым сдвигом времени — monkeypatch auth.time.time на real_time() + _TOKEN_TTL_SECONDS + 5 (in-memory реестр, рестарт недопустим — сбросил бы сессию).

## Шаги
1. POST /api/register → 200; POST /api/auth/login → 200, извлечь token.
2. Зафиксировать реальное значение time.time; подменить clock так, что «сейчас» = реальное время + _TOKEN_TTL_SECONDS + 5 с.
3. GET /api/auth/me с заголовком X-Session-Token: <token> при сдвинутом времени.
4. (Фронт-часть, отдельный прогон в браузере/Playwright) открыть /cabinet с этим токеном — фиксируется редирект на вход; покрыто TC-AUTH-021.

## Ожидаемый результат
3. 401 {"ok": false}; поле token в теле отсутствует; до сдвига времени тот же запрос давал 200 (контроль корректности шага 1–2: без сдвига /me → 200).

## Тестовые данные
- Базовый пользователь TC-AUTH-001; TTL = 12 ч (43200 с); сдвиг = TTL + 5 с.
