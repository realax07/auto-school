# TC-CAB-002 — Открытие /cabinet без токена: редирект на вход, кабинет не показывается

- ID кейса: TC-CAB-002
- ID чеклиста: CHK-19
- Источник: CHK-19 → Requirement «Доступ к кабинету по сессионному токену» (домен cabinet) → FR-7; Scenario «Попадание в кабинет без токена»; D3 (трактовка «страница входа» = лендинг / с модалкой m-login)
- Тип: негативный
- Приоритет: Must
- Статус: manual/toBeAutomated (браузерный сценарий; косвенный автоконтроль wiring — tests/test_cabinet_page.py::test_cab_wiring_401_redirect_to_landing)

## GIVEN / WHEN / THEN
- GIVEN пользователь не выполнял вход (вариант A); или его сессия истекла/аннулирована (вариант B — после выполнения TC-CAB-003/TC-AUTH-009); sessionStorage пуст
- WHEN он открывает /cabinet без действующего токена
- THEN система возвращает его на страницу входа (по D3: лендинг / с модалкой m-login), содержимое кабинета не показывается

## Предусловия
- Браузер/Playwright; сервис собан через create_app(); пользователь зарегистрирован (для варианта B).

## Шаги
1. Вариант A (входа не было): открыть /cabinet в чистом контексте браузера (sessionStorage пуст).
2. Зафиксировать итоговый URL после отработки скриптов страницы.
3. Проверить видимость модалки m-login и отсутствие контента кабинета.
4. Вариант B: войти (TC-CAB-001), выполнить logout (TC-CAB-004) либо сдвинуть время за TTL; повторить открытие /cabinet в той же сессии браузера.

## Ожидаемый результат
2. Итоговый URL — «/» (лендинг с модалкой входа, контракт D3).
3. Модалка m-login видима; блоки кабинета (приветствие, плитки, чат-бар) не отрисованы.
4. Вариант B — тот же результат: редирект на вход, содержимое кабинета не показывается.

## Тестовые данные
Базовый пользователь TC-AUTH-001.
