# TC-CAB-008 — Плитки и чат-бар — визуальные заглушки: клик не выполняет сервисных действий

- ID кейса: TC-CAB-008
- ID чеклиста: CHK-24
- Источник: CHK-24 → Requirement «Чат-бар и плитки-сервисы как визуал-заглушки» (домен cabinet) → FR-6; Scenario «Плитка не выполняет сервисного действия»
- Тип: негативный
- Приоритет: Must
- Статус: manual/toBeAutomated (браузерный сценарий с перехватом сети; косвенный автоконтроль — tests/test_cabinet_page.py::test_cab_page_keeps_mockup_stub_alert: alert «Заглушка: сервис появится в следующем спринте» сохранен)

## GIVEN / WHEN / THEN
- GIVEN ученик открыл кабинет
- WHEN он нажимает на каждую из трех плиток и элементы чат-бара (поле ввода, кнопка отправки)
- THEN никакого сервисного действия не происходит: нет сетевых запросов к данным/сервисам, нет переходов (location не меняется); поведение — как в мокапе (alert-заглушка «Заглушка: сервис появится в следующем спринте»)

## Предусловия
- Браузер/Playwright с перехватом сетевых запросов; пользователь вошел, кабинет открыт.

## Шаги
1. Открыть /cabinet под пользователем; включить перехват всех сетевых запросов.
2. Клик по плитке «Обучение ПДД» → зафиксировать запросы и URL.
3. Повторить для «Онлайн экзамен», «Найти водителя».
4. Клик по элементам чат-бара (строка промпта, кнопка ↑) → зафиксировать.
5. Дождаться 1–2 с после каждого клика (без переходов) и сверить перечень запросов с фоновым.

## Ожидаемый результат
2–4. После каждого клика: URL не изменился (location.href == "/cabinet"); новых запросов к API/сервисам нет (кроме фоновых /api/auth/me при загрузке, повторных не возникает); допустима только модальная заглушка-alert из мокапа.

## Тестовые данные
Базовый пользователь TC-AUTH-001; элементы: button.tile ×3, .prompt span, .prompt button.send, .quick button.
