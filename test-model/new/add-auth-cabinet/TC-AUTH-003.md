# TC-AUTH-003 — Единое сообщение об отказе: причины неразличимы

- ID кейса: TC-AUTH-003
- ID чеклиста: CHK-5, CHK-6, CHK-7
- Источник: CHK-5/CHK-6/CHK-7 → Requirement «Единое сообщение об отказе входа» (домен auth) → FR-2; Scenarios «Вход с неверным паролем», «Вход с несуществующим email», «Сообщение об отказе не раскрывает причину»
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_login_failures_identical_message

Примечание: CHK-5, CHK-6 и CHK-7 — одна проверка (три причины отказа и их посимвольное сравнение), поэтому по правилу «1 пункт ↔ 1 кейс без дробления» оформлены одним кейсом, а не тремя.

## GIVEN / WHEN / THEN
- GIVEN в системе зарегистрирован ученик с email E; учетной записи с email X нет
- WHEN (1) вход с E и неверным паролем; (2) вход с X и любым паролем; затем посимвольное сравнение двух ответов
- THEN оба ответа 401 {"ok": false, "error": "Неверный email или пароль"} (AUTH_FAIL_MESSAGE, sdd §10.1); код и строка ошибки идентичны посимвольно; причина не раскрыта; поле token в обоих телах отсутствует

## Предусловия
- Как в TC-AUTH-001 (create_app, чистая БД, env, health 200).
- Анти-брутфорс не должен вмешиваться: сценарий укладывается в порог неудач (5, D2) — попыток в кейсе меньше порога.

## Шаги
1. POST /api/register с базовым пользователем → 200.
2. POST /api/auth/login {"email": "petrova@example.com", "password": "wrong-pass"} → зафиксировать статус и тело.
3. POST /api/auth/login {"email": "ghost@example.com", "password": "whatever"} → зафиксировать статус и тело.
4. Сравнить два ответа: равенство кодов и посимвольное равенство строк ошибки.
5. В обоих телах убедиться в отсутствии поля token.

## Ожидаемый результат
2. 401 {"ok": false, "error": "Неверный email или пароль"}.
3. 401 {"ok": false, "error": "Неверный email или пароль"}.
4. Ответы идентичны: одинаковый код 401, идентичная строка ошибки (сравнение ==); причина («неверный пароль» vs «не найден») не раскрыта ни в одном из ответов.
5. Поле token отсутствует в обоих телах — токен не выдан.

## Тестовые данные
- Зарегистрированный: petrova@example.com / Qwerty123.
- Неверный пароль: "wrong-pass"; несуществующий email: ghost@example.com с паролем "whatever".
