# TC-AUTH-011 — Открытый пароль отсутствует в хранилище и логах

- ID кейса: TC-AUTH-011
- ID чеклиста: CHK-8, CHK-33 (частично: пароль в логах)
- Источник: CHK-8 → Requirement «Хранение учетных данных» (домен auth) → FR-3; Scenario «Открытый пароль отсутствует в хранилище и логах»; NFR-3
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_password_not_in_logs (часть CHK-33 про токены — TC-NFR-003)

## GIVEN / WHEN / THEN
- GIVEN выполнены регистрация и вход ученика с паролем P (успешный и неудачный)
- WHEN прямой просмотр таблицы users и журналов сервиса (логи регистрации и логина, уровень DEBUG)
- THEN строка P отсутствует и в хранилище (только bcrypt-хэш), и в логах

## Предусловия
- Как в TC-AUTH-001; перехват логов на уровне DEBUG (caplog), чтобы покрыть все записи логгера приложения.

## Шаги
1. Включить перехват записей логгера уровня DEBUG (caplog.at_level(DEBUG)).
2. POST /api/register с базовым пользователем (пароль P = "Qwerty123") → 200.
3. POST /api/auth/login с неверным паролем "wrong-pass" → 401.
4. POST /api/auth/login с корректным P → 200.
5. Прямой SELECT * FROM users — поиск подстрок "Qwerty123" и "wrong-pass" во всех колонках.
6. Поиск тех же подстрок в полном тексте логов.

## Ожидаемый результат
2–4. Как ожидается: 200 / 401 / 200.
5. Подстроки "Qwerty123" и "wrong-pass" в users не встречаются; в колонке password_hash — только bcrypt-хэш (префикс $2b$).
6. Подстроки "Qwerty123" и "wrong-pass" в логах не встречаются.

## Тестовые данные
Базовый пользователь TC-AUTH-001; пароль P = "Qwerty123"; неверный пароль "wrong-pass".
