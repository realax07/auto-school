# TC-AUTH-007 — Подделанный токен отклоняется защищенным ресурсом

- ID кейса: TC-AUTH-007
- ID чеклиста: CHK-10, CHK-11
- Источник: CHK-10/CHK-11 → Requirement «Сессии с ограниченным сроком действия» (домен auth) → FR-1, FR-7; Scenario «Запрос с подделанным токеном»
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_forged_token_401

## GIVEN / WHEN / THEN
- GIVEN пользователь не выполнял успешный вход
- WHEN запросы к защищенным ресурсам GET /api/auth/me и POST /api/auth/logout с заголовком X-Session-Token: "<произвольная строка>"
- THEN оба ответа 401 {"ok": false}; подделанный токен не принят; поле token в телах отсутствует

## Предусловия
- Как в TC-AUTH-001; успешных входов не было (реестр сессий пуст — подделка не совпадет ни с одной записью).

## Шаги
1. GET /api/auth/me с заголовком X-Session-Token: "forged-token-abc123" → зафиксировать ответ.
2. POST /api/auth/logout с тем же заголовком → зафиксировать ответ.
3. Повторить оба запроса после чужих успешных входов (другие пользователи вошли) — подделка по-прежнему не принята.

## Ожидаемый результат
1–3. Каждый запрос: 401 {"ok": false}; токен не выдается ни в одном ответе; 200 не возникает ни до, ни после чужих успешных входов.

## Тестовые данные
- Подделанный токен: "forged-token-abc123" (произвольная строка, не результат login).
