# TC-AUTH-016 — Окно наблюдения без неудач сбрасывает счетчик (R-BF3)

- ID кейса: TC-AUTH-016
- ID чеклиста: CHK-15 (вторая ветка сброса — по времени), R-BF3
- Источник: CHK-15 → Requirement «Ограничение попыток входа (анти-брутфорс)» (домен auth) → FR-2; R-BF3 (design: окно наблюдения ≥ 15 мин без неудач сбрасывает счетчик); Scenario «Счетчик сбрасывается после успешного входа» (временная ветка)
- Тип: граничный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_bruteforce_window_reset

## GIVEN / WHEN / THEN
- GIVEN с IP выполнено (порог - 1) неудачных попыток подряд; далее прошло окно наблюдения (_BF_WINDOW_SECONDS = 15 мин) без неудачных попыток
- WHEN поступает новая неудачная попытка с этого IP
- THEN счетчик считается от новой попытки: fails == 1 (окно наблюдения сбросило старый счетчик), блокировки нет

## Предусловия
- Как в TC-AUTH-001; IP 10.0.0.6; время управляемо (monkeypatch auth.time.time, без sleep).

## Шаги
1. POST /api/register → 200; подменить clock: now[0] = реальное время.
2. С IP 10.0.0.6 выполнить (_BF_MAX_FAILURES - 1) неудачных попыток; зафиксировать fails == _BF_MAX_FAILURES - 1.
3. Сдвинуть now[0] += _BF_WINDOW_SECONDS + 1 (окно истекло).
4. Выполнить одну неудачную попытку (ghost); зафиксировать fails.

## Ожидаемый результат
2. fails == _BF_MAX_FAILURES - 1.
4. fails == 1 — старый счетчик сброшен истечением окна; новая попытка начала счет заново; блокировки нет.

## Тестовые данные
IP 10.0.0.6; ghost@example.com; _BF_WINDOW_SECONDS = 900 (читать из backend/auth.py).
