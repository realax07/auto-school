# TC-UI-077 — Мобильный 390×844: вход (bottom-sheet) → кабинет → таб-бар → модалки → профиль-шит

- Автотест: `tests/web/test_ui_playwright.py::test_s18_mobile_login_bottomsheet_tabbar_cabinet`
- Приоритет: Must (Спринт 18, add-mobile-adaptive, задача 18.4.2)
- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-mobile-adaptive
- Трассировка:
  - Scenario: Таб-бар на 390px
    Requirement: Компактный таб-бар на мобильных ширинах
  - Scenario: Пополнение кошелька на 390px
    Requirement: Bottom-sheet модалки сохраняются

## GIVEN / WHEN / THEN
- GIVEN свежий контекст 390×844, ученик зарегистрирован через API (consent — FR-78)
- WHEN открыта модалка входа с лендинга; выполнен вход; последовательно: таб «Записи», таб «Обучение» → шит → «Билеты», таб «Кошелек» → «Пополнить» → «Отмена», таб «Профиль» → шит → «×»
- THEN модалка входа — bottom-sheet (вся ширина 390, прижата к низу, grab-хендл ::before 38×4, радиус 18/0); desktop-сайдбар display:none, `.mtabs` 54px у низа; «Записи» → `#sec-bookings` + хеш `#/my-bookings` + подсветка; «Билеты» → `#sec-pdd-tickets` + хеш `#/pdd-tickets`; модалка пополнения — bottom-sheet и КЛИК «Отмена» проходит, модалка закрылась (регресс BUG-069); профиль-шит показывает ФИО (FR-5) и «Выйти», закрывается крестиком

## Примечание
- Регресс BUG-069 (таб-бар перехватывал клики кнопок шита) и BUG-068
  (openTab в bindings setup) закреплен кликами этого сценария.
