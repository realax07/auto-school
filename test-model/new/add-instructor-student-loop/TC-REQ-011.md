# TC-REQ-011 — Принятие разрывает существующую принятую связь у другого инструктора

- ID кейса: TC-REQ-011
- ID чеклиста: CHK-59
- Источник: CHK-59 → Requirement «Принятие заявки с привязкой к автомобилю» (student-requests) → FR-39, ОВ-1; Scenario «Принятие разрывает существующую принятую связь у другого инструктора»
- Тип: граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN ученик принят инструктором Б (заявка 'accepted', car_id) и имеет активную заявку 'new' инструктору А
- WHEN инструктор А принимает свою заявку
- THEN заявка А → 'accepted' (car_id А); связь с Б разорвана: заявка Б → 'denied' с системным комментарием, car_id снят; ученик больше не числится принятым у Б; у ученика ровно одна активная связь «принят»

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Ученик принят Б (TC-REQ-008); затем подал заявку А (активная 'new' — ОВ-2/ОВ-1 допускают).
2. А выполняет accept {car_id} → код.
3. GET /api/instructor/summary Б: students содержит ученика?
4. GET /api/student/requests учеником — статусы и комментарии обеих заявок.
5. БД: student_requests ученика — все статусы и car_id.

## Ожидаемый результат
2. 200 {ok:true}.
3. Ученика в students Б нет.
4. Заявка А «принята»; заявка Б «отказана» с системным комментарием, видимым ученику.
5. Ровно одна 'accepted' (к А); Б — 'denied'; активная связь «принят» одна.
