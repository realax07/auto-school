# TC-CAR-004 — Фото автомобиля привязано и отображается владельцу

- ID кейса: TC-CAR-004
- ID чеклиста: CHK-17
- Источник: CHK-17 → Requirement «Фото автомобиля доступно владельцу» (instructor-cars) → FR-27, NFR-1, NFR-6; Scenario «Загруженное фото привязано к автомобилю и отображается»
- Тип: позитивный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN автомобиль создан инструктором А ({car_id})
- WHEN А загружает фото (JPEG, 3 МБ): POST /api/instructor/cars/{car_id}/photo
- THEN фото привязано к автомобилю; GET /api/instructor/cars/{car_id}/photo с токеном А возвращает изображение

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. POST photo с файлом car.jpg (JPEG 3 МБ), токен А.
2. GET photo с токеном А — статус, Content-Type, байты.
3. Раздел «Мои автомобили» в кабинете отображает фото (UI).

## Ожидаемый результат
1. 200 {ok:true}.
2. 200, image/jpeg, байты совпадают с car.jpg.
3. Фото видно в разделе (браузер/Playwright).

Тестовые данные: см. Предусловия; учетные записи фикстур (admin-token, инструкторы, ученик).
