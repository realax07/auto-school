# TC-CAR-008 — Удаление автомобиля: из раздела, из вариантов привязки; привязка ученика снимается, связь сохраняется

- ID кейса: TC-CAR-008
- ID чеклиста: CHK-21, CHK-22
- Источник: CHK-21/22 → Requirement «Редактирование и удаление автомобиля» (instructor-cars) → FR-28, ОВ-3; Scenarios «Удаление убирает автомобиль из раздела и из вариантов привязки», «Удаление автомобиля снимает привязку, связь с инструктором сохраняется»
- Тип: граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN ученик принят инструктором А с привязкой к автомобилю X (student_requests.car_id = X); у А есть автомобиль Y
- WHEN А удаляет автомобиль X: DELETE /api/instructor/cars/{X}
- THEN X исчезает из раздела и из вариантов выбора автомобиля при принятии новых учеников; car_id принятой заявки → NULL; ученик остается в «Моих учениках» (связь ученик↔инструктор сохранена); инструктор перекрепляет авто вручную (PATCH students/{id}/car на Y)

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Подготовить: заявка ученика к А принята с car_id=X (TC-REQ-008).
2. DELETE .../cars/{X} токеном А → код.
3. GET cars токеном А; GET /api/instructor/students (или summary.students) — привязки?
4. Проверить student_requests в БД: status и car_id.
5. PATCH /api/instructor/students/{ученик}/car {car_id:Y} → код; проверить car_id заявки.

## Ожидаемый результат
2. 200 {ok:true}.
3. X в списке/вариантах отсутствует; ученик в списке принятых есть (авто не указан).
4. status='accepted', car_id=NULL (ОВ-3).
5. 200 {ok:true}; car_id заявки = Y.
