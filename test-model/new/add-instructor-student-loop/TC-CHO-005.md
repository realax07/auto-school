# TC-CHO-005 — Каталог полностью работоспособен без гео-данных

- ID кейса: TC-CHO-005
- ID чеклиста: CHK-37
- Источник: CHK-37 → Requirement «Независимость каталога от картографических сервисов» (student-instructor-choice) → FR-33 (вне скоупа, точка расширения); Scenario «Каталог работает без гео-данных»
- Тип: граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN картографические сервисы недоступны (сеть к ним отсутствует), гео-данные в системе отсутствуют по конструкции
- WHEN ученик открывает каталог и применяет все фильтры (КПП, рейтинг, стаж, время)
- THEN каталог полностью работоспособен: карточки, фильтры и пустые состояния работают как в TC-CHO-001…TC-CHO-004, без ошибок и задержек на гео-вызовы

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. В окружении без доступа к картографическим сервисам выполнить сценарии TC-CHO-001–004 (полный проход).
2. Проверить отсутствие в коде/запросах обращений к внешним картам (инспекция + журналы).

## Ожидаемый результат
1. Все результаты идентичны результатам TC-CHO-001–004; ошибок нет.
2. Внешних вызовов карт нет — работоспособность от них не зависит (точка расширения FR-33 свободна).
