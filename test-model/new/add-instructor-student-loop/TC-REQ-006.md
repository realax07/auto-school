# TC-REQ-006 — Отказ: без комментария заблокирован (422), с комментарием виден ученику

- ID кейса: TC-REQ-006
- ID чеклиста: CHK-52, CHK-53
- Источник: CHK-52/53 → Requirement «Отказ с обязательным комментарием» (student-requests) → FR-38; Scenarios «Отказ без комментария заблокирован», «Отказ с комментарием виден ученику»
- Тип: негативный + позитивный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN у инструктора А есть входящая заявка в статусе 'new'
- WHEN А выполняет POST /api/instructor/requests/{id}/deny с пустым/отсутствующим comment (A); затем с непустым комментарием (B)
- THEN A: 422 {ok:false}, действие заблокировано, статус остается 'new'; B: 200, status='denied', deny_comment=comment; ученик в GET /api/student/requests видит статус «отказана» и текст комментария

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Ученик подал заявку А (TC-REQ-001).
2. POST deny без comment → код; POST deny {comment:""} → код.
3. GET /api/student/requests — статус?
4. POST deny {comment:"Не подходящий график"} → код.
5. GET /api/student/requests учеником — статус и комментарий.

## Ожидаемый результат
2. Оба → 422 {ok:false}.
3. Статус остался 'new'.
4. 200 {ok:true}.
5. Статус «отказана», deny_comment = «Не подходящий график» — текст виден ученику.
