# TC-REQ-005 — Список входящих заявок: свои видны, чужие нет

- ID кейса: TC-REQ-005
- ID чеклиста: CHK-50, CHK-51
- Источник: CHK-50/51 → Requirement «Список входящих заявок у инструктора» (student-requests) → FR-37; Scenarios «Новая заявка видна в списке с учеником и датой», «Чужие заявки не видны»
- Тип: позитивный + негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN ученик подал заявки инструкторам А и Б (обе 'new')
- WHEN А и Б открывают GET /api/instructor/requests
- THEN каждый видит только свою заявку: ученик (ФИО, стаж), дата подачи, статус 'new'; заявка соседнему инструктору не видна

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. POST requests {A}; POST requests {Б}.
2. GET /api/instructor/requests инструктором А.
3. GET /api/instructor/requests инструктором Б.

## Ожидаемый результат
2. Ровно одна заявка — к А; поля: ФИО и стаж ученика, дата, статус 'new'.
3. Ровно одна заявка — к Б; заявки к А в списке нет.
