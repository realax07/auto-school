# TC-CAL-002 — Некорректный интервал отклоняется

- ID кейса: TC-CAL-002
- ID чеклиста: CHK-25
- Источник: CHK-25 → Requirement «Выбор рабочих интервалов в календаре» (instructor-availability) → FR-29, NFR-5; Scenario «Некорректный интервал отклоняется»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN инструктор задает интервал с концом раньше начала (Пн 14:00–10:00)
- WHEN PUT /api/instructor/availability с таким интервалом
- THEN 422 {ok:false}, интервал не сохраняется (клиент получает ошибку валидации)

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. PUT availability {intervals:[{weekday:0,start_time:"14:00",end_time:"10:00"}]} → код.
2. Границы: weekday=7 → код; start_time==end_time → код; дубликат интервала дважды → код.
3. GET availability — содержимое.

## Ожидаемый результат
1. 422 {ok:false}.
2. weekday вне 0..6 → 422; start_time==end_time → 422; дубликаты схлопываются без ошибки (design.md).
3. Некорректные интервалы не появились (график прежний/пустой).
