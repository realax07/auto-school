# TC-REQ-007 — Чужую заявку отклонить нельзя (404)

- ID кейса: TC-REQ-007
- ID чеклиста: CHK-54
- Источник: CHK-54 → Requirement «Отказ с обязательным комментарием» (student-requests) → FR-38; Scenario «Чужую заявку отклонить нельзя»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN заявка адресована инструктору А ('new'); у инструктора Б своя валидная сессия
- WHEN Б выполняет POST /api/instructor/requests/{id}/deny {comment:"..."}
- THEN 404 {ok:false} (заявка не этому инструктору — существование не раскрывается), статус не меняется
- Дополнительно (разведение по design.md, D5 чеклиста): accept чужой заявки → 404; accept заявки не в статусе 'new' → 409

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Ученик подал заявку А.
2. POST deny с токеном Б → код.
3. GET /api/student/requests учеником — статус.
4. Дополнительно (чужая заявка): accept заявки А токеном Б → код.
5. Дополнительно (заявка не в 'new'): ученик подал заявку Б; Б принял её (accept, TC-REQ-008); повторный accept той же заявки Б → код.

## Ожидаемый результат
2. 404 {ok:false}.
3. Статус остался 'new'.
4. 404 {ok:false} — чужая заявка (матрица design.md: «чужой объект (авто, заявка) по id → 404», существование не раскрывается); заявка А не изменена.
5. 409 {ok:false} — конфликт состояния (design.md: accept допустим только для 'new'; 409 — конфликт состояния). Примечание: design.md для accept пишет «иначе 404/409» без разбиения условий — коды разведены по общей матрице design.md, фактический код фиксировать при исполнении (D5 чеклиста).
