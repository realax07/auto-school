# TC-CAL-001 — Выделенный интервал помечается рабочим

- ID кейса: TC-CAL-001
- ID чеклиста: CHK-24
- Источник: CHK-24 → Requirement «Выбор рабочих интервалов в календаре» (instructor-availability) → FR-29, NFR-5; Scenario «Выделенный интервал помечается рабочим»
- Тип: позитивный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN инструктор с валидной сессией находится в разделе «Календарь»
- WHEN он выделяет интервал Пн (weekday=0) 10:00–14:00 и сохраняет: PUT /api/instructor/availability {intervals:[{weekday:0,start_time:"10:00",end_time:"14:00"}]}
- THEN 200; GET /api/instructor/availability возвращает интервал как рабочий час инструктора

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. PUT /api/instructor/availability с интервалом Пн 10:00–14:00.
2. GET /api/instructor/availability.
3. UI календаря выделяет соответствующие ячейки (браузер).

## Ожидаемый результат
1. 200 {ok:true}.
2. Ровно один интервал {weekday:0, 10:00–14:00}.
3. Ячейки Пн 10:00–14:00 отмечены рабочими.
