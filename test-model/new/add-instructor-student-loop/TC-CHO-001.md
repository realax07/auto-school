# TC-CHO-001 — Каталог: карточки одобренных; waiting/deny не участвуют

- ID кейса: TC-CHO-001
- ID чеклиста: CHK-29, CHK-30
- Источник: CHK-29/30 → Requirement «Каталог одобренных инструкторов для ученика» (student-instructor-choice) → FR-31; Scenarios «Ученик видит карточки одобренных инструкторов», «Инструкторы в статусах waiting/deny не попадают в каталог»
- Тип: позитивный + негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN одобренные инструкторы А (стаж 10) и Б с заполненным профилем; заявки инструкторов В и Г в статусах waiting и deny; ученик с валидной сессией
- WHEN ученик открывает раздел «Выбор инструктора»: GET /api/student/instructors
- THEN карточки только А и Б (ФИО, стаж, автомобили, рейтинг, часы работы); В и Г отсутствуют; при отсутствии одобренных — корректное пустое состояние

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Подготовить: А, Б одобрены (users.role='instructor'); В waiting, Г deny (в users отсутствуют).
2. GET /api/student/instructors с X-Session-Token ученика.
3. Убрать одобренных (отдельная чистая БД: только waiting/deny) → GET еще раз.

## Ожидаемый результат
2. 200; список = {А, Б}; в карточках есть ФИО, стаж, автомобили (без фото/госномера), агрегат рейтинга, часы работы; В и Г не в списке.
3. 200 с пустым списком — пустое состояние, не ошибка.

Тестовые данные: см. Предусловия; учетные записи фикстур (admin-token, инструкторы, ученик).
