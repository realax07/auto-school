# TC-CAR-003 — Невалидные данные автомобиля отклоняются по полю

- ID кейса: TC-CAR-003
- ID чеклиста: CHK-15
- Источник: CHK-15 → Requirement «Добавление автомобиля инструктором» (instructor-cars) → FR-26, NFR-5; Scenario «Невалидные данные автомобиля отклоняются»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN инструктор с валидной сессией заполняет форму автомобиля
- WHEN POST /api/instructor/cars с пустой маркой (A), некорректным годом (B, вне разумного диапазона), transmission="robot" вне (manual, automatic) (C)
- THEN каждый вариант → 422 {ok:false} с ошибкой по соответствующему полю; автомобиль не создан

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. POST cars {brand:"", ...} — код, текст ошибки.
2. POST cars {year:"abcd"} — код, текст ошибки.
3. POST cars {transmission:"robot"} — код, текст ошибки.
4. GET /api/instructor/cars — число записей.

## Ожидаемый результат
1–3. Каждый POST → 422 {ok:false}, error указывает на соответствующее поле (brand/year/transmission).
4. Новых записей не появилось.
