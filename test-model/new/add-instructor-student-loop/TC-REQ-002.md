# TC-REQ-002 — Повторная активная заявка не создается (409)

- ID кейса: TC-REQ-002
- ID чеклиста: CHK-46
- Источник: CHK-46 → Requirement «Подача заявки инструктору» (student-requests) → FR-36; Scenario «Повторная активная заявка тому же инструктору не создается»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN ученик уже имеет активную заявку инструктору А (статус 'new'; повторить для 'accepted')
- WHEN POST /api/student/requests {instructor_id:A} еще раз
- THEN 409 {ok:false} без записи; дубликат не создается, ученик получает сообщение о существующей заявке

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. POST requests {A} → первая заявка.
2. POST requests {A} повторно → код.
3. SELECT count(*) FROM student_requests (ученик, А).
4. Повторить с заявкой в статусе 'accepted' (принять по TC-REQ-008), затем POST еще раз.

## Ожидаемый результат
2. 409 {ok:false}.
3. Ровно 1 запись.
4. Активная 'accepted' тоже блокирует: 409 {ok:false}, новых записей нет.
