# TC-VUD-004 — Изображение ВУ: отказ без/с неверным токеном, ученическая сессия; 404-неразличение

- ID кейса: TC-VUD-004
- ID чеклиста: CHK-6, CHK-7, CHK-8, CHK-10
- Источник: CHK-6/7/8/10 → Requirement «Выдача изображения ВУ только по админ-токену» (instructor-documents) → FR-24, NFR-1; Scenarios «Запрос изображения без токена отклоняется», «Запрос изображения с неверным токеном отклоняется», «Ученическая сессия не дает доступ к изображению ВУ» + матрица кодов design.md (404-неразличение)
- Тип: негативный + граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN существует заявка с загруженным ВУ ({id}); отдельно существуют несуществующий id и заявка без ВУ
- WHEN изображение запрашивается: A) без заголовка X-Admin-Token; B) с неверным значением X-Admin-Token; C) с валидной ученической сессией (X-Session-Token ученика); D) несуществующий {id} и {id} заявки без ВУ с валидным токеном
- THEN A/B/C: 401 {ok:false}, изображение не возвращается (проверяемые варианты: гость, неверный админ-токен, ученическая сессия; инструкторская сессия этим кейсом не проверяется — CHK-8 требует ученическую); D: 404 {ok:false} — код не раскрывает существование/отсутствие ВУ сверх контракта design.md

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Создать заявку с ВУ ({id1}) и заявку без ВУ ({id2}) — шаги TC-VUD-001/TC-VUD-002(вариант C).
   Fallback (D2 чеклиста): если по утвержденному макету поле ВУ обязательно, заявка без ВУ ({id2}) невоспроизводима — шаг 5 выполнять только для несуществующего id; проверка 404 для «заявка без ВУ» выполняется после утверждения макета (ветка D2 «поле необязательно»).
2. GET .../{id1}/license-image без заголовка — код?
3. GET .../{id1}/license-image с X-Admin-Token: wrong-token — код?
4. GET .../{id1}/license-image только с X-Session-Token ученика — код?
5. GET .../999999/license-image и GET .../{id2}/license-image с валидным токеном — коды?
6. Убедиться, что ни в одном ответе нет байтов изображения.

## Ожидаемый результат
2. 401 {ok:false}.
3. 401 {ok:false}.
4. 401 {ok:false}.
5. Оба → 404 {ok:false} (по design.md); различие «существует/не существует» не раскрывается телом ответа. Если {id2} невоспроизводим (D2 — поле ВУ обязательно) — только несуществующий id → 404.
6. Тела ошибок — JSON {ok:false}, без бинарных данных и без путей к файлу.
