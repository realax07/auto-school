# TC-REQ-013 — Перекрепление: чужой автомобиль (422) и чужой ученик (404)

- ID кейса: TC-REQ-013
- ID чеклиста: CHK-61, CHK-62
- Источник: CHK-61/62 → Requirement «Перекрепление автомобиля принятого ученика» (student-requests) → FR-28, ОВ-3; Scenarios «Перекрепление на чужой автомобиль отклоняется», «Ученик другого инструктора не перекрепляется»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN ученик принят инструктором А; автомобиль принадлежит инструктору Б; отдельный ученик принят только инструктором Б
- WHEN А выполняет PATCH students/{sid}/car {car_id: чужого авто} (A); Б выполняет PATCH students/{ученика А}/car {car_id: своего} (B)
- THEN A → 422 {ok:false} (авто не этого инструктора), привязка не изменена; B → 404 {ok:false} (ученик не принят этим инструктором — не раскрываем), привязка не изменена

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Подготовить принятые связи: ученик1↔А (авто), ученик2↔Б (авто).
2. PATCH students/{s1}/car {car_id: авто Б} токеном А → код.
3. PATCH students/{s1}/car {car_id: 999999} токеном А → код.
4. PATCH students/{s1}/car {car_id: свое авто} токеном Б → код.
5. БД: car_id обеих принятых заявок.

## Ожидаемый результат
2. 422 {ok:false}.
3. 422 {ok:false}.
4. 404 {ok:false}.
5. car_id заявок не изменились (ученик1 — авто А, ученик2 — авто Б).
