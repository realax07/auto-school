# TC-REQ-014 — Виджет «Привязанные ученики»: после принятия и пустое состояние

- ID кейса: TC-REQ-014
- ID чеклиста: CHK-63, CHK-64
- Источник: CHK-63/64 → Requirement «Виджет «Привязанные ученики»» (student-requests) → FR-40; Scenarios «После принятия ученик появляется в виджете», «До принятия и без учеников — пустое состояние»
- Тип: позитивный + граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN инструктор А; вариант без заявок; вариант с 'new' заявкой; вариант с принятой заявкой
- WHEN А открывает главную кабинета: GET /api/instructor/summary
- THEN students показывает только принятых (ФИО, авто, дата принятия); 'new' заявки в виджете не перечислены; пустой список — корректное пустое состояние

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Чистая БД: GET summary → students.
2. Заявка ученика 'new' (без accept) → GET summary.
3. А принимает (accept {car_id}) → GET summary; открыть главную в UI.

## Ожидаемый результат
1. students = [] — пустое состояние.
2. students = [] — 'new' заявка в виджете не появляется.
3. students содержит ученика (ФИО, автомобиль, дата принятия); виджет в UI отрисован (браузер).
