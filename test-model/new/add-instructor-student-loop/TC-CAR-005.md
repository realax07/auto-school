# TC-CAR-005 — Фото автомобиля не выдается другому пользователю (матрица 401/403/404)

- ID кейса: TC-CAR-005
- ID чеклиста: CHK-18
- Источник: CHK-18 → Requirement «Фото автомобиля доступно владельцу» (instructor-cars) → FR-27, NFR-1; Scenario «Фото не выдается другому пользователю» + матрица кодов design.md (MIN-2 arch-review)
- Тип: негативный + граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN автомобиль с фото принадлежит инструктору А ({car_id}); есть сессия инструктора Б, сессия ученика, гость; отдельный свой автомобиль А без фото
- WHEN GET /api/instructor/cars/{car_id}/photo: гость (A); ученик (B); инструктор Б (C); А запрашивает свой автомобиль без фото (D)
- THEN A → 401; B → 403; C → 404 (чужой — существование не раскрывается); D → 404 (без фото); фото не возвращается ни в одном случае

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. GET photo без заголовков → код?
2. GET photo с X-Session-Token ученика → код?
3. GET photo с X-Session-Token инструктора Б → код?
4. GET /api/instructor/cars/{car_id без фото}/photo с токеном А → код?
5. Проверить, что тела ответов — {ok:false} без байтов изображения.

## Ожидаемый результат
1. 401 {ok:false}.
2. 403 {ok:false}.
3. 404 {ok:false}.
4. 404 {ok:false}.
5. Бинарных данных нет ни в одном ответе.
