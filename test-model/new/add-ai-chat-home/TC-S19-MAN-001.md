# TC-S19-MAN-001 — Боевой smoke провайдера: реальный hermes chat — ответ по темам, latency ≤30 с, срез session_id на живом ответе, отказ на постороннем вопросе — ручной пункт приемки

- Автоматизация: НЕТ и не планируется в этой волне (design.md «Риски»: латency-прогон внешнего CLI не входит в unit-гейты — QA-кейс на боевой сессии, 19.4). Исполнение: вручную на стенде с hermes CLI на хосте (`hermes chat -Q --query-file - --oneshot --run-budget 25`, как собирает backend/ai/provider.py: заглавная -Q — quiet/программный режим (строчная -q с --query-file mutually exclusive — CLI падает на парсинге аргументов); бюджет hermes 25 с = _RUN_BUDGET_SECONDS; ≤30 с — собственный таймаут subprocess PROVIDER_TIMEOUT_SECONDS=30, страховка поверх бюджета; секундомер замеряет суммарно — ограничение 30 с); прогон против merge-кандидата (backend uvicorn + свежий dist).
- Приоритет: Must (FR-19.3 NFR ≤30 с; FR-19.6 — содержательное поведение тем; FR-19.3 «ответ без служебного хвоста» на живом провайдере)
- Статус: ручной — приемочный smoke (выполняет QA на боевой сессии, задача 19.4.3 acceptance); детерминированные носители 401/контракта/среза — юнит TC-S19-UNIT-001
- Трассировка:
  - Requirement: Ограничение тем ассистента (openspec/changes/add-ai-chat-home/specs/ai-chat/spec.md)
  - Scenario: Вопрос по темам ассистента (ответ по существу)
  - Scenario: Посторонний вопрос (вежливый видимый отказ без ответа по существу; свойство промпта — best effort, спека фиксирует видимое поведение)
  - Requirement: Композер отправляет сообщение и показывает ответ ассистента — Scenario: Ожидание и ошибка (NFR: бюджет hermes 25 с + таймаут адаптера 30 с, индикатор в UI)
  - Носитель: ручной прогон (протокол замеров — в Примечании)

## GIVEN / WHEN / THEN
- GIVEN бэкенд поднят на стенде, hermes CLI доступен на хосте; QA-ученик вошел в кабинет (мобилка 390 и веб 1440), «Главная» открыта
- WHEN отправлены по очереди: (1) вопрос по темам — «Можно ли парковаться на тротуаре?», (2) вопрос по дорожной ситуации в России/ГИБДД — например «Какой штраф за проезд на красный свет в 2026 году?», (3) посторонний вопрос — «Кто выиграл последний чемпионат мира по футболу?», (4) вопрос с продолжением диалога (уточнение к (1)); замеряется время ответа каждого; ответ (1) сверяется с сырым stdout провайдера
- THEN (1)–(2) ответ по существу вопроса (ПДД/ситуация/ГИБДД, опора на контент content/pdd и интернет — факты не противоречат правилам); (3) вежливый видимый отказ БЕЗ ответа по существу; (4) контекст диалога учтен (ответ связан с предыдущим обменом); каждый ответ — пузырь assistant без служебного хвоста («session_id: …», «Title: …» — сырой stdout hermes содержит хвост, в UI его нет = срез работает на живом ответе); latency каждого ответа в рамках NFR «бюджет hermes 25 с + таймаут адаптера 30 с» — секундомер замеряет суммарно, ограничение 30 с (при превышении/сбое — человеческий текст у поля, UI не висит молча — индикатор был виден в ожидании); в логах uvicorn нет секретов и служебных argv

## Примечание
- Протокол приемки фиксирует: вопрос → время (с) → наличие/отсутствие хвоста → ответ по существу (да/нет). Повтор сценария (3) на 2–3 формулировках (спорт, кулинария, код) — промпт-гард best effort, единичный «прорыв» обсуждать с ПМ/СА против формулировки FR-19.6.
- Параллельные вызовы провайдера НЕ проверяются (осознанное допущение design.md: sync-хендлер уходит в threadpool, нагрузки спринта малы; нагрузочного сценария в плане прогонов нет).
- Прогон по сети зависит от доступности интернета хоста (знания «+ интернет» по решению Заказчика) — при недоступности интернета фиксировать в протоколе, не считать дефектом реализации.
