# TC-APP-015 — Граница: порядок валидации, «первая ошибка» по контракту

- ID кейса: TC-APP-015
- ID чеклиста: CHK-15
- Источник: CHK-15 → Requirement «Сохранение заявки со статусом waiting» (домен instructor-application) → FR-11; Scenario «Отклонение некорректно заполненной анкеты» (порядок §15.1: обязательные → согласие → email-формат → телефон ≥ 10 цифр → пароль ≥ 8 → совпадение → госномер при own → валидность license_date)
- Тип: граничный
- Приоритет: Must
- Статус: automated (частично) — tests/test_instructors_apply.py::test_apply_order_consent_checked_before_email_format (согласие раньше формата email, MIN-2); остальные пары порядка — manual/toBeAutomated по той же параметризации test_apply_validation_contract_422. Плановые ID в docstring действуют до утверждения (rule 6)

## GIVEN / WHEN / THEN
- GIVEN анкета с несколькими нарушениями одновременно
- WHEN анкета отправляется
- THEN сообщается о ПЕРВОЙ ошибке по фиксированному порядку контракта §15.1: 1) обязательные поля → 1a) согласие → 2) формат email → 3) телефон ≥ 10 цифр → 4) пароль ≥ 8 → 5) совпадение подтверждения → 6) госномер при own → 7) валидность license_date

## Предусловия
- Сервис собран через create_app() с роутером instructors; TestClient без сети; чистая БД в tmp, init_db.

## Шаги
1. POST с пустым fio И битым email И consent=false → зафиксировать error (ожидание «ФИО: поле обязательно»).
2. POST с consent=false И битым email → зафиксировать error (ожидание «Согласие: поле обязательно»; автоматизировано).
3. POST с битым email И коротким телефоном → ожидание «Email: неверный формат».
4. POST с коротким телефоном И коротким паролем → ожидание «Телефон: укажите не менее 10 цифр».
5. POST с коротким паролем И несовпадающим подтверждением → ожидание «Пароль: не менее 8 символов».
6. POST с несовпадающим подтверждением И пустым plate при own → ожидание «Подтверждение пароля: пароли не совпадают».
7. POST с пустым plate при own И невалидной license_date → ожидание «Госномер: поле обязательно».
8. POST с валидным plate (own) И невалидной license_date → ожидание «Дата выдачи ВУ: неверный формат».

## Ожидаемый результат
Каждый прогон: 422 с сообщением строго о первой ошибке в списке, НЕ о более поздней; заявка не создается (COUNT = 0 после каждого прогона).

## Тестовые данные
Базовый валидный набор (TC-APP-005) с наложением нарушений по шагам 1–8.
