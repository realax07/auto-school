# TC-MOD-008 — Негатив: deny approved-заявки прямым POST → 409, users не тронут

- ID кейса: TC-MOD-008
- ID чеклиста: CHK-29
- Источник: CHK-29 → Requirement «Отклонение заявки с обязательным комментарием» (домен admin-moderation) → FR-15; Scenario «Отклонение не-waiting заявки отклоняется сервером» (guard статуса, sdd §15.4)
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_instructor_admin.py::test_deny_approved_application_409_users_untouched (approved → 409 «Заявка уже одобрена», запись users не меняется). Плановые ID в docstring действуют до утверждения (rule 6)

## GIVEN / WHEN / THEN
- GIVEN заявка в статусе approved (запись users создана); в UI кнопка «Отклонить» скрыта
- WHEN прямой POST deny с валидным админ-токеном (защита — API-гвард)
- THEN 409 «Заявка уже одобрена», статус НЕ меняется, запись users остается без изменений (рассинхрон исключен)

## Предусловия
- Сервис собран через create_app() с роутерами; TestClient без сети; чистая БД в tmp, init_db; существует approved-заявка (approve через API).

## Шаги
1. Создать заявку → id A; approve {A} с админ-токеном → 200.
2. Снять снапшот записи users по email заявки (SELECT *).
3. POST deny {A} с комментарием «попытка отклонить» и админ-токеном → зафиксировать.
4. Прочитать запись заявки A и записи users; сравнить users со снапшотом.

## Ожидаемый результат
3. 409 {"ok": false, "error": "Заявка уже одобрена"}.
4. status заявки = 'approved'; запись users побайтово равна снапшоту.

## Тестовые данные
Заявка — базовый валидный набор (TC-APP-005): instructor@example.com. Админ: admin / admin-pass-2026.
