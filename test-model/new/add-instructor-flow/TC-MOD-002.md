# TC-MOD-002 — Негатив: password_hash отсутствует в GET-списке и не рендерится UI

- ID кейса: TC-MOD-002
- ID чеклиста: CHK-23
- Источник: CHK-23 → Requirement «Раздел заявок инструкторов в админке» (домен admin-moderation) → FR-14; Scenario «Администратор видит все заявки» (решение 2026-10-12-hash-not-rendered); риск review-001-2.1 #2 — сторож-тест
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_instructor_admin.py::test_list_without_hash_key (ключ password_hash ОТСУТСТВУЕТ в каждом элементе списка, состав полей §15.2). Рендеринг UI и «ответ GET не логируется» — manual/toBeAutomated (инспекция admin-dashboard.html + контроль логов). Плановые ID в docstring действуют до утверждения (rule 6)

## GIVEN / WHEN / THEN
- GIVEN администратор с валидным токеном; в системе есть хотя бы одна заявка с password_hash
- WHEN GET /api/admin/instructor-applications
- THEN ключ password_hash ОТСУТСТВУЕТ в каждом элементе ответа; UI админки его не рендерит; ответ GET не логируется (хэш хранится в заявке, но не выдается API и не отображается)

## Предусловия
- Сервис собран через create_app() с роутерами; TestClient без сети; чистая БД в tmp, init_db; перехват логов (caplog).

## Шаги
1. Создать заявку публичным apply → 200.
2. GET /api/admin/instructor-applications с админ-токеном → 200.
3. Для каждого элемента проверить отсутствие ключа password_hash (и любого поля со значением bcrypt-хэша).
4. Инспекция frontend/admin-dashboard.html: строка/шаблон карточки заявки не содержит password_hash.
5. Пройти по логам: тело GET-ответа не залогировано.

## Ожидаемый результат
2. 200; элементы содержат данные анкеты §15.2 без password_hash.
3. Ни в одном элементе нет ключа password_hash (сторож: при расширении списка колонок тест падает — риск расхождения двух списков, review-001-2.1 #2).
4. В UI-шаблоне password_hash отсутствует.
5. Хэш отсутствует в логах; ответ GET не логируется.
