# TC-AUTH-010 — Негатив: единый учет анти-брутфорса для заявок; сброс при успехе

- ID кейса: TC-AUTH-010
- ID чеклиста: CHK-46
- Источник: CHK-46 → Requirement «Вход инструктора через общий механизм авторизации» (домен instructor-auth) → FR-13; sdd §15.5 (неудачные попытки против users и заявок учитываются единообразно, единый счетчик по IP)
- Тип: негативный
- Приоритет: Must
- Статус: automated (частично) — tests/test_auth_route.py::test_bruteforce_on_application_counts (блокировка при брутфорсе ЗАЯВКИ: waiting; единый учет по IP); сброс счетчика успешным входом — эталон users-пути test_auth.py::test_bruteforce_reset_after_success; сброс при статусном входе (pending/rejected) — toBeAutomated. До утверждения кейсов (rule 6)

## GIVEN / WHEN / THEN
- GIVEN существует заявка (waiting/deny) с email E; попытки с одного IP
- WHEN выполняются неудачные попытки входа против email ЗАЯВКИ (неверный пароль) сверх порога
- THEN блокировка срабатывает и при брутфорсе заявки (единый счетчик по IP, наравне с users): очередная попытка — 401 без проверки кредов; успешный вход по статусу (pending/rejected) сбрасывает счетчик

## Предусловия
- Сервис собран через create_app(); TestClient без сети; чистая БД; состояние анти-брутфорса чистое (auth._bf.clear()); порог _BF_MAX_FAILURES = 5 (D1: параметрически).

## Шаги
1. Создать заявку (waiting) instr@example.com / Instr1234.
2. 5 попыток login с неверным паролем WrongPass1 → каждая 401.
3. Попытка с верным паролем → 401 (IP заблокирован; для waiting-заявки даже статусный pending-маршрут недоступен).
4. Сброс-часть (toBeAutomated): на свежем состоянии — 4 неудачи (порог 5 не достигнут), затем успешный статусный вход (pending) → счетчик сброшен: следующая неудача лишь 1-я (порог не сработал досрочно).
5. Очистить auth._bf после теста.

## Ожидаемый результат
2. Пять 401.
3. 401 без проверки кредов (единый учет — брутфорс заявки блокирует IP).
4. После успешного статусного входа счетчик пуст — следующие неудачи считаются с нуля.

## Тестовые данные
instr@example.com / Instr1234, неверный WrongPass1. Контрастный IP для шага 4 — второй TestClient с подменой client host (паттерн test_auth.py::test_bruteforce_block_is_per_ip).
