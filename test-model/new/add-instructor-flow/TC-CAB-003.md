## GIVEN / WHEN / THEN
- GIVEN сервис запущен; маршруты статики смонтированы
- WHEN открываются /instructors/pending и /instructors/rejected (reason передана фронтовому слою после логина)
- THEN /instructors/pending → 200 «заявка на рассмотрении»; /instructors/rejected показывает причину из ответа логина; тон экранов соответствует макетам Заказчика (design check 6.1: тексты согласованы, служебные тексты дизайна и технические комментарии не на проде)

## Предусловия
- Сервис собран через create_app(); статические маршруты отдается (200).
- Для браузерной части: deny-заявка с комментарием C; вход выполнен (route=rejected).

## Шаги
1. GET /instructors/pending → статус; проверить текст «Заявка на рассмотрении», ссылку «На главную».
2. GET /instructors/rejected → статус; проверить структуру (заголовок «Заявка отклонена», блок причины).
3. (браузерная часть) После входа с deny-заявкой убедиться: причина C показана на /instructors/rejected.
4. Design check 6.1 (вручную): сверить тексты обоих экранов с макетами/согласованными текстами; убедиться в отсутствии служебного hint мокапа согласия («макет без реальной загрузки» — только на анкете как текст макета, решение ПМ) и HTML-комментариев о поведении на проде (review-001-4.3 #2).

## Ожидаемый результат
1. 200; «Заявка на рассмотрении», «Заявка инструктора», «СберАвтошкола», «Анкета отправлена»; href="/".
2. 200; «Заявка отклонена», «Причина отказа», href="/".
3. Причина C показана точно.
4. Служебные тексты дизайна и технические комментарии на прод-страницах отсутствуют.
