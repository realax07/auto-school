# TC-CAB-001 — Заглушка кабинета инструктора при действующей сессии

- ID кейса: TC-CAB-001
- ID чеклиста: CHK-43
- Источник: CHK-43 → Requirement «Заглушка кабинета инструктора» (домен instructor-auth) → FR-13; Scenario «Заглушка вместо кабинета»
- Тип: позитивный
- Приоритет: Must
- Статус: automated (частично) — tests/test_instructor_pages.py::test_cabinet_stub_exists_and_text (текст «Кабинет скоро», отсутствие функциональных блоков dashboard: Расписание занятий, Ближайшее занятие, Мой автомобиль, Последние операции, Быстрые действия, Заработано за месяц). Браузерный сценарий «сессия → заглушка» — manual/toBeAutomated (браузер + fetch /api/auth/me)

## GIVEN / WHEN / THEN
- GIVEN одобренный инструктор с действующей сессией (вход выполнен, token в sessionStorage)
- WHEN он открывает /instructor/cabinet-stub
- THEN показывается заглушка «кабинет скоро»; функциональные элементы кабинета (расписание, статистика, доходы) ОТСУТСТВУЮТ (dashboard-макет — следующий объем)

## Предусловия
- Браузер/Playwright; одобренный инструктор (apply + approve), вход через / выполнен (sessionStorage.session_token записан).
- Сервис запущен; /api/health → 200.

## Шаги
1. Выполнить вход одобренного инструктора (route=cabinet → фронт направляет на /instructor/cabinet-stub).
2. Зафиксировать итоговый URL и содержимое страницы.
3. Проверить отсутствие функциональных блоков dashboard-макета.
4. (wiring-контроль) В HTML: «Кабинет скоро» присутствует; forbidden-фрагменты отсутствуют; JS-гвард сессии (fetch /api/auth/me с X-Session-Token).

## Ожидаемый результат
1–2. URL /instructor/cabinet-stub; показана заглушка «Кабинет скоро», «Кабинет инструктора», брендинг «СберАвтошкола».
3. Нет блоков: расписание, ближайшее занятие, автомобиль, операции, быстрые действия, доходы.
4. Wiring подтвержден (test_cabinet_stub_exists_and_text + test_cabinet_stub_session_guard_wiring).
