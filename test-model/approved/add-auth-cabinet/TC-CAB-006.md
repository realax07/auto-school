# TC-CAB-006 — Два ученика: каждый видит собственное ФИО (не константу)

- ID кейса: TC-CAB-006
- ID чеклиста: CHK-22
- Источник: CHK-22 → Requirement «Отображение ФИО ученика» (домен cabinet) → FR-5; Scenario «ФИО берется из учетной записи, а не подставляется константой»
- Тип: позитивный
- Приоритет: Must
- Статус: manual/toBeAutomated (браузерный сценарий; данные — TC-AUTH-005, automated)

## GIVEN / WHEN / THEN
- GIVEN зарегистрированы два ученика с разными ФИО (Иванов Иван Иванович и Петрова-Водкина Анна Оттовна), оба вошли в систему (по очереди, разные контексты браузера)
- WHEN каждый открывает свой кабинет
- THEN в кабинете каждого отображается его собственное ФИО из учетной записи — не константа и не пример мокапа «Иван Иванов»/«Иван»

## Предусловия
- Браузер/Playwright (два изолированных контекста); оба ученика зарегистрированы.

## Шаги
1. Зарегистрировать ученика 1 (Иванов Иван Иванович, ivanov@example.com) и ученика 2 (Петрова-Водкина Анна Оттовна, petrova@example.com).
2. Контекст A: войти учеником 1 → открыть /cabinet → прочитать .uname и .greet b.
3. Контекст B (отдельный, изолированный sessionStorage): войти учеником 2 → открыть /cabinet → прочитать .uname и .greet b.
4. Сравнить значения с ФИО из учетных записей (данные GET /api/auth/me каждого).

## Ожидаемый результат
2. A: .uname = «Иванов Иван Иванович»; приветствие «Добро пожаловать, Иван!».
3. B: .uname = «Петрова-Водкина Анна Оттовна»; приветствие «Добро пожаловать, Анна!».
4. Строка-константа «Иван Иванов» (пример мокапа) не встречается ни в одном из кабинетов как отображаемое значение.

## Тестовые данные
- Ученик 1: Иванов Иван Иванович, ivanov@example.com / Qwerty123.
- Ученик 2: Петрова-Водкина Анна Оттовна, petrova@example.com / Qwerty123.
