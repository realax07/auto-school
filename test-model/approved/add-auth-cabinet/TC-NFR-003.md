## GIVEN / WHEN / THEN
- GIVEN выполнены неудачный и успешный вход; секреты сервиса заданы через .env
- WHEN проверяются: тела всех ответов, журналы сервиса, HTML страниц, git-статус репозитория
- THEN пароль P отсутствует в логах; токен присутствует ТОЛЬКО в теле 200-ответа login (нет в 401/422 телах, логах, HTML); секреты — только через .env, .env в .gitignore (в репозитории отсутствует)

## Предусловия
- Сервис запущен с перехватом логов (DEBUG); git-репозиторий рабочей копии доступен; базовый пользователь зарегистрирован.

## Шаги
1. Включить перехват логов (DEBUG); выполнить: POST /api/auth/login с неверным паролем → 401; POST /api/auth/login с пустым полем → 422; POST /api/auth/login с верными → 200, извлечь token.
2. Поиск подстроки token во всех записанных телах 401/422 и в полном тексте логов.
3. GET / и GET /cabinet → поиск token в HTML.
4. Поиск пароля "Qwerty123" в логах (дубль контроля TC-AUTH-011) и в теле 401.
5. git check: `git ls-files` — .env отсутствует в индексе; `grep -n "\.env" .gitignore` — строка присутствует.

## Ожидаемый результат
1. Статусы как ожидается: 401 / 422 / 200.
2. Строка token ни в одном отказном теле, ни в логах не встречается; в логах токена нет вовсе (только память процесса и sessionStorage).
3. В HTML страниц токен отсутствует.
4. Пароль "Qwerty123" не встречается ни в логах, ни в теле 401.
5. .env не закоммичен (нет в git ls-files); .gitignore содержит .env.

## Тестовые данные
Базовый пользователь TC-AUTH-001 (пароль Qwerty123); env-секреты: ADMIN_USER, ADMIN_PASSWORD_HASH, SECRET (значения — только в .env, не в коде).
