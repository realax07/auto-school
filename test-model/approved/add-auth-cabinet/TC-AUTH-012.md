# TC-AUTH-012 — Блокировка IP без проверки учетных данных, блокировка не раскрывается

- ID кейса: TC-AUTH-012
- ID чеклиста: CHK-13, CHK-16, CHK-11 (заблокированная ветка: токен не выдается), D10
- Источник: CHK-13/CHK-16 → Requirement «Ограничение попыток входа (анти-брутфорс)» (домен auth) → FR-2; Scenarios «Блокировка после превышения порога попыток», «Заблокированная попытка не раскрывает блокировку»; D10 (блокировка проверяется до валидации → ожидаем 401, не 422)
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_bruteforce_blocks_ip_without_credential_check

## GIVEN / WHEN / THEN
- GIVEN с одного IP подряд выполнено больше допустимого порога (_BF_MAX_FAILURES = 5) неудачных попыток входа
- WHEN с этого же IP поступает попытка входа с КОРРЕКТНЫМИ учетными данными существующего ученика
- THEN попытка отклонена БЕЗ проверки учетных данных: 401 {"ok": false, "error": "Неверный email или пароль"} — ответ посимвольно идентичен отказу при неверных кредах (R-BF4); блокировка нигде не названа; поле token отсутствует

## Предусловия
- Как в TC-AUTH-001.
- Изоляция состояния (замечание чеклиста о среде): учет в памяти процесса — использовать отдельный IP источника (TestClient client=(host, port)), не затрагивая IP других кейсов; рестарт не применяем.
- Значение порога параметрично: читать _BF_MAX_FAILURES из backend/auth.py, не хардкодить (D2).

## Шаги
1. POST /api/register базового пользователя → 200 (вход с него пригоден как «корректные креды»).
2. С IP 10.0.0.1 выполнить _BF_MAX_FAILURES неудачных попыток POST /api/auth/login {"email": "ghost@example.com", "password": "x"} — каждая → 401.
3. С того же IP выполнить POST /api/auth/login с корректными кредами (petrova@example.com / Qwerty123).
4. Сравнить ответ шага 3 с эталонным отказом при неверных кредах (код и текст ошибки).
5. В теле ответа проверить отсутствие поля token и упоминаний блокировки.

## Ожидаемый результат
2. Каждая попытка: 401.
3. 401 {"ok": false, "error": "Неверный email или пароль"} — несмотря на корректные креды (без проверки учетных данных).
4. Ответ идентичен эталонному отказу (тот же код, тот же текст) — блокировка не раскрыта (R-BF4).
5. Поле token отсутствует; строк «блокир», «block», «попытк» в теле нет.

## Тестовые данные
- IP нарушителя: 10.0.0.1; жертва подбора: ghost@example.com.
- Корректные креды: petrova@example.com / Qwerty123 (базовый пользователь TC-AUTH-001).
