# TC-MOD-002 — 401 при входе через модалку: единое сообщение под формой, без деталей причины

- ID кейса: TC-MOD-002
- ID чеклиста: CHK-28
- Источник: CHK-28 → Requirement «Единое сообщение об отказе входа» (домен auth) → FR-2; Scenario «Сообщение об отказе не раскрывает причину» (фронт-ветка); sdd §10.4
- Тип: негативный
- Приоритет: Must
- Статус: manual/toBeAutomated (браузерный сценарий; косвенный автоконтроль wiring — tests/test_login_modal.py::test_tc_auth_login_wiring_fragments_present: err.textContent из res.data.error; API-часть единого сообщения — TC-AUTH-003, automated)

## GIVEN / WHEN / THEN
- GIVEN открыта модалка входа m-login; учетная запись ученика существует (для ветки «неверный пароль»)
- WHEN (A) сабмит с верным email и неверным паролем; (B) сабмит с несуществующим email
- THEN сервер отвечает 401 {"ok": false, "error": "Неверный email или пароль"}; под формой выводится текст ошибки из ответа (единое сообщение, без деталей причины); пользователь остается на форме входа (модалка не закрывается, редиректа нет)

## Предусловия
- Браузер/Playwright с перехватом сети; ученик petrova@example.com зарегистрирован; попыток меньше порога анти-брутфорса (2 отказа — в пределах порога 5).

## Шаги
1. Открыть /, модалку m-login.
2. Вариант A: email petrova@example.com, пароль wrong-pass → «Войти».
3. Перехватить POST /api/auth/login; зафиксировать статус, тело и содержимое элемента ошибки (#login-error).
4. Вариант B: email ghost@example.com, любой пароль → «Войти»; зафиксировать то же.
5. Сравнить оба сообщения между собой и с телом ответа сервера.

## Ожидаемый результат
3. POST → 401 {"ok": false, "error": "Неверный email или пароль"}; #login-error = «Неверный email или пароль» (текст из ответа); пользователь остается на форме (URL «/», модалка открыта).
4. То же сообщение и то же состояние.
5. Сообщения A и B посимвольно идентичны; упоминаний причин («не найден», «неверный пароль», «блокировк») нет; токен в sessionStorage не появился.

## Тестовые данные
- Вариант A: petrova@example.com / wrong-pass.
- Вариант B: ghost@example.com / whatever.
