# TC-AUTH-004 — Пустые поля входа: 422 в формате Спринта 0, токен отсутствует

- ID кейса: TC-AUTH-004
- ID чеклиста: CHK-11
- Источник: CHK-11 → Requirement «Сессии с ограниченным сроком действия» (домен auth) → FR-1, FR-7 («токен выдается только после успешного входа», отказная ветка 422); контракт sdd.md §10.1
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_auth.py::test_login_empty_fields_422

## GIVEN / WHEN / THEN
- GIVEN сервис запущен; проверка полей выполняется до обращения к реестру сессий
- WHEN POST /api/auth/login с пустым email (1), затем с пустым паролем (2)
- THEN (1) 422 {"ok": false, "error": "Email: поле обязательно"}; (2) 422 {"ok": false, "error": "Пароль: поле обязательно"}; в обоих телах поле token отсутствует

## Предусловия
- Как в TC-AUTH-001.

## Шаги
1. POST /api/auth/login {"email": "  ", "password": "Qwerty123"} → зафиксировать ответ.
2. POST /api/auth/login {"email": "petrova@example.com", "password": ""} → зафиксировать ответ.
3. В обоих телах убедиться в отсутствии поля token.

## Ожидаемый результат
1. 422 {"ok": false, "error": "Email: поле обязательно"}.
2. 422 {"ok": false, "error": "Пароль: поле обязательно"}.
3. Ключ token нигде не встречается — токен не выдан ни в одной отказной ветке.

## Тестовые данные
- {"email": "  ", "password": "Qwerty123"}
- {"email": "petrova@example.com", "password": ""}
