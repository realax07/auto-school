# TC-MOD-005 — Негатив: deny без комментария → 422, статус остается waiting

- ID кейса: TC-MOD-005
- ID чеклиста: CHK-26
- Источник: CHK-26 → Requirement «Отклонение заявки с обязательным комментарием» (домен admin-moderation) → FR-15; Scenario «Отклонение без комментария недоступно»
- Тип: негативный
- Приоритет: Must
- Статус: automated — tests/test_instructor_admin.py::test_deny_without_comment_422 (тело None, {"comment": ""}, {"comment": "   "} → 422 «Комментарий: поле обязательно», статус waiting). UI-часть («в UI действие без комментария недоступно») — manual/toBeAutomated. Плановые ID в docstring действуют до утверждения (rule 6)

## GIVEN / WHEN / THEN
- GIVEN администратор выбрал заявку в статусе waiting; поле комментария пусто (или тело отсутствует)
- WHEN POST /api/admin/instructor-applications/{id}/deny с пустым/пробельным/отсутствующим комментарием
- THEN 422 {"ok": false, "error": "Комментарий: поле обязательно"}; действие не выполняется, статус остается waiting; в UI действие без комментария недоступно

## Предусловия
- Сервис собран через create_app() с роутерами; TestClient без сети; чистая БД в tmp, init_db; админ-токен получен; существует waiting-заявка id A.

## Шаги
1. Создать заявку публичным apply → id A.
2. POST deny {A} без тела (kwargs без json) с админ-токеном → зафиксировать.
3. POST deny {A} с телом {"comment": ""} → зафиксировать.
4. POST deny {A} с телом {"comment": "   "} (только пробелы) → зафиксировать.
5. SELECT status заявки A.
6. (браузерная часть, manual) Проверить, что кнопка «Отклонить» в UI неактивна/блокирует сабмит при пустом комментарии.

## Ожидаемый результат
2–4. Все три ответа 422 {"ok": false, "error": "Комментарий: поле обязательно"}.
5. status = 'waiting'.
6. UI не отправляет deny без комментария.

## Тестовые данные
Заявка — базовый валидный набор (TC-APP-005). Админ: admin / admin-pass-2026.
