## GIVEN / WHEN / THEN
- GIVEN реализованы backend/dashboard.py и backend/auth.py; клиентский wiring кабинета
- WHEN выполняется инспекция логирования и инспекция тел ответов 401/403
- THEN в dashboard.py/auth.py нет логирования ответа и заголовков (в т.ч. X-Session-Token); токен передается только в заголовке X-Session-Token (не в URL, не в теле запроса); тела 401/403 ({ok:false}) токен не содержат; в репозитории секретов/токенов нет

## Предусловия
- Исходники backend/dashboard.py, backend/auth.py, frontend/instructor-dashboard.html доступны; инстанция собрана.

## Шаги
1. Инспекция dashboard.py и auth.py: поиск print/logging-вызовов, выводящих ответ, заголовки или тело запроса (в т.ч. перебор headers, resp.text, json-тела).
2. Инспекция wiring: grep по frontend/instructor-dashboard.html — токен читается из sessionStorage и передается только заголовком 'X-Session-Token'; в URL-параметрах токена нет.
3. Выполнить GET /api/instructor/dashboard без токена → 401 и с токеном ученика → 403; осмотреть тела ответов.
4. Поиск по репозиторию (git tracked files) на предмет захардкоженных секретов/токенов, относящихся к кабинету.

## Ожидаемый результат
1. Ни один лог-вызов не выводит ответ, заголовки или токен.
2. Токен — только в заголовке X-Session-Token.
3. Тела 401/403 точно {"ok": false} — без токена и прочих чувствительных данных.
4. Секретов/токенов в репозитории нет.
