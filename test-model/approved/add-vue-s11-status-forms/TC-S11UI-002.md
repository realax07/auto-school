- Автоматизация: `tests/web/test_ui_playwright.py::test_s9_pilot_rejected_redirects_with_reason` (TC-S9UI-003, change add-vue-framework-pilot — прогон без правок селекторов/логики); механика записи причины — `tests/web/test_login_modal.py::test_login_route_mapping_wiring` (landing.js не затрагивается); перенос носителя источника — `tests/web/test_instructor_pages.py::test_rejected_page_exists_and_reason_wiring`
- Приоритет: Must
- Статус: автоматизирован существующими e2e (TC-S9UI-003 — дословно, NFR-27); кейс фиксирует трассировку сценария на партию, новый автотест не пишется
- Трассировка:
  - Requirement: Статусный экран отказа заявки на Vue (/instructors/rejected) (openspec/changes/add-vue-s11-status-forms/specs/Frontend/spec.md)
  - Scenario: Причина отказа — из ответа логина, контракт не меняется

## GIVEN / WHEN / THEN
- GIVEN вход выполнен с email заявки в статусе deny с комментарием C — логин отвечает route='rejected' и reason=C, модалка входа (landing.js, контракт логина не менялся) записала sessionStorage «instructor_rejected_reason» = C до редиректа; экран /instructors/rejected — вход каркаса Vue
- WHEN экран открыт (редирект после логина либо по прямой ссылке при живом sessionStorage в той же вкладке)
- THEN причина C видна в #reason-text (блок #reason-block показан) без входа и перелогина; источник причины остался ответом логина — страница НЕ запрашивает статус и причину из API; сценарий TC-S9UI-003 проходит без правок (якорь #reason-text и ключ sessionStorage дословны); тест-потребитель legacy (test_rejected_page_exists_and_reason_wiring) переведен на чтение входа `frontend/vue/instructors-rejected.html` + компонента App.vue — тексты и ключ sessionStorage дословны (прецедент 2.3 пилота)
