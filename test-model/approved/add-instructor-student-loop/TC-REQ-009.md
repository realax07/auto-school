# TC-REQ-009 — Принятие при 0 автомобилей (409) и с чужим car_id (422)

- ID кейса: TC-REQ-009
- ID чеклиста: CHK-56, CHK-57
- Источник: CHK-56/57 → Requirement «Принятие заявки с привязкой к автомобилю» (student-requests) → FR-39, ОВ-4; Scenarios «Принятие при 0 автомобилей недоступно», «Принятие с чужим автомобилем отклоняется»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN входящая заявка 'new'; инструктор А без автомобилей (A); во втором прогоне у А есть авто, но передается car_id чужого/несуществующего автомобиля (B)
- WHEN POST /api/instructor/requests/{id}/accept
- THEN A: 409 {ok:false} «заведите автомобиль» (ОВ-4), заявка остается 'new'; B: 422 {ok:false}, привязка не создается, заявка остается 'new'

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Заявка 'new' инструктору А без автомобилей → POST accept {car_id: любого авто Б} → код.
2. Создать автомобиль А; POST accept {car_id: авто инструктора Б} → код; POST accept {car_id: 999999} → код.
3. GET /api/student/requests — статусы; БД — student_requests.

## Ожидаемый результат
1. 409 {ok:false}, подсказка завести автомобиль; статус 'new'.
2. Оба → 422 {ok:false}; статус 'new', car_id NULL.
3. Связей «принят» не возникло.
