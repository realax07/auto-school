# TC-CAL-003 — Доступ к календарю без инструкторской сессии отклоняется

- ID кейса: TC-CAL-003
- ID чеклиста: CHK-26
- Источник: CHK-26 → Requirement «Выбор рабочих интервалов в календаре» (instructor-availability) → FR-29; Scenario «Доступ к календарю без инструкторской сессии отклоняется»
- Тип: негативный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN гость без сессии и пользователь с ролью 'student' с валидной сессией
- WHEN запрашивается график часов работы инструктора: GET/PUT /api/instructor/availability
- THEN гость → 401, student → 403; график не возвращается, изменения не применяются

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. GET availability без заголовков → код.
2. GET availability с X-Session-Token ученика → код.
3. PUT availability с X-Session-Token ученика → код.
4. GET availability валидным инструктором — график не изменился.

## Ожидаемый результат
1. 401 {ok:false}.
2. 403 {ok:false}.
3. 403 {ok:false}.
4. График без посторонних изменений.
