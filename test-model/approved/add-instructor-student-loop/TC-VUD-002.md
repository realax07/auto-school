# TC-VUD-002 — Анкета: файл ВУ недопустимого типа / больше лимита / без файла

- ID кейса: TC-VUD-002
- ID чеклиста: CHK-2, CHK-3, CHK-4
- Источник: CHK-2/3/4 → Requirement «Сохранение файла ВУ при подаче анкеты» (instructor-documents) → FR-23, NFR-6, ОВ-5; Scenarios «Файл недопустимого типа отклоняется», «Файл больше 5 МБ отклоняется», «Отправка без файла — по правилам макета»
- Тип: негативный + граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN анкета заполнена; вместо изображения выбран PDF (вариант A) или изображение 6 МБ (вариант B); вариант C — файл не выбран
- WHEN выполняется POST /api/instructors/apply (multipart) для каждого варианта
- THEN A: заявка НЕ создана, 422 {ok:false} — ошибка типа файла (проверка magic bytes, не только Content-Type); B: заявка НЕ создана, 422 {ok:false} — ошибка размера (> 5 МБ, ОВ-5); C: результат по правилам обязательности поля утвержденного макета (обязательно → 422 и заявки нет; необязательно → заявка создана без ссылки на файл)

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. POST /api/instructors/apply с license_photo=scan.pdf — зафиксировать код/ответ.
2. POST /api/instructors/apply с license_photo=big.jpg (6 МБ) — зафиксировать код/ответ.
3. Граница: license_photo=exact5mb.jpg (ровно 5 МБ) — зафиксировать код/ответ.
4. POST /api/instructors/apply без поля license_photo — зафиксировать поведение, сверить с утвержденным макетом анкеты (задача 3.3).

## Ожидаемый результат
1. 422 {ok:false}, заявки в БД нет.
2. 422 {ok:false}, заявки в БД нет.
3. Ровно 5 МБ — принимается (заявка создана).
4. По обязательности макета: поле обязательно → 422, заявки нет; необязательно → заявка создана, license_photo_path NULL. Фактическое поведение зафиксировать (чеклист, D2).

## Тестовые данные
Файлы: scan.pdf (минимальный валидный PDF), big.jpg (6 МБ JPEG), exact5mb.jpg (5 МБ JPEG).
