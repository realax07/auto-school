# TC-CAL-004 — График сохраняется, восстанавливается и полностью перезаписывается

- ID кейса: TC-CAL-004
- ID чеклиста: CHK-27, CHK-28
- Источник: CHK-27/28 → Requirement «Сохранение и восстановление графика» (instructor-availability) → FR-30; Scenarios «График восстанавливается после перезахода», «Изменение графика перезаписывает сохраненный»
- Тип: позитивный + граничный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN график Пн 10:00–14:00 сохранен (сущность availability)
- WHEN инструктор выходит, входит заново (новая сессия по /api/auth/login) и открывает календарь (A); затем снимает Пн, добавляет Ср 09:00–12:00 и сохраняет (B)
- THEN A: отмечены те же интервалы (Пн 10:00–14:00); B: полная замена — после перезахода отмечен только Ср 09:00–12:00

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. PUT availability Пн 10:00–14:00 (TC-CAL-001).
2. Логаут; повторный /api/auth/login инструктором; GET availability.
3. PUT availability только Ср 09:00–12:00; логаут; новый вход; GET availability.

## Ожидаемый результат
2. Ровно Пн 10:00–14:00 (восстановлен).
3. Ровно Ср 09:00–12:00; Пн 10:00–14:00 отсутствует (перезаписан, а не дополнен).
