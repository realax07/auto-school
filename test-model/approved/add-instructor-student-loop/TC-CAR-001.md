# TC-CAR-001 — Добавление автомобиля появляется в списке владельца

- ID кейса: TC-CAR-001
- ID чеклиста: CHK-13
- Источник: CHK-13 → Requirement «Добавление автомобиля инструктором» (instructor-cars) → FR-26; Scenario «Добавленный автомобиль появляется в списке владельца»
- Тип: позитивный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN одобренный инструктор А с валидной сессией находится в разделе «Мои автомобили»
- WHEN он добавляет автомобиль (марка/модель, год, госномер, тип КПП): POST /api/instructor/cars
- THEN автомобиль сохранен и отображается в GET /api/instructor/cars этого инструктора

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. POST /api/instructor/cars {brand:"Lada", model:"Vesta", plate:"А123ВС77", year:2022, transmission:"manual"} с X-Session-Token инструктора → зафиксировать {car_id}.
2. GET /api/instructor/cars с тем же токеном.
3. Проверить запись в БД: instructor_cars.instructor_id = А.

## Ожидаемый результат
1. 200 {ok:true, id:{car_id}}.
2. Список содержит автомобиль со всеми введенными полями.
3. Владелец записи — инструктор А.
