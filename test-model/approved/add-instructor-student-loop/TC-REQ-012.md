# TC-REQ-012 — Перекрепление своего автомобиля принятому ученику

- ID кейса: TC-REQ-012
- ID чеклиста: CHK-60
- Источник: CHK-60 → Requirement «Перекрепление автомобиля принятого ученика» (student-requests) → FR-28, ОВ-3 (MAJ-2 arch-review); Scenario «Перекрепление на свое авто обновляет привязку»
- Тип: позитивный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN ученик принят инструктором А; прежний автомобиль удален (car_id заявки NULL); у А есть другой автомобиль Y
- WHEN А выполняет PATCH /api/instructor/students/{id ученика}/car {car_id:Y}
- THEN 200; car_id принятой заявки обновлен на Y; ученик остается в «Моих учениках» (связь не меняется)

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Подготовить: принятая заявка, авто удален (TC-CAR-008); создать авто Y.
2. PATCH /api/instructor/students/{sid}/car {car_id:Y} токеном А.
3. GET /api/instructor/summary — students; БД: car_id заявки.

## Ожидаемый результат
2. 200 {ok:true}.
3. Ученик в списке; car_id заявки = Y.

## Тестовые данные
Тестовые данные: см. Предусловия; учетные записи фикстур (admin-token, инструкторы, ученик).
