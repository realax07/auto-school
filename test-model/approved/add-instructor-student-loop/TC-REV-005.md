# TC-REV-005 — Агрегат рейтинга: средняя оценка и число отзывов

- ID кейса: TC-REV-005
- ID чеклиста: CHK-43
- Источник: CHK-43 → Requirement «Агрегат рейтинга на карточке инструктора» (reviews) → FR-35; Scenario «Средний рейтинг и число отзывов на карточке»
- Тип: позитивный
- Приоритет: Must
- Статус: ручной (не исполнялся; автоматизация — после утверждения кейсов, контракт 6; плановые TC-ID в docstring автотестов действуют до утверждения, rule 6)

## GIVEN / WHEN / THEN
- GIVEN у инструктора А три принятых ученика, оставивших отзывы с оценками 5, 4, 4
- WHEN ученик открывает карточку: GET /api/student/instructors/{A}
- THEN агрегат рейтинга: средняя 4.3 и count 3

## Предусловия
- Сервис собран через create_app() (uvicorn, single-worker); допускается TestClient без сети (паттерн tests/conftest.py). Чистая БД (AUTOSCHOOL_DB_PATH в tmp), init_db при старте. Контроль живости: GET /api/health → 200 {"ok": true}.
- Сессии/данные фикстур: одобренные инструкторы А и Б (approved-заявка, Спринт 2; users.role='instructor'), ученик с валидной сессией (role='student'), X-Admin-Token администратора (Спринт 0). Сессии получены через /api/auth/login.
- Все запросы к API передают токены в заголовках X-Session-Token / X-Admin-Token (механика Спринтов 0–2).

## Шаги
1. Подготовить 3 учеников с принятыми заявками к А (TC-REQ-008 ×3).
2. Каждый оставляет отзыв: оценки 5, 4, 4.
3. GET /api/student/instructors/{A}.

## Ожидаемый результат
2. Все POST → 200.
3. В карточке {average: 4.3, count: 3} (допустимое округление — 4.33→4.3 по контракту UI); count = 3.

## Тестовые данные
Тестовые данные: см. Предусловия; учетные записи фикстур (admin-token, инструкторы, ученик).
Доп. ученики (сверх фикстурного) создаются механизмом Спринта 1: /api/auth/register + /api/auth/login, затем POST /api/student/requests к А и accept инструктором А (TC-REQ-008 ×3); всего 3 ученика с принятыми заявками к А.
