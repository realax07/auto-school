## GIVEN / WHEN / THEN
- GIVEN гость на /instructors (Vue-версия); в системе заведены заявки трех статусов на email E1 (approved, запись в users), E2 (waiting), E3 (deny с комментарием C), а также ученик с паролем; модалка входа — shared/LoginModal.vue с вариантом разметки лендинга инструкторов, wiring — общий композабл shared/loginWiring.js
- WHEN гость нажимает «Войти» (data-open-login), проверяется открытие модалки и семантика закрытия; затем выполняются входы по E1/E2/E3 и ученическая пара; отдельная попытка открыть /instructors/rejected напрямую (без успешного входа)
- THEN модалка открылась локально — без редиректа и без sessionStorage-флагов (BUG-055); закрытие — крестик/«Отмена»/Esc, клик по фону НЕ закрывает (BUG-056, TC-UI-052); route/reason контракт не изменен: E1 → /instructor/dashboard («Мой день»), E2 → /instructors/pending («заявка на рассмотрении», сессия не выдается), E3 → sessionStorage «instructor_rejected_reason»=C записан ДО редиректа на /instructors/rejected, где видна причина C (сессия не выдается), ученик → /cabinet; ошибка входа — текст сервера в #login-error; прямой доступ к /instructors/rejected без проверки пароля причину не раскрывает

## Примечание
- Ветки route/reason покрыты тремя слоями без правок: API-контракт (test_auth_route.py), wiring-носитель (test_login_modal.py на shared/loginWiring.js), живой браузер (TC-UI-004/005/052, TC-S9UI-003) — дублирующая автоматизация не создается (Н5, NFR-27).
- «Ученик → /cabinet» в браузере с лендинга инструкторов — ручной шаг (API-ветка test_login_student_route_student_cabinet автоматизирована).
- Модалка — ПОСЛЕДНИЙ дубль: после партии легаси-копий m-login нет (см. TC-S14-003).
