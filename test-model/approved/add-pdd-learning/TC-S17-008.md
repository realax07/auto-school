# TC-S17-008 — Производительность кабинета: разделы — отдельные lazy-чанки, первый заход каждой из 14 страниц не изменился (≤ 200 КБ gzip), каждый lazy-чанк ≤ 150 КБ gzip, гард срабатывает при распухании (R8: 3 сценария; NFR-26)

- Автоматизация: носитель гейта — `npm run check:budgets` (frontend/vue/scripts/check-budgets.mjs, amendment задачи 17.2.3; командный гейт приемки/CI, НЕ pytest): замыкание первого захода считается ТОЛЬКО по статическим импортам (`from"…`/`import"…` — семантика «static-import graph» NFR-26; динамические `import(…)` разведены), PAGES = 14 (новых html-входов НЕТ — разделы внутри /cabinet), роль 'lazy' для чанков pdd-* и Pdd* секций; правила: (а) vendor ≤ 150 КБ, (б) первый заход каждой из 14 страниц (page + static graph: shared + vendor) ≤ 200 КБ gzip, (в) чужих page-чанков в замыкании нет, (г) НОВОЕ — каждый lazy-чанк ≤ 150 КБ gzip (pdd-znaki ~61 КБ с details, pdd-pravila ~90 КБ, pdd-shtrafi ~6 КБ, билеты шардированы по билету 6–8 КБ — арифметика design «Бюджеты чанков»), (д) НОВОЕ — ни один lazy-чанк не входит в статическое замыкание ни одной из 14 страниц («кабинет не распухает»); шардинг билетов ПО БИЛЕТУ — вынужден правилом (г): `tests/web/test_pdd_sections.py::test_pdd_tickets_data_sharded_per_ticket_chunk` (import.meta.glob, чанк на билет, abm=40/cd=40); lazy-паттерн секций — `::test_pdd_signs_visited_async_component`, `::test_pdd_rules_visited_async_component`, `::test_pdd_tickets_lazy_component_and_visited`, `::test_pdd_fines_lazy_component_and_visited`; приёмка партии: `npm run build && npm run check:budgets` — green (а)–(д) (tasks 17.7.2a/17.7.4)
- Приоритет: Must
- Статус: автоматизированный командный гейт на сборке/приемке/CI + pytest-гарды паттерна (approved-кейс партии change add-pdd-learning, Спринт 17); NFR-26 (спека Frontend) остается истинным без правки — скрипт приведен к собственному тексту «static-import graph»
- Трассировка:
  - Requirement: Производительность кабинета — lazy-чанки и бюджеты (NFR-26) (openspec/changes/add-pdd-learning/specs/learning/spec.md)
  - Scenario: Первый заход кабинета не изменился
  - Scenario: Каждый lazy-чанк в бюджете
  - Scenario: Гард срабатывает при распухании

## GIVEN / WHEN / THEN
- GIVEN dist, собранный npm run build (с чанками pdd-знаков/правил/штрафов, pdd-bilety-index и pdd-bilety-<cat>-<nn> по билету, чанками секций Pdd*)
- WHEN выполняется npm run check:budgets (на приемке/CI после каждой сборки); в контрольной пробе — на искусственно распухшем чанке (ручной негатив)
- THEN первый заход КАЖДОЙ из 14 страниц ≤ 200 КБ gzip по СТАТИЧЕСКОМУ замыканию (поведение существующих страниц не изменилось — динамических импортов у них нет); ни один pdd-чанк не входит в статическое замыкание ни одной страницы (первый заход кабинета не меняется вообще); каждый lazy-чанк ≤ 150 КБ gzip, чанки билетов не объединены в один большой (JSON билета грузится при выборе — гард шардинга); при превышении (г) или попадании lazy-чанка в замыкание (д) проверка завершается ошибкой с указанием чанка и правила — пуш красный

## Примечание
- Автоматизация гейта — командная (Node-скрипт на артефактах dist), не pytest: негатив «гард срабатывает при распухании» проверяется ручной пробой (временное превышение лимита на копии dist → отличный от 0 exit с диагностикой чанка/правила); механика asserts скрипта — код-факт (правила (а)–(д) в check-budgets.mjs).
- Факт-прогон партии: build + check:budgets green (а)–(д) на ветке (tasks 17.7.2a/17.7.4); фактические размеры чанков бюджета — в логе гейта приемки; повторный прогон на HEAD при утверждении кейсов — в coverage.md (свод прогонов).
