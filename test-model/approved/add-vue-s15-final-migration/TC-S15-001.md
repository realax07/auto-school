# TC-S15-001 — Admin-контур на Vue: /admin-login — вход каркаса и контракт входа (POST → admin_token → /admin-dashboard; #err), /admin-dashboard — вход каркаса, гвард admin_token, четыре раздела одной страницей (BUG-047)

- Автоматизация: `tests/web/test_static.py` — PAGES: GET /admin-login → 200 с маркером «Админка», GET /admin-dashboard → 200 с маркером «Пользователи» (маркеры держат статические входы каркаса — прогон без правок); `tests/web/test_ui_playwright.py::test_s4_pages_tag_balance` (входы vue/admin-login.html, vue/admin-dashboard.html в параметризации — перенос носителя design-guard −2/+6, задача 5.1); `tests/web/test_ui_playwright.py::test_back_links_lead_to_role_home` (BUG-047-guard: негативный список standalone — /admin/cars и /admin/documents НЕ создаются, разделы остаются внутри одной страницы, список без правок). Отдача страниц входом каркаса (html со ссылками на ассеты префикса /vue/), отсутствие легаси-файлов, контракт входа (POST /api/admin/login → 200 {ok, token} → sessionStorage['admin_token'] → /admin-dashboard; отказ/сеть → «Неверный логин или пароль» в #err), редирект гварда без/с невалидным admin_token → /admin-login — ручные шаги кейса (behavioral e2e admin-login НЕТ: admin-сценарии входят через _seed_session admin_token — design.md «Страницы партии»)
- Приоритет: Must
- Статус: ручной (approved-кейс партии change add-vue-s15-final-migration, Спринт 15); статика/маркеры/tag-balance/негативный список BUG-047 — автотесты без правок сценариев (NFR-27)
- Трассировка:
  - Requirement: Вход администратора на Vue (/admin-login) (openspec/changes/add-vue-s15-final-migration/specs/Frontend/spec.md)
  - Scenario: Вход админа — контракт не меняется (отдача входом каркаса/отсутствие легаси-файлов — автотесты; клик-контракт входа/ошибки — ручной)
  - Requirement: Админ-панель на Vue (/admin-dashboard)
  - Scenario: Панель обслуживается каркасом Vue (маршрут/легаси-файлы/no-standalone — автотесты; гвард-редирект — ручной)

## GIVEN / WHEN / THEN
- GIVEN сборка каркаса выполнена (`npm ci && npm run build` в frontend/vue, dist существует); легаси admin-login.html, admin-dashboard.html и js/admin/* удалены; в `_PAGE_ROUTES` — «/admin-login»: «vue:admin-login.html», «/admin-dashboard»: «vue:admin-dashboard.html»; входы = дословный перенос legacy-разметки + `src/pages/admin-login/`, `src/pages/admin-dashboard/`
- WHEN гость открывает /admin-login и /admin-dashboard; затем выполняет вход с валидными (admin/admin — демо-доступ С0) и невалидными учетными данными, с отказом сети; прямой переход на /admin-dashboard без admin_token и с невалидным admin_token
- THEN обе страницы отдаются входом каркаса Vue (HTML со ссылками на `/vue/assets/<page>-*.<hash>.js`, а не legacy-HTML-монолитом); маршруты не изменились; при 200 {ok, token} токен пишется в sessionStorage['admin_token'] и выполняется переход на /admin-dashboard; при отказе/сети показывается «Неверный логин или пароль» дословно (эквивалент `#err.classList.add('show')` — реактивное состояние ошибки); без/с невалидным admin_token — редирект на /admin-login; standalone-страниц /admin/cars и /admin/documents НЕТ (носитель test_back_links_lead_to_role_home — негативный список без правок); легаси-файлы отсутствуют в исходниках

## Примечание
- Поведенческий контракт admin-login не имеет e2e-носителя (design.md: «behavioral-сценариев admin-login в e2e нет — вход через _seed_session admin_token»): клик-сценарий входа/ошибки — ручной smoke задачи 2.1 и шаг приемки (гейт 7.1). Автоматизация — статические маркеры и design-guard.
- Контракты разделов панели (users CSV, заявки, авто, документы) — TC-S15-002.
- Принцип Н5: кейс фиксирует трассировку на существующую автоматизацию и ручной остаток; новых автотестов партия не добавляет.
