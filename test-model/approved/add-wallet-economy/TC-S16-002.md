# TC-S16-002 — Бронь с ценой: снапшот цены + холд в одной транзакции, 402 при нехватке средств (брони нет), легаси без цены — без холда

- Автоматизация: `tests/api/test_s16_hold_booking.py::test_s16_hold_snapshot_and_frozen_on_create` (плановый ID TC-S16-030 — снапшот цены в брони + холд, «доступно»/«заморожено», средства инструктору не зачислены), `::test_s16_hold_insufficient_funds_402_no_booking` (TC-S16-031 — 402 {ok:false, error, need_kop, available_kop}, ни брони, ни холда, состояние кошелька не изменилось), `::test_s16_legacy_price_null_path_untouched` (TC-S16-041 — цена NULL: бронь без холда, hold_amount=0, прежние проверки/коды), `::test_s16_race_outcomes_terminal_and_complete_guard` (TC-S16-040 — терминальность исходов: повторная бронь/гонка не создают вторую бронь и второй холд, частичный UNIQUE), `tests/api/test_s16_backend.py::test_s16_ledger_hold_amount_kop_hours_floor` (TC-S16-009 — сумма холда = цена×100×часы, целые копейки), `::test_s16_instructor_price_save_validate_reset` (TC-S16-018 — цена часа: сохранение, валидация, сброс в NULL), `tests/api/test_qa_s16_money.py::test_tc_s16_m_001_money_is_integer_arithmetic_no_float_division` (NFR-33 — арифметика холда целочисленная), e2e `tests/web/test_ui_playwright.py::test_tc_ui_063_instructor_price_save_persists` (TC-UI-063 — цена через PUT /api/instructor/price с тостом-инвариантом «Существующие холды не изменились», переживает переоткрытие раздела)
- Приоритет: Must
- Статус: автоматизированный прогон на приемке/регрессе (approved-кейс партии change add-wallet-economy, Спринт 16); автоматизация существует (Н5) — кейс фиксирует трассировку, новые тесты не заводятся
- Трассировка:
  - Requirement: Запрос брони на слот — эконом-составляющая (openspec/changes/add-wallet-economy/specs/booking/spec.md, MODIFIED)
  - Scenario: Бронь с ценой создает холд и снапшот
  - Scenario: Недостаточно средств — бронь не создается
  - Scenario: Бронь у инструктора без цены — без холда (обратная совместимость)
  - Scenario: Повторная бронь того же экземпляра не дублирует холд
  - Requirement: Цена часа занятия задается инструктором (openspec/changes/add-wallet-economy/specs/instructor-management/spec.md)
  - Scenario: Инструктор выставляет цену часа
  - Scenario: Изменение цены не трогает существующие холды
  - Scenario: Некорректная цена отклоняется

## GIVEN / WHEN / THEN
- GIVEN одобренный инструктор с заданной ценой часа (целые рубли ≥ 0), ученик с пополненным кошельком, свободный будущий слот длительностью N часов
- WHEN ученик бронирует слот (POST создания брони), бронирует при доступном балансе меньше цены×N, бронирует слот инструктора без цены, повторно запрашивает тот же занятый экземпляр (в том числе параллельными запросами); инструктор меняет цену часа после создания брони
- THEN при достатке: в ОДНОЙ транзакции созданы бронь (снапшот цены, hold_amount = цена×100×N копеек) и ровно один холд журнала; «доступно» уменьшилось, «заморожено» выросло на hold_amount, инструктору средства не зачислены; при недостатке: 402 с суммами для UI (need_kop/available_kop), ни записи брони, ни холда, балансы без изменений; без цены: легаси-путь — бронь без холда (hold_amount=0), коды ответов прежние; повтор/гонка: отклонение без второй брони и второго холда; смена цены действует только на новые брони — снапшот и холд существующей не меняются

## Примечание
- Ручной остаток: проба брони с ценой через UI (честное сообщение 402 «недостаточно средств, пополните кошелек» в модале брони) — behavioral e2e брони с ценой нет; e2e-сценарии брони без цен (TC-UI-007, s5-кластер test_s5_booking_flow…409, BUG-052) прогоняются без правок как контроль легаси-пути.
- Дословная СА-трактовка Заказчика («деньги блокируются, но еще у инструктора»): блокируются на кошельке УЧЕНИКА — проверено TC-S16-030 (баланс инструктора не изменился при холде).
