# TC-S16-007 — Админ «Транзакции»: журнал всех типов/пользователей с фильтрами (только оператор), баланс компании = SUM fee, комиссии инструкторов за год, споры из раздела

- Автоматизация: `tests/api/test_s16_backend.py::test_s16_admin_transactions_filters_and_company_balance` (плановый ID TC-S16-020 — GET /api/admin/transactions: все типы (topup/hold/release/refund/payout)/роли/пользователи, свежие сверху, фильтры тип/роль/пользователь/период, company_balance_kop = SUM fee; доступ: сессия ученика не заменяет админ-токен (401)), `::test_s16_admin_disputes_resolve_release_refund` (TC-S16-022 — GET /api/admin/disputes + POST resolve: release (fee/net) или refund, комментарий обязателен (без — 422/недоступно), повторное решение 409, ровно одна журнальная транзакция), `::test_s16_admin_commission_and_yearly_commissions` (TC-S16-023 — GET /api/admin/commissions: инструктор × SUM fee за выбранный год, дефолт текущий, факт 0 и нули без релизов), `tests/api/test_qa_s16_money.py::test_tc_s16_m_002_ledger_is_append_only_no_update_or_delete` (NFR-34 — журнал только читается), e2e `tests/web/test_ui_playwright.py::test_tc_ui_062_admin_transactions_section_and_company_balance` (TC-UI-062 — слот «Платежи» заменен реальным разделом (soon() снят), #sec-transactions, журнал ровно по живому API со свежей записью сверху, «Баланс компании» 0 ₽ без релизов, таблица комиссий с фактом 0, честные пустые состояния выплат/споров; e2e admin-кластер TC-UI-006/011/013/014 без правок)
- Приоритет: Must
- Статус: автоматизированный прогон на приемке/регрессе (approved-кейс партии change add-wallet-economy, Спринт 16); автоматизация существует (Н5)
- Трассировка:
  - Requirement: Раздел «Транзакции» — весь журнал с фильтрами (openspec/changes/add-wallet-economy/specs/admin-transactions/spec.md)
  - Scenario: Оператор видит все транзакции без фильтров
  - Scenario: Фильтры сужают журнал
  - Scenario: Доступ только у оператора
  - Requirement: Баланс компании в админке
  - Scenario: Баланс компании равен сумме комиссий релизов
  - Requirement: Комиссии каждого инструктора за год
  - Scenario: Таблица за текущий год по умолчанию
  - Scenario: Селектор года переключает период
  - Requirement: Подтверждение выплат и решения по спорам в разделе — спорная очередь
  - Scenario: Оператор решает спор

## GIVEN / WHEN / THEN
- GIVEN журнал с транзакциями разных типов, ролей, пользователей и дат (в том числе release с fee и с fee=0 при комиссии 0); открытый спор по проведенному занятию с холдом; сессии ученика/инструктора и админ-токен
- WHEN оператор открывает раздел «Транзакции» (GET /api/admin/transactions) без фильтров и с фильтрами тип/роль/пользователь/период; ученик/инструктор вызывает API журнала прямой сессией; оператор решает спор (POST /api/admin/disputes/{id}/resolve: «перевести инструктору»/«вернуть ученику») с обязательным комментарием и повторно; оператор переключает год в таблице комиссий
- THEN журнал показывает все типы и всех пользователей, свежие сверху; фильтры сужают выборку (пустой результат — валидное состояние, не ошибка); доступ только по админ-токену — ученик/инструктор получают отказ, журнал не возвращается; «Баланс компании» = SUM fee по журналу release (без отдельной таблицы), релизы с комиссией 0 не увеличивают баланс; таблица комиссий за год: инструктор × SUM fee его release за выбранный год (дефолт — текущий), инструкторы без релизов — с 0; решение спора: ровно одна транзакция release (fee/net по комиссии) или refund (полный возврат), спор закрыт с решением и комментарием, повторное решение отклоняется; без комментария действие недоступно; журнал только читается (append-only, NFR-34)

## Примечание
- Ручные остатки: фильтры периода дат в UI раздела (дата-инпуты) и диалог решения спора (кнопка disabled до текста комментария — прецедент BUG-046 deny) — ручные пробы приемки; API-контракты фильтров и resolve покрыты TC-S16-020/022.
- Очередь выплат раздела — TC-S16-006 (кейс выплат); настоящий кейс — журнал/баланс компании/комиссии за год/споры.
- Баланс компании виден только оператору — гвард владельца API (TC-S16-020, 401 на ученическую сессию).
