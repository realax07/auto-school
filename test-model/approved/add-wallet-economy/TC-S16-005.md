# TC-S16-005 — Комиссия per-instructor: дефолт 10, границы 0–100 (оператор), релиз floor net/fee с фактом 0; статистика «Доходы» инструктора

- Автоматизация: `tests/api/test_s16_backend.py::test_s16_instructors_backfill_and_approve_point` (плановый ID TC-S16-006 — строка instructors создается при одобрении заявки с commission_percent=10; бэкфилл действующих инструкторов), `::test_s16_ledger_release_split_and_balances_commissions_0_10_100` (TC-S16-008 — floor-разбиение: 0→fee=0/net=gross; 10→net=floor(gross×90/100), fee=gross−net; 100→net=0/fee=gross; ровно одна release), `::test_s16_admin_commission_and_yearly_commissions` (TC-S16-023 — PUT /api/admin/instructors/{id}/commission: 0–100 целые, вне границ отклонение), `::test_s16_instructor_earnings_month_by_student` (плановый ID TC-S16-018b — GET /api/instructor/earnings: итог месяца и разбивка по ученикам = SUM net журнала; пустой месяц — нули без ошибки; второй инструктор видит только свои нули — чужая статистика недоступна), `tests/api/test_s16_hold_booking.py::test_s16_release_commission_zero_fact` (TC-S16-036 — «факт 0» учитывается на момент релиза при комиссии 0), `tests/api/test_qa_s16_money.py::test_tc_s16_m_001_money_is_integer_arithmetic_no_float_division` (NFR-33 — floor целочисленный), e2e `tests/web/test_ui_playwright.py::test_tc_ui_063_instructor_price_save_persists` (TC-UI-063 — раздел «Доходы и выплаты» только владельцу), `::test_tc_ui_062_admin_transactions_section_and_company_balance` (TC-UI-062 — таблица комиссий за год с инструктором-фактом 0)
- Приоритет: Must
- Статус: автоматизированный прогон на приемке/регрессе (approved-кейс партии change add-wallet-economy, Спринт 16); автоматизация существует (Н5)
- Трассировка:
  - Requirement: Комиссия инструктора по умолчанию 10, границы 0–100 (openspec/changes/add-wallet-economy/specs/instructor-management/spec.md)
  - Scenario: Новому инструктору назначена комиссия по умолчанию
  - Scenario: Релиз с комиссией 0 и 10 — целочисленный floor
  - Requirement: Статистика заработка инструктора
  - Scenario: Статистика месяца сходится с журналом
  - Scenario: Месяц без заработка — нули без ошибки
  - Scenario: Чужая статистика недоступна
  - Requirement: Комиссия инструктора редактируется оператором (openspec/changes/add-wallet-economy/specs/admin-transactions/spec.md)
  - Scenario: Оператор задает комиссию инструктору
  - Scenario: Некорректная комиссия отклоняется

## GIVEN / WHEN / THEN
- GIVEN инструктор, созданный одобрением заявки (точка создания строки instructors), с комиссией по умолчанию 10; проведенные занятия с release-транзакциями по нескольким ученикам; сессия оператора для PUT комиссии
- WHEN оператор задает комиссию 25 (или 0, или 100) и сохраняет; вводит вне 0–100 или нецелую; выполняется релиз холда при текущей комиссии; инструктор открывает «Доходы» (заполненный и пустой месяц); второй инструктор запрашивает экономику первого прямым вызовом API
- THEN по умолчанию строка instructors имеет commission_percent=10 (бэкфилл действующих — тоже 10); релиз: net = floor(gross×(100−комиссия)/100), fee = gross−net — при 0 fee=0/net=gross (факт 0 в журнале), при 10 — floor без дробей, при 100 net=0/fee=gross; ровно одна release с gross/fee/net целыми копейками; смена комиссии применяется только к последующим релизам — существующие журнальные записи и холды не пересчитываются; некорректная комиссия отклоняется валидацией, значение не меняется; «Доходы»: итог месяца и разбивка по ученикам = SUM net журнала за месяц, пустой месяц — корректные нули; чужая статистика недоступна (гвард владельца)

## Примечание
- Изменение комиссии НЕ пересчитывает существующие транзакции/холды — проверено инвариантом TC-S16-008 (release читает текущее значение на момент релиза; TC-S16-036 — «факт 0»).
- Ручной остаток: поле «Комиссия %» в разделе «Транзакции» админки (сохранение через UI) — ручная проба приемки; API-контракт PUT + валидация покрыты TC-S16-023.
