# TC-S16-003 — Размороз холда: refund при отклонении/отмене ДО старта, 409 «Занятие началось» после старта (МАЖ-1), timeout-defrost 72ч

- Автоматизация: `tests/api/test_s16_hold_booking.py::test_s16_hold_reject_refund_before_start` (плановый ID TC-S16-032 — reject до старта: refund в той же транзакции, что смена статуса), `::test_s16_hold_cancel_refund_and_legacy_guards` (TC-S16-033 — cancel confirmed до старта, BUG-049-механика, легаси-гварды), `::test_s16_maj1_cancel_reject_after_start_409` (TC-S16-034 — МАЖ-1: cancel/reject после старта → 409, статус и холд не изменены, refund-транзакции нет), `::test_s16_timeout_defrost_72h_refund` (TC-S16-039 — timeout-defrost: экземпляр начался ≥72ч назад, «проведена» не отмечена, спора нет → ровно одна refund; повторный свип не дублирует), `::test_s16_race_outcomes_terminal_and_complete_guard` (TC-S16-040 — терминальность: второй refund невозможен, частичный UNIQUE), `tests/api/test_s16_backend.py::test_s16_ledger_balances_hold_refund_cycle` (TC-S16-007 — балансы после размороза: заморожено обнулилось, доступно вернулось), `tests/api/test_s8_backend.py::test_s8_my_students_list_counters_and_access` ([test-adapted] Спринт 16 — отклоняемая бронь будущего экземпляра (reject ДО старта) + негативная проверка гварда 409 по прошлой брони; адаптация легитимна по МАЖ-1, семантика кейса С8 сохранена); контроль «без холда размороза нет» — легаси e2e BUG-049 (cancel confirmed брони без цены) без правок
- Приоритет: Must
- Статус: автоматизированный прогон на приемке/регрессе (approved-кейс партии change add-wallet-economy, Спринт 16); автоматизация существует (Н5), включая легитимную адаптацию s8 [test-adapted] по МАЖ-1 (reject после старта запрещен — 409)
- Трассировка:
  - Requirement: Размороз при отклонении или отмене брони до старта (openspec/changes/add-wallet-economy/specs/booking/spec.md, ADDED)
  - Scenario: Отклонение запроса возвращает средства
  - Scenario: Отмена подтвержденной брони возвращает средства
  - Scenario: Повторный размороз невозможен
  - Scenario: Отмена/отклонение после старта отклоняется
  - Scenario: Холд не висит вечно — авто-разморозка (timeout-defrost)

## GIVEN / WHEN / THEN
- GIVEN бронь с холдом (hold_amount_kop > 0); для 409-сценария — экземпляр начался (start_time ≤ NOW МСК, подстановка часов без sleep — детерминизм тестов); для defrost — подтвержденная/новая бронь с началом ≥72ч назад без отметки «проведена» и спора
- WHEN инструктор отклоняет запрос «новой» брони (POST reject с обязательным комментарием) или отменяет подтвержденную (POST cancel) ДО старта; повторные действия по уже закрытому холду; cancel/reject ПОСЛЕ старта — в том числе прямым вызовом API в обход UI; выполняется свип при чтении кошельков
- THEN до старта: статус меняется, ровно одна refund-транзакция в той же транзакции БД — заморожено уменьшилось, доступно вернулось на сумму холда; повторные действия не создают второй refund (частичный UNIQUE), балансы не искажены; после старта: 409 «Занятие началось» — статус и холд не изменились, refund-транзакции нет (деньги ждут «проведена», решения спора или timeout-defrost); defrost: свип создает ровно одну refund (заморожено обнулилось, доступно вернулось), повторный свип не дублирует

## Примечание
- МАЖ-1 — арх-ревью пакета: refund после старта невозможен; это же основание легитимной адаптации TC-S8BE-009 ([test-adapted], коммит 79e6ee7) — кейс фиксирует трассировку адаптации.
- Ручной остаток: UI-поведение cancel/reject после старта (честный 409-тост в интерфейсе инструктора) — ручная проба приемки; API-гвард покрыт TC-S16-034 (в т.ч. прямой вызов в обход UI).
