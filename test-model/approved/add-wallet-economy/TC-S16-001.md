## GIVEN / WHEN / THEN
- GIVEN зарегистрированный ученик с сессией (кошелек создается лениво, ни одной денежной операции); в исходниках зоны денег backend/wallet/**, backend/student/booking.py, backend/core/db.py
- WHEN ученик открывает «Кошелек» (GET /api/wallet), пополняет кошелек (POST /api/wallet/topup {amount_kop}, опционально X-Idempotency-Key), повторяет пополнение с тем же ключом, отправляет некорректную сумму, запрашивает кошелек другого ученика прямым вызовом API; параллельно выполняется полный pytest-набор (гварды исходников)
- THEN новый кошелек — доступно=0, заморожено=0, всего=0 без ошибки; пополнение создает запись acquiring_topups (мок, без внешних вызовов) и транзакцию topup, «доступно» растет на сумму; повтор с тем же X-Idempotency-Key возвращает результат первой операции (частичный UNIQUE idempotency_key), дубля-транзакции нет, баланс не удваивается; неположительная/нецелая (в копейках) сумма отклоняется валидацией без записей; чужой кошелек не возвращается (серверная проверка владельца); балансы всегда равны SUM по журналу (доступно = пополнения − холды − списания + возвраты; заморожено = холды − списания − возвраты), суммы — целые копейки, журнал append-only; e2e TC-UI-061: раздел открывается табом внутри кабинета, балансы и история рендерятся по свежему журналу
