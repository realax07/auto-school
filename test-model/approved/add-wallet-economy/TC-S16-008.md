- Автоматизация: `tests/test_container_contract.py::test_compose_yaml_valid_and_services_exactly_app_nginx` (TC-ADD-004 ред. 16.0 — compose валиден, services == {app, nginx}), `::test_compose_minio_absent` (негативный REMOVED-контракт: ни сервиса minio, ни volume minio-data, ни MINIO_*-интерполяций/кредов в docker-compose.yml), `::test_dockerfile_non_root_healthcheck_pinned` (образ: multi-stage .venv, non-root, пин базового образа), `::test_requirements_fully_pinned` (версии зависимостей зафиксированы), `::test_ci_docker_build_job_compose_without_dummy_env` (CI-шаг создания dummy .env с MinIO-переменными отсутствует, compose-команды без ручных переменных), контроль совместимости стек-контракта — полный набор `env -u GITHUB_EVENT_PATH pytest tests/ -q` (зеркало CI) включает контрактный файл без правок; пин nginx `nginx:1.29-trixie@sha256:1881…7ea` (docker-compose.yml) и публикация только 80/443 (app 8390 не публикуется) — факт HEAD, читается контрактными проверками compose
- Приоритет: Must
- Статус: автоматизированный (статические контрактные проверки) + ручной Docker-стенд на приемке/гейте (approved-кейс партии change add-wallet-economy, Спринт 16; дословное решение Заказчика «Закрой minio», BACKLOG п.4 — перевернут PR#134)

  - Scenario: В стеке ровно два сервиса и нет MinIO

## GIVEN / WHEN / THEN
- GIVEN docker-compose.yml, Dockerfile и CI-workflow репозитория на HEAD ветки (после 16.0)
- WHEN перечисляются сервисы и volumes compose (`docker compose config`), выполняется `docker compose down` и `docker compose up` после создания пользователя и загрузки файла, инспектируются образ/контекст сборки и публикуемые порты хоста, выполняются compose-команды CI; сборка образа повторяется без изменения зафиксированных входов
- THEN services = {app, nginx} ровно — сервиса minio и тома minio-data нет, MINIO_*-интерполяций нет, compose валиден; данные БД и загрузок переживают пересоздание контейнеров (named volumes db/uploads); секреты (админ-креды, TLS-ключи) приходят только через env_file/монтирования — в слоях образа и контексте сборки их нет; наружу публикуются только 80/443 nginx, порт app не публикуется; CI выполняет compose-команды без dummy .env с MinIO-переменными; nginx пинится tag+digest (MinIO-пин утрачен вместе с сервисом), базовый образ и requirements зафиксированы — повторная сборка детерминирована; сборка на чистой машине проходит без ручных шагов, процесс не от root, builder-артефакты не попадают в финальный образ

## Примечание
- Ручные Docker-шаги (гейт партии/задача 16.0): `docker compose build app` + подъем стека + down/up-персистентность (named volumes), инспекция `docker history`/`inspect` на секреты и builder-артефакты, проверка публикуемых портов — стенд с Docker, вне static-контракта; ADR-006 — только статусная приписка (история Спринта 6 не переписывается), решение по хранилищу отложено (BACKLOG п.4: SeaWeedFS/Garage/облачный S3 — будущий объем).
- История вопроса: контур MinIO был отключен профилем (Спринт 6, вендор удалил образы) — REMOVED-дельта закрывает требование дословно, прежний позитивный тест ${MINIO_*:?}-интерполяции заменен негативным test_compose_minio_absent.
