## GIVEN / WHEN / THEN
- GIVEN подтвержденная бронь с холдом; часы подставляются без sleep (детерминизм): экземпляр начался для complete; с отметки «проведено» прошло меньше/больше 24ч для окна релиза; спор с обязательным комментарием ученика
- WHEN инструктор отмечает проведенной (POST complete) начавшееся занятие (и пытается отметить будущее/не подтвержденное); выполняется свип авто-релиза до и после окна 24ч; ученик оспаривает в окне (вне окна; повторно при открытом; по бесплатной брони без холда — 422); оператор решает спор release/refund (с обязательным комментарием, повтор — отклонение)
- THEN complete: статус «проведена» с временем отметки, холд остается замороженным; будущее/не confirmed — отклонение без смены статуса; свип: до окна релиза нет (холд заморожен), после окна без спора — ровно одна release-транзакция (gross = сумма холда, fee по комиссии на момент релиза, net = floor(gross×(100−комиссия)/100)), заморожено по брони обнулилось, инструктору +net; открытый спор блокирует авто-релиз — холд закрывается только решением оператора (release или refund — ровно одна транзакция, спор закрыт, повторное решение 409); спор по брони без холда — 422; «проведена» не занимает будущие экземпляры серии (индекс активных — прежний), существующие контракты бронирования без цен не изменились

## Примечание
- Ручные остатки: кнопка «Проведено» в UI инструктора и форма спора в UI ученика — behavioral e2e-сценариев нет (ручные пробы приемки; API-контракты покрыты TC-S16-035/037/038); «проведенная бронь не занимает будущие экземпляры» — проба повторного бронирования следующего экземпляра серии на приемке (индекс активных статически прежний — контроль чтением схемы + зеленые s5/s10-наборы бронирования).
- Контроль «Существующие бронирования работают как прежде» — зеленые прогонy test_s5_backend/test_s10-кластеров без правок (NFR-27), включены в полный набор.
