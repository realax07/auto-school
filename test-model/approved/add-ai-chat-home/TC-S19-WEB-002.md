## GIVEN / WHEN / THEN
- GIVEN ученик вошел в кабинет, «Главная» открыта; провайдер заменен на QA-fake через set_provider (ответ фиксированный, детерминированный, без служебного хвоста); история учетки пуста
- WHEN в композер введен вопрос «Как проехать круг?» и нажата кнопка отправки (#ai-send); на время ответа наблюдается состояние ожидания; после получения ответа страница перезагружается
- THEN пузырь user с текстом вопроса появляется СРАЗУ (оптимистично), приветствие скрывается (ai-has-msgs); во время ожидания виден индикатор #ai-typing (aria-label «Ассистент печатает»), поле #ai-input и кнопка отправки disabled — UI не «висит» молча; ответ — пузырь .ai-msg-bot/.ai-bubble с текстом fake-провайдера ДОСЛОВНО, без «session_id: …»/«Title: …» (срез хвоста — юнит TC-S19-012); после перезагрузки страницы переписка восстановлена с сервера (GET /api/ai/chat/history, порядок user→assistant) вместо приветствия — один и тот же серверный журнал в обеих версиях представления

## Примечание
- На стороне сервера обмен сохраняется как пара user+assistant в ai_messages (контроль — юнит TC-S19-002); контекст провайдера — история учетки в окне 14 дней + новое сообщение (routes.py _recent_messages).
- Оптимистичный пузырь при ошибке убирается, текст возвращается в поле (ветка else в aiSend) — это отдельный кейс TC-S19-WEB-005.
- E2E-детерминизм через set_provider — осознанное решение против нестабильного CLI (design.md «Риски»: latency/доступность внешнего процесса); содержательное качество ответов боевого hermes — только TC-S19-MAN-001.
