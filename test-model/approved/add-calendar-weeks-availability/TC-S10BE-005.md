# TC-S10BE-005 — POST bookings с датой: бронь фиксируется на экземпляре; дата вне weekday серии → 422

- Автотест: `tests/test_s10_backend.py::test_s10_booking_exact_instance_date`
- Приоритет: Must (FR-96, D4)
- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-calendar-weeks-availability (Спринт 10, backend)
- Трассировка:
  - Requirement: Запрос брони на слот
  - Scenario: Бронь фиксируется на конкретной дате экземпляра

## GIVEN / WHEN / THEN
- GIVEN фиктивный NOW (сегодня 08:00 МСК, monkeypatch backend.booking.now_moscow); инструктор с recurring-серией «Чт 16:00–18:00»; принятая пара с учеником; id слота получен легаси-выдачей GET slots
- WHEN POST /api/student/bookings {availability_id, date = четверг следующей недели}; затем POST с датой, не попадающей на weekday серии (пятница); затем второй ученик той же пары бронирует экземпляр серии через неделю (+7 дней)
- THEN первая бронь создана (200) ровно на запрошенную дату: lesson_date = date и в ответе, и в БД (единственная запись по availability_id, status 'new'); дата вне weekday серии → 422 {ok:false}, записи в БД нет; другой экземпляр той же серии бронируется другим учеником на свою дату (200) — серия не блокируется целиком

## Примечание
- Партия change add-calendar-weeks-availability (Спринт 10, волна D-1 backend); кейсы живут трассировкой TC-ID в docstring автотеста (rule 6).
- Полный прогон: 365 passed — факт ПМ; контрольный живой прогон сессии (2026-11-05): tests/test_s10_backend.py — 19 passed.
