- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-calendar-weeks-availability (Спринт 10, backend)
- Трассировка:
  - Requirement: Сохранение и восстановление графика
  - Scenario: PUT, убирающий экземпляр с активной бронью, отклоняется с 409 (MAJ-1, уровень экземпляров)

## GIVEN / WHEN / THEN
- GIVEN фиктивный NOW; инструктор 1 с one_off «Чт 16:00–18:00» на дату next_weekday(3) (PUT 200); ученик пары с активной бронью 'new' на этот one_off (200)
- WHEN PUT, убирающий one_off (payload = один recurring Пн 09:00–10:00); после reject брони инструктором — тот же PUT; для инструктора 2 с серией «Чт 16:00–18:00» и бронью ученика на d1: PUT без серии; PUT с серией + Пн (серия сохранена); PUT после прямого UPDATE lesson_date брони на прошедшую «2026-01-08»
- THEN первый PUT → 409: conflicts[0] содержит date = дату one_off, weekday 3, booking_statuses ['new'], error содержит «16:00» и «18:00»; график не изменен (1 строка); после reject → 200 (только отклоненные брони замене не мешают); убрание серии с активной бронью на экземпляр → 409 с датой экземпляра в конфликте, сохранение серии в payload → 200 (экземпляр покрыт); прошедший экземпляр не блокирует → 200, запись брони осталась без изменений как история («2026-01-08», 'new')
