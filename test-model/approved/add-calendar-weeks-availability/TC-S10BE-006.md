# TC-S10BE-006 — Граница будущего (MIN-1): начало ровно NOW → 422, NOW+1мин → 200, прошедший → 422

- Автотест: `tests/test_s10_backend.py::test_s10_booking_future_boundary_min1`
- Приоритет: Must (FR-96, NFR-31, MIN-1)
- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-calendar-weeks-availability (Спринт 10, backend)
- Трассировка:
  - Requirement: Запрос брони на слот
  - Scenario: Запрос брони на прошедший или начавшийся слот отклоняется сервером

## GIVEN / WHEN / THEN
- GIVEN инструктор с recurring-серией «Чт 16:00–18:00», принятая пара, id слота; NOW подменяется через monkeypatch backend.booking.now_moscow (без time.sleep); прямой вызов API в обход UI
- WHEN POST {availability_id, date = четверг следующей недели} при NOW = 16:00 МСК того же четверга (начало РОВНО NOW); затем при NOW = 15:59 (начало NOW+1мин); затем при NOW «сегодня 17:00» на дату четверга неделю назад (начало уже прошло)
- THEN начало ровно NOW → 422 «Слот уже начался или прошел» (строгое «>»), в БД 0 броней; начало NOW+1мин → 200, бронь создана; прошедший экземпляр → 422 — сервер отклоняет независимо от клиента

## Примечание
- Партия change add-calendar-weeks-availability (Спринт 10, волна D-1 backend); кейсы живут трассировкой TC-ID в docstring автотеста (rule 6).
- Полный прогон: 365 passed — факт ПМ; контрольный живой прогон сессии (2026-11-05): tests/test_s10_backend.py — 19 passed.
