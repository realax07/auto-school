# TC-S10BE-015 — Запрет прошлого (новый формат, D6/MIN-1): 422 на изменение прошедшего, immutable-история, граница NOW

- Автотест: `tests/test_s10_backend.py::test_s10_availability_past_ban_new_format`
- Приоритет: Must (FR-93, NFR-31, D6, MIN-1)
- Статус: автоматизирован (rule 6 — TC-ID в docstring теста); кейс партии change add-calendar-weeks-availability (Спринт 10, backend)
- Трассировка:
  - Requirement: Запрет правки прошлого
  - Scenario: Сервер отклоняет сохранение, меняющее прошедший экземпляр, в обход UI
  - Requirement: Сохранение и восстановление графика
  - Scenario: Попытка изменения прошедшего слота отклоняется сервером

## GIVEN / WHEN / THEN
- GIVEN фиктивный NOW; инструктор; в БД прямым INSERT создана прошедшая one_off «вчера 10:00–12:00» (base_key — ее полный ключ нового формата); прямой вызов API в обход UI
- WHEN PUT нового формата: (б) без прошедшей one_off в payload; с измененным временем прошедшей (end 13:00); (а) с созданием второй one_off на прошедшую дату; затем прошедшая one_off возвращена БЕЗ изменений (+ recurring Пн); затем «завтрашний» one_off, прошедший по времени к моменту сохранения (NOW переведен на послезавтра 10:00), убран из payload; затем PUT при NOW = сегодня 16:00 с прошедшей one_off без изменений + one_off «сегодня 16:00–18:00»
- THEN первые три PUT → 422 «Прошедшие слоты не подлежат изменению», график не изменен (1 строка); прошедшая one_off, возвращенная без изменений, → 200 и строка цела в БД (клиентский контракт: прошедшие one_off возвращаются в payload); слот, прошедший по времени В МОМЕНТ сохранения и убранный из payload, → 422 (immutable-история); граница MIN-1: начало РОВНО NOW правится — PUT → 200
