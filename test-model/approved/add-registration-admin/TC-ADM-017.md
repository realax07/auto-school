# TC-ADM-017 — Токен выдается только после успешного входа

- ID кейса: TC-ADM-017
- ID чеклиста: CHK-35
- Источник: CHK-35 → Requirement «Токен доступа к админ-API» (домен admin) → FR-8; инвариант «токен MUST выдаваться только после успешного входа»
- Тип: негативный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.

## Шаги
1. Выполнить неудачные входы (по одному из TC-ADM-002…004): неверный пароль, неверный логин, пустые учетные данные.
2. В каждом ответе проверить отсутствие ключа token.
3. До любого успешного входа выполнить GET /api/admin/users с произвольной строкой в X-Admin-Token — зафиксировать ответ.
4. Контроль: выполнить успешный вход → token; GET /api/admin/users с выданным токеном.

## Ожидаемый результат
1–2. Все неудачные входы: 401 {"ok": false}; ни один ответ не содержит token.
3. 401 — ни один «токен», не выданный после успешного входа, не работает.
4. 200 — выданный после успешного входа токен работает.

## Тестовые данные
- Неудачные прогоны: {ADMIN_USER, "WrongPass1"}, {"root", верный}, {"", ""}.
