# TC-ADM-009 — CSV-санитизация: опасные префиксы = + - @ получают «'»

- ID кейса: TC-ADM-009
- ID чеклиста: CHK-27
- Источник: CHK-27 → Requirement «Выгрузка CSV» (домен admin) → FR-7; Scenario «Санитизация опасных значений в CSV»
- Тип: граничный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.

## Шаги
1. Зарегистрировать четырех пользователей (по одному на класс префикса; email/телефон валидные):
   A: surname = "=1+1" (ФИО начинается с «=»);
   B: phone = "+7 (999) 000-11-22" (телефон начинается с «+»);
   C: surname = "-Тестов" (ФИО начинается с «-»);
   D: surname = "@dmin" (ФИО начинается с «@»).
2. Войти администратором → токен.
3. GET /api/admin/users/export.csv с X-Admin-Token; декодировать utf-8-sig.
4. Для каждого пользователя найти его строку и проверить первый символ ячеек ФИО/Email/Телефон.
5. Контроль (ручной): открыть файл в Excel/LibreOffice — убедиться, что значение отображается как текст.

## Ожидаемый результат
4. Каждая ячейка пользовательского поля с опасным префиксом начинается с «'»: A → `'=1+1 Анна Оттовна…` (фактически вся fio-ячейка начинается с `'`); B → `'+7 (999) 000-11-22`; C → `'-Тестов …`; D → `'@dmin …`. Формула (=1+1) как формула не записана.
5. При открытии в Excel/LibreOffice ячейки отображаются как текст; формула не исполняется.

## Тестовые данные
- A: surname `=1+1`, email `a1@example.com`; B: phone `+7 (999) 000-11-22`, email `b1@example.com`; C: surname `-Тестов`, email `c1@example.com`; D: surname `@dmin`, email `d1@example.com`.
- Остальные поля каждого пользователя — валидные из базового набора.

## Примечания (дефекты спеки)
- D3 (недостижимый GIVEN): пример спеки «email вида =1+1» не проходит валидацию FR-2 — GIVEN невоспроизводим для email. Проверка выполнена на ФИО и телефоне (санитизируемые пользовательские поля по sdd 3.4: ФИО, email, телефон); для email нужен согласованный с валидацией пример.
- D4 (противоречие спеки): телефон «+7…» по FR-7 всегда получает префикс `'` — в этом кейсе контрактное ожидание `'+7 (999) 000-11-22` (читаемость номера в Excel деградирует; решение об исключении телефона из санитизации — за ПМ).
- Фактическое поведение фиксируем по design/sdd (решение ПМ 2026-10-08): санитизация ячеек пользовательских полей с префиксами = + - @ в export-функции.
