# TC-ADM-010 — CSV-санитизация не искажает безопасные значения

- ID кейса: TC-ADM-010
- ID чеклиста: CHK-28
- Источник: CHK-28 → Requirement «Выгрузка CSV» (домен admin) → FR-7; граница Scenario «Санитизация опасных значений в CSV»
- Тип: граничный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.

## Шаги
1. Зарегистрировать пользователя с «безопасными» значениями: surname "Петров", name "Анна", patronymic "Ивановна", email "petrov@example.com", phone "8 (999) 123-45-67" (начинается с «8», без «+»).
2. Войти администратором → токен.
3. GET /api/admin/users/export.csv; декодировать utf-8-sig.
4. Найти строку пользователя; проверить первые символы ячеек ФИО/Email/Телефон.

## Ожидаемый результат
4. Ни одна из ячеек не начинается с «'»; значения в CSV в точности равны введенным («Петров Анна Ивановна», «petrov@example.com», «8 (999) 123-45-67») — санитизация не искажает обычные данные.

## Тестовые данные
- surname `Петров`, name `Анна`, patronymic `Ивановна`, email `petrov@example.com`, phone `8 (999) 123-45-67`, пароль `Parol9999`.

## Примечания (дефекты спеки)
- D4: телефон, начинающийся с «+» (типичный формат из FR-1), санитизируется по контракту — в этом кейсе намеренно взят номер без «+», чтобы проверить отсутствие искажения именно безопасных значений.
