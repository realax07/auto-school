# TC-ADM-007 — Тай-брейк при совпадении created_at: выше запись с бо́льшим id

- ID кейса: TC-ADM-007
- ID чеклиста: CHK-25
- Источник: CHK-25 → Requirement «Список зарегистрированных пользователей» (домен admin) → FR-6; Scenario «Свежие записи сверху» (ветка «в одну и ту же секунду»)
- Тип: граничный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.

## Шаги
1. Зарегистрировать U1 (email "t1@example.com") и немедленно U2 (email "t2@example.com") — два запроса подряд без паузы.
2. Прямой SELECT created_at, id FROM users — убедиться, что created_at обеих записей совпали (одна секунда; если различаются — перезапустить шаг 1).
3. Войти администратором, GET /api/admin/users с токеном — зафиксировать порядок.
4. Повторить GET /api/admin/users — сверить порядок с шагом 3.

## Ожидаемый результат
2. created_at обеих записей одинаковы (одно и то же значение секунды).
3. Выше в списке запись с бо́льшим id (U2); порядок: t2@example.com, затем t1@example.com.
4. Повторный запрос дает тот же порядок — порядок детерминирован (тай-брейк id DESC).

## Тестовые данные
- U1: email `t1@example.com`; U2: email `t2@example.com`; остальные поля — из базового набора.
