# TC-NFR-003 — Секреты в .env; .env в .gitignore; .env.example в репозитории

- ID кейса: TC-NFR-003
- ID чеклиста: CHK-38
- Источник: CHK-38 → requirements.md NFR-3 (сквозное); контроль по design/sdd: .env в .gitignore, .env.example, отсутствие секрета в отслеживаемых файлах
- Тип: НФТ
- Приоритет: Must

## Предусловия
- Репозиторий проекта доступен; .env существует локально и содержит ADMIN_USER, ADMIN_PASSWORD_HASH, SECRET.
- Git используется ТОЛЬКО на чтение (git check-ignore / git grep); коммиты и изменения индекса запрещены.

## Шаги
1. Выполнить git check-ignore .env — зафиксировать вывод.
2. Проверить наличие .env.example в корне репозитория; убедиться, что описаны ADMIN_USER, ADMIN_PASSWORD_HASH, SECRET (и инструкция генерации bcrypt-хэша).
3. Выполнить git grep -n "ADMIN_PASSWORD_HASH" — зафиксировать файлы вхождений.
4. Взять фактическое значение ADMIN_PASSWORD_HASH из .env и выполнить поиск этого значения по отслеживаемым файлам (git grep -F "<значение>").

## Ожидаемый результат
1. .env выводится как игнорируемый (git check-ignore возвращает путь) — секреты не попадают в репозиторий.
2. .env.example присутствует и описывает все три переменные + инструкцию генерации bcrypt-хэша.
3. Вхождения ADMIN_PASSWORD_HASH — только в .env.example и документации (design/sdd); в исполняемом коде значения хэша нет.
4. Фактическое значение ADMIN_PASSWORD_HASH не встречается ни в одном отслеживаемом файле (0 вхождений).
