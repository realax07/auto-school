# TC-REG-007 — Границы email-формата

- ID кейса: TC-REG-007
- ID чеклиста: CHK-7
- Источник: CHK-7 → Requirement «Отклонение некорректной регистрации» (домен registration) → FR-2; Scenario «Неверный формат email»
- Тип: граничный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.

## Шаги
1. POST /api/register: email = "@example.com" (пустая локальная часть), остальные поля валидны.
2. POST /api/register: email = "ivanov@" (пустой домен), остальные поля валидны.
3. POST /api/register: email = "ivanov example@mail.com" (пробел), остальные поля валидны.
4. После каждого прогона SELECT COUNT(*) FROM users;

## Ожидаемый результат
1–3. Каждый вариант: 422 {"ok": false, "error": "Email: …"} с причиной о неверном формате email.
4. После каждого прогона COUNT(*) = 0.

## Тестовые данные
- Вариант A: `@example.com`; Вариант B: `ivanov@`; Вариант C: `ivanov example@mail.com`.
- Остальные поля каждого запроса — из базового набора.

## Примечания (дефекты спеки)
- D1: правило формата по sdd 3.1 — «@» и точка в домене. B (`ivanov@`) не содержит точку в домене; A — пустая локальная часть; C содержит пробел. Все три отклоняются фактической валидацией.
