# TC-ADM-016 — Запрос с истекшим токеном

- ID кейса: TC-ADM-016
- ID чеклиста: CHK-34
- Источник: CHK-34 → Requirement «Токен доступа к админ-API» (домен admin) → FR-8; Scenario «Запрос с неверным токеном» (ветка «истек срок действия»)
- Тип: граничный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.
- Доступ к in-memory реестру токенов admin-модуля из теста (фикстура/импорт; время на уровне API не инъецируется).

## Шаги
1. POST /api/admin/login с корректными учетными данными → token T.
2. Убедиться, что с T доступ работает: GET /api/admin/users → 200.
3. В тестовом окружении изменить запись реестра: tokens[T] = (now - 1 секунда) — имитация истечения TTL.
4. GET /api/admin/users с X-Admin-Token: T.
5. Зафиксировать статус и тело.

## Ожидаемый результат
2. 200 — до истечения токен валиден.
4–5. 401 {"ok": false}; данных нет — истекший токен отклоняется.

## Тестовые данные
- T: валидный токен из шага входа; смещение реестра: expires = now − 1s.

## Примечания (дефекты спеки)
- D6 (нетестируемо в лоб, эскалация): TTL (12 ч) определен только в design.md/sdd — в спеке FR-8 его нет; реестр in-memory, время не инъецируется. Проверка выполняется через прямой доступ к реестру в тесте; альтернативы без вмешательства в код нет. Требуется фиксация TTL в дельте либо тестового механизма управления временем.
