# TC-REG-004 — Каждое из 7 обязательных полей, оставленное пустым, отклоняется

- ID кейса: TC-REG-004
- ID чеклиста: CHK-4
- Источник: CHK-4 → Requirement «Отклонение некорректной регистрации» (домен registration) → FR-2; Scenario «Незаполненное обязательное поле»
- Тип: негативный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.

## Шаги
1. Выполнить 7 прогонов POST /api/register: в каждом один набор полей = "" (пустая строка), остальные — валидные (см. «Тестовые данные»).
2. После каждого прогона зафиксировать статус, тело ответа и выполнить SELECT COUNT(*) FROM users;

## Ожидаемый результат
1. Каждый из 7 прогонов: 422 {"ok": false, "error": "<Поле-ру>: <причина>"}; имя конкретного незаполненного поля присутствует в error («Фамилия: …», «Имя: …», «Отчество: …», «Email: …», «Телефон: …», «Пароль: …», «Подтверждение пароля: …»).
2. После каждого прогона COUNT(*) = 0 — ни в одном прогоне запись не создана.

## Тестовые данные
Базовый валидный пользователь (все 7 полей):
```json
{
  "surname": "Петрова-Водкина",
  "name": "Анна",
  "patronymic": "Оттовна",
  "email": "petrova@example.com",
  "phone": "+7 (912) 345-67-89",
  "password": "Qwerty123",
  "password_confirm": "Qwerty123"
}
```

Матрица прогонов (поле = "", остальные из базового набора):

| Прогон | Пустое поле | Ожидаемое начало error |
|---|---|---|
| 1 | surname | «Фамилия: …» |
| 2 | name | «Имя: …» |
| 3 | patronymic | «Отчество: …» |
| 4 | email | «Email: …» |
| 5 | phone | «Телефон: …» |
| 6 | password | «Пароль: …» |
| 7 | password_confirm | «Подтверждение пароля: …» |
