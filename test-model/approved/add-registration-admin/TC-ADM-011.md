# TC-ADM-011 — Дата регистрации в CSV — локальный календарный день (DD.MM.YYYY)

- ID кейса: TC-ADM-011
- ID чеклиста: CHK-29
- Источник: CHK-29 → Requirement «Выгрузка CSV» (домен admin) → FR-7; Scenario «Дата регистрации в CSV в локальном времени»
- Тип: граничный
- Приоритет: Must

## Предусловия
- Сервис запущен (uvicorn, single-worker); базовый URL: http://127.0.0.1:8000.
- БД data/app.db инициализирована (init_db при старте), таблица users пуста (чистое тестовое окружение).
- Окружение .env задано: ADMIN_USER, ADMIN_PASSWORD_HASH (bcrypt), SECRET.
- Контроль живости: GET /api/health -> 200 {"ok": true}.
- Сервис запущен с локальной зоной, у которой момент регистрации попадает на разные календарные дни UTC и локали (пример: TZ=Europe/Moscow, регистрация в 21:30 UTC = 00:30 локального следующего дня).

## Шаги
1. В выбранном окне (UTC-время такое, что локальная дата != UTC-дата) зарегистрировать пользователя (email "tz@example.com").
2. Прямой SELECT created_at — зафиксировать UTC-метку (формат «YYYY-MM-DD HH:MM:SS», UTC).
3. Вычислить локальную календарную дату регистрации (пересчет UTC → локальная зона).
4. Войти администратором → токен; GET /api/admin/users/export.csv; декодировать utf-8-sig.
5. Прочитать ячейку «Дата регистрации» строки пользователя.

## Ожидаемый результат
2. created_at хранится в UTC; его календарный день отличается от локального дня регистрации (GIVEN).
5. В колонке «Дата регистрации» указан ЛОКАЛЬНЫЙ календарный день в формате DD.MM.YYYY (пример: регистрация 00:30 МСК 09.10 → в CSV «09.10.2026», а не день UTC «08.10.2026»).

## Тестовые данные
- Регистрация в окне разных дней: UTC 21:30 при TZ=Europe/Moscow (локально 00:30 следующего дня).
