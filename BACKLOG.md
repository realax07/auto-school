# BACKLOG.md — Auto School

> Все пожелания к реализации попадают сюда. Разработка по пожеланию ведется
> НЕ сразу: из бэклога набираем фичи и формируем спринт после окончания
> предыдущего (решение Заказчика 2026-10-06).

## Как это работает

1. **Пожелание** (от Заказчика, из диалога, из ретро) → запись в «Идеи».
2. **Проработка:** формулировка уточняется до фичи (что, зачем, критерий готовности).
3. **Приоритет:** Заказчик управляет приоритетами (Must/Should/Could).
4. **Спринт:** при закрытии предыдущего спринта фичи из бэклога набираются
   в новый спринт → переносятся в PLAN.md → разработка.

## Статусы

| Статус | Значение |
|---|---|
| 💡 идея | сырая формулировка, без проработки |
| 🔍 проработка | уточняются детали, критерий готовности |
| 🎯 кандидат | готова к включению в спринт |
| 📦 в спринте | перенесена в PLAN.md, разрабатывается |
| ✅ готова | реализована и принята |
| 🗄 отложена | сознательно не берем (причина в записи) |
