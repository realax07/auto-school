# ADR-008: Миграция фронта на Vue 3 + Vite — multi-entry каркас (страница = отдельная точка входа), vendor-сплит с бюджетами NFR-26, постраничный план Спринты 9–11

- Статус: Принято
- Дата: 2026-11-03
- Решение: Заказчик — дословно «3 давай, но не забывай про модульную
  структуру выносы библиотек и прочее. 4 давай» (telegram:144324141,
  2026-11-02); расшифровка — ОВ-3 (стек Vue 3 + Vite, сохранение модульной
  структуры: вынос библиотек в chunks, постраничная миграция, e2e
  сохраняются), ОВ-4 (пилотная страница — «Ожидание модерации») в
  decisions/2026-11-02-sprint9-scope.md. React/Svelte и монолитный SPA
  исключены решением Заказчика (requirements-sprint9.md, «Ограничения»)
- Change: add-vue-framework-pilot (openspec/changes/add-vue-framework-pilot/)

## Контекст

Фронт — 13 HTML-монолитов `frontend/*.html` (статика тем же сервисом —
ADR-001; маршруты — `_PAGE_ROUTES` backend/app.py). Спринт 6 вынес скрипты
в native ES-модули `frontend/js/*` («модульный JS», решение Заказчика
2026-10-16), но разметка/стили/контент остаются вперемешку в каждом html:
нет сборки — нет чанков, бюджетов, минификации и переиспользования
компонентов; наращивание кабинетов (Спринты 5–8 добавили 6 страниц)
размазывает дубли по монолитам. Заказчик решил стартовать миграцию на
Vue 3 + Vite (ОВ-3/ОВ-4) при жестких ограничениях: не монолитный SPA,
библиотеки — в отдельные chunks, постранично, существующие Playwright e2e
(49 сценариев) сохраняются и остаются зелеными (NFR-27), бюджеты чанков —
150/200 КБ gzip на артефактах сборки (NFR-26). Нужно зафиксировать: каркас
сборки, доставку артефактов в контур (Dockerfile/compose/nginx — ADR-006),
правила сплита, план страниц на Спринты 9–11 и критерий приема каждого
шага.

## Решение

1. **Стек — Vue 3 + Vite (прямое решение Заказчика, ОВ-3).** Технические
   соображения (не основание выбора, а следствия): runtime Vue 3
   (composition API) ~20 КБ gzip — бюджет vendor-чанка NFR-26 (150 КБ)
   выполняется с запасом без tree-shaking-хитростей; SFC-компоненты
   продолжают модульную модель Спринта 6 (страница = модуль); Vite
   нативно поддерживает multi-entry MPA и manualChunks без слоя
   конфигурации. React/Svelte — отклонены решением Заказчика (ТЗ: «не
   рассматриваются»); версии vue/vite/@vitejs/plugin-vue — pinned в
   package.json (наследование практики pinned-образов ADR-006).
2. **Каркас — multi-entry MPA: страница = отдельная точка входа, НЕ
   SPA-монолит (ОВ-3).** Каждая мигрированная страница — собственный
   HTML-вход Vite и собственный чанк; клиентский роутер не вводится,
   навигация — обычные ссылки. Страница загружает только свои чанки и
   требуемые vendor-чанки (NFR-26), код немигрированных страниц в ее бандл
   физически не попадает. Общий код страниц (api-клиент, утилиты) —
   отдельный чанк `shared` (свой код, не библиотека); каждый шаг миграции
   изолирован — остальные страницы не затрагиваются.
3. **Vendor-сплит — библиотеки в собственные чанки, бюджеты NFR-26.**
   manualChunks: runtime Vue → чанк `vue`; любой будущий сторонний пакет →
   отдельный vendor-чанк по пакету; вендорный код не инлайнится в чанки
   страниц. Бюджеты: каждый vendor-чанк ≤ 150 КБ gzip; суммарный JS
   первого захода страницы (page-чанк + static-import graph) ≤ 200 КБ
   gzip. Проверка — на артефактах сборки (gzip-размеры файлов dist) на
   приемке каждого шага миграции; новая зависимость — только с оценкой
   бюджета чанка (чанк > 150 КБ gzip — отклонение или lazy-подключение).
   pinia/vue-router в каркас не входят: потребности пилота нет, лишние
   vendor-чанки против бюджетов (вернуться по потребности в плане
   миграции).
4. **Постраничная миграция: мигрированная страница заменяет HTML-монолит
   ЦЕЛИКОМ, немигрированные живут как есть.** Маршрут страницы начинает
   отдавать каркасный вход из `frontend/vue/dist`, legacy-файл удаляется
   (замена монолита целиком — «без большого переписывания» и без
   параллельного существования двух версий одной страницы). План
   очередности (Спринты 9–11): С9 — `/instructors/pending` (пилот, ОВ-4 —
   простейший статусный экран, синергия с блоком 2); С10 — одноцелевые
   экраны и формы (`/instructors/rejected`, `/registered`,
   `/admin-login`, `/instructor/cabinet-stub`, `/review`); С11 — лендинги,
   анкета с multipart, кабинеты (`/`, `/instructors`,
   `/instructors/apply`, `/cabinet`, `/instructor-choice`,
   `/instructor/dashboard`, `/admin-dashboard`). От простых к сложным;
   состав этапов внутри спринтов — за ПМ; каждый шаг принимается зеленым
   полным e2e (критерий 6).
5. **Доставка сборки в контур — node builder-этап в Dockerfile, статика
   тем же сервисом.** Workspace — `frontend/vue/` (весь фронт в frontend/,
   Docker-контекст единый); артефакты — `frontend/vue/dist` (в git не
   коммитятся). Dockerfile получает pinned node builder-этап перед python
   builder (наследование multi-stage ADR-006): `npm ci` → `npm run build`;
   runtime-этап забирает dist `COPY --from`; node_modules и dev-зависимости
   в прод-образ не попадают. `docker-compose.yml` и nginx-контур — без
   изменений: nginx остается reverse proxy, мигрированные страницы и
   ассеты (`/vue/assets/*`, base `/vue/` — вне коллизий с `/js/*`)
   отдает app (ADR-001); bare-metal FR-57 продолжает работать — перед
   деплоем тот же `npm ci && npm run build`. Dev-режим — `npm run dev`
   (Vite dev server с proxy `/api/*` на локальный uvicorn); e2e и приемка
   — только против собранного dist.
6. **Критерий приема каждого шага миграции — существующие e2e зелеными
   без правок (FR-85, NFR-27).** Сценарии `tests/test_ui_playwright.py`
   (49) не переписываются: селекторы, маршруты, ожидания — без правок
   (якорь пилота: TC-UI-004 — редирект на `/instructors/pending` и h1
   «Заявка на рассмотрении»). Порядок прогона: `npm ci && npm run build` →
   `pytest tests/test_ui_playwright.py` (тот же контур: uvicorn
   backend.app:app); CI добавляет шаг сборки перед e2e. Маршруты страниц и
   публичные API не меняются ломающим образом (`/api/*` каркасом не
   затрагиваются).

## Альтернативы (и почему отклонены)

- **React / Svelte** — отклонено: прямое решение Заказчика — Vue 3 + Vite;
  ТЗ фиксирует запрет на рассмотрение иных фреймворков. Технические
  соображения против (для полноты): React — тяжелее runtime и дальше от
  текущей HTML-модульности; Svelte — компиляторная модель как новый класс
  рисков сборки при меньшей экосистеме.
- **SPA-монолит (один вход + vue-router)** — отклонено: прямо запрещен
  директивой ОВ-3; вся навигация и все страницы в одном бандле — бюджеты
  NFR-26 невыполнимы, риск для 49 e2e максимален.
- **Один entry + динамические импорты страниц («SPA-lite»)** —
  отклонено: замаскированный SPA — единый runtime-вход и роутер-обвязка
  против буквы ОВ-3 («страница = отдельная точка входа»).
- **webpack/Vue CLI** — отклонено: решение Заказчика — Vite; тот же
  multi-entry + сплит потребовал бы большего слоя конфигурации.
- **Верхнеуровневый каталог `app/` для workspace** — отклонено: коллизия
  имени с backend/app.py, размытие зонирования (фронт в двух корнях
  репозитория), расширение Docker-контекста; выбран `frontend/vue/`.
- **Коммит dist в git** — отклонено: артефакт сборки в VCS расходится с
  исходниками и шумит diff (наследование INC-001: окружение — артефакт
  репозитория, собирается из исходников).
- **Сборка на хосте + монтирование dist / npm ci на runtime-этапе** —
  отклонено: первая ломает инвариант «образ самодостаточен» (ADR-006),
  вторая кладет Node и dev-зависимости в прод-образ (против чистоты
  ADR-006/NFR-11).
- **Отдача dist напрямую nginx (отдельный статик-контур)** — отклонено:
  новый контур доставки в pinned nginx-образ и второй конфиг для
  bare-metal — против ADR-001/FR-57; revisit — Релиз 1 (паттерны 1/2
  карты архитектуры).
- **e2e против legacy-страницы во время миграции** — отклонено: приемка
  фиктивна («мигрировано», а гоняется старое); против FR-86/GIVEN
  «страница обслуживается новым каркасом». e2e — только против dist.
- **pinia/vue-router в каркасе с первого шага** — отклонено: потребности
  пилота нет; лишние vendor-чанки против бюджетов; состояние и навигация
  кабинетов — вопрос последующих спринтов в границах плана (п.4).

## Последствия

- Положительные: постраничная миграция без «большого переписывания» —
  каждый шаг изолирован и принимается зеленым полным e2e; бюджеты чанков
  проверяемы на артефактах сборки, а не обещаниями; модульная структура
  Спринта 6 сохранена и усилена (vendor-чанки, shared-чанк, компоненты);
  контур доставки наследует multi-stage ADR-006 — compose, nginx,
  bare-metal и CI меняются минимально (один новый builder-этап и шаг
  сборки перед e2e).
- Отрицательные / техдолг (принят осознанно): второй pinned базовый образ
  (node) и удорожание docker build на npm ci (layer-cache по манифесту);
  сборка перед e2e — новый обязательный шаг контура (забытая сборка =
  красный прогон с понятной причиной: маршруты отдают 404 по dist);
  app.py остается точкой статики и для собранных страниц (revisit —
  Релиз 1); дублирование стилей/разметки шапки/футера между немигрированными
  монолитами и Vue-компонентами — временное состояние постраничной
  миграции, исчезает по мере миграции С10–С11; плана автотестов на
  бюджеты в CI (отдельно от приемки) нет — контроль ручной на приемке.
- Контроль допущений: сборка воспроизводима из чистого checkout
  (npm ci → npm run build без предупреждений блокирующих типов); бюджеты —
  фактические gzip-размеры чанков dist (задача 4.1 пакета); полный e2e —
  49 passed без правок сценариев (задача 5.1); образ содержит dist и не
  содержит node_modules (задача 2.2); Dev-режим не используется в приемке
  (e2e только против dist).
