# ADR-006: Контейнеризация (Спринт 6) — compose-контур app + nginx + MinIO, named volumes, секреты вне образов, переход bare-metal → compose без правок кода

- Статус: Принято
- Дата: 2026-10-25
- Решение: Заказчик — «контейнеризация + модульный JS» (Спринт 6, Партия A,
  задача 6.1, 2026-10-23); решения-дефолты утверждены составом Спринта 6
  (requirements-containerization.md, раздел «Решения-дефолты»); техрешения —
  research.md/design.md пакета add-containerization
- Change: add-containerization (openspec/changes/add-containerization/)
- Ревью: openspec/changes/add-containerization/arch-review.md (verdict:
  needs-rework — MAJ-1 механика доставки тестов в контейнер, MIN-1…4;
  ключевые решения настоящего ADR от замечаний не зависят — MAJ-1 касается
  только механики прогона тестов внутри уже выбранного контура; прецедент —
  ADR-003/004/005)

## Контекст

Рантайм живет в общемашиночных окружениях и bare-metal systemd — и это уже
дважды стреляло: INC-001 (рецидивирующий 502: обновление тулчейна сбросило
python-окружение, uvicorn «пропал», фикс потерялся в рантайм-копии юнита) и
INC-006 (секреты в cp-цепочках деплой-скриптов). Паттерн 4 архитектурной
карты («сервисы в контейнерах») до сих пор был отложенным решением
Заказчика. Нужно зафиксировать контур контейнеризации: образ, compose-стек,
хранилища состояния, секреты, сети — и способ сосуществования с действующим
bare-metal systemd-деплоем (переключение без правок кода, FR-57). Параллельно
готовится контур под файловое хранилище S3 (BACKLOG 2026-10-16): файловый
интерфейс уже изолирован в uploads.py.

## Решение

1. **Окружение — артефакт репозитория: multi-stage Dockerfile на pinned
   python:3.12-slim, .venv собирается в builder-этапе и переносится в
   финальный образ COPY --from, запуск от non-root appuser.** Тег базы
   согласован с CI (3.12) и systemd-рантаймом (.venv того же интерпретатора);
   версии зависимостей пинятся в requirements.txt по фактически
   установленным в .venv (контейнер = bare-metal рантайм, страховка FR-57).
   Каталоги точек монтирования /data/db и /data/uploads создаются в образе с
   владельцем appuser — named volume при первом монтировании наследует права,
   иначе root-владелец тома ломает non-root. Наследование урока INC-001:
   воспроизводимое одной командой окружение вместо состояния машины.
   Альтернативы (alpine, full, system pip) отклонены — research.md §1, §2.
2. **Compose-стек из трех сервисов: app (образ из Dockerfile) + nginx
   (reverse proxy, эквивалент deploy/nginx-autoschool.conf, TLS-файлы
   монтируются) + MinIO (S3-совместимое хранилище — контур под задачу 6.3).
   Две сети: frontend (nginx ↔ app) и backend (app ↔ MinIO); наружу
   публикуются только 80/443 nginx; порты app (8390) и MinIO (9000/9001) не
   публикуются.** Сегментация — буква NFR-16; MinIO включается в стек сразу,
   чтобы стек не менялся дважды (задача 6.1 → 6.3), S3-адаптер uploads.py —
   отдельная дельта, файловый интерфейс уже изолирован (AUTOSCHOOL_UPLOADS_DIR
   — единственная точка путей). Healthcheck — GET /api/health средствами
   python stdlib из образа (HEALTHCHECK + compose, без установки curl ради
   чека); nginx стартует по depends_on app service_healthy. Альтернативы
   (одна сеть, MinIO позже, curl-чек) отклонены — research.md §3, §5, §6.
3. **Состояние — именованные тома (db, uploads, minio-data); секреты —
   только env_file (.env вне git и вне контекста сборки) и монтируемые
   файлы (TLS); ни одного секрета в слоях образов.** Пути в контейнере
   переопределяются существующими env (AUTOSCHOOL_DB_PATH,
   AUTOSCHOOL_UPLOADS_DIR) — новая механика не изобретается; .dockerignore
   исключает .env*, deploy/tls/, data/ из контекста. Отсутствие обязательных
   секретов — явная ошибка старта (config.py _require), не тихий дефолт;
   дефолтные minioadmin-креды запрещены. Наследование NFR-3/INC-006.
   Bind mounts отклонены — research.md §4.
4. **Bare-metal systemd-деплой остается рабочим режимом: переключение
   compose ↔ systemd — только окружением и конфигурациями, код приложения не
   меняется (FR-57).** deploy/autoschool.service и
   deploy/nginx-autoschool.conf — без правок; env-изоляции config.py/db.py/
   uploads.py достаточно; единственное отличие контейнера (bind 0.0.0.0
   против 127.0.0.1) — аргумент CMD, не код. Инициализация БД при старте —
   существующая идемпотентная механика init_db/lifespan (FR-53), отдельный
   entrypoint не вводится. Оба режима и предупреждение INC-001 («не чинить
   рантайм мимо репо») документируются в deploy/container-README.md.
5. **Тесты — внутри контейнера на том же образе, что поставляется (один
   digest, никакого test-образа); CI собирает образ и гоняет pytest внутри
   на каждый PR.** Прогон с временной БД (/tmp) вне постоянных томов;
   механика одна локально и в CI; e2e остается хостовым. Механика доставки
   tests/ в контейнер (read-only mount при compose run — рекомендовано —
   либо COPY) доопределяется СА по MAJ-1 arch-review — на выбор контура
   (решения 1–4) не влияет.

## Альтернативы (и почему отклонены)

- **python:alpine / full** — сборочные сюрпризы bcrypt / лишний вес —
  research.md §1.
- **pip в system site-packages** — мусор в runtime, PEP 668 — research.md §2.
- **curl/wget ради healthcheck** — лишний пакет в прод-образе — research.md §3.
- **Bind mounts каталогов репо** — связывает стенд с деревом репо и uid хоста
  (non-root в контейнере) — research.md §4.
- **Одна default-сеть** — MinIO и nginx в одном сегменте с app — research.md §5.
- **MinIO отложить до S3-адаптера** — стек меняется дважды — research.md §6.
- **Отдельный test-target образ** — риск «тестировали не то, что поставляем» —
  research.md §7.
- **Ветвь конфигов/юнита для контейнеров, отказ от bare-metal** —
  дублирование и потеря рабочего режима — research.md §8, FR-57.
- **Kubernetes/swarm, watchtower, продовый TLS** — вне скоупа Спринта 6
  (границы ТЗ; один узел, single-worker-инвариант наследуется).

## Последствия

- Положительные: окружение воспроизводимо одной командой и версионируется
  вместе с кодом (закрытие класса INC-001); секреты вне образов, контекста и
  cp-цепочек (наследование NFR-3/INC-006); состояние переживает
  пересоздание контейнеров (named volumes); healthcheck — машинный признак
  живости для nginx и эксплуатации; тесты покрывают ровно поставляемый
  digest; второй режим деплоя не ломает первый (FR-57).
- Отрицательные / техдолг (принят осознанно): dev-зависимости (pytest,
  httpx) присутствуют в прод-образе — цена «одного digest» (research.md §7,
  объем мал); файлы на named volumes принадлежат uid appuser на хосте —
  обслуживание тома на хосте требует root/docker (буква NFR-11 об обслуживании
  на хосте — осознанное ограничение); Docker HEALTHCHECK сам контейнер не
  рестартует — живость чинит restart: unless-stopped (exited) и nginx
  routing (не отвечает); данные bare-metal (data/) и compose-томов — разные
  хранилища, перенос при первом переключении режимов не автоматизирован
  (процедура — container-README, доопределяется по MIN-2 arch-review);
  digest базового образа и образов nginx/minio — теги, не digest (NFR-12
  «в идеале digest» — задача dev).
- Контроль допущений: non-root (docker inspect USER) и отсутствие
  .env/tls/data в образе — готовность 1.1; порты наружу только 80/443
  (`ss -tlnp`) и переживание down/up — готовность 2.1; идемпотентный старт на
  несвежем томе — 2.2; тесты в контейнере на чистой машине — 3.1; красный CI
  на ломающем Dockerfile и падающем тесте — 4.1; полный контур и
  переключение режимов — 5.1; приемка — 6.5.
