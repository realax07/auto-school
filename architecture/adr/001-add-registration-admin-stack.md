# ADR-001: Стек и контур спринта-0 (регистрация + админка)

- Статус: Принято
- Дата: 2026-10-08
- Решение: Заказчик (утвержденный дизайн docs/superpowers/specs/2026-10-08-registration-admin-design.md, чат-лог 2026-10-08; ограничения ТЗ requirements.md)
- Ревью: test-model/reviews/add-registration-admin/review-001-architecture.md

## Контекст

Спринт-0 — минимальный работающий контур «регистрация ученика → БД → админка».
Инфраструктура (nginx/TLS, gateway, контейнеры, оркестрация) отложена
Заказчиком до первого ТЗ (решение 2026-10-06). Стек ограничен ТЗ:
FastAPI + SQLite + статика без сборки, Python ≥ 3.11. Нужно зафиксировать,
как контур ложится на карту: кто отдает статику, где живут секреты, как
авторизуется админ.

## Решение

1. **Один FastAPI-сервис (uvicorn, single-worker) отдает и API, и статику.**
   Фронт — дословные копии утвержденных макетов design/mocks + wiring (fetch,
   редиректы, показ ошибок). В спринте-0 нет отдельного веб-сервера — нет
   второго движущегося элемента.
2. **SQLite, файл data/app.db, режим WAL; SQL только параметризованный.**
   БД принадлежит только этому сервису (паттерн 3 карты); в БД только
   хранение (паттерн 5): UNIQUE-констрейнт, без логики; роль «Ученик» для
   CSV — в коде.
3. **Пароли — bcrypt напрямую (cost 12), без passlib.** Ученический пароль —
   только хэш в password_hash; админ-пароль — bcrypt-хэш в .env
   (ADMIN_PASSWORD_HASH), не открытый текст.
4. **Авторизация админ-API — in-memory токен** (secrets.token_urlsafe(32),
   TTL 12 ч, заголовок X-Admin-Token), выдается только успешным входом.
   Следствие: single-worker обязателен; рестарт = пере-вход. Задокументировано
   как приемлемое для спринта-0.
5. **Секреты — в .env (в .gitignore), в репозитории — .env.example** с
   инструкцией генерации bcrypt-хэша; отсутствие обязательной переменной —
   явная ошибка при старте, не тихий дефолт (NFR-3).

## Альтернативы (и почему отклонены)

- **Отдельный фронтенд-вебсервер для статики** — отклонено: второй
  движущийся элемент в нулевом спринте без выигрыша; именно такое непроверенное
  допущение обвалило доставку UI в прецеденте DEF-002. Здесь назначен
  единственный явный отдающий — сам сервис.
- **PostgreSQL** — отложено до Релиза 1: требует сервер/контейнер, что вне
  границы «без деплоя» (оркестрация — открытый вопрос).
- **JWT / сессионные cookie для админа** — отклонено для спринта-0: JWT —
  лишняя зависимость и управление секретом/ротацией для одного админа
  (отложено до появления кабинетов); cookie — CSRF-поверхность при
  fetch + заголовке.
- **JSON-файл вместо БД** — отклонено: нет атомарности и UNIQUE email,
  конфликт с паттерном 5.
- **argon2id/scrypt** — отклонено: ТЗ задает bcrypt cost 12.

## Последствия

- Положительные: нулевая инфраструктура; OpenAPI автогенерируется (паттерн 7);
  мгновенный отзыв всех токенов рестартом; переход к Релизу 1 (сервис за
  Nginx/Gateway, статика под веб-сервер) не меняет API-контрактов.
- Отрицательные / техдолг (принят осознанно): потеря токенов при рестарте;
  no rate-limit на /api/admin/login; плейн HTTP; UTC-времена vs локальная дата
  в выдаче; CSV-инъекция — решение Заказчика (см. review-001 MAJ-2).
- Контроль допущений: время bcrypt на целевой машине и WAL под нагрузкой —
  тестом замера (tasks 5.1), не принято на слово.
