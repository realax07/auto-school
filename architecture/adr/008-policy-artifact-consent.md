# ADR-008: Политика персональных данных — единый заменяемый артефакт в контуре деплоя, домен PersonalData (backend/policy.py), фиксация согласия (consent_at + версия из артефакта)

## Контекст

Сервис собирает ПД (ФИО, телефон, email, адрес, реквизиты и фото ВУ,
госномер, фото СТС/авто), но политики не существует: в анкете инструктора
заглушка «Перед запуском здесь должна быть ссылка…», в модалке регистрации
ученика согласие не выражается вовсе; согласие инструктора (MIN-2, Спринт 3)
проверяется, но НЕ фиксируется — ни даты, ни версии текста, на который
заявитель согласился. Блокер запуска в эксплуатацию. Требования блока 1
Спринта 9: FR-76…FR-79 + NFR-25 (подмена ОДНОГО артефакта ≤ 15 минут без
правки кода, пересборки бандлов и участия разработчика). Нужно зафиксировать:
где живет артефакт и как подменяется, как фиксируется согласие в модели
данных и как раздается текст без вшивания в HTML/JS.

## Решение

1. **Артефакт — файл `deploy/policy/policy.md` в контуре деплоя с точкой
   монтирования; переопределение — env `POLICY_FILE`.** Формат: шапка
   (`policy-version`, `policy-date` до разделителя `---`) + plain-text
   (абзацы через пустую строку, без HTML/markdown — рендер без инъекций).
   Композиция: bind-mount `${POLICY_DIR:-./deploy/policy}:/app/deploy/policy:ro`
   (механика deploy/container/nginx.conf и TLS — ADR-006: контур деплоя
   монтируется :ro, в образ НЕ входит — Dockerfile COPY deploy/ не выполняет).
   Подмена = замена файла на хосте (+ рестарт контейнера — страховка);
   чтение с диска НА КАЖДЫЙ запрос (кэш в процессе не вводится) — новый
   текст/версия актуальны сразу, без пересборки образа и правки HTML/JS,
   ≤ 15 минут без разработчика (NFR-25). Альтернативы отклонены:
   файл в образе — подмена требует пересборки (прямое нарушение NFR-25);
   named volume — артефакт не «состояние» (в отличие от db/uploads), а
   контент с источником истины в git (шаблон версионируется репозиторием),
   том усложняет аудит «что сейчас развернуто» и уходит от прецедента
   монтирований ADR-006. Отступлений от ADR-004 нет: артефакт — не ПД
   пользователей, лежит в deploy-контуре, выдается публичным эндпоинтом
   по замыслу.
2. **Домен PersonalData — отдельный модуль `backend/policy.py`** (директива
   модульности Спринта 6, прецедент booking.py/instructor_documents.py):
   единственный парсер артефакта read_policy(), публичный GET /api/policy
   (механика /api/health — без префикса роли: политика читается гостем ДО
   любой регистрации), хелпер версии для фиксации согласия. Нарушение
   формата (нет шапки/ключей/разделителя, пустой текст, файл отсутствует)
   → артефакт «поврежден»: GET /api/policy → 500 {ok:false, error:"Политика:
   временно недоступна"} без раскрытия содержимого (NFR-10). Страница
   /policy — оболочка frontend/policy.html в _PAGE_ROUTES: текста политики
   в HTML/JS нет (grep-контроль NFR-25), загрузка fetch-ом, рендер
   текстовыми узлами (не innerHTML).
3. **Фиксация согласия — атрибуты самой записи, без новой таблицы:**
   consent_at (UTC сервера, формат created_at) + consent_policy_version
   (версия ИЗ артефакта на момент сабмита — сервер читает сам, клиентской
   версии не доверять) в users и instructor_applications — 4 NULL-able
   TEXT-колонки через _COLUMN_MIGRATIONS (idempotent-механика users.role /
   instructor_cars.status, init_db через lifespan — наследование
   add-containerization). Легаси-строки — NULL БЕЗ seed/backfill (в отличие
   от seed verified v1 в ADR-007: дату/версию согласия легаси-записей взять
   неоткуда — повторное согласие вне объема). Консент-журнал аудита —
   точка расширения. Создание заявки/пользователя при поврежденном артефакте
   НЕ выполняется (500 {ok:false}) — fail-closed по FR-79: запись без
   согласия на конкретную версию не создается.
4. **Чекбоксы в обоих контурах — серверная проверка обязательна** (клиентский
   гейт — удобство, не защита): инструктор — проверка уже была (MIN-2,
   Спринт 3, позиция 1a instructors.py) — без изменений, добавляется только
   фиксация; ученик — НОВОЕ обязательное поле consent (bool = False,
   механика MAJ-1: дефолты, валидация в хендлере) в POST /api/register,
   позиция 1a → 422 {ok:false, error:"Согласие: поле обязательно"}.
   Обязательность consent для старых клиентов /api/register — требуемое
   изменение поведения (FR-78, Must), прецедент — введение consent в apply
   Спринтом 3; маршруты/шейпы/ответы ({ok:true, token}, {ok:true}) без
   изменений (NFR-27).

## Последствия

- Подмена политики — операция владельца сервиса (deploy-доступ), не
  разработчика: замена файла + рестарт, контроль GET /api/policy (RUNBOOK).
- Битый/отсутствующий артефакт блокирует ОБЕ регистрации и страницу /policy
  при зеленом /api/health (HEALTHCHECK артефакт не проверяет) — артефакт
  становится Tier-1 зависимостью эксплуатации (замечание MIN-1 arch-review;
  RUNBOOK обязан фиксировать операцию и контроль).
- consent_policy_version — ссылка на строку; текст версии НЕ архивируется:
  после подмены текст прежней версии невосстановим (сознательное ограничение,
  точка расширения при появлении требования аудита).
- История версий, повторное согласие, PDF-выгрузка, ссылка в футерах —
  точки расширения, не в объеме Спринта 9.
- Отсутствие rate-limit на публичных эндпоинтах (наследованный техдолг
  ADR-001/002) распространяется на GET /api/policy (полный текст на каждый
  запрос; чтение десятков КБ — незначительная нагрузка, single-worker).
