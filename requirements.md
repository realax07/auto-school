# Требования: Авторизация и кабинет ученика (Спринт 1)

> Автор: PM-агент (main, Egor Kotov)
> Статус: УТВЕРЖДЕН

## Описание

Площадка-автошкола. Спринт 1 добавляет к Спринту 0: авторизацию отдельным
сервисом (учетные записи двух типов — ученики и водители; в этом спринте
реализуются только ученики, водители — позже) и личный кабинет ученика по
утвержденному мокапу design/mocks/cabinet-student.html (плитки-сервисы и
чат — визуал-заглушки). Регистрация из Спринта 0 сохраняется без изменений.

## Аудитория

Ученики (вход в кабинет), администратор школы (Спринт 0).

## Функциональные требования

- FR-1: Сервис авторизации MUST принимать логин (email) и пароль и при
  совпадении с учетной записью ученика выдавать сессионный токен.
- FR-2: Сервис авторизации MUST отклонять вход при неверном email, неверном
  пароле или отсутствующей учетной записи (единое сообщение без раскрытия
  деталей).
- FR-3: Учетные данные MUST храниться в отдельной таблице users (bcrypt-хэш,
  в открытом виде пароли не хранятся и не логируются).
- FR-4: После успешного входа ученик MUST попадать в личный кабинет
  /cabinet (макет design/mocks/cabinet-student.html).
- FR-5: Кабинет MUST отображать ФИО ученика из учетной записи.
- FR-6: Кабинет MUST содержать чат-бар (Гига ГАИшник) и три плитки-сервиса
  (Обучение ПДД, Онлайн экзамен, Найти водителя) как визуал-заглушки;
  клики не выполняют сервисных действий.
- FR-7: Доступ к кабинету MUST требовать действующий сессионный токен; без
  него — возврат на страницу входа.
- FR-8: Выход MUST аннулировать сессионный токен и возвращать на главную.
- FR-9: Тексты и стили кабинета MUST соответствовать утвержденному мокапу
  дословно (кроме wiring и подстановки ФИО).

## Нефункциональные требования

- NFR-1: Ответ авторизации MUST быть ≤ 500 мс на типичных данных.
- NFR-2: SQL MUST быть параметризованным (без конкатенации строк).
- NFR-3: Токены и секреты MUST не попадать в репозиторий и логи.

## Приоритеты (MoSCoW)

- Must: FR-1…FR-9, NFR-1…NFR-3.

## Ограничения

- Авторизация — отдельный сервис/модуль (решение Заказчика), не вплетена в
  register.py Спринта 0.
- Водители (вторая учетка) — вне этого спринта.
- Кабинет: без реальных сервисов за плитками (визуал).
- Стек: FastAPI + SQLite + статика без сборки; Python ≥ 3.11.

## Открытые вопросы

- Нет (водители отложены Заказчиком: «Пока не трогай водил»).
