## INC-001: рецидивирующий 502 на стенде (2026-10-14 → 2026-10-15)

**Симптом:** сайт 502; сервис autoschool в цикле рестартов «No module named uvicorn».

**Хронология причин (луковица):**
1. Тулчейн-обновление машины сбросило npm/python-окружения → у python из systemd-юнита пропал uvicorn.
2. Первичный фикс был сделан в рантайм-копии юнита (/etc/systemd/system/...) и утерян: `~/service-start.sh` копирует юнит ИЗ РЕПО (deploy/autoschool.service) при каждом запуске — затирая фикс.
3. Sed-фикс в своё время не сработал из-за маскирования цифр версии в пути (см. «Урок 3»).

**Root cause:** фикс применён к симптом-копии, а не к источнику истины. deploy/autoschool.service оставался с битым ExecStart.

**Исправление:** PR#48 — ExecStart → /home/hermes-bot/auto-school/.venv/bin/python (venv живёт в репо, переживает сбросы тулчейна). service-start.sh теперь сам ставит рабочий юнит.

**Уроки (→ процесс):**
1. Фиксы конфигов вне репо — всегда временные; источник истины — в git. Если чинишь рантайм — сразу заводи PR на источник.
2. Инфраструктура (python-окружения) должна жить в проекте (.venv), не в общемашиночных тулчейнах.
3. Пути с маскируемыми секретами/версиями в sed — ломаются тихо; проверки после правки обязательны (systemctl is-active, curl health).
4. Деплой-скрипты в $HOME — часть сервиса: их поведение (что копируют, что затирают) должно быть известно ПМ до правок вокруг них.

## INC-002: BUG-044 — вёрстка кабинета «уезжала» в сайдбар (2026-10-14)

Регэксп-замена сайдбара по усечённому мокапу поглотила закрывающий `</aside>`; main остался внутри aside. Строковые юнит-тесты структурный дефект не ловили. Фикс: PR#44; структурная проверка вёрстки теперь покрыта e2e (TC-UI-005, playwright-ui-tests).

**Урок:** структурные HTML-правки — не регэкспами по вьюверу; структурные свойства — структурными тестами (локаторы/bounding-box), не substring-проверками.

## INC-003: QA-агент применил чужой stash (2026-10-15)

При проверке pre-existing ошибки qa-агент сделал `git stash pop/apply` чужого stash@{0} (Спринт 1) в общем дереве — сам откатил полностью (дерево == HEAD, stash цел). Урок: сабагентам запрещены stash-операции в общих деревьях; «чужой» stash не трогать, состояние верифицировать `git status`+`git diff`.

## INC-004: коммиты мимо ветки PR (паттерн, 2 раза за спринт)

После merge ПМ остается в main; следующий «быстрый фикс» без смены ветки уезжает в main. Ловится `git status -sb`, лечение: reset main → cherry-pick в ветку задачи. Урок: после merge первая команда — `git checkout -b <task-branch>`; правило уже в скилле — усилить контролем в чек-листе ПМ.

## INC-005: TC-трассировка backend-тестов — системный долг rule 6

Фабричный flow_check (rule 6) требует TC-трассировку в docstring ЛЮБЫХ тестов, включая backend (tests/test_s3_backend.py — 48 тестов). Репо-CI (старый flow_check) этого не видит. Решено Заказчиком как отложенный долг (вместе с 84 TC). Урок: trace-требование уточнить в контракте (backend-тесты → TC или отдельное правило), иначе долг растет каждым спринтом.
