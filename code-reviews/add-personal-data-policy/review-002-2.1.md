Не является замечанием (соответствует контракту/решениям):
- Чтение НА КАЖДЫЙ запрос без кэша: open/read в теле read_policy(), POLICY_FILE
  тоже читается на каждый вызов — подмена артефакта видна немедленно даже без
  рестарта (design «Формат артефакта»; смок: swap → 2.0 без правки кода,
  TC-PD-002).
- Парсер — единственный в домене: /api/policy и оба сабмита (3.1/4.1) идут
  через один read_policy()/current_policy_version() — дублирования логики
  разбора в register/instructors нет (модульность, директива домена ПД).
- PolicyError без деталей (путь/содержимое/системное сообщение не хранятся,
  логов в модуле нет вовсе — NFR-10/запрет логирования ПД); 500
  {ok:false, error:"Политика: временно недоступна"} — дословно design
  «Обработка ошибок»; смок: «случайная строка» из битого артефакта в ответе
  отсутствует.
- Публичность: /api/policy зарегистрирован без guards (механика /api/health),
  /policy — обычный FileResponse из _PAGE_ROUTES без авторизации —
  «политика читается гостями до любой регистрации»; правило префиксов
  design.md соблюдено (без префикса роли).
- XSS-гигиена: policy.js — только textContent/createTextNode, innerHTML нет;
  разбиение абзацев `/\n\s*\n/` + trim соответствует «абзацы через пустую
  строку»; ответ не-JSON/не-200/сетевая ошибка → один честный канал
  showError() («Политика временно недоступна. Попробуйте позже»), meta
  очищается (смок/TC-UI-044 — рендер и честная ошибка на живом клиенте).
- Страница-оболочка: текста политики в HTML нет (смок: ни version, ни первые
  60 символов текста в page-исходнике), заголовок, meta-строка «Версия: …
  от …», ссылка «Назад» — состав по design «Фронт».
- app.py-включения точечные: import/include/комментарий + строка _PAGE_ROUTES —
  остальная сборка не тронута (сверка с 8.1).
