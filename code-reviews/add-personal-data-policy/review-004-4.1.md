При single-worker/локальном файле задержка микроскопическая, гонок нет (design фиксирует single-worker наследованным инвариантом) — фиксирую как сознательное упрощение, не дефект | Перенос чтения версии до db.get_conn() сделал бы блок чище; не требуется — поведение идентично, инвариант наследован |

Не является замечанием (соответствует контракту/решениям):
- Поле consent: bool = False — механика MAJ-1 (дефолты вместо
  Pydantic-required, валидация в хендлере): старые клиенты без consent →
  контрактный 422 «Согласие: поле обязательно», а не FastAPI-422 {detail} —
  требуемое изменение поведения по FR-78/design («Внимание, NFR-27»).
- Позиция 1a точно по design: после всех обязательных полей (1), ДО формата
  email — смок: пустая фамилия при consent:true → «Фамилия: поле
  обязательно»; consent:false при валидных полях → «Согласие: …» (в том
  числе раньше, чем «Email: неверный формат» — механика instructors.py
  MIN-2 воспроизведена).
- Фиксация (FR-79): policy_version — из артефакта НА МОМЕНТ САБМИТА через
  backend.policy.current_policy_version() (клиентской версии в контракте
  нет); consent_at — UTC сервера, формат created_at; оба поля в INSERT
  users параметризованно (8 ?-плейсхолдеров, NFR-10); фиксация и INSERT в
  одной ветке до commit.
- Артефакт недоступен → 500 {ok:false, error:"Сервис: политика персональных
  данных временно недоступна"} — дословно design «Обработка ошибок»,
  пользователь НЕ создается (смок: счетчик users без роста); приоритет
  500 над error корректен: policy_unavailable возникает только при
  error=None и уникальном email.
- Уникальность email не сломана: SELECT-проверка и вторая линия
  IntegrityError → 422 «Email: уже зарегистрирован» на месте (унесенный
  блок diff не менял); регресс-гард TC-REG-012/013 продублирован в
  test_policy.py::test_s9_register_duplicate_email_regression.
- Ответ успеха {ok:true, token} без изменений: _session_issue тот же
  (TTL 12ч), редирект-контракт Спринта 1 сохранен; остальные поля
  RegisterRequest не тронуты — маршруты/шейпы обратно-совместимы (NFR-27).
- Логирования ПД/согласия/содержимого артефакта в модуле нет (NFR-10);
  PolicyError перехватывается до раскрытия деталей.
- JSON-клиент, присылающий consent строкой ("true"/"1") — Pydantic v2
  приводит к True; не-булев мусор ("да") даст FastAPI-дефолт 422 {detail} —
  вне контрактного формата поля (bool), за пределами спеки; multipart-
  нормализация «да» — специфика instructors.py и на register не переносилась
  (design этого и не требует).
