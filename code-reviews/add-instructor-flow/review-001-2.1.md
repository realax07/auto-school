## Проверенные Scenario (спека admin-moderation)

- Администратор видит все заявки (включая обработанные), password_hash
  отсутствует в ответе и UI.
- Доступ без админ-токена отклоняется (все три эндпоинта + невалидный).
- Одобрение waiting → users с хэшем H, статус approved; повторное — 409.
- Вход одобренного с паролем анкеты успешен (через 3.1, тесты
  test_auth_route) — хэш перенесен без повторного хэширования.
- Отклонение без комментария недоступно (422, waiting сохранен).
- Отклонение с комментарием → deny + сохраненная причина.
- Повторное отклонение не меняет причину.
- Отклонение не-waiting → 409, users без изменений.
- 404 неизвестной заявки (approve/deny).

## Что НЕ проверено (честно)

- UI-раздел «Заявки инструкторов» в админ-дашборде: фронт админки заявок не
  показывает — интеграция UI↔API не входит в файлы задач части 1 (API-домен
  готов и проверен; пользовательская админка — вопрос приемки 6.1).
- Одновременный approve из двух сессий (гонка guard-статуса) — по коду:
  оба в threadpool могут прочитать waiting до чужого UPDATE; второй UPDATE
  перезапишет approved тем же значением (не 409), users не задублируется —
  исход идентичен 409-пути, контракт не нарушен.
