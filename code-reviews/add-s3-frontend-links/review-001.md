## FINDINGS

### F1 · MAJOR · БЛОКИРУЮЩИЙ — фильтры «Моих заявок» не работают (рендер игнорирует фильтр)
`frontend/my-requests.html`, `render()` (~строки 180–184):

```js
var list=reqs.filter(function(r){return filter==='all'||r.status===filter});
document.getElementById('noreq').style.display=list.length?'none':'block';
reqs.forEach(function(r){          // ← рендерится reqs, а не list
```

Список строится из `reqs`, а не из `list` → чипы «На рассмотрении / Принятые /
Отказанные» визуально переключаются, но список НЕ фильтруется никогда. Хуже:
`noreq` считается по отфильтрованному списку → при фильтре с нулевым попаданием
одновременно показывается «Заявок пока нет» И полный список заявок ниже.
Контрарно к комментарию-шапке «единственные отличия — wiring»: wiring фильтров
написан, но не подключен к рендеру.

Почему прошло: e2e TC-UI-018 фильтры не трогает — ровно тот класс «пустых» мест,
ради которого введен запрет вакуумных e2e. Фикс — одна строка (`list.forEach`),
плюс e2e-шаг: клик по фильтру → count/статусы карточек.

### F2 · MINOR (design) — расхождение с мокапом my-requests: пропало «Стаж вождения»
Мокап `design/mocks/my-requests.html`: под ФИО инструктора —
`Стаж вождения: 11 лет · заявка от 16.10.2026`. Реализация — только
`заявка от 16.10.2026`. Отклонение НЕ задокументировано в шапке страницы
(заявлено «единственные отличия — wiring»), а данных стажа в контракте
GET /api/student/requests нет — т.е. это либо согласованное с архитектором
снятие элемента (тогда оно должно быть в комментарии, как снятие «Цвет» в my-cars),
либо недоделка. На согласование/документирование.

### F3 · MINOR (design) — my-requests: состояние «отзыв уже оставлен» не различается
Мокап у принятой заявки различает `reviewed:false` («оставить отзыв →») и
`reviewed:true` («вы уже оставляли отзыв»). Реализация всегда показывает
«Оставить отзыв» — повторный вход приводит на /review и только там 409-состояние.
В API нет флага `reviewed`, поэтому поведение «съесть 409» — рабочее, но это
видимое отклонение от согласованного мокапа без пометки в шапке. Нужен либо
флаг в контракте (отдельная задача), либо явная запись «снято, потому что…».

### F4 · MINOR (design) — review-form: состояние 2 беднее мокапа + мертвый CSS
Мокап: done-блок содержит `done-stars`, `done-text` (текст отзыва) и
`Отправлен 12.10.2026 · отображается в карточке инструктора`. Реализация:
только заголовок + общая note + `Отображается в карточке инструктора`;
CSS `.done-stars`/`.done-text` остался мертвым грузом. Причина понятна
(свой отзыв после reload неоткуда взять — в API его нет), после сабмита данные
были в форме и их можно отрисовать. Требуется документирование отклонения
в шапке (по образцу «демо-переключатель снят») и удаление мертвого CSS.
Текст ссылки «Вернуться к моим заявкам» vs мокап «Вернуться к инструктору» —
окей по смыслу (переход из моих заявок), но тоже незадокументированное
словесное отклонение.

### F5 · OBSERVATION — instructor-dashboard: «Мои автомобили» рядом с демо-«Мой автомобиль»
Новый рабочий пункт «Мои автомобили» (→ /my-cars) добавлен直接 над демо-заглушкой
«Мой автомобиль (демо)». Два визуально одинаковых пункта про одно и то же —
путаница для инструктора; демо-плитку стоит скрыть/переименовать (вне скоупа
этого change, но заметка Заказчику).

### NIT-1 · my-cars: `min="1950"` vs мокап `min="1980"`
Реализация следует бэкенд-контракту (_YEAR_MIN=1950) — правильно, но это
незадокументированное числовое отклонение от «1в1». Плюс из подстроки карточки
мокапа снято «· ученик: N» (в контракте поля нет) — тоже без пометки в шапке
(помечено только снятие «Цвет»).

### NIT-2 · my-cars `render()`: для карточек с фото добавляется скрытый пустой
`.ph-inner` (style display:none) — мертвый узел в DOM, удалить.

### NIT-3 · review-form `paint()`: `innerHTML` со статическими LABELS
Безопасно (данных пользователя нет), но противоречит собственной дисциплине
страницы «пользовательские строки — только через textContent»; лучше собрать
через textContent/`<b>`-элемент.

### NIT-4 · `scripts/check_tag_balance_s4.py` — одноразовый скрипт вне pytest
Баланс проверен вручную (OK), но при следующем редактировании страниц никто
не перезапустит скрипт. Перенести как параметризованный pytest-тест
(3 строки), скрипт удалить.

### NIT-5 · e2e-покрытие — дыры, не заблокировавшие приемку, но желательные
- фильтры my-requests (см. F1 — именно здесь и проскочил баг);
- отказ невалидного файла фото через UI (422-тост, magic bytes);
- фото на СОЗДАВАЕМОМ авто (сейчас фото проверено только через edit-путь);
- /review без `?instructor=` → редирект на /my-requests;
- «Повторить заявку» при активной (409-тост) через UI.

## Мокапы (фокус 3) — сводка
my-cars: структура/классы/тексты 1в1; отклонения — «Цвет» (задокументировано),
min года, «· ученик: N», бейдж «·2» у «Запросы» (демо-данные, допустимо).

Ни одно отклонение, кроме «Цвет» и демо-переключателя, в шапках страниц
не задокументировано — design-guard просит: «снятый элемент = строка в шапке».
