Не является замечанием (соответствует контракту/решениям):
- **Все три критерия 4.1/NFR-26 реализованы:** (а) каждый vendor-чанк ≤150 КБ
  gzip (individual check по ролям); (б) суммарный JS первого захода ≤200 КБ gzip
  — page-чанк + BFS-замыкание static-import графа от входа, найденного в dist
  html (`/vue/assets/*.js`); (в) в замыкании нет чужих page-чанков (multi-entry).
- **Метод — дословно по задаче:** `gzip -c <file> | wc -c` (execFileSync, длима
  stdout), фолбэк zlib level 6 при отсутствии CLI gzip — та же семантика дефолтного
  уровня gzip; новых зависимостей нет (node:fs/zlib/child_process).
- **Роли чанков** парсятся по правилам manualChunks (имя до 8-символьного хэша):
  shared/page/имя-пакета-vendor — согласованы с vite.config.mjs (2.1).
- **Dynamic `import(` в замыкание не входит** — соответствует определению
  NFR-26 «static-import graph»; lazy-чанки по ADR-008 — отдельная оценка бюджета
  при введении (регламент новых зависимостей).
- **Отчет задачи** (фактические размеры всех чанков) — таблица выше, годится
  для протокола приемки 6.1; скрипт печатает таблицу и роль каждого чанка.
- Контроль ручной на приемке, не в CI — сознательное ограничение, зафиксированное
  в ADR-008 («Последствия»: «плана автотестов на бюджеты в CI нет — контроль
  ручной на приемке») — противоречия нет.
