# Code review: задача 1.1 (change add-application-status-polling)

Дифф `424155f` (в составе 2946ea2..HEAD) — backend/db.py (миграция) +
backend/instructors.py (apply). Ревью по трем кругам: (1) design.md пакета
(«Модель данных», «Решение СА», MIN-2 arch-review-002) как закон,
(2) практики/безопасность (неперебираемость NFR-28, разведение веток
IntegrityError, токены вне логов), (3) интеграция с 2.1/6.1 (консумация
exchange_token эндпоинтом обмена). Факты — по диффу и свежим прогонам этой
сессии, не по памяти.

Проверено по существу:

- **Миграция idempotent** — колонки poll_token/exchange_token через
  `_COLUMN_MIGRATIONS` с guard'ом `PRAGMA table_info` (добавление только при
  отсутствии колонки); частичные UNIQUE-индексы — `CREATE UNIQUE INDEX IF NOT
  EXISTS` (`_TOKEN_INDEXES`), выполняются ПОСЛЕ миграционного цикла
  (backend/db.py:295–299) — порядок обязателен: индексы ссылаются на колонки,
  которых на legacy-БД до ALTER нет, а executescript(_SCHEMA) отрабатывает
  раньше миграций (в _SCHEMA токен-колонок и индексов нет — сверено).
  Повторный запуск init_db ничего не меняет — покрыто TC-S9BE-006 (legacy-БД
  со старыми строками: колонки добавлены, старые строки NULL — backfill НЕТ,
  повторный запуск — колонки не задвоены).
- **Токены неперебираемые** — `secrets.token_urlsafe(32)` (256 бит энтропии,
  43 симв. base64url; backend/instructors.py:65–70) — тот же генератор, что у
  сессий Спринта 1; тест фиксирует длину 43 и алфавит `[A-Za-z0-9_-]{43}`,
  несовпадение токенов двух заявок и внутри пары. Коллизия (частичный UNIQUE)
  → регенерация пары токенов и повторная вставка.
- **IntegrityError разведен (MIN-2)** — классификатор `_integrity_kind`
  (backend/instructors.py:81–90) по сообщению ошибки: маркеры poll_token /
  exchange_token → ветка регенерации (без 422), всё остальное (email) →
  `raise` → внешний обработчик → контрактная 422 «Email: уже зарегистрирован»
  БЕЗ регенерации и повторной вставки (цикла регенерации для гонки email нет:
  raise выходит из while до повторной попытки). Классификация сверена с
  РЕАЛЬНЫМИ сообщениями SQLite (колоночный UNIQUE vs имя частичного индекса)
  — test_integrity_branches_classified_by_real_sqlite_messages.
- **422 — токены не выдаются**: переменные остаются None вне INSERT-пути,
  контрактная 422 возвращается до финального return (backend/instructors.py:
  371–374) — тест проверяет отсутствие ключей poll_token/exchange_token в
  теле 422 и отсутствие строки в БД.
- Запись токенов — той же транзакцией, что INSERT заявки; ответ расширен
  добавлением полей (старые потребители игнорируют — NFR-27).

Не является замечанием (соответствует контракту/решениям design.md):

- Регенерация при коллизии обновляет ОБА токена, даже если индекс нарушил
  один — безвредно (оба еще не выданы никому, в ответ уходит финальная пара).
- `while True` без верхней границы попыток: выход из цикла гарантирован
  практически (256-битная коллизия пренебрежима), ветка email исключена из
  цикла raise'ом — смешение веток, которого требовал MIN-2, отсутствует.
- Классификация IntegrityError по ТЕКСТУ сообщения зависит от формата
  сообщений SQLite; риск снят тестом, сверяющим классификатор с сообщениями
  реального рантайма (TC-S9BE-001).
- `PRAGMA table_info({table})` в миграционном цикле — f-строка, но table —
  статическая константа кортежа `_COLUMN_MIGRATIONS` (унаследованная механика
  db.py, не новая); новые SQL-запросы в instructors.py полностью
  параметризованы (0 конкатенаций — grep по измененным модулям).
- Токены в логах отсутствуют: logging/print/logger в backend/instructors.py
  и backend/application_status.py нет вовсе (grep); в URL токены не пишутся.

## Проверенные Scenario (спека StudentFlow, дельта)

- «Экран опрашивает статус по неперебираемому идентификатору» — источник
  идентификатора (apply 200 с обоими токенами), неперебираемость
  (длина/алфавит/уникальность), сохранение в заявку той же транзакцией.
- «Экран без сохраненного идентификатора — статичный режим без запросов» —
  исторические строки NULL после миграции (backfill НЕТ) — TC-S9BE-006.
- Негативные: 422 apply (валидация) — токенов нет, заявки нет; гонка дубля
  email (IntegrityError-линия) → 422, одна заявка; коллизия токена → 200
  с регенерацией; idempotent-миграция на legacy-БД и повторный запуск;
  уникальность частичных индексов реально enforced (дубль poll_token →
  IntegrityError в тесте).
