# Code review: задача 3.1 (change add-application-status-polling)

Дифф `40f2007` (+ переформулировка комментария `7026f05`) —
frontend/js/apply.js (+16/−1). Ревью по трем кругам: (1) design.md пакета
(ключи localStorage, порядок «сохранение ДО редиректа», MIN-5 arch-review-002
— осознанность localStorage), (2) контракт ответа apply задачи 1.1
({ok, poll_token, exchange_token}; 422 — токенов нет), (3) NFR-27 —
существующий редирект/поведение формы без изменений. Факты — по коду HEAD
(2946ea2..HEAD), свежий прогон e2e этой задачей не заявлялся.

Проверено по существу:

- **Ключи — в точности по design**: `application_poll_token` /
  `application_exchange_token` (frontend/js/apply.js:84–85) — посимвольно
  совпадают с design.md («Компоненты», «Машина состояний») и tasks.md 3.1.
- **Сохранение ДО редиректа**: `localStorage.setItem` — синхронные вызовы,
  выполняются до `location.href='/instructors/pending'` (apply.js:87) —
  гонки «редирект раньше записи» нет; порядок ok-ветки: проверка 200/ok →
  запись обоих токенов → редирект.
- **422/ошибка — токены не пишутся**: запись только в ok-ветке; ветка else
  (ошибка/422) и .catch (сеть) не содержат ни одного обращения к
  localStorage — при неуспешном сабмите хранилище не трогается (в т.ч. не
  затираются токены предыдущей успешной заявки — их задача 4.1 чистит по
  своей машине состояний).
- **Отказ записи не ломает флоу**: try/catch вокруг setItem — при
  недоступном localStorage (приватный режим/квота) редирект все равно
  происходит; экран /instructors/pending без токенов уходит в STATIC-режим
  (0 запросов) — это ровно поведение design.md «нет токенов → статичный
  режим», деградации контракта нет.
- **Guard на наличие полей**: `if(res.data.poll_token)` / `if(res.data.
  exchange_token)` — пустые/отсутствующие значения не записываются
  (защита от записи "undefined" строкой при расхождении контракта).
- **NFR-27**: цель редиректа и остальная механика формы (файловые ошибки
  413/415, notice, scrollIntoView) не изменены; комментарий в коде
  точен (7026f05) — ссылается на design.md и осознанность localStorage
  (arch-review-002 MIN-5), не противоречит реализации.
- Токены в URL не пишутся и в логи не попадают: fetch POST body (FormData),
  токены только в теле ответа → localStorage; логирований в модуле нет.
