# RUNBOOK — эксплуатационные операции (Спринт 9, add-personal-data-policy)

Фактические пути/имена deploy-контура (design.md «Deploy-контур»: точные
значения фиксирует RUNBOOK).

## Контур артефакта политики (задача 6.1, NFR-25)

| Что | Значение |
|---|---|
| Артефакт на хосте | `deploy/policy/policy.md` (в git; переопределяется каталогом `POLICY_DIR` в `.env`) |
| Точка монтирования | `${POLICY_DIR:-./deploy/policy}` → `/app/deploy/policy` (**read-only**, механика `deploy/container/nginx.conf`) |
| Переменная приложения | `POLICY_FILE=/app/deploy/policy/policy.md` (docker-compose.yml, сервис `app`) |
| Локальный контур без Docker | `POLICY_FILE` не задана — используется относительный `deploy/policy/policy.md` от корня репозитория (механика `AUTOSCHOOL_DB_PATH`) |

Формат артефакта — design.md «Формат артефакта»: шапка `policy-version:`
и `policy-date:` (YYYY-MM-DD), разделитель `---`, дальше непустой текст
(plain text, абзацы через пустую строку). Нарушение формата → артефакт
считается поврежденным: /api/policy и оба контура согласия отдают 500
(сабмиты НЕ создают записи), страницы /policy показывают честную ошибку.

## Операция «Подмена политики» (NFR-25: ≤ 15 минут, без разработчика)

Замена текста политики = замена файла на хосте + рестарт backend-контейнера.
Без правки кода, без пересборки образа (`docker compose build` НЕ нужен).
Примечание: файл читается с диска на каждый запрос — текст/версия
актуальны сразу после замены; рестарт — страховка контура (и обновление
монтирования, если менялся каталог), не обязательный шаг чтения.

1. **Подготовить новый файл** (локально, любым редактором):
   поднять `policy-version` (например `1.0` → `2.0`), обновить
   `policy-date`, заменить текст после `---`. Файл — UTF-8 plain text
   без HTML/разметки (см. «Формат артефакта»).
2. **Заменить файл на хосте** (в каталоге, который смонтирован в `app`;
   дефолтно — репозиторий):
   ```
   cp policy-new.md deploy/policy/policy.md
   ```
   Если артефакт вынесен из репозитория — класть в каталог `POLICY_DIR`
   из `.env` той машины, где работает стек.
3. **Перезапустить backend-контейнер**:
   ```
   docker compose restart app
   ```
   (nginx не трогается; `up -d --build` НЕ требуется.)
4. **Контроль** (обязательный шаг операции):
   ```
   curl -s http://127.0.0.1:8390/api/policy        # или через nginx: https://<host>/api/policy
   ```
   - `GET /api/policy` → 200 `{"ok":true,"version":"2.0",...}` — версия
     в ответе равна новой `policy-version`;
   - страница `https://<host>/policy` (или `http://127.0.0.1:8390/policy`)
     показывает новый текст и новую версию в шапке;
   - если осталась старая версия — проверить, что заменили файл в том
     каталоге, который смонтирован (`docker compose exec app cat
     $POLICY_FILE | head -2`), и что формат шапки не нарушен
     (поврежденный артефакт дает 500, см. выше).

Хронометраж: шаги 1–4 — минуты; бюджет NFR-25 (15 минут) выполняется
с запасом. Откат = вернуть предыдущую версию файла и повторить шаги 3–4.
